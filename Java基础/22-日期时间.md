# 日期时间

日期时间是开发中绕不开的主题：订单的下单时间、用户的生日、定时任务的触发时机、日志的时间戳、活动的开始结束时间……几乎每个业务都要和时间打交道。Java 在这块历史上有一段「黑历史」——早期的 `Date`/`Calendar` 设计缺陷很多（月份从 0 开始、可变、线程不安全），直到 Java 8 引入 `java.time` 包才真正解决问题。

> 💡 本篇分两条线讲：先讲**旧 API**（`Date`/`SimpleDateFormat`/`Calendar`），因为维护老项目、读老源码一定会遇到；再重点讲 **Java 8 新 API**（`java.time`），这是现代开发的首选，也是面试高频考点。新 API 内容放在正文，不是补充——Java 8 是本系列的基准版本。

---

## 一、旧 API 总览

Java 早期（JDK 1.0/1.1）提供了三件套处理时间：

```
旧日期时间 API
├── java.util.Date        // 时间点（毫秒数），大部分方法已过时
├── java.text.SimpleDateFormat  // 格式化与解析
└── java.util.Calendar    // 日历字段操作（年月日时分秒）
```

> ⚠️ 这三个类**至今未被移除**，老项目大量使用。看懂它们是维护历史代码的前提，但**新代码不要再写它们**。

---

## 二、java.util.Date

`Date` 内部本质就是一个 `long` 毫秒数（距离 1970-01-01 00:00:00 UTC 的毫秒值），代表一个时间点。

### 2.1 创建与基本方法

```java
import java.util.Date;

// 创建
Date now = new Date();              // 当前时间
Date d1 = new Date(0L);            // 1970-01-01 08:00:00（东八区）
Date d2 = new Date(1000L * 60 * 60 * 24);  // 1970-01-02 08:00:00

// getTime：返回距离 1970-01-01 的毫秒数
long millis = now.getTime();
System.out.println(millis);        // 如 1700000000000

// setTime：设置毫秒数（可变！）
now.setTime(0L);

// toString：默认格式（不推荐用于展示）
System.out.println(now.toString()); // Thu Jan 01 08:00:00 CST 1970
```

### 2.2 过时方法（Deprecated）

`Date` 中大量方法被标记为 `@Deprecated`，**不要用**：

```java
Date d = new Date();
int year = d.getYear();     // ❌ 已过时，返回「年份-1900」
int month = d.getMonth();   // ❌ 已过时，月份 0-based（0~11）
int day = d.getDate();     // ❌ 已过时
d.setYear(123);            // ❌ 已过时
// 编译器会画删除线，IDE 也会警告
```

> ⚠️ 这些方法为什么过时？因为 `Date` 把「年月日」当成本地日历字段处理，但不同时区、不同日历系统下结果不一致。JDK 官方建议用 `Calendar` 替代（旧 API 内部），新代码则用 `LocalDate`。

> 📌 **规范**：新代码中 `Date` 只用于两件事——① 当作「时间戳载体」传递；② 与旧库/数据库交互。不要用它的 `getYear`/`getMonth` 等方法。

## 三、java.text.SimpleDateFormat

`SimpleDateFormat` 负责日期与字符串之间的转换：`format`（对象→字符串）和 `parse`（字符串→对象）。

### 3.1 模式字母

| 字母 | 含义 | 示例 |
| :---: | :--- | :--- |
| `y` | 年 | `yyyy` → 2024，`yy` → 24 |
| `M` | 月 | `MM` → 03，`M` → 3 |
| `d` | 日（月中） | `dd` → 09 |
| `H` | 时（24 小时制，0~23） | `HH` → 14 |
| `h` | 时（12 小时制，1~12） | `hh` → 02 |
| `m` | 分 | `mm` → 05 |
| `s` | 秒 | `ss` → 30 |
| `S` | 毫秒 | `SSS` → 789 |
| `E` | 星期 | `E` → Mon，`EEEE` → Monday（中文环境：星期一） |
| `a` | 上午/下午 | `a` → PM / 下午 |

> 💡 **大小写要分清**：`M` 是月、`m` 是分；`H` 是 24 小时制、`h` 是 12 小时制；`y` 是年、`Y` 是 Week Year（容易出错，慎用）。

### 3.2 format：日期 → 字符串

```java
import java.text.SimpleDateFormat;
import java.util.Date;

Date now = new Date();
SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss.SSS");
String text = sdf.format(now);           // 2024-05-20 14:30:45.789
System.out.println(text);

// 常见格式
new SimpleDateFormat("yyyy/MM/dd").format(now);        // 2024/05/20
new SimpleDateFormat("yyyy年MM月dd日").format(now);     // 2024年05月20日
new SimpleDateFormat("yyyyMMddHHmmss").format(now);    // 20240520143045，常用于文件名
```

### 3.3 parse：字符串 → 日期

```java
import java.text.SimpleDateFormat;
import java.text.ParseException;
import java.util.Date;

SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd");
try {
    Date d = sdf.parse("2024-05-20");   // ✅ 解析成功
    System.out.println(d);
} catch (ParseException e) {           // ❌ 解析失败必须捕获
    e.printStackTrace();
}

// ⚠️ 宽松解析：默认 lenient=true，会自动纠正非法日期
SimpleDateFormat lenient = new SimpleDateFormat("yyyy-MM-dd");
lenient.setLenient(false);              // 关闭宽松模式，严格校验
Date d = lenient.parse("2024-13-45");   // ❌ 关闭后抛 ParseException
```

> ⚠️ `parse` 一定要处理 `ParseException`（受检异常）。字符串格式与模式不匹配、日期非法（如 2 月 30 日）都会抛异常。

> 📌 **规范**：解析用户输入的日期时，务必 `setLenient(false)`，否则 `2024-02-31` 会被「纠正」成 `2024-03-02`，埋下数据错误。

## 四、java.util.Calendar

`Calendar` 是个抽象类，用 `getInstance()` 获取实例（默认返回 `GregorianCalendar`），可以按字段操作年月日时分秒。

### 4.1 基本用法

```java
import java.util.Calendar;
import java.util.Date;

Calendar cal = Calendar.getInstance();   // 当前时间

// get：取字段
int year = cal.get(Calendar.YEAR);          // 2024
int month = cal.get(Calendar.MONTH);       // ⚠️ 0~11，5 月返回 4！
int day = cal.get(Calendar.DAY_OF_MONTH);  // 20
int hour = cal.get(Calendar.HOUR_OF_DAY);  // 14
int minute = cal.get(Calendar.MINUTE);     // 30
int second = cal.get(Calendar.SECOND);     // 45
int week = cal.get(Calendar.DAY_OF_WEEK); // ⚠️ 周日=1，周六=7

// set：设置字段
cal.set(Calendar.YEAR, 2025);
cal.set(2025, Calendar.MAY, 20);           // 一次性设年月日

// add：加减（会自动进位/退位）
cal.add(Calendar.DAY_OF_MONTH, 7);         // 加 7 天
cal.add(Calendar.MONTH, -1);              // 减 1 个月

// getTime：转回 Date
Date d = cal.getTime();
```

### 4.2 月份 0-based 的坑

```java
Calendar cal = Calendar.getInstance();
cal.set(2024, 12, 1);          // ❌ 想设 12 月，实际设成次年 1 月（12 进位）
cal.set(2024, Calendar.DECEMBER, 1);  // ✅ 用常量，避免出错

int month = cal.get(Calendar.MONTH);  // 11（12 月返回 11）
System.out.println("当前月份：" + (month + 1));  // 显示要 +1
```

> ⚠️ **Calendar 的月份是 0~11**：1 月是 0、12 月是 11。这是旧 API 最臭名昭著的设计缺陷，无数 bug 源于此。务必用 `Calendar.JANUARY` 等常量，显示时记得 `+1`。

## 五、旧 API 的问题

为什么 Java 要重做一套日期 API？因为旧的有硬伤：

| 问题 | 说明 |
| :--- | :--- |
| **可变（Mutable）** | `Date`、`Calendar` 都可变，一个对象被多处引用后修改，会引发难以追踪的 bug |
| **线程不安全** | `SimpleDateFormat` 内部有共享状态，多线程并发用同一个实例会数据错乱 |
| **月份 0-based** | 1 月=0，反人类，极易出错 |
| **API 设计混乱** | `Date` 大部分方法过时，职责不清；`Calendar` 接口臃肿 |
| **时区处理弱** | 几乎只能默认时区，跨时区操作困难 |

```java
// 可变性陷阱
Date start = new Date();
Date end = start;          // ❌ 只是引用拷贝
end.setTime(end.getTime() + 1000);  // start 也被改了！
```

> ⚠️ `SimpleDateFormat` 线程不安全的坑在实战案例里专门演示，这是生产事故的常见来源。

## 六、Java 8 新 API：java.time ⭐⭐⭐

Java 8 借鉴 Joda-Time，推出了全新的 `java.time` 包。核心设计原则：**不可变**（线程安全）、**清晰分类型**（日期/时间/时间戳）、**月份 1-based**（符合直觉）。

```
java.time 包核心类
├── LocalDate        // 日期：年月日（2024-05-20）
├── LocalTime        // 时间：时分秒（14:30:45）
├── LocalDateTime    // 日期+时间（2024-05-20T14:30:45）
├── Instant          // 时间戳（UTC 秒/纳秒）
├── Duration         // 时间间隔（时分秒维度）
├── Period           // 日期间隔（年月日维度）
├── DateTimeFormatter// 格式化与解析
├── ZoneId           // 时区
└── ZonedDateTime    // 带时区的日期时间
```

> 💡 所有 `java.time` 类都是**不可变**的：`plus`/`minus`/`with` 方法都返回**新对象**，原对象不变。这点和 `String` 一样，是线程安全的根本原因。

### 6.1 LocalDate：日期

只含年月日，不涉及时区、时间，适合表示生日、纪念日、订单日期。

```java
import java.time.LocalDate;

// 创建
LocalDate today = LocalDate.now();          // 当前日期（系统时区）
LocalDate birthday = LocalDate.of(2000, 5, 20);  // 2000-05-20，月份 1-based ✅
LocalDate parsed = LocalDate.parse("2024-05-20"); // 从默认格式解析

// get：取字段
int year = today.getYear();                 // 2024
int month = today.getMonthValue();          // 5（1~12，符合直觉 ✅）
int day = today.getDayOfMonth();            // 20
int week = today.getDayOfWeek().getValue(); // 1~7，周一=1，周日=7

// plus/minus：加减（返回新对象）
LocalDate nextWeek = today.plusWeeks(1);    // 加 1 周
LocalDate lastMonth = today.minusMonths(1); // 减 1 个月
LocalDate future = today.plusDays(100);     // 加 100 天

// with：修改某字段（返回新对象）
LocalDate firstDay = today.withDayOfMonth(1);          // 改成本月 1 号
LocalDate lastDay = today.withDayOfMonth(today.lengthOfMonth()); // 本月最后一天

// 比较
boolean after = today.isAfter(birthday);    // 是否在 birthday 之后
boolean before = today.isBefore(birthday);
boolean equal = today.equals(birthday);

// 判断
today.isLeapYear();   // 是否闰年
```

> 💡 **`LocalDate` 的月份是 1~12**，和 `Calendar` 的 0~11 完全不同。这是新 API 最大的改进之一，也是从旧 API 迁移时最容易踩的坑（注意区分）。

### 6.2 LocalTime：时间

只含时分秒纳秒，不含日期，适合表示「每天 9:00 开门」「打卡时间」。

```java
import java.time.LocalTime;

LocalTime now = LocalTime.now();            // 14:30:45.123
LocalTime of = LocalTime.of(9, 30, 0);      // 09:30:00
LocalTime parsed = LocalTime.parse("14:30:00");

int hour = now.getHour();        // 14
int minute = now.getMinute();   // 30
int second = now.getSecond();    // 45

LocalTime later = now.plusHours(2);     // 加 2 小时
LocalTime earlier = now.minusMinutes(15); // 减 15 分钟
```

### 6.3 LocalDateTime：日期+时间

最常用的类，含年月日时分秒纳秒，但不带时区信息。

```java
import java.time.LocalDateTime;

LocalDateTime now = LocalDateTime.now();
LocalDateTime of = LocalDateTime.of(2024, 5, 20, 14, 30, 0);
LocalDateTime parsed = LocalDateTime.parse("2024-05-20T14:30:00");

// 拆分/合并
LocalDate date = now.toLocalDate();     // 取日期部分
LocalTime time = now.toLocalTime();     // 取时间部分
LocalDateTime ldt = LocalDateTime.of(date, time);  // 合并

// 加减与修改
LocalDateTime later = now.plusDays(7).plusHours(3);  // 链式调用
LocalDateTime atMonthStart = now.withDayOfMonth(1).withHour(0).withMinute(0).withSecond(0);

// 比较
now.isAfter(of);
now.isBefore(of);
```

> 💡 `LocalDateTime` 默认 `toString` 用 `T` 分隔日期和时间（如 `2024-05-20T14:30:00`），这是 ISO 8601 标准。展示给用户前要用 `DateTimeFormatter` 格式化。

### 6.4 Instant：时间戳

`Instant` 表示 UTC 时间线上的一个点（秒+纳秒），适合存储、传递、计算时间差，与 `Date` 语义最接近。

```java
import java.time.Instant;

Instant now = Instant.now();            // 当前 UTC 时间戳
Instant epoch = Instant.ofEpochSecond(0);   // 1970-01-01T00:00:00Z
Instant ofMilli = Instant.ofEpochMilli(1700000000000L);

long seconds = now.getEpochSecond();   // 秒
long millis = now.toEpochMilli();      // 毫秒，等价于 System.currentTimeMillis()

// 加减
Instant later = now.plusSeconds(60);
Instant earlier = now.minusMillis(1000);

// 比较
now.isAfter(epoch);
now.isBefore(epoch);
```

> ⚠️ `Instant` 是 **UTC 时间**，`Instant.now()` 和 `LocalDateTime.now()` 看起来可能差 8 小时——因为 `LocalDateTime` 是本地时区，`Instant` 是 UTC。处理跨时区数据时务必用 `Instant`。

### 6.5 Duration：时间间隔（时分秒维度）

`Duration` 以「时-分-秒-纳秒」为单位度量两个时间点之间的间隔。

```java
import java.time.Duration;
import java.time.LocalDateTime;
import java.time.LocalTime;

LocalDateTime start = LocalDateTime.of(2024, 5, 20, 9, 0, 0);
LocalDateTime end = LocalDateTime.of(2024, 5, 20, 11, 30, 0);

Duration d = Duration.between(start, end);
long hours = d.toHours();          // 2
long minutes = d.toMinutes();      // 150
long seconds = d.getSeconds();      // 9000

// 创建与运算
Duration twoHours = Duration.ofHours(2);
Duration combined = twoHours.plusMinutes(30);  // 2 小时 30 分

// 用 LocalTime 也可算
Duration d2 = Duration.between(LocalTime.of(9, 0), LocalTime.of(11, 30));
```

> 💡 `Duration` 适合度量「时长」（如视频时长、任务耗时、会话时长），不适合度量跨月/跨年的「年龄」——那种用 `Period`。

### 6.6 Period：日期间隔（年月日维度）

`Period` 以「年-月-日」为单位度量两个日期之间的间隔。

```java
import java.time.Period;
import java.time.LocalDate;

LocalDate birth = LocalDate.of(2000, 5, 20);
LocalDate today = LocalDate.now();

Period p = Period.between(birth, today);
int years = p.getYears();        // 如 24
int months = p.getMonths();      // 余下的月
int days = p.getDays();          // 余下的天
System.out.printf("年龄：%d 岁 %d 月 %d 天%n", years, months, days);

// 创建
Period tenDays = Period.ofDays(10);
Period oneYear = Period.of(1, 0, 0);
LocalDate future = today.plus(oneYear);   // 加 1 年
```

> ⚠️ `Period` 计算的是「日历意义上的差」，不是绝对天数。例如 5 月 20 日到 6 月 20 日是 `P1M`（1 个月），但天数可能是 31。要算绝对天数用 `ChronoUnit.DAYS.between(a, b)`。

```java
import java.time.temporal.ChronoUnit;
import java.time.LocalDate;

long days = ChronoUnit.DAYS.between(birth, today);  // 绝对天数
```

### 6.7 DateTimeFormatter：格式化与解析

`java.time` 自己的格式化器，**线程安全**（不可变），替代 `SimpleDateFormat`。

```java
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

LocalDateTime now = LocalDateTime.now();

// 格式化：对象 → 字符串
DateTimeFormatter fmt = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
String text = now.format(fmt);            // 2024-05-20 14:30:45
String text2 = fmt.format(now);           // 等价写法

// 解析：字符串 → 对象
LocalDateTime parsed = LocalDateTime.parse("2024-05-20 14:30:00", fmt);

// 内置格式
DateTimeFormatter isoDate = DateTimeFormatter.ISO_LOCAL_DATE;       // yyyy-MM-dd
DateTimeFormatter isoTime = DateTimeFormatter.ISO_LOCAL_TIME;        // HH:mm:ss
DateTimeFormatter isoDateTime = DateTimeFormatter.ISO_LOCAL_DATE_TIME;

// 自定义展示
String cn = now.format(DateTimeFormatter.ofPattern("yyyy年MM月dd日 HH时mm分"));
```

> 📌 **规范**：`DateTimeFormatter` 是不可变的，可以放心定义为 `static final` 常量在多线程间共享，这是它和 `SimpleDateFormat` 的本质区别。

## 七、与旧 API 互转

新代码用 `java.time`，但要和数据库、老库、`Date` 类型的字段打交道，必须会互转。桥梁是 `Instant`。

### 7.1 Date ↔ Instant

```java
import java.time.Instant;
import java.util.Date;

// Date → Instant
Date date = new Date();
Instant instant = date.toInstant();

// Instant → Date
Date back = Date.from(instant);
```

### 7.2 Date ↔ LocalDateTime（带时区转换）

```java
import java.time.*;
import java.util.Date;

Date date = new Date();
Instant instant = date.toInstant();

// Date → LocalDateTime（需要指定时区，因为 LocalDateTime 没有时区）
LocalDateTime ldt = LocalDateTime.ofInstant(instant, ZoneId.systemDefault());

// LocalDateTime → Date
Instant back = ldt.atZone(ZoneId.systemDefault()).toInstant();
Date result = Date.from(back);
```

### 7.3 Date ↔ LocalDate（只取日期）

```java
Date date = new Date();
LocalDate ld = date.toInstant()
        .atZone(ZoneId.systemDefault())
        .toLocalDate();

// LocalDate → Date（时间补 00:00:00）
Date back = Date.from(ld.atStartOfDay(ZoneId.systemDefault()).toInstant());
```

> 💡 互转的核心：`Date` 和 `Instant` 一一对应；`LocalDateTime`/`LocalDate` 没有时区，转换时必须显式给时区（一般用 `ZoneId.systemDefault()`）。

## 八、时区：ZoneId 与 ZonedDateTime

跨时区业务（国际化、海外用户、日志统一用 UTC）需要 `ZonedDateTime`。

```java
import java.time.*;

// 时区
ZoneId shanghai = ZoneId.of("Asia/Shanghai");   // 东八区
ZoneId london = ZoneId.of("Europe/London");
ZoneId utc = ZoneId.of("UTC");

// 当前各时区时间
ZonedDateTime nowSh = ZonedDateTime.now(shanghai);
ZonedDateTime nowLn = ZonedDateTime.now(london);
ZonedDateTime nowUtc = ZonedDateTime.now(utc);

// LocalDateTime 转带时区
LocalDateTime ldt = LocalDateTime.now();
ZonedDateTime zdt = ldt.atZone(shanghai);

// 时区转换（同一时刻，不同时区表示）
ZonedDateTime londonTime = zdt.withZoneSameInstant(london);  // 同一时刻的伦敦时间

// 常用时区 ID
// Asia/Shanghai  Asia/Tokyo  Europe/London  America/New_York  UTC
```

> ⚠️ 时区 ID 用「地区/城市」格式（如 `Asia/Shanghai`），不要用 `CST`/`EST` 这种缩写——`CST` 在美国是中部标准时间，在中国是标准时，歧义极大。

## ⚠️ 重点

### 重点 1：SimpleDateFormat 线程不安全 ⭐⭐⭐

```java
// ❌ 错误：多线程共享一个 SimpleDateFormat
private static final SimpleDateFormat SDF = new SimpleDateFormat("yyyy-MM-dd");
// 线程 A 和线程 B 同时调用 SDF.parse(...)，结果会错乱、甚至抛 NumberFormatException

// ✅ 正确方案一：每次 new（性能差）
String s = new SimpleDateFormat("yyyy-MM-dd").format(new Date());

// ✅ 正确方案二：用 ThreadLocal 缓存（旧 API 标准做法）
private static final ThreadLocal<SimpleDateFormat> TL =
        ThreadLocal.withInitial(() -> new SimpleDateFormat("yyyy-MM-dd"));
String s = TL.get().format(new Date());

// ✅ 正确方案三（推荐）：Java 8 直接用 DateTimeFormatter
private static final DateTimeFormatter FMT =
        DateTimeFormatter.ofPattern("yyyy-MM-dd");   // 不可变，线程安全
String s = FMT.format(LocalDate.now());
```

> ⚠️ 这是**生产事故高发点**。线上高并发接口用 `static SimpleDateFormat`，压测时偶发解析错误，排查极难。新项目一律用 `DateTimeFormatter`。

### 重点 2：月份 0-based vs 1-based ⭐⭐

```java
// 旧 API：1 月 = 0
Calendar cal = Calendar.getInstance();
cal.set(2024, 4, 20);              // 实际是 5 月 20 日！
cal.get(Calendar.MONTH);           // 5 月返回 4

// 新 API：1 月 = 1
LocalDate.of(2024, 5, 20);         // 就是 5 月 20 日 ✅
localDate.getMonthValue();         // 5 月返回 5
```

> ⚠️ 维护老代码时，看到 `Calendar.MONTH` 一定要脑内 `+1`；新代码用 `LocalDate` 不用管。两套 API 混用时最容易在这里出错。

### 重点 3：LocalDateTime 没有时区 ⭐⭐

```java
LocalDateTime ldt = LocalDateTime.now();   // 用系统默认时区
Instant instant = Instant.now();          // UTC

// ⚠️ 两者可能差 8 小时！
// ldt 是「本地墙上时间」，instant 是「绝对时刻」
// 存数据库、跨时区传递，优先用 Instant 或带时区的 ZonedDateTime
```

> 📌 **规范**：数据库存 `DATETIME` 一般对应 `LocalDateTime`；存时间戳（`TIMESTAMP`）对应 `Instant`。跨时区系统建议统一存 UTC。

### 重点 4：Duration vs Period 别混用 ⭐

```java
LocalDate birth = LocalDate.of(2000, 5, 20);
LocalDate today = LocalDate.now();

// ❌ Period 算的是日历差，不是绝对天数
Period p = Period.between(birth, today);
// p.getDays() 只是「余下的天」，不是总天数！

// ✅ 算绝对天数用 ChronoUnit
long totalDays = ChronoUnit.DAYS.between(birth, today);

// ✅ 算时长（小时/分钟）用 Duration
Duration d = Duration.between(start, end);
long hours = d.toHours();
```

### 重点 5：plus/minus 返回新对象 ⭐

```java
LocalDate today = LocalDate.now();
today.plusDays(7);            // ❌ 返回值丢了！today 本身不变
LocalDate next = today.plusDays(7);  // ✅ 必须接收返回值

// 对比旧 API：Calendar.add 会修改原对象
Calendar cal = Calendar.getInstance();
cal.add(Calendar.DAY_OF_MONTH, 7);   // 原对象被改（可变）
```

> 💡 这是新 API 和旧 API 的本质差异：新 API 不可变，所有「修改」都返回新对象。忘记接收返回值是新手最常犯的错。

### 案例 1：计算订单创建到现在的天数 ⭐⭐

电商后台常见需求：展示「订单已创建 N 天」。

```java
import java.time.LocalDateTime;
import java.time.temporal.ChronoUnit;

// 模拟订单创建时间（从数据库读出的 LocalDateTime）
LocalDateTime orderTime = LocalDateTime.of(2024, 5, 1, 10, 30, 0);

    System.out.println("订单超时，自动取消");
```

### 案例 2：生日提醒 ⭐⭐

后台定时任务每天扫描，提醒 7 天内过生日的用户。

```java
import java.time.LocalDate;
import java.time.MonthDay;
import java.time.temporal.ChronoUnit;
import java.util.Arrays;
import java.util.List;

class User {
    String name;
    LocalDate birthday;   // 数据库存生日
    // 省略构造方法
    User(String name, LocalDate birthday) { this.name = name; this.birthday = birthday; }
}

List<User> users = Arrays.asList(
        new User("张三", LocalDate.of(1995, 5, 25)),
        new User("李四", LocalDate.of(1990, 9, 10)),
        new User("王五", LocalDate.of(2000, 12, 31))
);

LocalDate today = LocalDate.now();

for (User u : users) {
    // 用 MonthDay 处理「月日」，避免闰年 2 月 29 的问题
    MonthDay birthMd = MonthDay.from(u.birthday);
    MonthDay todayMd = MonthDay.from(today);

    // 今年的生日（若今天是 2 月 28，生日是 2 月 29，今年非闰年会取 2 月 28）
    LocalDate thisYearBirthday = birthMd.atYear(today.getYear());
    if (thisYearBirthday.isBefore(today)) {
        // 今年的已过，看明年
        thisYearBirthday = birthMd.atYear(today.getYear() + 1);
    }

    long daysToBirthday = ChronoUnit.DAYS.between(today, thisYearBirthday);
    if (daysToBirthday <= 7) {
        System.out.println(u.name + " 还有 " + daysToBirthday + " 天过生日，发送提醒");
    }
}
```

> 💡 用 `MonthDay` 单独表示「月日」是处理生日的标准做法，能优雅应对 2 月 29 日这种边界情况。

### 案例 3：定时任务时间计算 ⭐⭐

后台系统常见：每天凌晨 2 点执行对账，下次执行时间怎么算？

```java
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.LocalTime;
import java.time.temporal.ChronoUnit;

// 目标：每天 02:00 执行
LocalDateTime now = LocalDateTime.now();
LocalDateTime nextRun = LocalDateTime.of(LocalDate.now().plusDays(1), LocalTime.of(2, 0));

// 如果现在还没到今天 2 点，今天就执行
LocalDateTime todayRun = LocalDateTime.of(LocalDate.now(), LocalTime.of(2, 0));
if (now.isBefore(todayRun)) {
    nextRun = todayRun;
}

long hoursToNext = ChronoUnit.HOURS.between(now, nextRun);
System.out.println("下次执行时间：" + nextRun + "，还有 " + hoursToNext + " 小时");

// 每月 1 号 0 点执行
LocalDateTime firstOfNextMonth = LocalDate.now()
        .plusMonths(1)
        .withDayOfMonth(1)
        .atStartOfDay();
System.out.println("下月 1 号：" + firstOfNextMonth);
```

### 案例 4：SimpleDateFormat 线程不安全踩坑 ⭐⭐⭐

模拟高并发下 `SimpleDateFormat` 出错：

```java
import java.text.SimpleDateFormat;
import java.util.concurrent.*;

public class SdfTrap {
    // ❌ 共享实例，多线程下会出错
    private static final SimpleDateFormat SDF = new SimpleDateFormat("yyyy-MM-dd");

    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(10);
        for (int i = 0; i < 100; i++) {
            pool.submit(() -> {
                try {
                    // 多线程并发解析，偶发 NumberFormatException 或结果错乱
                    SDF.parse("2024-05-20");
                } catch (Exception e) {
                    System.out.println("出错：" + e);
                }
            });
        }
        pool.shutdown();
    }
}

// ✅ 正确做法：用 DateTimeFormatter（不可变，天然线程安全）
private static final java.time.format.DateTimeFormatter FMT =
        java.time.format.DateTimeFormatter.ofPattern("yyyy-MM-dd");
// 多线程并发用 FMT.parse(...) 完全安全
```

> ⚠️ 这个坑在压测时才会暴露，开发环境单线程跑没事，上线后被高并发打爆。务必养成「不共享 `SimpleDateFormat`」的习惯。

### 案例 6：新旧 API 互转 ⭐⭐

老系统数据库字段是 `Date`，新代码想用 `LocalDateTime`：

```java
import java.time.*;
import java.util.Date;

// 模拟从老接口拿到的 Date
Date oldDate = new Date();

// 1. Date → LocalDateTime（用系统默认时区）
LocalDateTime ldt = LocalDateTime.ofInstant(oldDate.toInstant(), ZoneId.systemDefault());

// 2. LocalDateTime → Date（存回老接口）
Date back = Date.from(ldt.atZone(ZoneId.systemDefault()).toInstant());

// 3. Date → LocalDate（只取日期，用于按天统计）
LocalDate day = oldDate.toInstant()
        .atZone(ZoneId.systemDefault())
        .toLocalDate();

// 4. 毫秒时间戳 → LocalDateTime
long ts = System.currentTimeMillis();
LocalDateTime fromTs = LocalDateTime.ofInstant(Instant.ofEpochMilli(ts), ZoneId.systemDefault());

// 5. LocalDateTime → 毫秒时间戳
long millis = ldt.atZone(ZoneId.systemDefault()).toInstant().toEpochMilli();

System.out.println("Date: " + oldDate);
System.out.println("LocalDateTime: " + ldt);
System.out.println("LocalDate: " + day);
System.out.println("timestamp: " + millis);
```

> 📌 **封装建议**：在工具类里写两个静态方法 `toLocalDateTime(Date)` 和 `toDate(LocalDateTime)`，全项目统一调用，避免到处复制时区代码。

### 案例 7：金融系统按交易日计算 ⭐⭐

金融系统常按「自然日」而非「24 小时」计息，且要避开周末：

```java
import java.time.DayOfWeek;
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;

// 计息开始日（不含周末）
LocalDate start = LocalDate.of(2024, 5, 1);   // 周三
LocalDate end = LocalDate.of(2024, 5, 10);    // 周五

// 计算两个日期之间的「工作日」天数
long workDays = 0;
LocalDate cursor = start;
while (!cursor.isAfter(end)) {
    DayOfWeek dow = cursor.getDayOfWeek();
    if (dow != DayOfWeek.SATURDAY && dow != DayOfWeek.SUNDAY) {
        workDays++;
    }
    cursor = cursor.plusDays(1);
}
System.out.println("计息天数：" + workDays);   // 8 天

// 自然日总数
long totalDays = ChronoUnit.DAYS.between(start, end) + 1;  // 含首尾
System.out.println("自然日：" + totalDays);
```

> 💡 金融场景对「哪天算利息」非常敏感，用 `LocalDate` 按日历日逐天判断比用毫秒数除以 86400000 可靠得多——后者会被夏令时、闰秒坑到。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 旧 API 三件套 | `Date`（时间点）、`SimpleDateFormat`（格式化）、`Calendar`（日历字段） |
| 旧 API 缺陷 | 可变、线程不安全、月份 0-based、API 混乱 |
| `Date.getTime()` | 返回距离 1970-01-01 的毫秒数 |
| `SimpleDateFormat` | `format` 格式化、`parse` 解析（抛 ParseException），**线程不安全** |
| `Calendar.MONTH` | 1 月=0，显示要 +1，用常量避免出错 |
| 新 API 核心 | `java.time` 包，**不可变**、线程安全、月份 1-based |
| `LocalDate` | 日期，`now/of/get/plus/minus/with` |
| `LocalTime` | 时间（时分秒） |
| `LocalDateTime` | 日期+时间，无时区 |
| `Instant` | UTC 时间戳，与 `Date` 互转的桥梁 |
| `Duration` | 时分秒维度间隔 |
| `Period` | 年月日维度间隔（非绝对天数） |
| `ChronoUnit.DAYS.between` | 算绝对天数 |
| `DateTimeFormatter` | 线程安全的格式化器，可定义为常量共享 |
| 互转 | `Date`↔`Instant`↔`LocalDateTime`，转换需指定时区 |
| 时区 | `ZoneId.of("Asia/Shanghai")`、`ZonedDateTime` |

---

## 学习建议

1. **新代码一律用 `java.time`**：`LocalDate`/`LocalDateTime`/`DateTimeFormatter` 是现代 Java 日期时间处理的标准答案，从第一行就养成习惯，绝不要在新项目里写 `new Date()` 或 `SimpleDateFormat`。
2. **旧 API 要看得懂但不要写**：维护老项目、读开源库时一定会遇到 `Date`/`Calendar`，重点记住「月份 0-based」「`SimpleDateFormat` 不能共享」这两个坑，能看懂、能改对就行。
3. **动手跑一遍互转**：把「实战案例 6」的代码敲进 IDE，用断点看 `Date`、`Instant`、`LocalDateTime` 之间的转换过程，理解时区在转换中的作用——这是连接新旧代码的桥梁，必须熟练。
4. **重点练 Duration/Period/ChronoUnit 的区别**：算年龄、算天数、算时长分别用哪个，是面试和实战的高频考点。写几个小例子（生日还有几天、订单超时几分钟、工龄几年几月）对比一遍就清楚了。
5. **警惕时区**：跨时区系统、存时间戳到数据库、日志统一用 UTC，这些场景务必用 `Instant` 或 `ZonedDateTime`，不要用 `LocalDateTime` 存「绝对时刻」——它没时区，跨时区会出错。结合「重点 3」理解这一点。
