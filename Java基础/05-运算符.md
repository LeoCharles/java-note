# 运算符

运算符是操作数据的「工具」——加減乘除、比较大小、逻辑判断、位运算，都是运算符。Java 运算符看似简单，但暗藏不少坑：整数除法丢精度、`++` 前后顺序影响结果、短路与避免空指针、位运算做权限标志位……理解运算符的底层行为，是写出正确、高效代码的前提。

> 💡 本篇与 [04-数据类型与类型转换](04-数据类型与类型转换.md) 紧密关联：运算符的隐式类型转换、运算提升规则都建立在数据类型的基础上，建议两篇对照阅读。

## 一、算术运算符

算术运算符用于数值计算，是最基础的运算符。

| 运算符 | 说明 | 示例 |
| :---: | :--- | :--- |
| `+` | 加法 | `1 + 2 = 3` |
| `-` | 减法 | `5 - 2 = 3` |
| `*` | 乘法 | `3 * 4 = 12` |
| `/` | 除法 | `10 / 3 = 3` |
| `%` | 取模（取余） | `10 % 3 = 1` |
| `++` | 自增 | `i++`、`++i` |
| `--` | 自减 | `i--`、`--i` |

### 1.1 基本四则运算

```java
int a = 10;
int b = 3;
System.out.println(a + b);  // 13
System.out.println(a - b);  // 7
System.out.println(a * b);  // 30
System.out.println(a / b);  // 3，整数除整数，结果还是整数（截断小数）
System.out.println(a % b);  // 1，10 除以 3 余 1
```

### 1.2 整数除法的坑

```java
// 整数 / 整数 = 整数（直接截断小数，不是四舍五入）
System.out.println(10 / 3);    // 3，不是 3.33
System.out.println(7 / 2);     // 3，不是 3.5
System.out.println(1 / 2);     // 0

// 想要小数结果，至少有一个操作数是浮点数
System.out.println(10 / 3.0);  // 3.3333333333333335
System.out.println(10.0 / 3);  // 3.3333333333333335
System.out.println((double) 10 / 3);  // 3.333...，强转 10 为 double

// ❌ 常见错误：以为先算出 0.5 再乘 10
double result = 1 / 2 * 10;
System.out.println(result);   // 0.0！因为 1/2=0，0*10=0.0

// ✅ 正确写法
double result2 = 1.0 / 2 * 10;  // 5.0
```

> ⚠️ **整数除法是最常见的 bug 来源**：`1 / 2` 结果是 `0` 而不是 `0.5`。只要除号两边都是整数，结果就是整数（截断小数）。需要小数结果时，把至少一个操作数变成浮点数。

### 1.3 取模运算 `%`

取模结果是除法后的余数，符号与被除数（左操作数）一致：

```java
System.out.println(10 % 3);   // 1
System.out.println(-10 % 3);  // -1，符号跟被除数
System.out.println(10 % -3);  // 1，符号跟被除数
System.out.println(-10 % -3); // -1

// 常见用途：判断奇偶
int n = 7;
System.out.println(n % 2 == 1);  // true，奇数
System.out.println(n % 2 == 0);  // false，偶数

// 取模也适用于浮点数（但很少用）
System.out.println(10.5 % 3);  // 1.5
```

> ⚠️ **判断奇偶的陷阱**：负数取模 `% 2` 可能得到 `-1`，所以 `n % 2 == 1` 对负奇数会判错。更安全的写法是 `n % 2 != 0` 或用位运算 `((n & 1) == 1)`（见第六节位运算）。

```java
int n = -7;
System.out.println(n % 2 == 1);   // false！-7 % 2 = -1，不等于 1
System.out.println(n % 2 != 0);   // true，正确判断奇数
```

### 1.4 `+` 号的字符串拼接

`+` 不仅是数值加法，还能拼接字符串：

```java
System.out.println("hello" + "world");  // helloworld
System.out.println("age=" + 18);        // age=18
System.out.println(1 + 2);             // 3，纯数值是加法
System.out.println(1 + 2 + "3");       // 33，从左到右：1+2=3，3+"3"="33"
System.out.println("1" + 2 + 3);       // 123，从左到右："1"+2="12"，"12"+3="123"
System.out.println(1 + (2 + "3"));      // 123，括号先算：2+"3"="23"，1+"23"="123"
```

> 💡 **拼接规则**：从左到右运算，遇到字符串就变拼接。想先算数值加法，用括号括起来。

### 1.5 自增 `++` 与自减 `--`

`++` 和 `--` 让变量自身加 1 或减 1。**前置**和**后置**有区别：

| 写法 | 名称 | 说明 |
| :---: | :--- | :--- |
| `++i` | 前置自增 | 先加 1，再用新值参与运算 |
| `i++` | 后置自增 | 先用旧值参与运算，再加 1 |
| `--i` | 前置自减 | 先减 1，再用新值 |
| `i--` | 后置自减 | 先用旧值，再减 1 |

```java
int i = 5;
int a = i++;   // 先把 5 赋给 a，i 再变 6
System.out.println("a=" + a + ", i=" + i);  // a=5, i=6

int j = 5;
int b = ++j;   // j 先变 6，再把 6 赋给 b
System.out.println("b=" + b + ", j=" + j);  // b=6, j=6

// 单独使用时（不参与其他运算），前置后置效果一样
int x = 5;
x++;        // x = 6
++x;        // x = 7
```

> ⚠️ **经典面试题**：`int i = 5; int r = i++ + ++i + i++;` 结果是多少？
> 拆解：`i++`（用 5，i→6）+ `++i`（i→7，用 7）+ `i++`（用 7，i→8）= 5+7+7 = 19，最终 i=8。
> 实际开发中**绝不写这种代码**，可读性极差，拆开写才是正道。

### 1.6 `char` 参与运算

`char` 参与算术运算时，会自动提升为 `int`（取其 Unicode 码值）：

```java
char c = 'A';      // 'A' 的 Unicode 码是 65
System.out.println(c + 1);    // 66，char 提升为 int
System.out.println(c + 'B'); // 131，65 + 66

// 大小写转换：大小写字母差 32
char upper = 'A';
char lower = (char)(upper + 32);  // 'a'
char lower2 = (char)(upper + ('a' - 'A'));  // 'a'，更规范的写法

// 数字字符转数值
char digit = '7';
int num = digit - '0';   // 7，'7'的码值 - '0'的码值
```

## 二、赋值运算符

| 运算符 | 等价写法 | 说明 |
| :---: | :--- | :--- |
| `=` | — | 基本赋值 |
| `+=` | `a = a + b` | 加后赋值 |
| `-=` | `a = a - b` | 减后赋值 |
| `*=` | `a = a * b` | 乘后赋值 |
| `/=` | `a = a / b` | 除后赋值 |
| `%=` | `a = a % b` | 取模后赋值 |

```java
int a = 10;
a += 5;   // a = 15
a -= 3;   // a = 12
a *= 2;   // a = 24
a /= 5;   // a = 4
a %= 3;   // a = 1
```

### 复合赋值的隐式强转 ⭐

这是与 [04-数据类型与类型转换](04-数据类型与类型转换.md) 联动的重要知识点：

```java
byte b = 10;
b = b + 5;    // ❌ 编译错误：b+5 结果是 int，不能直接赋给 byte
b += 5;       // ✅ 编译通过！复合赋值自带隐式强转
// 等价于 b = (byte)(b + 5);

short s = 5;
s = s + 2;    // ❌ 编译错误：s+2 是 int
s += 2;       // ✅ 等价于 s = (short)(s + 2)
```

> ⚠️ **复合赋值 `+=` 不等于 `a = a + b`**！`a += b` 等价于 `a = (a的类型)(a + b)`，自带隐式强转。这能避免 `byte`/`short` 运算提升为 `int` 的编译错误，但也可能悄悄截断数据：

```java
byte b = 100;
b += 100;   // 编译通过，但 (byte)(100+100) = (byte)200 = -56，溢出了！
// b = b + 100;  // 编译错误，反而更安全（能提前发现问题）
```

## 三、比较运算符

比较运算符的结果一定是 `boolean`（`true` 或 `false`）。

| 运算符 | 说明 | 示例 |
| :---: | :--- | :--- |
| `==` | 等于 | `1 == 1` → true |
| `!=` | 不等于 | `1 != 2` → true |
| `>` | 大于 | `2 > 1` → true |
| `<` | 小于 | `1 < 2` → true |
| `>=` | 大于等于 | `2 >= 2` → true |
| `<=` | 小于等于 | `1 <= 2` → true |
| `instanceof` | 引用类型判断 | `"x" instanceof String` → true |

```java
System.out.println(1 == 1);   // true
System.out.println(1 != 2);   // true
System.out.println(2 > 1);    // true
System.out.println(2 <= 2);   // true
```

### `==` 对引用类型比的是地址 ⭐

```java
// 基本类型 ==：比较值
int a = 10, b = 10;
System.out.println(a == b);   // true，值相等

// 引用类型 ==：比较地址（是否指向同一个对象）
String s1 = new String("hello");
String s2 = new String("hello");
System.out.println(s1 == s2);        // false！两个 new 出来的对象地址不同
System.out.println(s1.equals(s2));   // true，equals 比较内容

String s3 = "hello";
String s4 = "hello";
System.out.println(s3 == s4);   // true，字符串常量池，同一地址
```

> ⚠️ **新手最常踩的坑**：用 `==` 比较字符串内容。`==` 对引用类型比的是内存地址，不是内容！比较字符串内容必须用 `.equals()`。

```java
// ❌ 错误：用 == 比字符串
String input = "admin";
if (input == "admin") { }    // 可能 false（如果 input 是 new 出来的）

// ✅ 正确：用 equals 比内容
if ("admin".equals(input)) { }  // true，且把常量放前面避免空指针
```

> 💡 **技巧**：比较字符串时，把确定不为 null 的常量放前面：`"admin".equals(input)`，这样即使 `input` 为 null 也不会抛空指针异常。

## 四、逻辑运算符

逻辑运算符用于组合多个布尔条件。

| 运算符 | 说明 | 示例 |
| :---: | :--- | :--- |
| `&` | 逻辑与（非短路） | `true & false` → false |
| `&&` | 短路与 | `true && false` → false |
| `|` | 逻辑或（非短路） | `true | false` → true |
| `||` | 短路或 | `true || false` → true |
| `^` | 逻辑异或 | `true ^ false` → true |
| `!` | 逻辑非 | `!true` → false |

### 4.1 基本逻辑运算

```java
boolean a = true, b = false;
System.out.println(a & b);   // false，全真才真
System.out.println(a | b);   // true，一真即真
System.out.println(a ^ b);   // true，不同为真
System.out.println(!a);      // false，取反
System.out.println(a && b);  // false
System.out.println(a || b);  // true
```

### 4.2 短路与 `&&` vs 逻辑与 `&` ⭐⭐

**短路与 `&&`**：左边为 false 时，右边不计算（短路），因为结果一定是 false。
**逻辑与 `&`**：左右两边都会计算，不管左边结果。

```java
int x = 5;
// 短路与：左边 false，右边不执行
boolean r1 = (x > 10) && (x++ > 0);
System.out.println(r1);   // false
System.out.println(x);    // 5，x++ 没执行

int y = 5;
// 逻辑与：左边 false，右边仍执行
boolean r2 = (y > 10) & (y++ > 0);
System.out.println(r2);   // false
System.out.println(y);    // 6，y++ 执行了
```

### 4.3 短路或 `||` vs 逻辑或 `|`

**短路或 `||`**：左边为 true 时，右边不计算（短路），因为结果一定是 true。
**逻辑或 `|`**：左右两边都会计算。

```java
int x = 5;
// 短路或：左边 true，右边不执行
boolean r1 = (x > 0) || (x++ > 0);
System.out.println(r1);   // true
System.out.println(x);    // 5，x++ 没执行

int y = 5;
// 逻辑或：左边 true，右边仍执行
boolean r2 = (y > 0) | (y++ > 0);
System.out.println(r2);   // true
System.out.println(y);    // 6，y++ 执行了
```

> 💡 **实际开发中几乎只用 `&&` 和 `||`**，`&` 和 `|` 很少用。短路特性既能提升性能，又能避免空指针等异常（见实战案例）。

### 4.4 短路特性避免空指针 ⭐⭐

```java
String str = null;

// ❌ 逻辑与：两边都执行，右边抛空指针
// boolean r = (str != null) & (str.length() > 0);  // NullPointerException!

// ✅ 短路与：左边 false，右边不执行，安全
boolean r = (str != null) && (str.length() > 0);  // false，不报错
```

> ⚠️ **短路特性是实际开发中避免空指针的关键技巧**：判断对象非空后再访问其属性/方法，必须用 `&&`。

## 五、三元运算符

三元运算符（条件运算符）是 Java 中唯一的三目运算符：

```
条件 ? 表达式A : 表达式B
```

条件为 true 执行 A，false 执行 B。

```java
int a = 10, b = 20;
int max = (a > b) ? a : b;   // 20，求最大值
System.out.println(max);

// 判断奇偶
String result = (a % 2 == 0) ? "偶数" : "奇数";
System.out.println(result);  // 偶数

// 判断是否为空，给默认值
String name = input != null ? input : "匿名";
```

### 嵌套三元

```java
int a = 10, b = 20, c = 15;
// 求三个数最大值：嵌套三元
int max = (a > b) ? ((a > c) ? a : c) : ((b > c) ? b : c);
System.out.println(max);  // 20
```

> ⚠️ 嵌套三元可读性差，实际开发中超过两层嵌套建议改用 `if-else`。简单判断用三元，复杂逻辑用 `if-else`。

### 三元运算符的类型提升 ⭐

```java
// 两个分支类型不同，结果会提升为范围大的类型
Object o = true ? Integer.valueOf(1) : "hello";  // ✅ Object
int n = true ? 1 : 2;   // ✅ 都是 int

// ⚠️ 经典陷阱：包装类和原始类型
char c = 'A';
int i = 65;
System.out.println(true ? c : i);    // 65，char 提升为 int
System.out.println(false ? c : i);   // 65

// ⚠️ 更隐蔽的陷阱：null 和 int
Integer obj = null;
int r = (obj != null) ? obj : 0;   // ❌ NullPointerException！
// 原因：三元运算符会尝试把 Integer 拆箱为 int，obj 为 null 时拆箱失败
// 第二个分支 0 是 int，所以 obj 会被拆箱
```

> ⚠️ 三元运算符的两个分支如果一个是包装类、一个是基本类型，包装类会被**拆箱**，为 null 时抛空指针。这是非常隐蔽的坑。

## 六、位运算符

位运算直接操作二进制位，是 Java 中最高效的运算。理解位运算需要先了解原码、反码、补码。

### 6.1 原码、反码、补码

计算机用**补码**存储和运算整数。以 4 位 `int` 为例（实际 int 是 32 位）：

| 概念 | 正数 `+5` | 负数 `-5` |
| :--- | :--- | :--- |
| 原码 | `0000 0101` | `1000 0101`（最高位是符号位） |
| 反码 | `0000 0101`（正数同原码） | `1111 1010`（符号位不变，其余取反） |
| 补码 | `0000 0101`（正数同原码） | `1111 1011`（反码 +1） |

> 💡 **正数**的原码 = 反码 = 补码。**负数**的补码 = 反码 + 1。计算机中所有整数运算都基于补码（统一了加减法，0 只有一种表示）。

### 6.2 按位运算符

| 运算符 | 名称 | 说明 |
| :---: | :--- | :--- |
| `&` | 按位与 | 两位都 1 才 1 |
| `|` | 按位或 | 有一位 1 就 1 |
| `^` | 按位异或 | 两位不同才 1 |
| `~` | 按位取反 | 0 变 1，1 变 0（单目） |

```java
int a = 0b1100;   // 12
int b = 0b1010;   // 10

System.out.println(Integer.toBinaryString(a & b));  // 1000 = 8，都1才1
System.out.println(Integer.toBinaryString(a | b));  // 1110 = 14，有1即1
System.out.println(Integer.toBinaryString(a ^ b));  // 0110 = 6，不同为1
System.out.println(~a);  // -13，取反（包括符号位）
// ~12：0000...01100 → 1111...10011，这是 -13 的补码
```

### 6.3 移位运算符

| 运算符 | 名称 | 说明 |
| :---: | :--- | :--- |
| `<<` | 左移 | 各位左移，低位补 0，相当于 `×2` |
| `>>` | 有符号右移 | 高位补符号位，相当于 `÷2` |
| `>>>` | 无符号右移 | 高位补 0（无论正负） |

```java
int a = 8;     // 0000...1000
System.out.println(a << 1);   // 16，左移1位 = ×2
System.out.println(a << 2);   // 32，左移2位 = ×4
System.out.println(a >> 1);   // 4，右移1位 = ÷2

// 负数右移
int b = -8;
System.out.println(b >> 1);   // -4，有符号右移，高位补1
System.out.println(b >>> 1); // 2147483644，无符号右移，高位补0，变正数
```

> 💡 **移位运算的高效性**：`<< 1` 比 `* 2` 快，`>> 1` 比 `/ 2` 快（CPU 直接操作二进制位，无需除法运算）。但现代 JVM 已对 `* 2`、`/ 2` 做了优化，实际开发中不必刻意用移位代替乘除，可读性更重要。位运算的优势在于**权限标志位、位掩码**等场景。

### 6.4 位运算高效场景

**用 `&` 判断奇偶**（比 `%` 高效）：

```java
int n = 7;
// 奇数的最低位一定是 1，偶数一定是 0
boolean isOdd = (n & 1) == 1;   // true，比 n % 2 == 1 更快
boolean isEven = (n & 1) == 0;  // false
// 且对负数也正确：-7 & 1 = 1，不会出现 % 的符号问题
```

**用 `^` 交换两个变量**（不用临时变量）：

```java
int a = 10, b = 20;
a = a ^ b;   // a = 10 ^ 20
b = a ^ b;   // b = (10 ^ 20) ^ 20 = 10
a = a ^ b;   // a = (10 ^ 20) ^ 10 = 20
System.out.println("a=" + a + ", b=" + b);  // a=20, b=10
```

> 💡 **异或特性**：`a ^ a = 0`，`a ^ 0 = a`，`a ^ b ^ b = a`。异或运算满足交换律和结合律。

**用 `<<` 快速乘 2 的幂**：

```java
int n = 5;
System.out.println(n << 1);  // 10，×2
System.out.println(n << 2);  // 20，×4
System.out.println(n << 3);  // 40，×8
System.out.println(n >> 1);  // 2，÷2（截断）
```

## ⚠️ 重点

### 重点 1：整数除法截断小数 ⭐⭐

```java
System.out.println(10 / 3);     // 3，不是 3.33
System.out.println(1 / 2);      // 0，不是 0.5
System.out.println(1.0 / 2);    // 0.5，至少一个浮点数才有小数
```

> ⚠️ 整数除整数，结果截断小数部分（不是四舍五入）。需要小数结果，至少一个操作数用浮点数。

### 重点 2：`++` 前置与后置的区别 ⭐⭐

```java
int i = 5;
int a = i++;   // a=5, i=6，先用旧值再加
int b = ++i;   // b=7, i=7，先加再用新值
```

> 💡 **记忆口诀**：`++` 在前，先加后用；`++` 在后，先用后加。

### 重点 3：短路与 `&&` 避免空指针 ⭐⭐⭐

```java
String str = null;
// ❌ 逻辑与 &：两边都执行，str.length() 抛空指针
// if (str != null & str.length() > 0) { }   // NullPointerException

// ✅ 短路与 &&：左边 false，右边不执行
if (str != null && str.length() > 0) { }   // 安全
```

> ⚠️ **这是实际开发中最常用的短路场景**：先判断非空，再访问属性/方法。必须用 `&&`，不能用 `&`。

### 重点 4：复合赋值的隐式强转 ⭐⭐

```java
byte b = 10;
b = b + 5;    // ❌ b+5 是 int，不能赋给 byte
b += 5;       // ✅ 等价于 b = (byte)(b + 5)，自带强转

short s = 5;
s += 2;       // ✅ 等价于 s = (short)(s + 2)
```

> ⚠️ `a += b` 不等于 `a = a + b`，而是 `a = (a的类型)(a + b)`。自带隐式强转，可能悄悄溢出。

### 重点 5：`==` 比较引用类型比的是地址 ⭐⭐

```java
String s1 = new String("hello");
String s2 = new String("hello");
System.out.println(s1 == s2);        // false，地址不同
System.out.println(s1.equals(s2));   // true，内容相同
```

> ⚠️ `==` 对基本类型比值，对引用类型比地址。比较内容用 `.equals()`。

### 重点 6：位运算做权限标志位 ⭐⭐⭐

```java
// 权限定义：每个权限占一位
final int PERM_READ    = 1;   // 0001
final int PERM_WRITE   = 2;   // 0010
final int PERM_DELETE  = 4;   // 0100
final int PERM_ADMIN   = 8;   // 1000

// 组合权限：用 |（按位或）
int userPerm = PERM_READ | PERM_WRITE;  // 0011 = 3

// 判断是否有某权限：用 &（按位与）
boolean canRead  = (userPerm & PERM_READ) != 0;   // true
boolean canWrite = (userPerm & PERM_WRITE) != 0;  // true
boolean canDelete = (userPerm & PERM_DELETE) != 0; // false

// 移除权限：用 & ~（按位与取反）
userPerm = userPerm & ~PERM_WRITE;  // 移除写权限，0001 = 1

// 添加权限：用 |
userPerm = userPerm | PERM_DELETE;  // 添加删权限，0101 = 5
```

> 💡 **位运算权限标志位**是 Linux 文件权限、Android 权限系统、数据库权限设计的底层原理。一个 `int` 就能表示 32 种权限组合，极致节省存储。

### 重点 7：三元运算符的拆箱陷阱 ⭐

```java
Integer obj = null;
int r = (obj != null) ? obj : 0;  // ❌ NullPointerException
// obj != null 为 false，应取 0，但三元运算符会统一类型
// obj 是 Integer，0 是 int，编译器尝试拆箱 obj → 失败

// ✅ 安全写法：两边都用包装类
Integer r2 = (obj != null) ? obj : Integer.valueOf(0);  // 0
```

## 💻 实战案例

### 案例 1：用位运算做权限标志位（增删改查） ⭐⭐⭐

后台系统中，用户角色对应不同操作权限。用位运算可以用一个 `int` 表示所有权限组合：

```java
public class PermissionSystem {
    // 权限定义：每位代表一个权限
    public static final int PERM_QUERY  = 1;   // 0001 查
    public static final int PERM_ADD    = 2;   // 0010 增
    public static final int PERM_UPDATE = 4;   // 0100 改
    public static final int PERM_DELETE = 8;   // 1000 删

    // 角色权限组合
    public static final int ROLE_VISITOR = PERM_QUERY;                              // 只能查
    public static final int ROLE_EDITOR  = PERM_QUERY | PERM_ADD | PERM_UPDATE;     // 查增改
    public static final int ROLE_ADMIN   = PERM_QUERY | PERM_ADD | PERM_UPDATE | PERM_DELETE; // 全部

    /** 判断是否有某权限 */
    public static boolean hasPermission(int userPerm, int perm) {
        return (userPerm & perm) != 0;
    }

    /** 添加权限 */
    public static int addPermission(int userPerm, int perm) {
        return userPerm | perm;
    }

    /** 移除权限 */
    public static int removePermission(int userPerm, int perm) {
        return userPerm & ~perm;
    }

    public static void main(String[] args) {
        int userPerm = ROLE_EDITOR;  // 编辑者：查+增+改

        System.out.println("能查询: " + hasPermission(userPerm, PERM_QUERY));   // true
        System.out.println("能新增: " + hasPermission(userPerm, PERM_ADD));     // true
        System.out.println("能修改: " + hasPermission(userPerm, PERM_UPDATE));  // true
        System.out.println("能删除: " + hasPermission(userPerm, PERM_DELETE));  // false

        // 给编辑者加上删除权限 → 升级为管理员
        userPerm = addPermission(userPerm, PERM_DELETE);
        System.out.println("升级后能删除: " + hasPermission(userPerm, PERM_DELETE));  // true

        // 移除新增权限
        userPerm = removePermission(userPerm, PERM_ADD);
        System.out.println("移除后能新增: " + hasPermission(userPerm, PERM_ADD));    // false
    }
}
```

> 📌 **真实场景**：Linux 文件权限（`r=4, w=2, x=1`，`chmod 755`）、Android `permission` flags、数据库权限位字段，都是这个原理。一个 `int` 字段存 32 种权限，比建 32 个 boolean 列高效得多。

### 案例 2：用 `^` 交换两个变量（不用临时变量） ⭐

```java
// 传统写法：用临时变量（推荐，可读性好）
int a = 10, b = 20;
int temp = a;
a = b;
b = temp;

// 位运算写法：用异或（面试常考，实际开发少用）
int x = 10, y = 20;
x = x ^ y;   // x = 10 ^ 20
y = x ^ y;   // y = (10 ^ 20) ^ 20 = 10
x = x ^ y;   // x = (10 ^ 20) ^ 10 = 20
System.out.println("x=" + x + ", y=" + y);  // x=20, y=10

// ⚠️ 注意：x 和 y 不能是同一个变量（同一内存地址），否则异或后变 0
// arr[0] ^= arr[0];  // 会变成 0！
```

> 💡 **原理**：`a ^ b ^ b = a`，异或同一个数两次还原原值。但实际开发中用临时变量更清晰，异或交换主要用于面试和底层代码。

### 案例 3：用 `&` 判断奇偶数（比 `%` 高效） ⭐

```java
// 判断 1~10 的奇偶
for (int i = 1; i <= 10; i++) {
    // 位运算：最低位是1就是奇数
    if ((i & 1) == 1) {
        System.out.println(i + " 是奇数");
    } else {
        System.out.println(i + " 是偶数");
    }
}

// ❌ 用 % 判断奇偶的陷阱：负数
int n = -7;
System.out.println(n % 2 == 1);   // false！-7 % 2 = -1
System.out.println(n % 2 != 0);   // true，正确但需注意
System.out.println((n & 1) == 1); // true，位运算对负数也正确
```

> 💡 位运算判断奇偶的优势：① 比 `%` 快（CPU 直接操作二进制位）；② 对负数也正确，没有符号问题。

### 案例 4：短路与避免空指针（后台参数校验） ⭐⭐⭐

后台接口开发中，参数校验是高频场景。短路与能安全地链式判断：

```java
public class UserValidator {

    /** 校验用户注册参数 */
    public String validateRegister(String username, String password, String email) {
        // ❌ 错误写法：用逻辑与 &，可能空指针
        // if (username != null & username.length() >= 6 & ...) { }
        // 如果 username 为 null，username.length() 抛空指针

        // ✅ 正确写法：用短路与 &&，依次校验，前面失败后面不执行
        if (username == null || username.trim().isEmpty()) {
            return "用户名不能为空";
        }
        if (username.length() < 6 || username.length() > 20) {
            return "用户名长度需 6-20 位";
        }
        if (password == null || password.length() < 8) {
            return "密码至少 8 位";
        }
        // 链式判断：先判非空，再判内容（必须用 &&）
        if (email != null && email.contains("@") && email.endsWith(".com")) {
            return null;  // 校验通过
        }
        return "邮箱格式不正确";
    }

    /** 安全地获取字符串长度 */
    public int safeLength(String str) {
        // 短路与：先判空，再取长度
        return (str != null) ? str.length() : 0;
    }

    /** 安全地获取嵌套对象属性 */
    public String getCity(User user) {
        // 多层判空：用短路与逐层判断
        if (user != null && user.getAddress() != null && user.getAddress().getCity() != null) {
            return user.getAddress().getCity();
        }
        return "未知";
    }
}
```

> ⚠️ **多层嵌套对象的判空**是后台开发的高频场景：`user.getAddress().getCity()` 任何一层为 null 都会空指针。用 `&&` 逐层判断是最基本的安全写法（Java 8 也可用 `Optional` 更优雅地处理，见 [函数式编程]）。

### 案例 5：用移位运算计算哈希桶数量 ⭐

```java
public class HashUtils {
    // HashMap 中计算哈希桶位置：用 & 代替 %（要求容量是 2 的幂）
    // hash & (capacity - 1) 等价于 hash % capacity，但更快

    static final int DEFAULT_CAPACITY = 16;  // 2^4

    static int indexFor(int hash, int capacity) {
        return hash & (capacity - 1);  // 位运算取模，比 % 快
    }

    public static void main(String[] args) {
        int hash = "hello".hashCode();  // 某个哈希值
        int bucket = indexFor(hash, DEFAULT_CAPACITY);
        System.out.println("哈希桶位置: " + bucket);  // 0~15

        // 快速判断一个数是否是 2 的幂
        int n = 16;
        boolean isPowerOfTwo = (n & (n - 1)) == 0;  // true
        // 原理：2 的幂二进制只有一个 1，n-1 全是 1，& 后为 0
        System.out.println(n + " 是2的幂: " + isPowerOfTwo);
    }
}
```

> 💡 这正是 `HashMap` 底层计算桶位置的算法。`hash & (capacity - 1)` 比 `hash % capacity` 快得多，这也是 HashMap 容量必须是 2 的幂的原因。

### 案例 6：三元运算符做默认值兜底 ⭐

```java
public class DefaultService {
    // 配置项读取：配置为空时用默认值
    public int getTimeout(String configValue) {
        return (configValue != null) ? Integer.parseInt(configValue) : 3000;
    }

    // 分页参数：页码为空或非法时用默认值
    public int getPageNum(Integer pageNum) {
        return (pageNum != null && pageNum > 0) ? pageNum : 1;
    }

    // 显示用户名：昵称为空时显示"匿名用户"
    public String getDisplayName(String nickname, String username) {
        return (nickname != null && !nickname.isEmpty())
            ? nickname
            : (username != null ? username : "匿名用户");
    }
}
```

> 📌 三元运算符适合简单的「条件取值」场景，复杂逻辑用 `if-else` 更清晰。

import java.util.Optional;

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 算术运算符 | `+ - * / % ++ --`，整数除法截断小数 |
| 整数除法 | 两边整数→结果整数，需小数则用浮点 |
| `++` 前后置 | 前置先加后用，后置先用后加 |
| 赋值运算符 | `+=` 等自带隐式强转，不等价于 `a = a + b` |
| 比较运算符 | 结果 boolean，`==` 对引用比地址 |
| 逻辑运算符 | `&&` 短路与、`||` 短路或，实际开发只用短路 |
| 短路特性 | 左边能决定结果则右边不执行，避免空指针 |
| 三元运算符 | `条件 ? A : B`，注意拆箱陷阱 |
| 位运算符 | `& | ^ ~ << >> >>>`，高效操作二进制 |
| 权限标志位 | 一个 int 表示 32 种权限组合 |
| 运算优先级 | 乘除 > 加减 > 比较 > 逻辑与 > 逻辑或 > 三元 > 赋值 |

**运算符优先级简表**（从高到低）：

| 优先级 | 运算符 | 说明 |
| :---: | :--- | :--- |
| 1 | `()` `[]` `.` | 括号、数组、成员访问 |
| 2 | `!` `~` `++` `--` | 单目运算符 |
| 3 | `*` `/` `%` | 乘除取模 |
| 4 | `+` `-` | 加减 |
| 5 | `<<` `>>` `>>>` | 移位 |
| 6 | `<` `<=` `>` `>=` `instanceof` | 比较 |
| 7 | `==` `!=` | 相等判断 |
| 8 | `&` | 按位与 |
| 9 | `^` | 按位异或 |
| 10 | `|` | 按位或 |
| 11 | `&&` | 逻辑与 |
| 12 | `||` | 逻辑或 |
| 13 | `?:` | 三元 |
| 14 | `=` `+=` `-=` `*=` `/=` `%=` | 赋值 |

> 💡 **优先级记不住？** 实际开发中用括号 `()` 明确运算顺序，可读性远比记优先级表重要。`a + b * c` 写成 `a + (b * c)` 更清晰。

## 学习建议

1. **动手验证每个易错点**：把整数除法、`++` 前后置、短路特性、复合赋值强转的代码敲进 IDE 运行一遍，亲眼看到结果比看十遍文字都管用。
2. **牢记短路特性**：`&&` 和 `||` 是实际开发中用得最多的逻辑运算符，理解「左边能决定结果就不算右边」是避免空指针的关键。凡是先判空再访问属性的场景，必须用 `&&`。
3. **掌握位运算权限标志位**：这是位运算在实际开发中最典型的应用。理解「`|` 组合权限、`&` 判断权限、`& ~` 移除权限」三件套，Linux 权限、数据库权限设计都基于此。
4. **不要刻意用位运算代替乘除**：`<< 1` 代替 `* 2` 在现代 JVM 中性能差异微乎其微，可读性更重要。位运算的真正价值在权限标志位、哈希取模等特定场景。
5. **用括号明确运算优先级**：不要依赖运算符优先级表写代码，用 `()` 让意图一目了然。`a && b || c` 写成 `(a && b) || c`，同事和未来的你都会感谢你。
