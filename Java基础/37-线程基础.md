# 线程基础

线程是 Java 并发的起点。从 Web 服务器「每个请求一个线程」、到后台定时任务、到多线程下载、再到 Spring 的 `@Async`——所有并发能力的根基都在本篇：什么是进程与线程、怎么创建线程、`Thread` 有哪些常用方法、线程有几种状态、为什么多线程会出 bug。理解这些，才能看懂后续的 `synchronized`、`Lock`、线程池、`CompletableFuture`。本篇以 Java 8 为基准，把线程的核心概念和易错点一次讲透。

> 💡 在阅读本篇前，建议先看 [22-System与Runtime类](22-System与Runtime类.md) 中 `availableProcessors` 的介绍——线程池大小要根据 CPU 核心数来定，理解核数与线程数的关系会更容易理解后面的并发设计。

---

## 一、进程与线程

**进程**是程序的一次执行实例，是操作系统**资源分配**的基本单位；**线程**是进程内的执行单元，是 **CPU 调度**的基本单位。一个进程包含至少一个线程（主线程），也可以包含多个线程。

| 对比项 | 进程 | 线程 |
| :--- | :--- | :--- |
| **本质** | 程序执行实例 | 进程内执行单元 |
| **资源** | 独立内存空间、文件句柄 | 共享进程的内存、文件句柄 |
| **开销** | 创建/切换开销大 | 创建/切换开销小 |
| **通信** | 进程间通信（管道、消息队列、Socket） | 直接读写共享变量（快但危险） |
| **隔离** | 一个进程崩溃不影响其他进程 | 一个线程崩溃可能拖垮整个进程 |
| **类比** | 一栋办公楼 | 办公楼里的一个工位 |

```java
// ✅ 每个 Java 程序启动时至少有一个线程：main 线程
public class Main {
    public static void main(String[] args) {
        // 获取当前线程
        Thread current = Thread.currentThread();
        System.out.println("当前线程：" + current.getName());  // main
        System.out.println("线程 ID：" + current.getId());
        System.out.println("是否守护线程：" + current.isDaemon());  // false
    }
}
```

> 💡 **记忆要点**：进程是「资源分配」单位，线程是「CPU 调度」单位。同一进程内的线程共享堆、方法区，但各有独立的栈和程序计数器。这就是为什么多线程能直接共享变量（快），但也因此产生了线程安全问题。

## 二、并发与并行

| 概念 | 含义 | 例子 |
| :--- | :--- | :--- |
| **并发（Concurrency）** | 多个线程**交替**使用 CPU，同一时刻只有一个在执行 | 单核 CPU 上同时跑 10 个线程 |
| **并行（Parallelism）** | 多个线程在**多核**上**同时**执行 | 8 核 CPU 上 8 个线程同时跑 |
| **串行** | 一个接一个执行，前一个没完不能开始下一个 | 单人排队办事 |

```
并发（单核交替）：     并行（多核同时）：     串行：
Thread A ▓▓  ▓▓       Thread A ▓▓▓▓        A ▓▓▓▓
Thread B   ▓▓  ▓▓     Thread B ▓▓▓▓        B     ▓▓▓▓
        ↑  ↑  ↑                ↑
      时间片切换          同一时刻都在跑
```

```java
// ✅ 查看 CPU 核心数
int cores = Runtime.getRuntime().availableProcessors();
System.out.println("CPU 逻辑核心数：" + cores);  // 如：8
// 并行能力上限 = 核心数；超过这个数的线程只能并发（交替）执行
```

> ⚠️ **并发 ≠ 并行**：并发是「能处理多个任务」（可能靠快速切换），并行是「能同时执行多个任务」（必须多核）。单核 CPU 也能并发，但无法真正并行。Java 的多线程在单核上是并发，在多核上可以并行。

## 三、线程调度

操作系统如何把 CPU 时间分配给多个线程，叫**线程调度**：

| 调度方式 | 说明 | 典型场景 |
| :--- | :--- | :--- |
| **分时调度** | 每个线程轮流用 CPU，时间片用完让出 | 早期系统、协作式 |
| **抢占式调度** | 优先级高的线程抢占 CPU，时间片用完也被抢 | 现代 OS、Java 默认 |

> 💡 **Java 采用抢占式调度**：线程的执行顺序由优先级和时间片共同决定，但**优先级不保证**执行顺序。这就是为什么多线程程序的输出顺序不可预期——不能依赖「先 start 的先执行完」。

```java
// ✅ 优先级范围 1-10，默认 5
Thread t = new Thread(() -> System.out.println("hi"));
t.setPriority(Thread.MAX_PRIORITY);  // 10，但不保证先执行
t.start();
```

> ⚠️ **不要依赖优先级控制业务逻辑**：优先级只是「建议」，OS 和 JVM 都可能忽略。两个线程的执行顺序在业务上必须保证时，要用 `join`、`CountDownLatch` 或锁，绝不能靠优先级。

## 四、创建线程方式一：继承 Thread ⭐⭐

最直接的方式：继承 `java.lang.Thread`，重写 `run()` 方法，调用 `start()` 启动。

```java
// ✅ 方式一：继承 Thread
class MyThread extends Thread {
    @Override
    public void run() {
        // 线程要执行的任务写在这里
        for (int i = 0; i < 5; i++) {
            System.out.println(getName() + " 执行 " + i);
        }
    }
}

public class Demo {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();
        t1.start();  // ✅ 启动新线程，自动调用 run
        t2.start();
    }
}
```

### 4.1 start 与 run 的致命区别 ⭐⭐⭐

```java
MyThread t = new Thread();

// ✅ start()：启动新线程，在新线程中执行 run
t.start();   // 开新线程，run 在新线程跑

// ❌ run()：普通方法调用，不开新线程！
t.run();     // 在当前线程（main）执行，和普通方法没区别
```

```java
// ✅ 验证：start 开新线程，run 不开
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("执行 run 的线程：" + Thread.currentThread().getName());
    }
}

public class Demo {
    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.start();  // 输出：执行 run 的线程：Thread-0（新线程）
        t.run();    // 输出：执行 run 的线程：main（当前线程）
    }
}
```

> ⚠️ **新手最常犯的错**：把 `start()` 写成 `run()`，结果「多线程」程序其实是单线程跑的，毫无并发效果。记住：**启动线程永远用 `start()`，`run()` 只是定义任务**。

### 4.2 start 不能重复调用

```java
MyThread t = new MyThread();
t.start();  // ✅ 第一次：启动新线程
// t.start();  // ❌ 第二次：抛 IllegalThreadStateException
// 一个 Thread 对象只能 start 一次，想再跑要 new 一个新对象
```

> ⚠️ `Thread` 对象一旦 `start` 过就进入「已启动」状态，不能再 `start`。要再执行同样任务，必须 `new` 一个新的 `Thread` 对象。这也是为什么线程池要复用线程——`new Thread` 开销大且不能重用。

### 4.3 继承 Thread 的局限

```java
// ❌ Java 单继承：继承了 Thread 就不能再继承其他类
class MyService extends Thread {  // 占用了唯一的继承名额
    @Override
    public void run() { /* ... */ }
}
// class MyService extends BaseService, Thread { }  // ❌ Java 不允许多继承
```

> 💡 因为单继承局限，**实际开发中很少用继承 Thread 的方式**，推荐用「实现 Runnable」。

## 五、创建线程方式二：实现 Runnable ⭐⭐

把任务和线程解耦：实现 `java.lang.Runnable` 接口的 `run()`，再传入 `Thread` 构造方法。

```java
// ✅ 方式二：实现 Runnable（推荐）
class MyTask implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 5; i++) {
            System.out.println(Thread.currentThread().getName() + " 执行 " + i);
        }
    }
}

public class Demo {
    public static void main(String[] args) {
        MyTask task = new MyTask();
        // ✅ 把任务传给 Thread 构造
        Thread t1 = new Thread(task, "窗口1");
        Thread t2 = new Thread(task, "窗口2");
        t1.start();
        t2.start();
    }
}
```

> 💡 **推荐理由**：① 避免单继承局限，`MyTask` 还能继承其他类；② 任务与线程解耦，同一个 `Runnable` 可以传给多个 `Thread`、也可以传给线程池；③ 更符合「组合优于继承」的设计原则。

### 5.1 Thread 的 run 方法源码

```java
// Thread 类的 run 方法（简化版）
public class Thread implements Runnable {
    private Runnable target;  // 构造时传入的 Runnable

    @Override
    public void run() {
        if (target != null) {
            target.run();  // ✅ 如果传了 Runnable，就执行它的 run
        }
        // 没传 Runnable 就什么都不做（除非子类重写了 run）
    }
}
```

> 💡 **本质**：`Thread` 自己也实现了 `Runnable`。继承 `Thread` 重写 `run`，和实现 `Runnable` 传入 `Thread`，最终都是让 `Thread.run` 执行任务。区别只是「任务写在哪」。`Thread` 的 `run` 默认会调用传入的 `target.run`，所以两种方式效果一致。

### 5.2 Runnable 适合资源共享

```java
// ✅ 多个窗口卖同一批票（共享 ticket 资源）
class TicketTask implements Runnable {
    private int tickets = 100;  // 共享资源

    @Override
    public void run() {
        while (tickets > 0) {
            // ⚠️ 这里有线程安全问题，后面会讲
            System.out.println(Thread.currentThread().getName()
                    + " 卖险 卖票，剩余 " + tickets--);
        }
    }
}

public class Demo {
    public static void main(String[] args) {
        TicketTask task = new TicketTask();  // ✅ 一个任务对象
        new Thread(task, "窗口1").start();   // 三个窗口共享同一批票
        new Thread(task, "窗口2").start();
        new Thread(task, "窗口3").start();
    }
}
```

> 💡 用 `Runnable` 时，三个 `Thread` 共享同一个 `task` 对象，所以 `tickets` 字段是共享的。如果用继承 `Thread`，要共享资源就得用 `static`，不够灵活。这是 `Runnable` 的另一优势。

## 六、创建线程方式三：实现 Callable ⭐

`Runnable` 的 `run` 没有返回值、不能抛 checked 异常。Java 5 起提供 `java.util.concurrent.Callable`，配合 `FutureTask` 可以拿到返回值。

```java
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;
import java.util.concurrent.ExecutionException;

// ✅ 方式三：实现 Callable，有返回值
class SumTask implements Callable<Long> {
    private final int start;
    private final int end;

    public SumTask(int start, int end) {
        this.start = start;
        this.end = end;
    }

    @Override
    public Long call() throws Exception {  // ✅ 有返回值，可抛异常
        long sum = 0;
        for (int i = start; i <= end; i++) {
            sum += i;
        }
        return sum;
    }
}

public class Demo {
    public static void main(String[] args) throws ExecutionException, InterruptedException {
        // ✅ Callable 包装成 FutureTask（实现了 RunnableFuture）
        FutureTask<Long> future = new FutureTask<>(new SumTask(1, 1000000));
        Thread t = new Thread(future, "求和线程");
        t.start();

        // ✅ get() 会阻塞，直到任务完成
        Long result = future.get();
        System.out.println("1 到 100 万的和：" + result);  // 500000500000

        // ✅ 可以设置超时，避免一直阻塞
        // Long r2 = future.get(3, TimeUnit.SECONDS);
    }
}
```

| 对比 | Runnable | Callable |
| :--- | :--- | :--- |
| **方法** | `run()` | `call()` |
| **返回值** | 无（void） | 有（泛型 V） |
| **异常** | 不能抛 checked 异常 | 可抛 checked 异常 |
| **配合** | `Thread` | `FutureTask` + `Thread`，或线程池 `submit` |
| **场景** | 简单任务、不需结果 | 需要返回值、需异步等待结果 |

> 💡 **开发中**：需要返回值用 `Callable` + 线程池 `submit`（返回 `Future`）；不需要返回值用 `Runnable`。直接 `new Thread` 在生产环境几乎不用，都用线程池。

## 七、匿名内部类与 Lambda 创建线程

```java
// ✅ 方式一：匿名内部类（继承 Thread）
new Thread() {
    @Override
    public void run() {
        System.out.println("匿名 Thread：" + Thread.currentThread().getName());
    }
}.start();

// ✅ 方式二：匿名内部类（实现 Runnable）
new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("匿名 Runnable：" + Thread.currentThread().getName());
    }
}).start();

// ✅ 方式三：Lambda（Java 8+，Runnable 是函数式接口）
new Thread(() -> System.out.println("Lambda：" + Thread.currentThread().getName())).start();

// ✅ 方式四：带名字的 Lambda 线程
Thread t = new Thread(() -> {
    for (int i = 0; i < 3; i++) {
        System.out.println(Thread.currentThread().getName() + " - " + i);
    }
}, "worker-1");
t.start();
```

> 💡 Java 8 起，`Runnable` 是函数式接口（只有一个抽象方法 `run`），可以直接用 Lambda。这是最简洁的写法，但生产环境仍推荐用线程池 + `Runnable`/`Callable`，避免频繁创建销毁线程。

## 八、Thread 常用方法

| 方法 | 说明 | 注意 |
| :--- | :--- | :--- |
| `start()` | 启动新线程 | 不能重复调用 |
| `run()` | 线程任务 | 直接调用是普通方法调用 |
| `getName()` / `setName(String)` | 获取/设置线程名 | 默认 `Thread-0`、`Thread-1` |
| `currentThread()` | 获取当前线程 | 静态方法 |
| `sleep(long ms)` | 当前线程睡眠 | **不释放锁**，静态方法 |
| `join()` | 等待该线程结束 | 阻塞当前线程 |
| `join(long ms)` | 最多等待 ms 毫秒 | 超时不再等 |
| `yield()` | 让出 CPU（不保证） | 只是建议，可能继续跑 |
| `setDaemon(true)` | 设为守护线程 | 必须在 start 前调用 |
| `getPriority()` / `setPriority(int)` | 优先级 1-10 | 不保证 |
| `isAlive()` | 线程是否存活 | start 后、死亡前为 true |
| `interrupt()` | 中断线程 | 设置中断标志，不强制停止 |
| `isInterrupted()` | 是否被中断 | 不清除标志 |

### 8.1 getName / setName / currentThread

```java
// ✅ 命名线程，方便调试
Thread t1 = new Thread(() -> {
    System.out.println("当前线程名：" + Thread.currentThread().getName());
}, "order-worker-1");
t1.start();

// ✅ 也可以用 setName
Thread t2 = new Thread(() -> {
    System.out.println(Thread.currentThread().getName());
});
t2.setName("payment-worker-1");
t2.start();

// ✅ currentThread 是静态方法，任何地方都能拿到当前线程
Thread current = Thread.currentThread();
System.out.println("我在 " + current.getName() + " 线程里");
```

> 📌 **规范**：给线程起有意义的名字（如 `order-worker-1`），排查线上问题时能从线程栈一眼看出是哪个业务线程。线程池用 `ThreadFactory` 命名，Spring 的线程池默认有 `task-` 前缀。

### 8.2 sleep：当前线程睡眠（不释放锁）⭐⭐

```java
// ✅ sleep 是静态方法，让「当前线程」睡眠
Thread.sleep(1000);  // 当前线程睡 1 秒

// ❌ 常见误区：以为 t.sleep() 让 t 睡，其实还是让当前线程睡
Thread t = new Thread(() -> {
    try {
        Thread.sleep(5000);  // 子线程自己睡 5 秒
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
});
t.start();
// t.sleep(2000);  // ⚠️ 这不是让 t 睡 2 秒！是让「调用者所在线程」睡 2 秒
// Thread.sleep 是静态方法，编译后等价于 Thread.sleep(2000)

// ✅ 正确：在哪个线程调用，就睡哪个线程
public class Demo {
    public static void main(String[] args) throws InterruptedException {
        System.out.println("开始：" + System.currentTimeMillis());
        Thread.sleep(2000);  // main 线程睡 2 秒
        System.out.println("结束：" + System.currentTimeMillis());  // 相差约 2000
    }
}
```

> ⚠️ **`Thread.sleep` 不释放锁**！如果线程持有某个 `synchronized` 锁，sleep 期间其他线程拿不到这个锁。要释放锁等待，用 `Object.wait()` 或 `Lock.await()`（后续章节讲）。

> ⚠️ `sleep` 抛 `InterruptedException`，必须处理。捕获后建议恢复中断标志：`Thread.currentThread().interrupt()`，否则中断状态丢失。

```java
// ✅ 正确处理 sleep 的中断
try {
    Thread.sleep(5000);
} catch (InterruptedException e) {
    // 收到中断信号，提前结束睡眠
    Thread.currentThread().interrupt();  // 恢复中断标志
    System.out.println("被中断，提前醒来");
}
```

### 8.3 join：等待线程结束 ⭐⭐

```java
// ✅ join：当前线程阻塞，直到 t 线程执行完
Thread t1 = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) {}
    System.out.println("t1 完成");
});
Thread t2 = new Thread(() -> {
    try { Thread.sleep(2000); } catch (InterruptedException e) {}
    System.out.println("t2 完成");
});

t1.start();
t2.start();

// ✅ main 线程等 t1 和 t2 都完成
t1.join();   // main 阻塞，直到 t1 完成
t2.join();   // main 阻塞，直到 t2 完成
System.out.println("main 继续，t1 和 t2 都完成了");

// ✅ 带超时的 join
// t1.join(3000);  // 最多等 3 秒，超时不再等
```

> 💡 **join 的本质**：在当前线程上调用 `t.join()`，等价于「当前线程 wait 在 t 对象上，直到 t 死亡」。`Thread` 的 `join` 内部用了 `wait`+`isAlive` 循环。所以 `join` 会**释放** `t` 对象的锁（虽然没人会对 Thread 对象加锁）。

### 8.4 yield：让出 CPU（不保证）

```java
// ✅ yield：暗示「我暂时让出 CPU，其他线程可以跑」
Thread t = new Thread(() -> {
    for (int i = 0; i < 5; i++) {
        System.out.println(Thread.currentThread().getName() + " - " + i);
        if (i == 2) {
            Thread.yield();  // 让一下 CPU，但不保证真的让
        }
    }
});
```

> ⚠️ `yield` 只是「建议」，JVM 和 OS 都可能忽略，调用后可能立刻继续执行。**实际开发几乎不用 `yield`**，它主要用于测试和调试。要可靠地控制顺序，用 `join`、`CountDownLatch`、锁。

### 8.5 守护线程：setDaemon ⭐⭐

```java
// ✅ 守护线程：为其他线程服务，所有非守护线程结束时自动退出
Thread daemon = new Thread(() -> {
    while (true) {
        System.out.println("守护线程运行中...");
        try { Thread.sleep(1000); } catch (InterruptedException e) { break; }
    }
});
daemon.setDaemon(true);  // ✅ 必须在 start 前设置
daemon.start();

// 主线程结束 → 所有非守护线程结束 → 守护线程强制终止
Thread.sleep(3000);
System.out.println("main 结束，daemon 会随之退出");
```

> ⚠️ **`setDaemon` 必须在 `start` 前调用**，否则抛 `IllegalThreadStateException`。守护线程的 `finally` 块**不保证执行**——因为它可能被强制终止，所以守护线程里不要做关键资源释放。

> 💡 **典型守护线程**：JVM 的 GC 线程就是守护线程。开发中常用守护线程做心跳、日志刷写、定时清理等「非关键」任务——主业务结束就一起退出，不用手动管理。

### 8.6 优先级：setPriority

```java
// ✅ 优先级 1-10，默认 5
Thread t = new Thread(() -> System.out.println("hi"));
t.setPriority(Thread.MIN_PRIORITY);  // 1
t.setPriority(Thread.NORM_PRIORITY);  // 5（默认）
t.setPriority(Thread.MAX_PRIORITY);  // 10
t.start();

// ⚠️ 优先级只是建议，不保证执行顺序
// 不同 OS 对优先级的映射不同，跨平台表现可能完全不一样
```

> ⚠️ **优先级不可靠**：Windows 上 `Thread.MAX_PRIORITY` 和 `MIN_PRIORITY` 可能映射成相同的 OS 优先级。**永远不要用优先级控制业务逻辑**，它只用于「希望某些线程尽量多跑一点」的微调。

## 九、线程的六种状态 ⭐⭐⭐

Java 6 起（`java.lang.Thread.State` 枚举）定义了 6 种线程状态。这是面试高频题，也是排查线程卡死的基础。

```
        ┌─────────────────────────────────────────────────┐
        │                                                 ▼
   NEW ──→ RUNNABLE ←──(synchronized)──→ BLOCKED
              │  ▲                            │
   start()    │  │ run()结束                  │ 拿到锁
              │  │                            ▼
              ▼  │                        RUNNABLE
          WAITING ←──notify/notifyAll─── (等待)
              │  ▲                            ▲
   wait()     │  │ notify/超时                 │ 超时/notify
              ▼  │                            │
        TIMED_WAITING ────────────────────────┘
              │
              │ run()结束
              ▼
         TERMINATED
```

| 状态 | 说明 | 触发条件 |
| :--- | :--- | :--- |
| **NEW** | 已创建未启动 | `new Thread()` 后、`start()` 前 |
| **RUNNABLE** | 可运行（可能在跑也可能在等 CPU） | `start()` 后 |
| **BLOCKED** | 阻塞于锁 | 等待 `synchronized` 锁 |
| **WAITING** | 无限等待 | `wait()`、`join()`、`LockSupport.park()` |
| **TIMED_WAITING** | 限时等待 | `sleep(ms)`、`wait(ms)`、`join(ms)` |
| **TERMINATED** | 已终止 | `run()` 执行完或异常退出 |

### 9.1 各状态演示

```java
// ✅ NEW：创建了但没 start
Thread t1 = new Thread(() -> {});
System.out.println(t1.getState());  // NEW

// ✅ RUNNABLE：start 后
t1.start();
Thread.sleep(100);  // 给点时间启动
System.out.println(t1.getState());  // RUNNABLE（可能在跑）

// ✅ TERMINATED：run 执行完
Thread t2 = new Thread(() -> System.out.println("done"));
t2.start();
t2.join();  // 等它跑完
System.out.println(t2.getState());  // TERMINATED

// ✅ TIMED_WAITING：sleep 中
Thread t3 = new Thread(() -> {
    try { Thread.sleep(5000); } catch (InterruptedException e) {}
});
t3.start();
Thread.sleep(100);
System.out.println(t3.getState());  // TIMED_WAITING

// ✅ WAITING：join 中（main 线程会 WAITING）
Thread t4 = new Thread(() -> {
    try { Thread.sleep(5000); } catch (InterruptedException e) {}
});
t4.start();
Thread waitReporter = new Thread(() -> {
    try { Thread.sleep(200); } catch (InterruptedException e) {}
    System.out.println("main 状态：" + getMainState());  // WAITING
});
// 简化：用 join 让 main 等待
new Thread(() -> {
    try { Thread.sleep(200); } catch (Exception e) {}
    System.out.println("t4 状态：" + t4.getState());  // TIMED_WAITING
}).start();
t4.join();  // main 线程进入 WAITING
```

### 9.2 BLOCKED 状态（等待锁）

```java
// ✅ BLOCKED：等待 synchronized 锁
Object lock = new Object();
Thread holder = new Thread(() -> {
    synchronized (lock) {
        try { Thread.sleep(5000); } catch (InterruptedException e) {}
    }
});
Thread waiter = new Thread(() -> {
    synchronized (lock) {
        System.out.println("拿到锁了");
    }
});
holder.start();
Thread.sleep(200);  // 让 holder 先拿到锁
waiter.start();
Thread.sleep(200);
System.out.println("waiter 状态：" + waiter.getState());  // BLOCKED
```

> ⚠️ **BLOCKED 只针对 `synchronized` 锁**！用 `java.util.concurrent.locks.Lock`（如 `ReentrantLock`）等待时，线程状态是 **WAITING**，不是 BLOCKED。这是排查线程卡死时容易误判的点。

### 9.3 状态转换要点

```java
// ✅ 状态转换的关键点
// 1. NEW → RUNNABLE：调用 start()
// 2. RUNNABLE → TERMINATED：run() 结束（正常或异常）
// 3. RUNNABLE → BLOCKED：等 synchronized 锁
// 4. RUNNABLE → WAITING：wait()、join()、park()
// 5. RUNNABLE → TIMED_WAITING：sleep(ms)、wait(ms)、join(ms)
// 6. WAITING/TIMED_WAITING → RUNNABLE：notify、超时、interrupt
```

> 💡 **记忆要点**：① `sleep` → TIMED_WAITING；② `wait`/`join` 无参 → WAITING；③ `wait(ms)`/`join(ms)` → TIMED_WAITING；④ 等 `synchronized` 锁 → BLOCKED；⑤ `Lock.await` → WAITING（不是 BLOCKED）。

## 十、线程安全问题引出（卖票案例）⭐⭐⭐

多线程共享资源时，会出现「数据错乱」——这就是线程安全问题。最经典的例子是卖票：

```java
// ❌ 线程不安全：三个窗口卖 100 张票
class TicketTask implements Runnable {
    private int tickets = 100;

    @Override
    public void run() {
        while (tickets > 0) {
            // ⚠️ 这里不是原子操作：判断 >0、减 1、打印，三步之间可能被打断
            if (tickets > 0) {
                try { Thread.sleep(10); } catch (InterruptedException e) {}  // 模拟出票耗时
                System.out.println(Thread.currentThread().getName()
                        + " 卖险 卖票 " + tickets + "，剩余 " + --tickets);
            }
        }
    }
}

public class Demo {
    public static void main(String[] args) {
        TicketTask task = new TicketTask();
        new Thread(task, "窗口1").start();
        new Thread(task, "窗口2").start();
        new Thread(task, "窗口3").start();
    }
}
// 输出可能：
// 窗口1 卖票 100，剩余 99
// 窗口2 卖票 100，剩余 99   ← 同一张票被卖了两次！
// 窗口3 卖票 98，剩余 97
// ...
// 窗口1 卖票 0，剩余 -1     ← 卖出了不存在的票！
// 窗口2 卖票 -1，剩余 -2    ← 甚至卖负数票
```

### 10.1 问题原因分析

`tickets--` 看似一行代码，实际是三步：

```
1. 读取 tickets 的值（如 100）
2. 计算 100 - 1 = 99
3. 把 99 写回 tickets
```

线程 A 执行到第 2 步（刚算出 99 还没写回）时，线程 B 也来读 `tickets`，读到的还是 100——于是两张票都卖给了 100 号。这就是**竞态条件（Race Condition）**。

```
时间点    线程 A              线程 B
t1       读 tickets=100
t2       计算 100-1=99
t3                            读 tickets=100  ← 读到旧值！
t4       写回 tickets=99
t5                            计算 100-1=99
t6                            写回 tickets=99  ← 两次卖票，只减了一次
```

### 10.2 初步解决：synchronized

```java
// ✅ 加 synchronized：同一时刻只有一个线程能进入临界区
class TicketTask implements Runnable {
    private int tickets = 100;
    private final Object lock = new Object();  // 锁对象

    @Override
    public void run() {
        while (true) {
            synchronized (lock) {  // ✅ 互斥：同一时刻只有一个线程能进来
                if (tickets > 0) {
                    try { Thread.sleep(10); } catch (InterruptedException e) {}
                    System.out.println(Thread.currentThread().getName()
                            + " 卖险 卖票 " + tickets + "，剩余 " + --tickets);
                } else {
                    break;
                }
            }
        }
    }
}
```

> 💡 `synchronized` 的细节、`Lock`、`volatile`、原子类等是后续章节的重点。本篇只要理解：**多线程共享可变资源时，必须同步**，否则会出现数据错乱。

## ⚠️ 重点

### 重点 1：start 与 run 的区别 ⭐⭐⭐

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("线程：" + Thread.currentThread().getName());
    }
}

MyThread t = new MyThread();
t.start();  // ✅ 开新线程，输出 Thread-0
// t.run();  // ❌ 不开新线程，输出 main
```

> ⚠️ **这是新手第一大坑**。`start()` 才是启动新线程，`run()` 只是普通方法调用。判断方法：在 `run` 里打印 `Thread.currentThread().getName()`，如果是 `Thread-0` 说明是新线程，如果是 `main` 说明没开线程。

### 重点 2：sleep 不释放锁 ⭐⭐⭐

```java
Object lock = new Object();
Thread t1 = new Thread(() -> {
    synchronized (lock) {
        System.out.println("t1 拿到锁，开始 sleep");
        try { Thread.sleep(5000); } catch (InterruptedException e) {}
        System.out.println("t1 醒了，释放锁");
    }
});
Thread t2 = new Thread(() -> {
    synchronized (lock) {
        System.out.println("t2 拿到锁");
    }
});
t1.start();
Thread.sleep(100);
t2.start();  // t2 会阻塞 5 秒，直到 t1 sleep 完释放锁
```

> ⚠️ `Thread.sleep` **不释放锁**！sleep 期间其他线程拿不到它持有的锁。要释放锁等待，用 `Object.wait()`（会释放锁，需在 synchronized 块内调用）。这是 `sleep` 和 `wait` 的核心区别。

### 重点 3：join 等待子线程完成 ⭐⭐

```java
// ❌ 不用 join：main 线程可能先结束，看不到子线程结果
Thread t = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) {}
    System.out.println("子线程完成");
});
t.start();
System.out.println("main 结束");  // 先打印，子线程结果后打印甚至不打印

// ✅ 用 join：main 等子线程完成
Thread t2 = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) {}
    System.out.println("子线程完成");
});
t2.start();
t2.join();  // main 阻塞等 t2
System.out.println("main 结束");  // 子线程完成 → main 结束
```

> 💡 **场景**：主线程启动多个子线程并行计算，最后汇总结果，必须用 `join` 或 `CountDownLatch` 等所有子线程完成。`join` 是最简单的方式。

### 重点 4：守护线程的 finally 不保证执行 ⭐⭐

```java
Thread daemon = new Thread(() -> {
    try {
        while (true) {
            Thread.sleep(1000);
        }
    } finally {
        System.out.println("守护线程 finally");  // ⚠️ 不保证执行！
    }
});
daemon.setDaemon(true);
daemon.start();
Thread.sleep(3000);
System.out.println("main 结束，daemon 被强制终止");
// 可能输出 "守护线程 finally"，也可能不输出
```

> ⚠️ 守护线程被强制终止时，`finally` 块**不保证执行**。所以守护线程里不要做关闭数据库连接、刷写文件等关键操作。关键资源释放要用非守护线程或注册关闭钩子。

### 重点 5：线程状态 BLOCKED vs WAITING ⭐⭐⭐

```java
// ✅ BLOCKED：等 synchronized 锁
synchronized (lock) { ... }  // 其他线程等这个锁时是 BLOCKED

// ✅ WAITING：Lock.await（不是 synchronized）
lock.lock();
try { condition.await(); } finally { lock.unlock(); }  // 等待时是 WAITING

// ✅ TIMED_WAITING：sleep、wait(ms)、join(ms)
Thread.sleep(1000);  // TIMED_WAITING
```

> ⚠️ **排查线程卡死时**：`jstack` 输出里 `BLOCKED` 通常是 `synchronized` 锁竞争，`WAITING` 可能是 `Lock.await`、`park`、`join`。两者成因不同，解决方案也不同。混淆会导致排查方向错误。

### 重点 6：线程不安全的根因——竞态条件 ⭐⭐⭐

```java
// ❌ tickets-- 不是原子操作
private int tickets = 100;
// tickets-- 等价于：
//   1. 读 tickets
//   2. 计算 -1
//   3. 写回
// 三步之间可能被打断 → 数据错乱

// ✅ 解决一：synchronized
synchronized (lock) {
    if (tickets > 0) { tickets--; }
}

// ✅ 解决二：原子类（后续章节）
private AtomicInteger tickets = new AtomicInteger(100);
tickets.decrementAndGet();  // 原子操作
```

> 💡 **核心**：多线程共享可变资源时，非原子操作会产生竞态条件。判断标准：① 有共享资源；② 有修改操作（写）；③ 操作非原子。三者都满足就有线程安全问题，必须同步。

### 案例 1：多窗口卖票（线程安全问题引出）⭐⭐⭐

电影院三个窗口卖 100 张票，演示线程不安全及修复：

```java
// ❌ 线程不安全版本
class UnsafeTicket implements Runnable {
    private int tickets = 100;

    @Override
    public void run() {
        while (tickets > 0) {
            try { Thread.sleep(10); } catch (InterruptedException e) {}
            System.out.println(Thread.currentThread().getName()
                    + " 危险 卖票 " + tickets--);  // ⚠️ 重票、负票
        }
    }
}

// ✅ 线程安全版本：synchronized
class SafeTicket implements Runnable {
    private int tickets = 100;

    @Override
    public void run() {
        while (true) {
            synchronized (this) {  // ✅ 互斥
                if (tickets <= 0) break;
                try { Thread.sleep(10); } catch (InterruptedException e) {}
                System.out.println(Thread.currentThread().getName()
                        + " 危险 卖票 " + tickets--);
            }
        }
    }
}

public class TicketDemo {
    public static void main(String[] args) {
        SafeTicket task = new SafeTicket();
        new Thread(task, "窗口1").start();
        new Thread(task, "窗口2").start();
        new Thread(task, "窗口3").start();
    }
}
```

> 💡 这是线程安全问题的「Hello World」。实际开发中，库存扣减、秒杀、余额变更都是同类问题——共享资源被多个线程修改，必须同步。后续章节会用 `Lock`、`AtomicInteger`、`CAS` 等更高效的方式解决。

### 案例 2：Callable + FutureTask 带返回值的异步任务 ⭐⭐⭐

电商系统并行查询多个服务，汇总结果返回：

```java
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;
import java.util.concurrent.ExecutionException;

// ✅ 模拟三个服务：查商品、查库存、查优惠
class ProductService implements Callable<String> {
    @Override
    public String call() throws Exception {
        Thread.sleep(500);  // 模拟远程调用
        return "商品：iPhone 15，价格 5999";
    }
}

class StockService implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        Thread.sleep(300);
        return 50;  // 库存 50 件
    }
}

class CouponService implements Callable<Double> {
    @Override
    public Double call() throws Exception {
        Thread.sleep(400);
        return 500.0;  // 优惠 500 元
    }
}

public class ProductDetailDemo {
    public static void main(String[] args) throws ExecutionException, InterruptedException {
        long start = System.currentTimeMillis();

        // ✅ 三个任务并行执行
        FutureTask<String> productFuture = new FutureTask<>(new ProductService());
        FutureTask<Integer> stockFuture = new FutureTask<>(new StockService());
        FutureTask<Double> couponFuture = new FutureTask<>(new CouponService());

        new Thread(productFuture, "product").start();
        new Thread(stockFuture, "stock").start();
        new Thread(couponFuture, "coupon").start();

        // ✅ 分别等待结果（哪个先完成先拿哪个）
        String product = productFuture.get();
        Integer stock = stockFuture.get();
        Double coupon = couponFuture.get();

        System.out.println(product);
        System.out.println("库存：" + stock + " 件");
        System.out.println("优惠：" + coupon + " 元");
        System.out.println("总耗时：" + (System.currentTimeMillis() - start) + " ms");
        // 并行耗时约 500ms（取最慢的），串行则需 500+300+400=1200ms
    }
}
```

> 💡 这是商品详情页的典型场景——并行调用多个下游服务，总耗时取决于最慢的那个，而非累加。实际开发用 `CompletableFuture`（Java 8）更优雅，但底层思想一致。

### 案例 3：join 等待子线程完成汇总 ⭐⭐⭐

大数据统计：把数据分块，多个线程并行计算，主线程汇总：

```java
// ✅ 多线程分块求和，join 汇总
class SumTask extends Thread {
    private final long[] data;
    private final int start;
    private final int end;
    private long result;

    public SumTask(long[] data, int start, int end) {
        this.data = data;
        this.start = start;
        this.end = end;
    }

    @Override
    public void run() {
        for (int i = start; i < end; i++) {
            result += data[i];
        }
    }

    public long getResult() { return result; }
}

public class ParallelSum {
    public static void main(String[] args) throws InterruptedException {
        // 准备 1 千万个数据
        long[] data = new long[10_000_000];
        for (int i = 0; i < data.length; i++) {
            data[i] = i;
        }

        int threadCount = 4;
        int chunk = data.length / threadCount;
        SumTask[] tasks = new SumTask[threadCount];

        long t1 = System.currentTimeMillis();
        for (int i = 0; i < threadCount; i++) {
            int start = i * chunk;
            int end = (i == threadCount - 1) ? data.length : start + chunk;
            tasks[i] = new SumTask(data, start, end);
            tasks[i].start();
        }

        // ✅ join 等待所有子线程完成
        long total = 0;
        for (SumTask task : tasks) {
            task.join();  // 阻塞等该线程完成
            total += task.getResult();
        }
        long t2 = System.currentTimeMillis();

        System.out.println("总和：" + total);
        System.out.println("并行耗时：" + (t2 - t1) + " ms");
        // 4 线程并行比单线程快约 2-3 倍（受核数限制）
    }
}
```

> 💡 这是 ForkJoin 框架的雏形——分而治之。Java 8 的 `parallelStream`、`CompletableFuture.allOf` 底层都是这个思想：拆分任务 → 并行执行 → 汇总结果。

### 案例 4：守护线程做心跳上报 ⭐⭐

后台服务启动一个守护线程，定时上报心跳到监控中心：

```java
// ✅ 心跳守护线程：主服务退出时自动终止
public class HeartbeatService {
    private volatile boolean running = true;

    public void start() {
        // ✅ 心跳线程设为守护线程
        Thread heartbeat = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted() && running) {
                try {
                    // 上报心跳到监控中心
                    reportHeartbeat();
                    Thread.sleep(10000);  // 每 10 秒上报一次
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    break;
                } catch (Exception e) {
                    System.err.println("心跳上报失败：" + e.getMessage());
                }
            }
        }, "heartbeat-daemon");
        heartbeat.setDaemon(true);  // ✅ 守护线程，主服务退出时自动终止
        heartbeat.start();
        System.out.println("心跳服务已启动");
    }

    private void reportHeartbeat() {
        // 模拟 HTTP 上报
        System.out.println("[" + Thread.currentThread().getName()
                + "] 上报心跳，时间 " + System.currentTimeMillis());
    }

    public void stop() {
        running = false;
    }

    public static void main(String[] args) throws InterruptedException {
        HeartbeatService service = new HeartbeatService();
        service.start();

        // 主业务运行 25 秒后退出
        Thread.sleep(25000);
        System.out.println("主服务退出，心跳守护线程随之终止");
    }
}
```

> 💡 守护线程做心跳、日志刷写、定时清理等「辅助」任务很合适——主业务结束就一起退出，不用手动管理生命周期。但要注意：守护线程的 `finally` 不保证执行，关键数据要主动落盘。

### 案例 5：sleep 模拟延时（限流降级）⭐⭐

调用下游接口时，控制请求频率避免压垮对方：

```java
// ✅ 简易限流器：固定间隔发请求
public class RateLimiter {
    private final long interval;  // 请求间隔（毫秒）
    private long lastTime = 0;

    public RateLimiter(long interval) {
        this.interval = interval;
    }

    public synchronized void acquire() throws InterruptedException {
        long now = System.currentTimeMillis();
        long elapsed = now - lastTime;
        if (elapsed < interval) {
            // ✅ sleep 模拟延时，控制频率
            Thread.sleep(interval - elapsed);
        }
        lastTime = System.currentTimeMillis();
    }
}

// 使用：调用短信接口，每秒最多 1 次
public class SmsService {
    private final RateLimiter limiter = new RateLimiter(1000);  // 1 秒 1 次

    public void sendSms(String phone, String content) throws InterruptedException {
        limiter.acquire();  // ✅ 限流
        System.out.println("发送短信到 " + phone + "：" + content + "，时间 "
                + System.currentTimeMillis());
    }

    public static void main(String[] args) throws InterruptedException {
        SmsService service = new SmsService();
        for (int i = 0; i < 5; i++) {
            service.sendSms("13800000000", "验证码 " + i);
        }
        // 输出间隔约 1000ms
    }
}
```

> 💡 这是令牌桶/漏桶限流的雏形。生产环境用 Guava `RateLimiter` 或 Sentinel，但理解 `sleep` 控制频率的原理是基础。注意 `sleep` 不释放锁，所以这里的 `synchronized` 在 sleep 期间会阻塞其他调用者——这正是限流要的效果。

### 案例 6：线程状态演示（教学/调试）⭐⭐

打印线程各阶段状态，帮助理解状态转换：

```java
public class StateDemo {
    private static final Object lock = new Object();

    public static void main(String[] args) throws InterruptedException {
        // ✅ NEW
        Thread t = new Thread(() -> {
            // 子线程内部状态
            try {
                // TIMED_WAITING（sleep）
                Thread.sleep(2000);

                // WAITING（join 等待另一个线程）
                Thread helper = new Thread(() -> {
                    try { Thread.sleep(1000); } catch (InterruptedException e) {}
                });
                helper.start();
                helper.join();  // 子线程 WAITING

                // BLOCKED（等 synchronized 锁）
                synchronized (StateDemo.class) {
                    // 拿到锁
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        System.out.println("1. 创建后：" + t.getState());  // NEW

        t.start();
        Thread.sleep(200);
        System.out.println("2. sleep 中：" + t.getState());  // TIMED_WAITING

        Thread.sleep(2000);
        System.out.println("3. join 中：" + t.getState());  // WAITING

        t.join();
        System.out.println("4. 结束后：" + t.getState());  // TERMINATED

        // ✅ BLOCKED 演示
        Thread holder = new Thread(() -> {
            synchronized (lock) {
                try { Thread.sleep(3000); } catch (InterruptedException e) {}
            }
        });
        Thread waiter = new Thread(() -> {
            synchronized (lock) { }
        });
        holder.start();
        Thread.sleep(200);
        waiter.start();
        Thread.sleep(200);
        System.out.println("5. 等锁中：" + waiter.getState());  // BLOCKED
    }
}
```

> 💡 这是排查线程卡死的基础——用 `jstack` 看线程栈时，会看到各线程的状态。理解状态转换，才能从「线程 X 处于 BLOCKED」推断出「它在等某个锁」，进而定位死锁。

### 案例 7：多线程下载文件（Runnable + join 汇总）⭐⭐

```java
// ✅ 多线程下载：每个线程下载一块，join 汇总进度
class DownloadTask implements Runnable {
    private final String name;
    private final long size;
    private long downloaded;
    private boolean done;

    public DownloadTask(String name, long size) {
        this.name = name;
        this.size = size;
    }

    @Override
    public void run() {
        try {
            while (downloaded < size) {
                long chunk = Math.min(1024, size - downloaded);
                Thread.sleep(50);  // 模拟下载耗时
                downloaded += chunk;
            }
            done = true;
            System.out.println(name + " 下载完成");
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }

    public int getProgress() {
        return (int) (downloaded * 100 / size);
    }

    public boolean isDone() { return done; }
}

public class MultiDownloadDemo {
    public static void main(String[] args) throws InterruptedException {
        DownloadTask[] tasks = {
            new DownloadTask("文件1.bin", 10240),
            new DownloadTask("文件2.bin", 8192),
            new DownloadTask("文件3.bin", 12288)
        };

        // ✅ 启动所有下载线程
        Thread[] threads = new Thread[tasks.length];
        for (int i = 0; i < tasks.length; i++) {
            threads[i] = new Thread(tasks[i], "downloader-" + i);
            threads[i].start();
        }

        // ✅ 进度监控线程（守护线程）
        Thread monitor = new Thread(() -> {
            while (true) {
                int total = 0, done = 0;
                for (DownloadTask t : tasks) {
                    total += t.getProgress();
                    if (t.isDone()) done++;
                }
                System.out.printf("总进度：%d%%，完成 %d/%d%n",
                        total / tasks.length, done, tasks.length);
                if (done == tasks.length) break;
                try { Thread.sleep(500); } catch (InterruptedException e) { break; }
            }
        }, "progress-monitor");
        monitor.setDaemon(true);
        monitor.start();

        // ✅ join 等待所有下载完成
        for (Thread t : threads) t.join();
        System.out.println("全部下载完成！");
    }
}
```

> 💡 这是 `Runnable` + `join` + 守护线程的综合应用：任务用 `Runnable`、汇总用 `join`、监控用守护线程。下载工具（迅雷、IDM）的核心逻辑就是这个模式——多线程分块下载 + 进度汇总。

## 🚀 新版本补充

### Java 9：Thread 的改进

Java 9 对线程 API 做了小幅增强，主要是 `onSpinWait` 和 CompletableFuture 相关（后者不在本篇范围）：

```java
// Java 9+：Thread.onSpinWait()，提示 CPU 当前在自旋等待
// 在自旋锁场景下可能优化性能（x86 上对应 PAUSE 指令）
while (!isReady) {
    Thread.onSpinWait();  // Java 9+，比空循环更友好
}
```

> 💡 `Thread.onSpinWait()` 是一个性能提示，在 x86 上编译成 `PAUSE` 指令，减少自旋循环的功耗和流水线冲突。普通业务开发用不到，主要在高性能并发框架（如 AQS 自旋）中使用。

### Java 19：虚拟线程（预览特性）

Java 19 引入虚拟线程（Project Loom），用「轻量级线程」大幅提升并发能力：

```java
// Java 19+（预览）：虚拟线程，创建百万级线程不费力
// Java 8 只能这样创建平台线程（重）：
Thread t = new Thread(() -> System.out.println("hi"));
t.start();

// Java 21 正式版：虚拟线程
// Thread vt = Thread.startVirtualThread(() -> System.out.println("virtual"));
// 虚拟线程由 JVM 调度在少量平台线程上，开销极小
```

> ⚠️ 虚拟线程是 Java 21 正式发布的重大特性。它让「一个请求一个线程」的模型重新可行——百万并发不再是线程池的天下。但本篇以 Java 8 为基准，了解即可，后续会有专门章节。

### Java 5+：线程池（推荐替代 new Thread）

```java
// Java 5+：用线程池替代 new Thread（生产环境标准做法）
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

ExecutorService pool = Executors.newFixedThreadPool(4);
for (int i = 0; i < 10; i++) {
    pool.submit(() -> {
        System.out.println(Thread.currentThread().getName() + " 执行任务");
    });
}
pool.shutdown();  // 关闭线程池
```

> 📌 **规范**：生产环境**不要 `new Thread`**，用线程池。`new Thread` 每次创建销毁开销大、无法控制并发数、容易 OOM。线程池复用线程、限制并发、提供队列和拒绝策略。详见后续线程池章节。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 进程 vs 线程 | 进程是资源分配单位，线程是 CPU 调度单位 |
| 并发 vs 并行 | 并发是交替执行，并行是多核同时执行 |
| 线程调度 | Java 用抢占式，优先级不保证 |
| 创建方式一 | 继承 Thread，重写 run，调 start（不调 run） |
| 创建方式二 | 实现 Runnable，传 Thread 构造（推荐） |
| 创建方式三 | 实现 Callable + FutureTask，有返回值 |
| `start` vs `run` | start 开新线程，run 是普通方法调用 |
| `sleep(ms)` | 当前线程睡眠，不释放锁，TIMED_WAITING |
| `join()` | 等待线程结束，当前线程 WAITING |
| `yield()` | 让出 CPU，不保证 |
| `setDaemon(true)` | 守护线程，必须在 start 前设，finally 不保证执行 |
| `setPriority(1-10)` | 优先级不保证，默认 5 |
| 线程六状态 | NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED |
| BLOCKED | 等 synchronized 锁 |
| WAITING | wait/join/park，Lock.await 也是 WAITING |
| 线程安全 | 共享 + 修改 + 非原子 = 竞态条件，需同步 |

## 学习建议

1. **手写卖票案例**：先写线程不安全版本，看到重票、负票；再加 `synchronized` 修复。亲眼看到多线程 bug 比看十遍文字都管用——这是理解线程安全的起点。
2. **牢记 start 和 run 的区别**：这是新手第一大坑。在 `run` 里打印 `Thread.currentThread().getName()`，如果输出 `main` 说明没开线程。养成「启动线程永远用 start」的肌肉记忆。
3. **用 jstack 观察线程状态**：写一个会 `sleep`、`join`、等锁的程序，运行时用 `jstack <pid>` 看线程栈，对照六种状态。这是排查线上线程卡死的核心技能，光看理论记不牢。
4. **理解 sleep 不释放锁**：写一个线程持锁后 sleep，另一个线程等同一把锁，观察第二个线程被阻塞。对比 `wait`（释放锁）的区别——这是 `sleep` 和 `wait` 最容易混淆的点。
5. **生产环境用线程池不用 new Thread**：本篇的 `new Thread` 是教学用，理解原理即可。真实开发用 `ExecutorService`，能复用线程、控制并发、提供拒绝策略。养成这个习惯，能避免一半的线上 OOM 和性能问题。
