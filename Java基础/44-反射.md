# 反射

**反射（Reflection）** 是 Java 的「动态」能力：在程序运行期间，可以动态获取一个类的所有信息（构造方法、成员方法、成员变量），甚至能创建对象、调用方法、修改字段值——这一切都不需要在编译期写死。Spring 的 IOC、MyBatis 的 ORM、JUnit 的测试方法扫描，底层都靠反射驱动。可以说，**不懂反射，就看不懂任何主流框架的源码**。

> 💡 阅读本篇前，建议先掌握 [09-类与对象](09-类与对象：封装与构造方法.md) 的构造方法、[11-继承](11-继承与final.md) 的继承体系，以及 [13-接口](13-接口.md)——反射操作的核心就是类和接口的元信息。本篇也是下一篇 [45-注解](45-注解.md) 的前置，注解的读取完全依赖反射。

## 一、反射的概念

### 1.1 什么是反射

普通方式：**编译期**就确定要 new 哪个类、调哪个方法。

```java
// 普通方式：编译期就写死了类型和方法
Student s = new Student();      // 写死 new Student
s.study();                       // 写死调 study()
```

反射方式：**运行期**才知道操作哪个类，通过 Class 对象动态获取信息、调用方法。

```java
// 反射方式：运行时才知道类名，动态创建对象、调用方法
String className = "com.example.Student";  // 类名可以来自配置文件
Class<?> clazz = Class.forName(className);  // 运行时加载
Object obj = clazz.getDeclaredConstructor().newInstance();  // 动态创建
Method m = clazz.getMethod("study");        // 动态获取方法
m.invoke(obj);                              // 动态调用
```

> 💡 **通俗理解**：普通方式是「照着图纸施工」，图纸（代码）在开工前就定死了；反射是「边看图纸边施工」，图纸可以在施工时才拿到，甚至可以临时改。

### 1.2 反射的应用场景

反射不是日常业务代码的首选（性能差、破坏封装），但它是**框架的基石**：

| 场景 | 说明 | 代表框架 |
| :--- | :--- | :--- |
| **IOC 容器** | 读配置/注解，动态创建 Bean 并注入依赖 | Spring |
| **ORM 映射** | 表字段 ↔ 对象属性，动态 get/set | MyBatis、Hibernate |
| **注解处理** | 运行时扫描注解，执行对应逻辑 | Spring MVC、JUnit |
| **动态代理** | 运行时生成代理类，实现 AOP | Spring AOP |
| **序列化** | 遍历对象字段，转 JSON/XML | FastJSON、Jackson |
| **测试框架** | 扫描 @Test 方法并执行 | JUnit |

> 📌 **一句话总结**：业务代码用接口和多态就够了，需要「运行时才知道操作谁」时才用反射。框架之所以大量用反射，是因为框架写代码时根本不知道用户会写什么类。

## 二、获取 Class 对象的三种方式 ⭐⭐⭐

反射的入口是 `Class` 对象。同一个类在 JVM 中只会有一个 `Class` 对象（同一类加载器前提下）。获取它有三种方式，分别对应不同使用场景：

### 2.1 方式一：Class.forName("全类名")

```java
// 多用于：读配置文件，类名是字符串
Class<?> clazz = Class.forName("com.example.Student");
```

- 参数是**全类名**（包名 + 类名），写错会抛 `ClassNotFoundException`。
- 会触发类的**初始化**（执行 static 代码块、给 static 变量赋值）。
- 典型场景：JDBC 加载驱动 `Class.forName("com.mysql.cj.jdbc.Driver")`。

### 2.2 方式二：类名.class

```java
// 多用于：参数传递，编译期就知道类型
Class<Student> clazz = Student.class;
Class<?> intClazz = int.class;       // 基本类型也有 Class 对象
Class<?> arrClazz = String[].class; // 数组也有
```

- 编译期检查，写错类名直接编译报错。
- **不会**触发类初始化（只加载、不执行 static 块）。
- 典型场景：`synchronized (Student.class)`、`List.class` 作为同步锁或参数。

### 2.3 方式三：对象.getClass()

```java
// 多用于：运行时拿到对象，反推它的类型
Student s = new Student();
Class<? extends Student> clazz = s.getClass();
```

- `getClass()` 定义在 `Object` 类中，所有引用类型都有。
- 返回的是对象的**实际运行时类型**，不是引用类型。

```java
Object obj = new Student();   // 引用类型是 Object
Class<?> clazz = obj.getClass();
System.out.println(clazz.getName()); // com.example.Student，是实际类型
```

### 2.4 三种方式对比与「一次加载」原则

| 方式 | 触发初始化 | 编译期检查 | 典型场景 |
| :--- | :---: | :---: | :--- |
| `Class.forName("全类名")` | ✅ 是 | ❌ 否 | 配置文件、JDBC |
| `类名.class` | ❌ 否 | ✅ 是 | 参数传递、同步锁 |
| `对象.getClass()` | ❌ 否 | ❌ 否 | 运行时反推类型 |

> ⚠️ **核心原则⭐**：同一个字节码文件（`.class`）在一次程序运行过程中**只会被加载一次**，所以三种方式拿到的是同一个 `Class` 对象：

```java
Class<?> c1 = Class.forName("com.example.Student");
Class<?> c2 = Student.class;
Class<?> c3 = new Student().getClass();
System.out.println(c1 == c2);  // true
System.out.println(c2 == c3);  // true，三个是同一个对象
```

### 2.5 Class 类的常用方法

```java
Class<?> clazz = Student.class;

// 获取类名
clazz.getName();        // com.example.Student（全类名）
clazz.getSimpleName();  // Student（简单名）

// 获取父类与接口
clazz.getSuperclass();           // class com.example.Person
clazz.getInterfaces();           // 实现的接口数组
clazz.getModifiers();            // 修饰符（public=1，private=2...）

// 判断关系
clazz.isInterface();             // 是否接口
clazz.isArray();                 // 是否数组
clazz.isAssignableFrom(Person.class); // Student 能否赋给 Person
```

## 三、获取构造方法并创建对象 ⭐⭐

### 3.1 准备一个目标类

```java
package com.example;

public class Student {
    private String name;
    public int age;

    public Student() {                          // 无参构造
        System.out.println("无参构造");
    }

    public Student(String name) {               // 公有有参
        this.name = name;
        System.out.println("公有有参：" + name);
    }

    private Student(String name, int age) {      // 私有有参
        this.name = name;
        this.age = age;
        System.out.println("私有有参：" + name + "," + age);
    }

    public void study() { System.out.println(name + " 正在学习"); }
}
```

### 3.2 获取构造方法的方法

| 方法 | 范围 |
| :--- | :--- |
| `getConstructors()` | 所有 **public** 构造方法 |
| `getDeclaredConstructors()` | **所有**构造方法（含 private/默认/protected） |
| `getConstructor(参数类型...)` | 指定参数的 **public** 构造方法 |
| `getDeclaredConstructor(参数类型...)` | 指定参数的**任意**构造方法（含 private） |

> 💡 **记忆规律**：带 `Declared` 的能拿到本类**所有**声明的方法（含私有），不带的只能拿 **public**；带 `s` 的返回数组，不带的返回单个。

```java
Class<?> clazz = Student.class;

// 获取所有 public 构造
Constructor<?>[] cs = clazz.getConstructors();
for (Constructor<?> c : cs) {
    System.out.println(c);   // 只打印 public 的
}

// 获取所有构造（含私有）
Constructor<?>[] all = clazz.getDeclaredConstructors();

// 获取无参 public 构造
Constructor<?> c1 = clazz.getConstructor();
// 获取有参 public 构造
Constructor<?> c2 = clazz.getConstructor(String.class);
// 获取私有有参构造（带 Declared）
Constructor<?> c3 = clazz.getDeclaredConstructor(String.class, int.class);
```

### 3.3 创建对象：newInstance

```java
// 方式一：Class.newInstance()（Java 9 起废弃，仅限 public 无参）
Object o1 = clazz.newInstance();   // ⚠️ Java 9+ 已废弃

// 方式二：Constructor.newInstance（推荐，通用）
Constructor<?> c1 = clazz.getDeclaredConstructor();
Object o2 = c1.newInstance();                       // 无参

Constructor<?> c2 = clazz.getDeclaredConstructor(String.class);
Object o3 = c2.newInstance("张三");                  // 有参
```

### 3.4 暴力反射：突破 private

私有构造方法默认不能在外部调用，但反射可以突破：

```java
// 私有构造，默认不能访问
Constructor<?> c = clazz.getDeclaredConstructor(String.class, int.class);
// c.newInstance("李四", 20);  // ❌ IllegalAccessException

// ✅ 暴力反射：取消访问检查
c.setAccessible(true);
Object o = c.newInstance("李四", 20);  // 成功，突破 private
```

> ⚠️ `setAccessible(true)` 是暴力反射的核心，它不仅作用于构造方法，对私有方法和字段同样有效。这也是为什么单例模式遇到反射会失效——反射能强行调用私有构造。

## 四、获取成员方法并调用 ⭐⭐

### 4.1 获取方法的方法

| 方法 | 范围 |
| :--- | :--- |
| `getMethods()` | 本类及继承的所有 **public** 方法（含 Object 的） |
| `getDeclaredMethods()` | **本类**所有方法（含私有，不含继承） |
| `getMethod(名, 参数类型...)` | 指定 public 方法（含继承） |
| `getDeclaredMethod(名, 参数类型...)` | 指定本类方法（含私有） |

```java
Class<?> clazz = Student.class;

// 获取所有 public 方法（含继承自 Object 的）
Method[] ms = clazz.getMethods();
for (Method m : ms) {
    System.out.println(m.getName());   // study, equals, hashCode, toString...
}

// 获取本类所有方法（含私有，不含继承）
Method[] all = clazz.getDeclaredMethods();

// 获取指定方法
Method m1 = clazz.getMethod("study");                       // 无参
Method m2 = clazz.getDeclaredMethod("setName", String.class); // 有参
```

### 4.2 调用方法：invoke

```java
Object obj = clazz.getDeclaredConstructor().newInstance();
Method m = clazz.getMethod("study");
// invoke(对象, 参数...)：静态方法对象可传 null
m.invoke(obj);   // 张三 正在学习
```

带参数与返回值的方法：

```java
public class Calculator {
    public int add(int a, int b) { return a + b; }
    private int multiply(int a, int b) { return a * b; }
    public static double square(double x) { return x * x; }
}
```

```java
Class<?> clazz = Calculator.class;
Object obj = clazz.getDeclaredConstructor().newInstance();

// 有参有返回
Method add = clazz.getMethod("add", int.class, int.class);
Object result = add.invoke(obj, 3, 5);     // 返回 8（Integer）
System.out.println(result);

// 静态方法：对象传 null
Method square = clazz.getMethod("square", double.class);
System.out.println(square.invoke(null, 4.0));  // 16.0

// 私有方法：暴力反射
Method mul = clazz.getDeclaredMethod("multiply", int.class, int.class);
mul.setAccessible(true);
System.out.println(mul.invoke(obj, 3, 4));     // 12
```

### 4.3 Method 的信息方法

```java
Method m = clazz.getMethod("add", int.class, int.class);
m.getName();                  // add，方法名
m.getReturnType();            // int.class，返回值类型
m.getParameterTypes();        // [int, int]，参数类型数组
m.getModifiers();             // 修饰符
m.getExceptionTypes();        // 抛出的异常类型
m.isVarArgs();                // 是否可变参数
```

## 五、获取成员变量并操作 ⭐⭐

### 5.1 获取字段的方法

| 方法 | 范围 |
| :--- | :--- |
| `getFields()` | 本类及父类的所有 **public** 字段 |
| `getDeclaredFields()` | **本类**所有字段（含私有） |
| `getField(名)` | 指定 public 字段（含父类） |
| `getDeclaredField(名)` | 指定本类字段（含私有） |

```java
Class<?> clazz = Student.class;
Field[] fs = clazz.getDeclaredFields();
for (Field f : fs) {
    System.out.println(f.getName() + " : " + f.getType());
}
// name : class java.lang.String
// age : int
```

### 5.2 读写字段：get / set

```java
Object obj = clazz.getDeclaredConstructor().newInstance();

Field nameF = clazz.getDeclaredField("name");
nameF.setAccessible(true);          // ✅ 私有字段必须先取消访问检查
nameF.set(obj, "王五");             // 设置值
Object v = nameF.get(obj);          // 获取值
System.out.println(v);              // 王五

Field ageF = clazz.getField("age");  // public 字段无需 setAccessible
ageF.set(obj, 18);
System.out.println(ageF.get(obj));  // 18
```

> ⚠️ **基本类型字段**有专门的 `getInt/setInt`、`getDouble/setDouble` 等方法，避免自动装箱开销：
> ```java
> Field ageF = clazz.getDeclaredField("age");
> ageF.setAccessible(true);
> ageF.setInt(obj, 18);
> int age = ageF.getInt(obj);
> ```

### 5.3 Field 的信息方法

```java
Field f = clazz.getDeclaredField("name");
f.getName();          // name
f.getType();          // class java.lang.String
f.getModifiers();     // 修饰符
f.setAccessible(true);
```

## 六、反射操作泛型与数组

### 6.1 获取字段的泛型类型

```java
class Box {
    public List<String> items;
}

Field f = Box.class.getField("items");
Type type = f.getGenericType();   // java.util.List<java.lang.String>
if (type instanceof ParameterizedType) {
    ParameterizedType pt = (ParameterizedType) type;
    Type[] args = pt.getActualTypeArguments();  // [class java.lang.String]
    System.out.println(args[0]);  // class java.lang.String
}
```

### 6.2 获取方法的泛型参数与返回值

```java
import java.lang.reflect.Method;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.List;
import java.util.Map;

class Dao {
    public Map<String, Integer> query() { return null; }
    public void save(List<String> list) {}
}

// 返回值的泛型
Method m = Dao.class.getMethod("query");
Type t = m.getGenericReturnType();   // Map<String, Integer>
// 参数的泛型
Type[] pts = m.getGenericParameterTypes();
```

> 💡 这类 API 在 JSON 序列化框架（如 Jackson、Gson）中大量使用，用来还原泛型类型，避免类型擦除导致的信息丢失。

## 七、动态代理 ⭐⭐⭐

动态代理是反射的**高级应用**，也是 **AOP（面向切面编程）** 的底层基础。它可以在运行时动态生成一个代理对象，在不修改原代码的前提下增强方法。

### 7.1 静态代理的局限

```java
interface UserService {
    void save();
}

class UserServiceImpl implements UserService {
    public void save() { System.out.println("保存用户"); }
}

// 静态代理：每个被代理类都要手写一个代理类
class UserServiceProxy implements UserService {
    private UserService target;
    public UserServiceProxy(UserService target) { this.target = target; }
    public void save() {
        System.out.println("【日志】方法开始");   // 增强
        target.save();                              // 目标方法
        System.out.println("【日志】方法结束");   // 增强
    }
}
```

> ⚠️ 静态代理的问题：一个接口写一个代理类，接口方法一多就重复；几十个 Service 就要写几十个代理类，无法维护。

### 7.2 JDK 动态代理

JDK 动态代理用 `Proxy.newProxyInstance` 在运行时生成代理类，**只能代理接口**。核心是 `InvocationHandler` 接口：

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

interface UserService {
    void save(String name);
    String find(String name);
}

class UserServiceImpl implements UserService {
    public void save(String name) { System.out.println("保存：" + name); }
    public String find(String name) { System.out.println("查询：" + name); return name + "-result"; }
}

// 通用日志处理器：对所有方法统一增强
class LogHandler implements InvocationHandler {
    private Object target;   // 被代理的真实对象

    public LogHandler(Object target) { this.target = target; }

    // 代理对象调任何方法都会进这里
    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("【日志】" + method.getName() + " 开始，参数：" + Arrays.toString(args));
        Object result = method.invoke(target, args);   // 真正调用目标方法
        System.out.println("【日志】" + method.getName() + " 结束，返回：" + result);
        return result;
    }
}

// 使用
public class Demo {
    public static void main(String[] args) {
        UserService target = new UserServiceImpl();
        // 生成代理对象
        UserService proxy = (UserService) Proxy.newProxyInstance(
            target.getClass().getClassLoader(),   // 类加载器
            target.getClass().getInterfaces(),      // 代理的接口
            new LogHandler(target)                  // 处理器
        );
        proxy.save("张三");
        proxy.find("李四");
    }
}
```

输出：

```
【日志】save 开始，参数：[张三]
保存：张三
【日志】save 结束，返回：null
【日志】find 开始，参数：[李四]
查询：李四
【日志】find 结束，返回：李四-result
```

> 💡 **三个参数的理解**：
> - `ClassLoader`：代理类是运行时动态生成的，需要类加载器把它加载进 JVM，用目标对象的类加载器即可。
> - `Class[] interfaces`：代理类要实现哪些接口，决定代理对象能调什么方法。
> - `InvocationHandler`：代理对象每调用一个方法，都会转发到 `invoke`，在这里做增强 + 调目标方法。

### 7.3 JDK 动态代理的局限：只能代理接口

```java
class OrderService {   // 注意：没有实现接口
    public void pay() { System.out.println("支付"); }
}

OrderService target = new OrderService();
// ❌ 下面的代理对没有接口的类无效，生成的代理对象无法强转
Object proxy = Proxy.newProxyInstance(
    target.getClass().getClassLoader(),
    new Class[]{},   // 没有接口可代理
    (p, m, a) -> m.invoke(target, a)
);
// proxy 无法当 OrderService 用，因为代理类不继承 OrderService
```

> ⚠️ **JDK 动态代理只能代理接口类型**，目标类必须至少实现一个接口。这是 JDK 代理最大的限制，也是 CGLIB 存在的原因。

### 7.4 CGLIB 动态代理（简述）

CGLIB（Code Generation Library）通过**生成目标类的子类**来实现代理，不要求目标类实现接口，但**不能代理 final 类/方法**。

```java
// 需引入 cglib 依赖（Spring 内置了 cglib）
import net.sf.cglib.proxy.Enhancer;
import net.sf.cglib.proxy.MethodInterceptor;
import net.sf.cglib.proxy.MethodProxy;
import java.lang.reflect.Method;

class OrderService {   // 没实现任何接口
    public void pay() { System.out.println("支付"); }
}

class LogInterceptor implements MethodInterceptor {
    private Object target;
    public LogInterceptor(Object target) { this.target = target; }

    @Override
    public Object intercept(Object o, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        System.out.println("【CGLIB】" + method.getName() + " 前");
        Object result = method.invoke(target, args);
        System.out.println("【CGLIB】" + method.getName() + " 后");
        return result;
    }
}

// 使用
OrderService target = new OrderService();
OrderService proxy = (OrderService) Enhancer.create(
    target.getClass(),
    new LogInterceptor(target)
);
proxy.pay();
```

| 代理方式 | 要求 | 原理 | Spring 中的选择 |
| :--- | :--- | :--- | :--- |
| **JDK 动态代理** | 目标类实现接口 | 实现同一接口 | 默认（有接口时） |
| **CGLIB 代理** | 目标类非 final | 生成子类 | 无接口时自动切换 |

> 💡 **Spring AOP** 默认策略：目标类有接口用 JDK 代理，没接口用 CGLIB；也可强制全部用 CGLIB（`spring.aop.proxy-target-class=true`）。这就是 AOP「@Aspect 切面」能生效的底层原因。

## 八、反射的缺点

反射强大，但代价不小，日常业务代码应避免滥用：

1. **性能损耗**：反射调用要经过方法查找、参数装箱、访问检查等步骤，比直接调用慢几倍到几十倍。JIT 优化后差距缩小，但仍存在。
2. **破坏封装**：`setAccessible(true)` 能强行访问私有成员，绕过访问控制，破坏了类的封装性，可能引发安全问题。
3. **不安全**：反射能绕过泛型检查、破坏单例、修改不可变对象（如改 String 的 value），容易产生难以排查的 bug。
4. **可读性差**：反射代码晦涩，IDE 无法做静态检查，重构时容易漏改。

> 📌 **使用原则**：框架底层用反射，业务代码用接口+多态。能不用反射就不用，必须用时尽量缓存 `Class`/`Method`/`Field` 对象，避免重复查找。

## ⚠️ 重点

### 重点 1：三种获取 Class 的方式与「一次加载」⭐⭐⭐

```java
Class<?> c1 = Class.forName("com.example.Student");  // 触发初始化
Class<?> c2 = Student.class;                          // 不初始化
Class<?> c3 = new Student().getClass();              // 不初始化
System.out.println(c1 == c2 && c2 == c3);  // true，同一个对象
```

> 📌 **面试高频**：三种方式分别适用什么场景？为什么说「一个字节码只加载一次」？答：因为类加载器对同一个类只会执行一次加载+链接+初始化，`Class` 对象存在方法区/元空间，全局唯一。

### 重点 2：getDeclaredXxx 与 getXxx 的区别 ⭐⭐

```java
// getMethods()：包含继承的 public 方法（Object 的也有）
// getDeclaredMethods()：本类所有方法（含私有），不含继承
// getFields()：包含父类的 public 字段
// getDeclaredFields()：本类所有字段（含私有）
```

> 💡 **一句话**：带 `Declared` = 本类全部（含私有）；不带 = public 全部（含继承）。这是反射 API 最容易混淆的点。

### 重点 3：setAccessible(true) 暴力反射 ⭐⭐

```java
Constructor<?> c = clazz.getDeclaredConstructor(String.class, int.class);
// c.newInstance("x", 1);  // ❌ private，IllegalAccessException
c.setAccessible(true);      // ✅ 取消访问检查
c.newInstance("x", 1);      // 成功
```

> ⚠️ `setAccessible(true)` 对私有构造、私有方法、私有字段都有效。但它**不能突破模块系统**的限制（Java 9+ 模块化），且可能被安全管理器（`SecurityManager`）拦截。

### 重点 4：invoke 的参数与返回 ⭐⭐

```java
// 实例方法：第一个参数是对象，后面是方法参数
method.invoke(obj, arg1, arg2);
// 静态方法：对象传 null
method.invoke(null, arg1);
// 无参方法：不传参数
method.invoke(obj);
// 有返回值：返回 Object，需强转
String r = (String) method.invoke(obj);
```

### 重点 5：JDK 动态代理只能代理接口 ⭐⭐⭐

```java
// ✅ 目标类实现接口：可代理
List<String> proxy = (List<String>) Proxy.newProxyInstance(
    ArrayList.class.getClassLoader(),
    new Class[]{List.class},
    (p, m, a) -> m.invoke(new ArrayList<>(), a)
);

// ❌ 目标类没接口：代理对象无法强转
// Proxy.newProxyInstance 生成的类只实现指定接口，不继承目标类
```

> 📌 **面试题**：JDK 动态代理为什么只能代理接口？答：因为 `Proxy.newProxyInstance` 生成的代理类继承了 `Proxy` 类，而 Java 是单继承，所以只能通过实现接口来获得目标类型的能力。要代理类本身得用 CGLIB（生成子类）。

### 重点 6：反射破坏单例 ⭐

```java
class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
    public static Singleton getInstance() { return INSTANCE; }
}

// 反射强行调用私有构造
Constructor<Singleton> c = Singleton.class.getDeclaredConstructor();
c.setAccessible(true);
Singleton fake = c.newInstance();
System.out.println(fake == Singleton.getInstance());  // false，单例被破坏
```

> ⚠️ 防御方法：在私有构造里加判断，第二次创建就抛异常；或用枚举实现单例（枚举的反射创建被 JVM 禁止）。

## 💻 实战案例

### 案例 1：模拟 Spring IOC——读配置创建对象 ⭐⭐⭐

真实 Spring 通过 XML 或注解配置 Bean，运行时反射创建。这里用一个 `properties` 文件模拟：

```properties
# beans.properties
userService=com.example.UserServiceImpl
orderService=com.example.OrderServiceImpl
```

```java
import java.io.InputStream;
import java.util.HashMap;
import java.util.Map;
import java.util.Properties;

// 简易 IOC 容器
public class MyContainer {
    private Map<String, Object> beans = new HashMap<>();

    // 读配置，反射创建所有 Bean
    public void init(String config) throws Exception {
        Properties props = new Properties();
        try (InputStream in = MyContainer.class.getClassLoader().getResourceAsStream(config)) {
            props.load(in);
        }
        for (String name : props.stringPropertyNames()) {
            String className = props.getProperty(name);
            Class<?> clazz = Class.forName(className);
            Object obj = clazz.getDeclaredConstructor().newInstance();
            beans.put(name, obj);   // 存进容器
        }
    }

    @SuppressWarnings("unchecked")
    public <T> T getBean(String name) {
        return (T) beans.get(name);
    }

    public static void main(String[] args) throws Exception {
        MyContainer c = new MyContainer();
        c.init("beans.properties");
        UserService svc = c.getBean("userService");
        svc.save();
    }
}
```

> 💡 这就是 Spring IOC 的雏形：**读配置 → Class.forName → newInstance → 存 Map**。Spring 在此基础上加了依赖注入、生命周期、AOP，但核心还是反射。

### 案例 2：通过反射执行任意方法（方法调度器） ⭐⭐

后台任务系统：收到 `{类名, 方法名, 参数}`，动态调用。

```java
import java.lang.reflect.Method;

public class MethodDispatcher {
    @SuppressWarnings("unchecked")
    public static Object call(String className, String methodName,
                              Class<?>[] paramTypes, Object[] args) throws Exception {
        Class<?> clazz = Class.forName(className);
        Object obj = clazz.getDeclaredConstructor().newInstance();
        Method m = clazz.getMethod(methodName, paramTypes);
        return m.invoke(obj, args);
    }

    public static void main(String[] args) throws Exception {
        // 等价于 new Calculator().add(3, 5)
        Object r = call("com.example.Calculator", "add",
                new Class[]{int.class, int.class}, new Object[]{3, 5});
        System.out.println(r);  // 8
    }
}
```

> 💡 RPC 框架（如 Dubbo）服务端收到请求后，就是根据方法名+参数类型反射调用对应实现，原理与此一致。

### 案例 3：动态代理实现统一日志（AOP 雏形） ⭐⭐⭐

电商系统中，所有 Service 方法都要记日志、统计耗时、处理异常。用动态代理统一处理，避免每个方法手写：

```java
import java.lang.reflect.*;
import java.util.Arrays;

interface OrderService {
    String createOrder(String userId, double amount);
    void cancelOrder(String orderId);
}

class OrderServiceImpl implements OrderService {
    public String createOrder(String userId, double amount) {
        System.out.println("创建订单：" + userId + "，金额：" + amount);
        return "ORD-" + System.currentTimeMillis();
    }
    public void cancelOrder(String orderId) {
        System.out.println("取消订单：" + orderId);
    }
}

// 通用增强处理器：日志 + 耗时 + 异常
class ServiceAspect implements InvocationHandler {
    private Object target;
    public ServiceAspect(Object target) { this.target = target; }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        long start = System.currentTimeMillis();
        System.out.println("【入参】" + method.getName() + Arrays.toString(args));
        try {
            Object result = method.invoke(target, args);
            long cost = System.currentTimeMillis() - start;
            System.out.println("【返回】" + result + "，耗时 " + cost + "ms");
            return result;
        } catch (InvocationTargetException e) {
            // 目标方法抛的异常被包装，要取 cause
            System.out.println("【异常】" + e.getCause());
            throw e.getCause();
        }
    }

    @SuppressWarnings("unchecked")
    public static <T> T wrap(T target) {
        return (T) Proxy.newProxyInstance(
            target.getClass().getClassLoader(),
            target.getClass().getInterfaces(),
            new ServiceAspect(target)
        );
    }
}

// 使用
public class Demo {
    public static void main(String[] args) {
        OrderService raw = new OrderServiceImpl();
        OrderService proxy = ServiceAspect.wrap(raw);   // 一行包成代理
        String orderId = proxy.createOrder("U001", 199.0);
        proxy.cancelOrder(orderId);
    }
}
```

> 💡 这就是 **Spring AOP @Around** 通知的简化版。真实 Spring 用 `AspectJ` 切点表达式匹配方法，但运行时增强逻辑与此一致。

### 案例 4：通过反射读取注解（模拟 ORM 字段映射） ⭐⭐

```java
import java.lang.reflect.Field;

// 自定义表注解
@java.lang.annotation.Retention(java.lang.annotation.RetentionPolicy.RUNTIME)
@java.lang.annotation.Target(java.lang.annotation.ElementType.TYPE)
@interface Table {
    String value();
}

// 自定义列注解
@java.lang.annotation.Retention(java.lang.annotation.RetentionPolicy.RUNTIME)
@java.lang.annotation.Target(java.lang.annotation.ElementType.FIELD)
@interface Column {
    String value();
}

@Table("t_user")
class User {
    @Column("user_id")
    private Integer id;
    @Column("user_name")
    private String name;
    @Column("user_age")
    private Integer age;
}

public class OrmDemo {
    // 根据 @Table 和 @Column 生成建表 SQL
    public static String buildCreateSQL(Class<?> clazz) {
        Table t = clazz.getAnnotation(Table.class);
        if (t == null) throw new RuntimeException("缺少 @Table");
        StringBuilder sb = new StringBuilder("CREATE TABLE ");
        sb.append(t.value()).append(" (");
        for (Field f : clazz.getDeclaredFields()) {
            Column c = f.getAnnotation(Column.class);
            if (c == null) continue;
            sb.append(c.value()).append(" ")
              .append(f.getType() == String.class ? "VARCHAR(255)" : "INT")
              .append(", ");
        }
        sb.delete(sb.length() - 2, sb.length()).append(")");
        return sb.toString();
    }

    public static void main(String[] args) {
        System.out.println(buildCreateSQL(User.class));
        // CREATE TABLE t_user (user_id INT, user_name VARCHAR(255), user_age INT)
    }
}
```

> 💡 MyBatis、Hibernate 就是这么把对象映射成表、把字段映射成列的。注解的详细用法见下一篇 [45-注解](45-注解.md)。

### 案例 5：通用对象转 Map（序列化工具） ⭐⭐

```java
import java.lang.reflect.Field;
import java.util.HashMap;
import java.util.Map;

public class ObjectToMap {
    // 把任意对象转成 Map：字段名 → 字段值
    public static Map<String, Object> toMap(Object obj) throws Exception {
        Map<String, Object> map = new HashMap<>();
        Class<?> clazz = obj.getClass();
        // 遍历本类及所有父类的字段
        while (clazz != null && clazz != Object.class) {
            for (Field f : clazz.getDeclaredFields()) {
                f.setAccessible(true);
                // 跳过静态字段
                if (Modifier.isStatic(f.getModifiers())) continue;
                map.put(f.getName(), f.get(obj));
            }
            clazz = clazz.getSuperclass();   // 往上找父类字段
        }
        return map;
    }

    public static void main(String[] args) throws Exception {
        User u = new User();
        u.id = 1; u.name = "张三"; u.age = 20;
        System.out.println(toMap(u));
        // {id=1, name=张三, age=20}
    }
}
```

> 💡 Jackson、FastJSON 把对象序列化成 JSON，核心就是反射遍历字段取值（还要处理嵌套、循环引用、注解配置等）。这个案例是它的最小实现。

### 案例 6：反射扩展——通用 Setters 赋值（表单填充） ⭐

Web 框架把请求参数自动填充到对象，靠反射调 setter：

```java
import java.lang.reflect.Method;
import java.util.Map;

public class BeanWrapper {
    // 把 Map 中的值通过 setter 填充到对象
    public static void populate(Object obj, Map<String, String> params) throws Exception {
        Class<?> clazz = obj.getClass();
        for (Map.Entry<String, String> e : params.entrySet()) {
            String name = e.getKey();
            String value = e.getValue();
            try {
                Field f = clazz.getDeclaredField(name);
                String setterName = "set" + Character.toUpperCase(name.charAt(0)) + name.substring(1);
                Method setter = clazz.getMethod(setterName, f.getType());
                // 类型转换（简化版，仅支持常用类型）
                Object arg = convert(value, f.getType());
                setter.invoke(obj, arg);
            } catch (NoSuchFieldException ignored) {
                // 字段不存在则跳过
            }
        }
    }

    private static Object convert(String value, Class<?> type) {
        if (type == String.class) return value;
        if (type == int.class || type == Integer.class) return Integer.parseInt(value);
        if (type == long.class || type == Long.class) return Long.parseLong(value);
        if (type == boolean.class || type == Boolean.class) return Boolean.parseBoolean(value);
        if (type == double.class || type == Double.class) return Double.parseDouble(value);
        return value;
    }

    public static void main(String[] args) throws Exception {
        Map<String, String> form = new HashMap<>();
        form.put("name", "李四");
        form.put("age", "25");
        User u = new User();
        populate(u, form);
        System.out.println(u.name + "," + u.age);  // 李四,25
    }
}
```

> 💡 Spring MVC 的 `@ModelAttribute`、Struts2 的表单填充，底层都是这个套路：**反射找 setter + 类型转换 + invoke**。

## 🚀 新版本补充

### Java 9：模块系统对反射的影响

Java 9 引入模块系统后，反射受到模块边界限制。即使 `setAccessible(true)`，也不能随意访问其他模块的非公开成员（除非模块通过 `opens` 开放）。

```java
// Java 9+ 模块描述文件 module-info.java
module com.example.app {
    requires java.sql;
    opens com.example.entity to com.fasterxml.jackson.databind;  // 仅对 Jackson 开放反射
    // opens com.example;  // 对所有模块开放反射
}
```

> ⚠️ 这导致很多老框架（如 Jackson、Spring）在 Java 9+ 需要加 `--add-opens` 启动参数才能正常工作。`setAccessible` 不再万能。

### Java 9：Constructor.newInstance 推荐 + Class.newInstance 废弃

```java
// Java 9 起，Class.newInstance() 被废弃
Object o1 = clazz.newInstance();   // ⚠️ deprecated

// 推荐用 Constructor
Object o2 = clazz.getDeclaredConstructor().newInstance();
```

### Java 9：VarHandle 替代部分反射

`java.lang.invoke.VarHandle` 提供了对字段更高效、更安全的访问方式，部分场景替代反射的 `Field`：

```java
import java.lang.invoke.MethodHandles;
import java.lang.invoke.VarHandle;

class Counter {
    private int count;
    static final VarHandle COUNT;
    static {
        try {
            COUNT = MethodHandles.privateLookupIn(Counter.class, MethodHandles.lookup())
                .findVarHandle(Counter.class, "count", int.class);
        } catch (Exception e) { throw new RuntimeException(e); }
    }
}
```

> 💡 `VarHandle` 比 `Field` 快（可被 JIT 内联），且能做 CAS 原子操作，是 `AtomicInteger` 等的新底层。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 反射概念 | 运行时动态获取/操作类的信息 |
| 获取 Class | `Class.forName`、`类名.class`、`对象.getClass()`，一次只加载一次 |
| 构造方法 | `getDeclaredConstructor` + `newInstance`，私有用 `setAccessible(true)` |
| 成员方法 | `getDeclaredMethod` + `invoke(obj, args)`，静态方法传 null |
| 成员变量 | `getDeclaredField` + `get/set(obj, 值)` |
| 暴力反射 | `setAccessible(true)` 突破 private |
| JDK 动态代理 | `Proxy.newProxyInstance` + `InvocationHandler`，只能代理接口 |
| CGLIB 代理 | 生成子类，可代理类，不能代理 final |
| 反射缺点 | 性能损耗、破坏封装、不安全、可读性差 |

## 学习建议

1. **先跑通「三种获取 Class」的代码**：把三种方式打印出来，亲眼看到 `==` 为 true，理解「一次加载」原则，这是反射的基石。
2. **手写一个简易 IOC 容器**：照着案例 1，读 properties 创建对象存进 Map，再写个 `getBean` 方法。这一步做完，你对 Spring 的理解会上一个台阶。
3. **务必手写动态代理**：案例 3 的 `ServiceAspect` 是理解 Spring AOP 的钥匙。自己写一遍，把日志、耗时、异常处理都加上，再对比静态代理，体会「动态」二字的威力。
4. **理解 getDeclaredXxx 与 getXxx 的边界**：这是反射 API 最容易混淆的点。写个小程序，给一个有继承关系的类，分别打印 `getMethods` 和 `getDeclaredMethods` 的结果，差异一目了然。
5. **业务代码慎用反射**：反射是框架的武器，不是业务的日常工具。能用接口+多态解决的，不要用反射；必须用时，缓存 `Class`/`Method`/`Field` 对象避免重复查找，并做好异常处理（`ClassNotFoundException`、`NoSuchMethodException`、`InvocationTargetException` 都要 catch）。
