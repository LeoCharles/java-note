# 线程池

线程的创建和销毁是有代价的：每次 `new Thread()` 都要向操作系统申请线程、分配栈空间，用完再销毁。在高并发场景下，频繁创建销毁线程会严重拖垮系统。线程池（Thread Pool）通过**预先创建一批线程、重复利用**来解决这个问题，同时提供任务队列和拒绝策略，是 Java 后端开发的核心基础设施。

> 💡 在阅读本篇前，建议先看 [38-多线程基础](38-多线程基础.md) 和 [40-JUC并发包](40-JUC并发包.md)，理解线程生命周期和 BlockingQueue，再来学习线程池会更顺畅。

## 一、线程池的好处

```java
// ❌ 每次请求都 new Thread：资源消耗大、响应慢、无法管理
for (int i = 0; i < 1000; i++) {
    new Thread(() -> handleRequest()).start();  // 创建1000个线程！
}

// ✅ 用线程池：线程复用、可控并发数
ExecutorService pool = Executors.newFixedThreadPool(10);
for (int i = 0; i < 1000; i++) {
    pool.submit(() -> handleRequest());  // 复用10个线程
}
```

线程池三大好处：

| 好处 | 说明 |
| :--- | :--- |
| 降低资源消耗 | 线程复用，避免频繁创建/销毁的开销 |
| 提高响应速度 | 任务到达直接用现有线程执行，无需创建 |
| 便于管理 | 统一调优、监控线程数、任务队列、拒绝策略 |

> 📌 **核心思想**：线程是宝贵资源，像数据库连接一样要「池化」管理。

## 二、ThreadPoolExecutor ⭐⭐⭐⭐

`ThreadPoolExecutor` 是 JUC 线程池的核心实现类，所有线程池功能都基于它。`Executors` 工厂方法创建的线程池内部也是 new 了这个类。

### 2.1 七个核心参数

```java
public ThreadPoolExecutor(
    int corePoolSize,                  // 1. 核心线程数
    int maximumPoolSize,              // 2. 最大线程数
    long keepAliveTime,               // 3. 空闲存活时间
    TimeUnit unit,                    // 4. 时间单位
    BlockingQueue<Runnable> workQueue,// 5. 任务队列
    ThreadFactory threadFactory,      // 6. 线程工厂
    RejectedExecutionHandler handler  // 7. 拒绝策略
)
```

逐个解释：

| 参数 | 说明 | 常用值 |
| :--- | :--- | :--- |
| corePoolSize | 核心线程数，常驻不销毁 | CPU 密集 N+1，IO 密集 2N |
| maximumPoolSize | 最大线程数，超过核心的为「非核心线程」 | 根据业务压测 |
| keepAliveTime | 非核心线程空闲多久后销毁 | 60L |
| unit | 时间单位 | TimeUnit.SECONDS |
| workQueue | 任务队列，核心线程忙时排队 | LinkedBlockingQueue |
| threadFactory | 创建线程的工厂，可设线程名 | 自定义带命名 |
| handler | 任务太多处理不了的拒绝策略 | AbortPolicy |

```java
import java.util.concurrent.*;

// 标准创建方式（阿里推荐）
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    2,                              // 核心线程 2
    4,                              // 最大线程 4
    60L,                            // 空闲 60 秒
    TimeUnit.SECONDS,               // 时间单位
    new ArrayBlockingQueue<>(10),   // 队列容量 10
    new ThreadFactory() {           // 线程工厂，给线程起名
        private int count = 0;
        @Override
        public Thread newThread(Runnable r) {
            return new Thread(r, "biz-pool-" + (count++));
        }
    },
    new ThreadPoolExecutor.AbortPolicy()  // 拒绝策略
);
```

> 📌 **规范**：用 `ThreadPoolExecutor` 显式创建，不要用 `Executors`（见第三章）。

### 2.2 执行流程 ⭐⭐⭐

这是面试必考题：任务提交后线程池如何处理？

```
提交任务 execute(task)
    │
    ▼
当前线程数 < corePoolSize？
    │ 是
    ├──────────────────► 创建核心线程执行 ✅
    │ 否
    ▼
任务队列未满？
    │ 是
    ├──────────────────► 任务入队列等待 ✅
    │ 否
    ▼
当前线程数 < maximumPoolSize？
    │ 是
    ├──────────────────► 创建非核心线程执行 ✅
    │ 否
    ▼
执行拒绝策略 ❌
```

**口诀：核心 → 队列 → 非核心 → 拒绝**

```java
// 演示执行流程
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    2, 4, 30L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(2)  // 队列容量 2
);

// 任务1、2：创建核心线程（2个核心线程占满）
pool.execute(() -> sleep(1000));  // 核心线程1
pool.execute(() -> sleep(1000));  // 核心线程2

// 任务3、4：核心线程忙，入队列（队列容量2，刚好放满）
pool.execute(() -> sleep(1000));  // 入队列
pool.execute(() -> sleep(1000));  // 入队列

// 任务5、6：队列满，创建非核心线程（到最大4）
pool.execute(() -> sleep(1000));  // 非核心线程3
pool.execute(() -> sleep(1000));  // 非核心线程4

// 任务7：核心满、队列满、最大线程满 → 拒绝策略
pool.execute(() -> sleep(1000));  // ❌ RejectedExecutionException
```

> ⚠️ **关键点**：线程池**先填满队列，再创建非核心线程**，不是先创建线程再排队！这是最常被误解的地方。

### 2.3 四种拒绝策略

当核心线程满、队列满、最大线程也满时，触发拒绝策略：

| 拒绝策略 | 行为 | 适用场景 |
| :--- | :--- | :--- |
| `AbortPolicy` | 抛 `RejectedExecutionException`（默认） | 不容忍丢任务，必须感知 |
| `CallerRunsPolicy` | 让提交任务的线程自己执行 | 不丢任务，降级（如主线程自己跑） |
| `DiscardPolicy` | 静默丢弃新任务 | 可容忍丢任务 |
| `DiscardOldestPolicy` | 丢弃队列最旧的任务，腾位置给新任务 | 新任务更重要 |

```java
// 四种策略的使用方式
new ThreadPoolExecutor.AbortPolicy();        // 默认，抛异常
new ThreadPoolExecutor.CallerRunsPolicy();   // 调用者执行
new ThreadPoolExecutor.DiscardPolicy();      // 丢弃，不报错
new ThreadPoolExecutor.DiscardOldestPolicy(); // 丢最旧的
```

> 💡 **实际开发选哪个？**
> - 关键业务（订单、支付）：`AbortPolicy` + 报警，绝不能丢
> - 非关键（日志、统计）：`DiscardPolicy`，丢了无所谓
> - 需要降级：`CallerRunsPolicy`，让调用方限速

### 2.4 线程池的关闭

```java
pool.shutdown();      // 温和：不再接新任务，等已提交任务执行完
pool.shutdownNow();   // 强制：停止所有任务，返回未执行的任务列表
pool.isShutdown();    // 是否已关闭
pool.isTerminated();  // 是否所有任务都结束了
pool.awaitTermination(60, TimeUnit.SECONDS);  // 等待关闭，最多60秒
```

| 方法 | 行为 |
| :--- | :--- |
| `shutdown()` | 不接新任务，已执行完的等结束，队列中的继续执行 |
| `shutdownNow()` | 尝试中断正在执行的任务，返回队列中未执行的任务 |
| `awaitTermination()` | 阻塞等待关闭完成 |

> ⚠️ **优雅关闭**：先 `shutdown()` 不接新任务，再 `awaitTermination()` 等一段时间，超时还没结束再 `shutdownNow()` 强制关。

```java
// 优雅关闭模板
pool.shutdown();
try {
    if (!pool.awaitTermination(60, TimeUnit.SECONDS)) {
        pool.shutdownNow();  // 超时强制关
    }
} catch (InterruptedException e) {
    pool.shutdownNow();
}
```

## 三、Executors 工厂方法 ⭐⭐

`Executors` 提供了快捷创建线程池的工厂方法，但**不推荐使用**（见 3.5）。

### 3.1 newFixedThreadPool

```java
// 固定线程数，无界队列
ExecutorService pool = Executors.newFixedThreadPool(10);
// 源码等价于：
// new ThreadPoolExecutor(10, 10, 0L, MILLISECONDS,
//     new LinkedBlockingQueue<>())  // 队列无界！
```

> ⚠️ `LinkedBlockingQueue` 默认容量是 `Integer.MAX_VALUE`（约 21 亿），任务堆积会 **OOM**。

### 3.2 newSingleThreadExecutor

```java
// 单线程，保证任务顺序执行
ExecutorService pool = Executors.newSingleThreadExecutor();
// 源码：core=max=1，无界队列
```

### 3.3 newCachedThreadPool

```java
// 可缓存，线程数 0~Integer.MAX_VALUE
ExecutorService pool = Executors.newCachedThreadPool();
// 源码：core=0, max=Integer.MAX_VALUE, 60秒空闲销毁
// 来任务就创建线程，空闲60秒回收
```

> ⚠️ 最大线程数无上限，突发大量任务会创建海量线程导致 **OOM**。

### 3.4 newScheduledThreadPool

```java
// 定时任务线程池
ScheduledExecutorService pool = Executors.newScheduledThreadPool(2);

// 延迟 5 秒执行
pool.schedule(() -> System.out.println("延迟执行"), 5, TimeUnit.SECONDS);

// 固定速率：每 10 秒执行一次（不管上次有没有执行完）
pool.scheduleAtFixedRate(() -> System.out.println("固定速率"),
    0, 10, TimeUnit.SECONDS);

// 固定延迟：上次结束后等 10 秒再执行下一次
pool.scheduleWithFixedDelay(() -> System.out.println("固定延迟"),
    0, 10, TimeUnit.SECONDS);
```

### 3.5 阿里规范：禁止用 Executors ⭐⭐⭐

> 📌 **阿里巴巴 Java 开发手册**：
> 线程池不允许使用 `Executors` 去创建，而是通过 `ThreadPoolExecutor` 的方式，这样的处理方式让写的同学更加明确线程池的运行规则，规避资源耗尽的风险。

| Executors 方法 | 弊端 |
| :--- | :--- |
| `newFixedThreadPool` | 队列无界 → OOM |
| `newSingleThreadExecutor` | 队列无界 → OOM |
| `newCachedThreadPool` | 最大线程无上限 → OOM |
| `newScheduledThreadPool` | 队列无界 → OOM |

```java
// ❌ 禁止
ExecutorService pool = Executors.newFixedThreadPool(10);

// ✅ 推荐
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    10, 10, 60L, TimeUnit.SECONDS,
    new LinkedBlockingQueue<>(1000),  // 有界队列
    new ThreadPoolExecutor.CallerRunsPolicy()
);
```

## 四、线程池参数设置经验

线程池大小的设置取决于任务类型：

| 任务类型 | 推荐核心线程数 | 说明 |
| :--- | :--- | :--- |
| CPU 密集型 | N + 1 | N = CPU 核心数，+1 防止偶发停顿 |
| IO 密集型 | 2N 或更多 | IO 等待时让出 CPU，可多开线程 |
| 混合型 | 拆分成 CPU 型和 IO 型分别建池 | |

```java
// 获取 CPU 核心数
int cpuCores = Runtime.getRuntime().availableProcessors();

// CPU 密集型
ThreadPoolExecutor cpuPool = new ThreadPoolExecutor(
    cpuCores + 1, cpuCores + 1, 0L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100));

// IO 密集型
ThreadPoolExecutor ioPool = new ThreadPoolExecutor(
    cpuCores * 2, cpuCores * 2, 60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(500),
    new ThreadPoolExecutor.CallerRunsPolicy());
```

> ⚠️ 公式只是起点，**最终要靠压测调整**。线程数太少 → 吞吐低；太多 → 上下文切换开销大。

> 💡 **实际经验**：
> - 队列别太大，否则任务堆积延迟高
> - 给线程起名字（自定义 ThreadFactory），方便排查问题
> - 加监控：`getActiveCount()`、`getQueue().size()`、`getCompletedTaskCount()`

## 五、CompletableFuture ⭐⭐⭐

`CompletableFuture` 是 Java 8 引入的异步编程利器，比 `Future` 更强大——支持链式回调、组合、异常处理，是写异步代码的首选。

### 5.1 创建异步任务

```java
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

// supplyAsync：有返回值，默认用 ForkJoinPool.commonPool()
CompletableFuture<String> future1 = CompletableFuture.supplyAsync(() -> {
    sleep(100);
    return "结果1";
});

// runAsync：无返回值
CompletableFuture<Void> future2 = CompletableFuture.runAsync(() -> {
    System.out.println("执行无返回值任务");
});

// 指定线程池（推荐！不要用默认的公共池）
ExecutorService myPool = Executors.newFixedThreadPool(4);
CompletableFuture<String> future3 = CompletableFuture.supplyAsync(() -> {
    return "用自定义线程池";
}, myPool);

System.out.println(future1.get());  // 阻塞获取结果
```

> ⚠️ `CompletableFuture` 默认用 `ForkJoinPool.commonPool()`，这是全局共享的，任务多了会互相影响。**生产环境务必传自定义线程池**。

### 5.2 链式回调

```java
CompletableFuture.supplyAsync(() -> "hello")
    .thenApply(s -> s + " world")       // 拿到结果，返回新值
    .thenAccept(s -> System.out.println(s))  // 拿到结果，消费，无返回
    .thenRun(() -> System.out.println("完成"));  // 不关心结果，执行收尾

// thenApply：有输入有输出（Function）
// thenAccept：有输入无输出（Consumer）
// thenRun：无输入无输出（Runnable）
```

```java
// thenApplyAsync：回调也在异步线程执行
CompletableFuture.supplyAsync(() -> queryUser())
    .thenApplyAsync(user -> enrichUser(user), myPool)  // 异步链式
    .thenAccept(u -> System.out.println(u));
```

### 5.3 合并两个异步结果

```java
CompletableFuture<String> futureUser = CompletableFuture.supplyAsync(() -> "Tom");
CompletableFuture<Integer> futureAge = CompletableFuture.supplyAsync(() -> 18);

// thenCombine：合并两个 future 的结果
CompletableFuture<String> combined = futureUser.thenCombine(futureAge,
    (user, age) -> user + " 今年 " + age + " 岁");

System.out.println(combined.get());  // Tom 今年 18 岁
```

### 5.4 allOf / anyOf

```java
CompletableFuture<String> f1 = CompletableFuture.supplyAsync(() -> { sleep(100); return "A"; });
CompletableFuture<String> f2 = CompletableFuture.supplyAsync(() -> { sleep(200); return "B"; });
CompletableFuture<String> f3 = CompletableFuture.supplyAsync(() -> { sleep(150); return "C"; });

// allOf：等所有完成
CompletableFuture<Void> all = CompletableFuture.allOf(f1, f2, f3);
all.get();  // 阻塞，等三个都完成
System.out.println(f1.get() + f2.get() + f3.get());  // ABC

// anyOf：任一完成即返回
CompletableFuture<Object> any = CompletableFuture.anyOf(f1, f2, f3);
System.out.println(any.get());  // 最先完成的那个结果
```

> 💡 **allOf 典型场景**：并行调用多个接口，全部完成后再聚合（如电商首页聚合多个服务）。

### 5.5 异常处理

```java
// exceptionally：仅处理异常，正常不干预
CompletableFuture.supplyAsync(() -> {
    if (true) throw new RuntimeException("出错了");
    return "ok";
}).exceptionally(ex -> {
    System.out.println("捕获异常: " + ex.getMessage());
    return "默认值";  // 返回降级值
}).thenAccept(System.out::println);  // 默认值

// handle：正常和异常都处理
CompletableFuture.supplyAsync(() -> 10 / 0)
    .handle((result, ex) -> {
        if (ex != null) {
            return "异常: " + ex.getMessage();
        }
        return "结果: " + result;
    })
    .thenAccept(System.out::println);  // 异常: ...
```

> 💡 `exceptionally` 相当于 try-catch；`handle` 相当于 try-catch-finally，不管正常异常都走。

## ⚠️ 重点

### 重点 1：执行流程是「核心→队列→非核心」⭐⭐⭐

不是先创建到最大线程数再排队，而是**先填满队列再扩容**：

```java
// 队列容量 100 的池，即使来了 50 个任务也只用核心线程，不会扩容
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    2, 10, 60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100)  // 队列很大 → 很难触发扩容
);
// 这也是为什么 newFixedThreadPool 永远不扩容：队列无界，永远填不满
```

> ⚠️ 如果用无界队列，`maximumPoolSize` 永远不会生效！这是 `Executors` 系列的陷阱。

### 重点 2：禁止用 Executors ⭐⭐⭐

```java
// ❌ OOM 风险
Executors.newFixedThreadPool(10);     // 队列无界
Executors.newCachedThreadPool();      // 线程无上限

// ✅ 显式 ThreadPoolExecutor + 有界队列
new ThreadPoolExecutor(..., new ArrayBlockingQueue<>(1000), ...);
```

### 重点 3：核心线程数设置 ⭐⭐

```java
int n = Runtime.getRuntime().availableProcessors();
// CPU 密集型：N+1
// IO 密集型：2N（甚至更多，IO 等待长）
// 不要盲目设大，线程太多上下文切换开销大
```

### 重点 4：CompletableFuture 要传线程池 ⭐⭐⭐

```java
// ❌ 用默认公共池，全局共享，互相影响
CompletableFuture.supplyAsync(() -> doSomething());

// ✅ 传自定义线程池
CompletableFuture.supplyAsync(() -> doSomething(), myThreadPool);
```

### 重点 5：线程池要优雅关闭 ⭐⭐

```java
// ❌ 不关，程序退出时线程泄漏
// pool = null;  // 线程还在跑

// ✅ 优雅关闭
pool.shutdown();
pool.awaitTermination(10, TimeUnit.SECONDS);
```

### 重点 6：scheduleAtFixedRate vs scheduleWithFixedDelay ⭐⭐

```java
// AtFixedRate：固定速率，不管上次执行多久，每 10 秒一次
// （如果任务执行超过 10 秒，下一次会立即执行）
pool.scheduleAtFixedRate(task, 0, 10, TimeUnit.SECONDS);

// WithFixedDelay：固定延迟，上次结束后等 10 秒再下一次
pool.scheduleWithFixedDelay(task, 0, 10, TimeUnit.SECONDS);
```

## 💻 实战案例

### 案例 1：自定义线程池处理电商订单 ⭐⭐⭐⭐

```java
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

class OrderThreadPool {
    public static void main(String[] args) {
        // 自定义线程池
        ThreadPoolExecutor orderPool = new ThreadPoolExecutor(
            4,                              // 核心线程
            8,                              // 最大线程
            60L, TimeUnit.SECONDS,          // 空闲回收
            new ArrayBlockingQueue<>(200),  // 有界队列
            new ThreadFactory() {           // 命名线程
                final AtomicInteger counter = new AtomicInteger(0);
                @Override
                public Thread newThread(Runnable r) {
                    return new Thread(r, "order-pool-" + counter.getAndIncrement());
                }
            },
            new ThreadPoolExecutor.CallerRunsPolicy()  // 满了让调用方执行（降级限流）
        );

        // 提交订单处理任务
        for (int i = 0; i < 50; i++) {
            final int orderId = i;
            orderPool.execute(() -> processOrder(orderId));
        }

        // 优雅关闭
        orderPool.shutdown();
        try {
            if (!orderPool.awaitTermination(60, TimeUnit.SECONDS)) {
                orderPool.shutdownNow();
            }
        } catch (InterruptedException e) {
            orderPool.shutdownNow();
        }
    }

    static void processOrder(int orderId) {
        System.out.println(Thread.currentThread().getName() + " 处理订单: " + orderId);
        try { Thread.sleep(100); } catch (Exception e) {}
    }
}
```

### 案例 2：CompletableFuture 并行聚合接口 ⭐⭐⭐⭐

电商首页并行调用用户、商品、推荐三个接口，聚合返回：

```java
import java.util.concurrent.*;

class HomePageAggregator {
    static ExecutorService pool = Executors.newFixedThreadPool(3);

    public static void main(String[] args) throws Exception {
        long start = System.currentTimeMillis();

        // 三个接口并行调用
        CompletableFuture<String> userFuture = CompletableFuture
            .supplyAsync(() -> {
                sleep(200);
                return "用户信息";
            }, pool);

        CompletableFuture<String> productFuture = CompletableFuture
            .supplyAsync(() -> {
                sleep(300);
                return "商品列表";
            }, pool);

        CompletableFuture<String> recommendFuture = CompletableFuture
            .supplyAsync(() -> {
                sleep(250);
                return "推荐数据";
            }, pool)
            .exceptionally(ex -> "推荐服务降级");  // 单个服务降级

        // 等所有完成
        CompletableFuture.allOf(userFuture, productFuture, recommendFuture)
            .get();

        // 聚合
        String result = userFuture.get() + " | " + productFuture.get() + " | " + recommendFuture.get();
        System.out.println(result);
        System.out.println("耗时: " + (System.currentTimeMillis() - start) + "ms");
        // 串行需要 750ms，并行只需约 300ms

        pool.shutdown();
    }

    static void sleep(long ms) { try { Thread.sleep(ms); } catch(Exception e){} }
}
```

### 案例 3：定时任务线程池 ⭐⭐

import java.util.concurrent.*;

class ThreadPoolTuning {
    public static void main(String[] args) {
        int cores = Runtime.getRuntime().availableProcessors();
        System.out.println("CPU 核心数: " + cores);

        // CPU 密集型任务（纯计算）
        ThreadPoolExecutor cpuPool = new ThreadPoolExecutor(
            cores + 1, cores + 1, 0L, TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(100)
        );

        // IO 密集型任务（网络/数据库调用）
        ThreadPoolExecutor ioPool = new ThreadPoolExecutor(
            cores * 2, cores * 2, 60L, TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(500),
            new ThreadPoolExecutor.CallerRunsPolicy()
        );

        System.out.println("CPU 池核心: " + cpuPool.getCorePoolSize());
        System.out.println("IO 池核心: " + ioPool.getCorePoolSize());
    }
}

### 案例 6：CompletableFuture 链式编排订单流程 ⭐⭐⭐

```java
import java.util.concurrent.*;

class OrderPipeline {
    static ExecutorService pool = Executors.newFixedThreadPool(4);

    public static void main(String[] args) throws Exception {
        CompletableFuture.supplyAsync(() -> {
            // 1. 创建订单
            System.out.println("创建订单");
            return "ORDER_001";
        }, pool)
        .thenApplyAsync(orderId -> {
            // 2. 扣库存
            System.out.println("扣减库存: " + orderId);
            return orderId;
        }, pool)
        .thenApplyAsync(orderId -> {
            // 3. 支付
            System.out.println("支付: " + orderId);
            return orderId;
        }, pool)
        .thenAcceptAsync(orderId -> {
            // 4. 发通知
            System.out.println("发送通知: " + orderId);
        }, pool)
        .exceptionally(ex -> {
            System.out.println("流程异常: " + ex.getMessage());
            return null;
        })
        .get();  // 等待整个流程完成

        pool.shutdown();
    }
}
```

## 🚀 新版本补充

### Java 9：CompletableFuture 增强

Java 9 给 `CompletableFuture` 增加了超时和延迟支持：

```java
// Java 9+
// orTimeout：超时自动完成（异常）
future.orTimeout(3, TimeUnit.SECONDS);

// completeOnTimeout：超时给默认值
future.completeOnTimeout("默认值", 3, TimeUnit.SECONDS);

// delayedExecutor：延迟执行
CompletableFuture.delayedExecutor(2, TimeUnit.SECONDS)
    .execute(() -> System.out.println("延迟2秒执行"));
```

### Java 19+：虚拟线程（Loom）

Java 21 正式发布虚拟线程，可以创建海量线程而无需精细调参：

```java
// Java 21+
// 每个请求一个虚拟线程，无需线程池
Thread.startVirtualThread(() -> handleRequest());

// 虚拟线程的线程池
ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor();
```

> 💡 虚拟线程由 JVM 调度，阻塞在 IO 时不占用 OS 线程，IO 密集型场景可能不再需要精心设置线程池大小。但 CPU 密集型任务仍需传统线程池。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 线程池好处 | 复用线程、快速响应、便于管理 |
| ThreadPoolExecutor | 七参数：核心/最大线程、存活时间、队列、工厂、拒绝策略 |
| 执行流程 | 核心 → 队列 → 非核心 → 拒绝策略 |
| 四种拒绝策略 | Abort/CallerRuns/Discard/DiscardOldest |
| Executors | 禁用！队列/线程无界有 OOM 风险 |
| 参数设置 | CPU 密集 N+1，IO 密集 2N |
| 关闭 | shutdown 温和 / shutdownNow 强制 |
| CompletableFuture | 异步编程，链式回调、组合、异常处理 |
| allOf/anyOf | 等待全部/任一完成 |

## 学习建议

1. **手写 ThreadPoolExecutor**：不要用 Executors，亲手 new 一个带七个参数的线程池，理解每个参数的含义，这是面试和开发的基本功。
2. **画执行流程图**：在纸上画出「核心→队列→非核心→拒绝」的流程，能口述任务提交后的完整流转路径，这是面试高频题。
3. **压测感受参数影响**：用不同核心线程数和队列容量跑同一批任务，观察吞吐量和响应时间的变化，建立参数直觉。
4. **用 CompletableFuture 重写串行调用**：找一个项目中串行调多个接口的地方，用 `allOf` 改成并行，对比耗时差异，这是最直接的性能优化。
5. **养成线程池监控习惯**：给线程池起名字、加监控日志，线上出问题时能快速定位是哪个池、队列积了多少任务——排查问题的第一线索。
