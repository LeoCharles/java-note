# 内部类

内部类（Inner Class）是定义在**另一个类的内部**的类。它不是 Java 的花架子，而是解决特定设计问题的利器：当一个类只服务于另一个类、或需要访问外部类的私有成员、或只想「用一次就扔」时，内部类能让代码更内聚、更简洁。理解内部类，也是理解 Lambda 表达式和 Java 事件机制的前提。

> 💡 在阅读本篇前，建议先掌握 [11-面向对象](11-面向对象.md) 的封装与继承、[13-接口](13-接口.md) 的接口与匿名实现，内部类常与接口配合使用。

---

## 一、内部类是什么

### 1.1 概念

把一个类定义在另一个类的内部，就是内部类：

```java
public class Outer {        // 外部类
    class Inner {           // 内部类
        // ...
    }
}
```

`Inner` 定义在 `Outer` 内部，它是 `Outer` 的成员之一（像字段、方法一样）。内部类根据**定义位置和修饰符**分为四种：

| 类型 | 定义位置 | 修饰符 | 特点 |
| :--- | :--- | :--- | :--- |
| 成员内部类 | 类中、方法外 | 无 static | 依赖外部类实例，能访问外部类所有成员 |
| 静态内部类 | 类中、方法外 | static | 不依赖外部类实例，最常用 |
| 局部内部类 | 方法中 | 无 | 只能在定义它的方法内使用 |
| 匿名内部类 | 方法中（new 时） | 无 | 没有名字，一次性使用，重点 |

### 1.2 为什么要用内部类

```java
// 场景：一个集合类只和它的迭代器强绑定，迭代器只服务于这个集合
public class MyList {
    private Object[] data;

    // 迭代器只服务于 MyList，定义在外面没意义，放内部更内聚
    class MyIterator {
        private int cursor = 0;

        public boolean hasNext() { return cursor < data.length; }
        public Object next() { return data[cursor++]; }
        // 直接访问 MyList 的私有 data，无需暴露 data
    }

    public MyIterator iterator() { return new MyIterator(); }
}
```

> 💡 **内部类的价值**：
> 1. **内聚**：只服务于外部类的类，放内部更符合「高内聚」
> 2. **访问私有**：内部类能访问外部类的私有成员（包括私有字段、私有方法），外部类无需暴露
> 3. **隐藏实现**：内部类对外不可见，实现细节不暴露
> 4. **一次性使用**：匿名内部类让「用一次的接口实现」不必单独建类

## 二、成员内部类

### 2.1 定义与创建

成员内部类定义在类中、方法外，**没有 `static` 修饰**。它像实例字段一样，依赖外部类实例存在：

```java
public class Outer {
    private String outerField = "外部类字段";

    // 成员内部类
    class Inner {
        public void show() {
            System.out.println("内部类方法");
        }
    }
}

// 创建成员内部类对象：必须先有外部类实例
Outer.Inner inner = new Outer().new Inner();
inner.show();   // 内部类方法
```

> ⚠️ **关键**：成员内部类**不能脱离外部类实例独立存在**。必须先 `new Outer()` 再 `.new Inner()`，因为它本质上是外部类实例的「成员」。

### 2.2 访问外部类成员（包括私有）

内部类的最大特权：**能直接访问外部类的所有成员，包括 private**：

```java
public class Outer {
    private String secret = "外部类的秘密";
    private static String staticSecret = "外部类静态秘密";

    class Inner {
        public void access() {
            // ✅ 直接访问外部类私有字段
            System.out.println(secret);         // 外部类的秘密
            System.out.println(staticSecret);   // 外部类静态秘密
        }
    }
}

Outer.Inner inner = new Outer().new Inner();
inner.access();
```

> 💡 **原理**：编译后，内部类会隐式持有一个外部类实例的引用（`this$0`），所以能访问外部类实例成员。这也是它必须依赖外部类实例的原因。

### 2.3 内外部重名成员：Outer.this ⭐

当内部类和外部类有同名字段时，用 `外部类名.this.字段` 访问外部类的：

```java
public class Outer {
    private String name = "外部类的 name";

    class Inner {
        private String name = "内部类的 name";

        public void print() {
            String name = "局部变量 name";

            System.out.println(name);              // 局部变量 name（就近原则）
            System.out.println(this.name);         // 内部类的 name
            System.out.println(Outer.this.name);   // 外部类的 name ✅
        }
    }
}

new Outer().new Inner().print();
// 输出：
// 局部变量 name
// 内部类的 name
// 外部类的 name
```

> ⚠️ `Outer.this` 是固定语法，表示「持有我的外部类实例」。这是访问重名外部成员的唯一方式，面试常考。

### 2.4 成员内部类不能有 static 成员

```java
public class Outer {
    class Inner {
        // static int x = 1;   // ❌ 编译错误：非静态内部类不能有静态成员
        int x = 1;             // ✅ 实例成员可以

        // static void f() { } // ❌ 同理不能有静态方法
    }
}
```

> 💡 **例外**：`static final` 编译期常量可以（因为不依赖实例，编译期就确定）：
> ```java
> class Inner {
>     static final int MAX = 100;   // ✅ 编译期常量
> }
> ```

## 三、静态内部类

### 3.1 定义与创建

用 `static` 修饰的成员内部类，**不依赖外部类实例**，可以独立创建：

```java
public class Outer {
    private static String staticField = "静态字段";
    private String instanceField = "实例字段";

    // 静态内部类
    static class StaticInner {
        public void show() {
            // ✅ 能访问外部类的静态成员
            System.out.println(staticField);

            // ❌ 不能直接访问外部类的实例成员（没有外部实例）
            // System.out.println(instanceField);
        }
    }
}

// 创建：不需要外部类实例，直接 new
Outer.StaticInner inner = new Outer.StaticInner();
inner.show();
```

> 💡 **静态内部类 vs 成员内部类**：
> - 成员内部类：隐式持有外部实例引用 → 能访问实例成员 → 必须 `new Outer().new Inner()`
> - 静态内部类：不持有外部实例引用 → 只能访问静态成员 → 直接 `new Outer.StaticInner()`

### 3.2 静态内部类可以有静态成员

```java
public class Outer {
    static class StaticInner {
        static int x = 1;          // ✅ 静态成员可以
        int y = 2;                 // ✅ 实例成员也可以

        static void staticMethod() { System.out.println("静态方法"); }
        void instanceMethod() { System.out.println("实例方法"); }
    }
}

// 静态成员直接用类名访问
Outer.StaticInner.staticMethod();   // 静态方法
System.out.println(Outer.StaticInner.x);   // 1
```

### 3.3 静态内部类是最常用的内部类 ⭐

实际开发中，**静态内部类用得最多**，典型场景是 Builder 模式和 Map.Entry：

```java
// JDK 源码：HashMap 的 Node 就是静态内部类
public class HashMap<K,V> {
    static class Node<K,V> {   // 静态内部类，不依赖 HashMap 实例
        final int hash;
        K key;
        V value;
        // ...
    }
}

// Map.Entry 也是静态接口（嵌套接口）
public interface Map<K,V> {
    interface Entry<K,V> {   // 嵌套接口，默认 static
        K getKey();
        V getValue();
    }
}
```

> 📌 **规范**：如果一个内部类不需要访问外部类的实例成员，**优先用静态内部类**。这样避免隐式持有外部实例引用，减少内存占用，也防止外部类无法被 GC 回收（成员内部类会阻止外部类实例被回收，是内存泄漏隐患）。

## 四、局部内部类

### 4.1 定义在方法中

局部内部类定义在**方法、构造方法、代码块内部**，作用域仅限该方法：

```java
public class Outer {
    public void process() {
        int localVar = 10;   // 局部变量

        // 局部内部类：定义在方法内
        class Helper {
            public void run() {
                System.out.println("局部内部类");
                System.out.println(localVar);   // ✅ 能访问方法的局部变量
            }
        }

        Helper h = new Helper();   // 只能在方法内使用
        h.run();
    }
}

new Outer().process();
```

> ⚠️ 局部内部类**不能**在方法外使用，也不能加访问修饰符（`public`/`private` 等），因为它不是外部类的成员，只是方法的局部存在。

### 4.2 访问局部变量：必须是 effectively final ⭐

```java
public class Outer {
    public void process() {
        int x = 10;
        // x = 20;   // 如果这里修改了 x，下面的局部内部类就会编译报错

        class Helper {
            public void show() {
                System.out.println(x);   // ✅ x 是 effectively final 才能访问
            }
        }
        new Helper().show();
    }
}
```

> ⚠️ **规则**：局部内部类（和匿名内部类）访问的局部变量，必须是 **effectively final**（事实上的 final，即赋值后不再修改）。Java 8 之前必须显式加 `final`，Java 8 后只要「没被重新赋值」即可，称为 effectively final。
>
> **原因**：局部内部类对象的生命周期可能比方法栈长（比如方法返回了内部类对象）。它访问的局部变量其实是**值的副本**，如果原变量还能变，副本和原值就会不一致。强制 final 保证一致性。

```java
// ❌ 错误示例：局部变量被修改，内部类无法访问
public void process() {
    int x = 10;
    class Helper {
        public void show() { System.out.println(x); }
    }
    x = 20;   // ❌ 这行会导致上面访问 x 的地方编译错误
}
```

### 4.3 局部内部类也能访问外部类成员

```java
public class Outer {
    private String field = "外部字段";

    public void process() {
        class Helper {
            public void show() {
                System.out.println(field);   // ✅ 能访问外部类实例成员
            }
        }
        new Helper().show();
    }
}
```

> 💡 局部内部类用得少（多数场景被匿名内部类或 Lambda 取代），但在「方法内需要复用一段逻辑、又不想暴露为外部类方法」时仍有用武之地。

## 五、匿名内部类 ⭐⭐

匿名内部类是**最常用的内部类**，也是面试重点。它没有名字，在 `new` 的同时定义类并创建对象，本质是「一个继承了类/实现了接口的匿名子类对象」。

### 5.1 基本语法

```java
// 接口
public interface Greetable {
    void greet();
}

// 匿名内部类：new 接口名() { 重写方法 }
Greetable g = new Greetable() {
    @Override
    public void greet() {
        System.out.println("匿名实现：你好！");
    }
};
g.greet();   // 匿名实现：你好！
```

> 💡 **本质**：`new Greetable() { ... }` 并不是实例化接口（接口不能 new），而是**创建了一个实现了 Greetable 接口的匿名类的对象**。编译器会生成类似 `Outer$1.class` 的匿名类文件。

### 5.2 匿名内部类的本质

```java
// 这段代码
Greetable g = new Greetable() {
    @Override
    public void greet() { System.out.println("匿名"); }
};

// 等价于（编译器帮你生成了这个类，只是没名字）
class AnonymousGreetable implements Greetable {
    @Override
    public void greet() { System.out.println("匿名"); }
}
Greetable g = new AnonymousGreetable();
```

> ⚠️ **关键认知**：匿名内部类是「类 + 对象」一步到位——定义类的同时就创建了对象。这个类没有名字，所以**只能用一次**（想再 new 一个同类型的，得再写一遍匿名类）。

### 5.3 匿名内部类继承抽象类

```java
public abstract class Animal {
    private String name;
    public Animal(String name) { this.name = name; }
    public abstract void sound();
}

// 匿名内部类继承抽象类，必须调用父类构造方法
Animal a = new Animal("小猫") {
    @Override
    public void sound() {
        System.out.println("喵喵喵");
    }
};
a.sound();   // 喵喵喵
```

> 💡 与接口不同，继承抽象类时 `new 抽象类名(参数)` 可以传参给父类构造方法。

### 5.4 使用场景

匿名内部类适合「**一次性使用**」的场景，避免为只用一次的接口实现单独建类：

```java
// 场景 1：线程创建（Runnable 匿名内部类）
new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("线程运行中");
    }
}).start();

// 场景 2：临时排序（Comparator 匿名内部类）
List<String> list = Arrays.asList("banana", "apple", "cherry");
Collections.sort(list, new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();   // 按长度排序
    }
});

// 场景 3：事件监听（Android 风格的回调）
button.setOnClickListener(new OnClickListener() {
    @Override
    public void onClick(View v) {
        System.out.println("按钮被点击");
    }
});
```

> 📌 **何时用匿名内部类**：
> - 实现只在本处用一次，不需要复用
> - 实现逻辑简短（复杂逻辑应抽成独立类）
> - 需要传给方法作为参数（如 `sort` 的 `Comparator`）

### 5.5 匿名内部类访问局部变量

和局部内部类一样，访问的局部变量必须是 effectively final：

```java
public void process() {
    String prefix = "Hello";   // effectively final
    // prefix = "Hi";          // ❌ 修改后下面访问会报错

    Runnable r = new Runnable() {
        @Override
        public void run() {
            System.out.println(prefix + " World");   // ✅ 访问 effectively final 变量
        }
    };
    r.run();
}
```

### 5.6 匿名内部类没有构造方法

匿名内部类没有名字，自然没有显式构造方法。需要初始化时用**实例初始化块**：

```java
Runnable r = new Runnable() {
    private int count;

    {   // 实例初始化块，相当于构造方法
        count = 10;
        System.out.println("匿名内部类初始化");
    }

    @Override
    public void run() {
        System.out.println("count = " + count);
    }
};
r.run();
```

## 六、内部类的访问修饰符

成员内部类（成员内部类、静态内部类）作为外部类的成员，可以用四种访问修饰符：

```java
public class Outer {
    public class PublicInner { }       // 公开，任何类都能访问
    protected class ProtectedInner { } // 同包 + 子类
    class DefaultInner { }             // 默认，同包
    private class PrivateInner { }     // 私有，仅外部类内部
    static class StaticNested { }      // 静态内部类，同样可用四种修饰符
}
```

> 💡 局部内部类和匿名内部类**不能**加访问修饰符（它们是方法的局部存在，不是外部类成员）。

## 七、Lambda 表达式与匿名内部类的关系

当匿名内部类实现的接口是**函数式接口**（只有一个抽象方法）时，Java 8 起可以用 Lambda 替代，更简洁：

```java
// 匿名内部类写法
Runnable r1 = new Runnable() {
    @Override
    public void run() {
        System.out.println("匿名内部类");
    }
};

// ✅ Lambda 写法（函数式接口才能用）
Runnable r2 = () -> System.out.println("Lambda");

// Comparator 也能简化
Collections.sort(list, new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
});
// ✅ Lambda
Collections.sort(list, (a, b) -> a.length() - b.length());
```

| 对比项 | 匿名内部类 | Lambda |
| :--- | :--- | :--- |
| 适用对象 | 任何接口/抽象类 | 仅函数式接口（一个抽象方法） |
| 关键字 | `new 接口名() { ... }` | `() -> { ... }` |
| `this` 指向 | 指向匿名类自身 | 指向外部类（Lambda 不引入新作用域） |
| 生成的类 | 编译后生成 .class 文件 | 编译后不生成额外类（基于 invokedynamic） |
| 性能 | 每次创建对象 | 更轻量，JVM 优化 |

> ⚠️ **关键区别**：匿名内部类中的 `this` 指向匿名类实例本身；Lambda 中的 `this` 指向**外部类**。这在重名变量访问时有影响：
>
> ```java
> public class Demo {
>     public void test() {
>         Runnable r1 = new Runnable() {
>             @Override
>             public void run() {
>                 System.out.println(this);   // 匿名类对象
>             }
>         };
>         Runnable r2 = () -> System.out.println(this);  // Demo 对象
>     }
> }
> ```

> 💡 Lambda 的详细语法见 [15-Lambda与函数式接口](15-Lambda与函数式接口.md)。本节只需建立「Lambda 是函数式接口匿名内部类的简写」这个认知。

## ⚠️ 重点

### 重点 1：成员内部类创建对象的两步语法 ⭐

```java
public class Outer {
    class Inner { }
}

// ✅ 标准写法：先 new 外部类，再 .new 内部类
Outer.Inner inner = new Outer().new Inner();

// ❌ 错误写法
// Inner inner = new Inner();           // 找不到 Inner
// Outer.Inner inner = new Outer.Inner();  // 这是静态内部类的写法，成员内部类不行
```

> ⚠️ 成员内部类必须依赖外部类实例，语法是 `new 外部类().new 内部类()`，别和静态内部类的 `new 外部类.内部类()` 搞混。

### 重点 2：访问重名成员用 Outer.this ⭐⭐

```java
public class Outer {
    String name = "外部";

    class Inner {
        String name = "内部";

        void show() {
            String name = "局部";
            System.out.println(name);              // 局部
            System.out.println(this.name);         // 内部
            System.out.println(Outer.this.name);   // 外部 ✅
        }
    }
}
```

> 💡 这是面试高频题：三层重名时如何分别访问。记住 `外部类名.this.成员` 这个固定语法。

### 重点 3：匿名内部类访问局部变量必须 effectively final ⭐⭐

```java
public void process() {
    int x = 10;
    Runnable r = new Runnable() {
        @Override
        public void run() {
            System.out.println(x);   // ✅ x 没被修改，是 effectively final
        }
    };

    // x = 20;   // ❌ 如果这行存在，上面访问 x 会编译报错
}
```

> ⚠️ 这是新手最常遇到的编译错误之一。原因：匿名内部类对象可能比方法生命周期长，访问的局部变量是副本，必须保证不可变。

### 重点 4：静态内部类优先于成员内部类 ⭐

```java
// ❌ 不推荐：成员内部类，隐式持有外部实例，可能内存泄漏
public class Outer {
    class Inner { }   // 持有 Outer 实例引用
}

// ✅ 推荐：静态内部类，不持有外部实例
public class Outer {
    static class Inner { }   // 独立存在
}
```

> 📌 **规范**：内部类不需要访问外部类实例成员时，**一律加 static**。这是 Effective Java 的建议，能避免内存泄漏、降低耦合。JDK 的 `HashMap.Node`、`Thread.Builder` 都是静态内部类。

### 重点 5：匿名内部类和 Lambda 的 this 不同 ⭐

```java
public class Demo {
    public void test() {
        Runnable r1 = new Runnable() {
            @Override
            public void run() {
                System.out.println(this.getClass());   // 匿名类
            }
        };
        Runnable r2 = () -> System.out.println(this.getClass());  // Demo 类
    }
}
```

> 💡 匿名内部类的 `this` 是匿名对象自己；Lambda 的 `this` 是外部类实例。改写匿名内部类为 Lambda 时要注意这点。

### 重点 6：匿名内部类只能实现一个接口/继承一个类 ⭐

```java
// ✅ 匿名内部类实现一个接口
new Runnable() { ... }

// ✅ 匿名内部类继承一个抽象类
new AbstractList<String>() { ... }

// ❌ 不能同时实现多个接口
// new Runnable, Callable() { ... }   // 语法不支持
```

## 💻 实战案例

### 案例 1：匿名内部类实现按钮点击回调 ⭐⭐

GUI/Android 开发中，事件监听是匿名内部类最经典的舞台：

```java
// 模拟按钮和监听器接口
public interface OnClickListener {
    void onClick(String buttonId);
}

public class Button {
    private String id;
    private OnClickListener listener;

    public Button(String id) { this.id = id; }

    public void setOnClickListener(OnClickListener listener) {
        this.listener = listener;
    }

    public void click() {
        if (listener != null) {
            listener.onClick(id);   // 回调
        }
    }
}

// 使用：匿名内部类注册监听
Button saveBtn = new Button("save");
saveBtn.setOnClickListener(new OnClickListener() {
    @Override
    public void onClick(String buttonId) {
        System.out.println("按钮 [" + buttonId + "] 被点击，执行保存逻辑");
    }
});

Button cancelBtn = new Button("cancel");
cancelBtn.setOnClickListener(new OnClickListener() {
    @Override
    public void onClick(String buttonId) {
        System.out.println("按钮 [" + buttonId + "] 被点击，执行取消逻辑");
    }
});

saveBtn.click();    // 按钮 [save] 被点击，执行保存逻辑
cancelBtn.click();  // 按钮 [cancel] 被点击，执行取消逻辑
```

> 💡 每个按钮的点击逻辑不同且只用一次，用匿名内部类就地实现，无需为每个按钮建单独的类。Android 的 `setOnClickListener` 就是这个模式。

### 案例 2：Comparator 匿名内部类实现多字段排序 ⭐

后台系统对订单列表按多字段排序（先按状态、再按金额、再按时间）：

```java
public class Order {
    private String orderId;
    private int status;        // 0 待付款 1 已付款 2 已发货 3 已完成
    private BigDecimal amount;
    private long createTime;   // 创建时间戳

    public Order(String orderId, int status, String amount, long createTime) {
        this.orderId = orderId;
        this.status = status;
        this.amount = new BigDecimal(amount);
        this.createTime = createTime;
    }

    @Override
    public String toString() {
        return orderId + "[状态" + status + ",¥" + amount + "]";
    }

    // getter 省略
    public int getStatus() { return status; }
    public BigDecimal getAmount() { return amount; }
    public long getCreateTime() { return createTime; }
}

List<Order> orders = Arrays.asList(
    new Order("A001", 1, "299", 1000),
    new Order("A002", 0, "99", 2000),
    new Order("A003", 1, "199", 3000),
    new Order("A004", 0, "599", 4000)
);

// 需求：按状态升序，状态相同按金额降序
Collections.sort(orders, new Comparator<Order>() {
    @Override
    public int compare(Order a, Order b) {
        if (a.getStatus() != b.getStatus()) {
            return a.getStatus() - b.getStatus();   // 状态升序
        }
        return b.getAmount().compareTo(a.getAmount());  // 金额降序
    }
});

System.out.println(orders);
// [A004[状态0,¥599], A002[状态0,¥99], A003[状态1,¥199], A001[状态1,¥299]]
```

> 💡 排序规则多变且临时，用匿名内部类就地定义，比单独建 `OrderComparator` 类更直观。Java 8 后可简化为 Lambda：`Comparator.comparing(Order::getStatus).thenComparing(Order::getAmount, reverseOrder())`。

### 案例 3：Runnable 匿名内部类创建线程 ⭐

多线程场景中，`Runnable` 是函数式接口，匿名内部类是其传统写法：

```java
// 模拟后台批量发短信任务
public class SmsSender {
    public void sendBatch(List<String> phones) {
        // 匿名内部类创建线程，异步发送
        Thread worker = new Thread(new Runnable() {
            @Override
            public void run() {
                for (String phone : phones) {
                    System.out.println("发送短信到 " + phone);
                    try {
                        Thread.sleep(100);   // 模拟发送耗时
                    } catch (InterruptedException e) {
                        e.printStackTrace();
                    }
                }
                System.out.println("全部发送完成");
            }
        });
        worker.start();   // 启动异步任务
        System.out.println("主线程继续执行其他逻辑");
    }
}

new SmsSender().sendBatch(Arrays.asList("13800000001", "13800000002", "13800000003"));
```

> 💡 Java 8 后可简化为 `new Thread(() -> { ... }).start()`，但理解匿名内部类写法是掌握 Lambda 的前提。

### 案例 4：Builder 模式（静态内部类构建器）⭐⭐

Builder 模式是静态内部类最经典的实战应用，解决「构造参数多、可选参数多」的对象构建问题：

```java
public class User {
    // 必填字段
    private final String username;
    private final String email;
    // 可选字段，带默认值
    private final String nickname;
    private final int age;
    private final String phone;
    private final String address;

    // 构造方法私有，只能通过 Builder 创建
    private User(Builder builder) {
        this.username = builder.username;
        this.email = builder.email;
        this.nickname = builder.nickname;
        this.age = builder.age;
        this.phone = builder.phone;
        this.address = builder.address;
    }

    // ✅ 静态内部类 Builder
    public static class Builder {
        // 必填字段
        private final String username;
        private final String email;
        // 可选字段，默认值
        private String nickname = "匿名用户";
        private int age = 0;
        private String phone = "";
        private String address = "";

        // 必填字段通过构造方法传入
        public Builder(String username, String email) {
            this.username = username;
            this.email = email;
        }

        // 可选字段通过方法链式设置，返回 this
        public Builder nickname(String nickname) { this.nickname = nickname; return this; }
        public Builder age(int age) { this.age = age; return this; }
        public Builder phone(String phone) { this.phone = phone; return this; }
        public Builder address(String address) { this.address = address; return this; }

        // 构建最终对象
        public User build() {
            return new User(this);
        }
    }

    @Override
    public String toString() {
        return username + "/" + email + "/" + nickname + "/" + age;
    }
}

// 使用：链式调用，清晰优雅
User user = new User.Builder("leo", "leo@example.com")
    .nickname("Leo")
    .age(28)
    .phone("13800000000")
    .address("北京")
    .build();

System.out.println(user);   // leo/leo@example.com/Leo/28
```

> 📌 **Builder 模式价值**：
> 1. 解决「参数爆炸」：避免 `new User(a, b, c, d, e, f)` 分不清谁是谁
> 2. 可选参数灵活：想设哪个调哪个，不设的用默认值
> 3. 不可变对象：字段 final，构建后不可改，线程安全
> 4. 链式调用：代码可读性高
>
> MyBatis 的 `SqlSessionFactoryBuilder`、OkHttp 的 `Request.Builder` 都是这个模式。

### 案例 5：局部内部类做方法内辅助逻辑

当方法内有一段需要复用、又不想暴露为类方法的逻辑时，局部内部类可以胜任：

```java
public class ReportService {
    // 生成报表，内部需要一个「数据聚合器」辅助
    public String generateReport(List<Integer> data) {
        // 局部内部类：只在 generateReport 内使用，不暴露给外部
        class Aggregator {
            private int sum = 0;
            private int max = Integer.MIN_VALUE;
            private int count = 0;

            void add(int value) {
                sum += value;
                if (value > max) max = value;
                count++;
            }

            String summary() {
                return String.format("总数%d，合计%d，最大%d", count, sum, max);
            }
        }

        Aggregator agg = new Aggregator();
        for (int value : data) {
            agg.add(value);
        }
        return agg.summary();
    }
}

System.out.println(new ReportService().generateReport(Arrays.asList(10, 20, 5, 30)));
// 总数4，合计65，最大30
```

> 💡 这种「方法内辅助类」实际开发中多用 Lambda + Stream 替代，但理解局部内部类有助于看清 Java 的作用域机制。

### 案例 6：静态内部类实现单例模式

静态内部类实现「懒加载 + 线程安全」的单例，是面试常考的优雅写法：

```java
public class Singleton {
    // 私有构造，外部不能 new
    private Singleton() {
        System.out.println("Singleton 初始化");
    }

    // 静态内部类：持有单例实例
    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
        // 静态内部类不依赖外部类实例，且只在被访问时才加载（懒加载）
    }

    // 获取实例
    public static Singleton getInstance() {
        return Holder.INSTANCE;   // 首次访问触发 Holder 类加载
    }
}

// 使用
Singleton s1 = Singleton.getInstance();   // Singleton 初始化
Singleton s2 = Singleton.getInstance();   // 不再初始化
System.out.println(s1 == s2);   // true，同一个实例
```

> 💡 **原理**：静态内部类 `Holder` 在 `Singleton` 加载时不会加载，只有 `getInstance()` 被调用时才加载 `Holder`（JVM 的类加载机制保证线程安全）。这实现了「懒加载 + 无锁线程安全」，比双重检查锁更优雅。

## 🚀 新版本补充

### Java 16：局部内部类和匿名内部类可位于静态上下文

Java 16 之前，静态方法中定义的局部/匿名内部类仍有一些限制。Java 16 进一步放宽了内部类在静态上下文中的使用规则，允许在更多静态场景灵活定义内部类（了解即可，日常开发影响不大）。

### Java 16+：Record 类替代部分内部类

Java 14 预览、16 正式的 `record` 关键字，可以更简洁地定义「纯数据载体」，替代一些只装数据的静态内部类：

```java
// 传统静态内部类写法（Java 8）
public static class Point {
    private final int x;
    private final int y;
    public Point(int x, int y) { this.x = x; this.y = y; }
    public int getX() { return x; }
    public int getY() { return y; }
}

// Java 16 record 写法（一行搞定）
public record Point(int x, int y) { }
```

> ⚠️ `record` 是 Java 16 正式特性，Java 8 不可用。它自动生成构造方法、getter、equals、hashCode、toString，适合「不可变数据载体」场景，能简化部分静态内部类的样板代码。

## 本章小结

| 类型 | 定义位置 | 修饰符 | 创建方式 | 访问外部成员 | 典型场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 成员内部类 | 类中方法外 | 无 static | `new Outer().new Inner()` | 全部（含私有） | 强绑定外部类 |
| 静态内部类 | 类中方法外 | static | `new Outer.StaticInner()` | 仅静态 | Builder、Map.Entry |
| 局部内部类 | 方法中 | 无 | 方法内 `new` | 外部成员 + effectively final 局部变量 | 方法内辅助逻辑 |
| 匿名内部类 | 方法中 new 时 | 无 | `new 接口名() { ... }` | 同局部内部类 | 一次性回调、监听、排序 |

| 知识点 | 要点 |
| :--- | :--- |
| 成员内部类创建 | `new Outer().new Inner()` |
| 访问重名外部成员 | `Outer.this.成员` |
| effectively final | 局部/匿名内部类访问的局部变量不可变 |
| 静态内部类优先 | 不需要外部实例时加 static |
| 匿名内部类本质 | 实现接口/继承类的匿名子类对象 |
| Lambda vs 匿名 | 函数式接口可简化为 Lambda，this 指向不同 |

## 学习建议

1. **重点攻克匿名内部类**：它是四种内部类中实际用得最多的，也是理解 Lambda 的前提。把案例 1（按钮回调）、案例 2（Comparator）、案例 3（Runnable）都敲一遍，体会「就地实现、一次性使用」的便利。
2. **牢记两条易错语法**：成员内部类创建用 `new Outer().new Inner()`，重名访问用 `Outer.this.成员`——这两条是面试必考、实战必用的语法点，写错就编译不过。
3. **理解 effectively final 的原因**：不要死记规则，要理解「内部类对象生命周期可能长于方法，访问的局部变量是副本，必须不可变才一致」。理解了原理，自然不会去改那些被内部类引用的局部变量。
4. **实战 Builder 模式**：照着案例 4，用静态内部类给一个多字段类（如 `Article`、`Order`）写 Builder，体会链式调用的优雅。这是实际开发（尤其框架源码）高频出现的设计模式，提前练手受益无穷。
5. **建立「静态内部类优先」的意识**：从现在起写内部类，先问自己「需要访问外部实例成员吗？」不需要就加 `static`。这个习惯能避免内存泄漏、降低耦合，是 Effective Java 明确推荐的实践。
