# 类与对象：封装与构造方法

Java 是一门**面向对象**的语言。前面几篇我们写的都是「一个 main 方法搞定一切」的过程式代码，从本篇开始，我们要正式进入 OOP 的世界——学会用「类」来组织代码，用「对象」来描述数据。掌握类、对象、封装、构造方法，是看懂任何 Java 框架源码的第一道门槛。

> 💡 本篇会频繁涉及「栈存引用、堆存对象」的内存概念，建议结合 [02-JVM内存模型](02-JVM内存模型.md) 一起理解，不要死记硬背。

---

## 一、面向对象思想概述

### 1.1 从面向过程到面向对象

**面向过程**（C 语言为代表）：关注「分几步做完一件事」，用方法按顺序调用实现。

**面向对象**（Java 为代表）：关注「这件事涉及哪些角色（对象），每个角色有什么属性和行为」，用对象之间的协作完成。

以「电商下单」为例：

- 面向过程：`创建订单() → 扣库存() → 生成支付记录() → 发短信()`
- 面向对象：`用户.下单(商品)` → `商品.扣库存()` → `支付服务.生成订单(订单)` → `通知服务.发短信(用户)`

### 1.2 OOP 三大特性

| 特性 | 一句话解释 | 本篇是否涉及 |
| :--- | :--- | :---: |
| **封装**（Encapsulation） | 隐藏实现细节，对外暴露统一接口 | ✅ 本篇重点 |
| **继承**（Inheritance） | 子类复用父类的属性和方法 | 后续篇章 |
| **多态**（Polymorphism） | 同一调用，不同对象表现不同行为 | 后续篇章 |

> 💡 本篇聚焦**封装**，继承和多态会在后续篇章展开。但封装是三大特性的基石——没有封装，继承和多态都无从谈起。

## 二、类和对象的概念

### 2.1 类是图纸，对象是实体

**类（Class）**：是一类事物的抽象描述，是「模板 / 图纸」。定义了这一类事物有哪些属性（状态）和行为（功能）。

**对象（Object）**：是类的具体实例，是「实体 / 产品」。一个类可以创建无数个对象，每个对象都有独立的属性值。

生活类比：

- 类 = 「汽车设计图纸」；对象 = 「一辆具体的车」
- 类 = 「学生模板」；对象 = 「张三这个学生」「李四这个学生」

```java
// 类 = 图纸
class Student {
    String name;   // 属性：姓名
    int age;       // 属性：年龄

    void study() { // 行为：学习
        System.out.println(name + " 正在学习");
    }
}

// 对象 = 实体
Student s1 = new Student();  // 用图纸造出第一辆车
s1.name = "张三";
s1.study();                  // 张三 正在学习

Student s2 = new Student();  // 造出第二辆车
s2.name = "李四";
s2.study();                  // 李四 正在学习
```

### 2.2 类与对象的关系

- 一个类可以创建多个对象（一对多）
- 每个对象拥有独立的成员变量值（互不影响）
- 所有对象共享类的同一个方法定义（方法在方法区）

```
类 Student（图纸）
   │
   ├── new Student() → 对象1（name=张三, age=20）  ← 堆中一块内存
   ├── new Student() → 对象2（name=李四, age=22）  ← 堆中另一块内存
   └── new Student() → 对象3（name=王五, age=21）  ← 堆中又一块内存
```

## 三、类的定义

### 3.1 类的完整语法

```java
修饰符 class 类名 {
    // 1. 成员变量（属性）
    数据类型 变量名;

    // 2. 成员方法（行为）
    修饰符 返回值类型 方法名(参数列表) {
        方法体;
    }

    // 3. 构造方法（本篇后半部分讲）
    类名(参数列表) {
        构造方法体;
    }
}
```

### 3.2 定义一个商品类

```java
public class Product {
    // 成员变量（属性）
    String name;       // 商品名
    double price;      // 价格
    int stock;         // 库存

    // 成员方法（行为）
    public void showInfo() {
        System.out.println("商品：" + name + "，价格：" + price + "，库存：" + stock);
    }
}
```

> 📌 **命名规范**：类名用**大驼峰**（如 `Product`、`OrderItem`），变量名/方法名用**小驼峰**（如 `stock`、`showInfo`）。一个 `.java` 文件只能有一个 `public` 类，且类名必须与文件名一致。

## 四、对象的创建与使用

### 4.1 new 关键字

创建对象的标准语法：

```java
类名 对象名 = new 类名(参数);
```

`new` 做了三件事：

1. 在**堆**中开辟内存，分配对象空间
2. 给成员变量赋默认值（int→0、boolean→false、引用→null）
3. 调用构造方法初始化对象，返回堆中的地址给栈中的引用变量

```java
Product p = new Product();
// 栈中变量 p 存的是堆中对象的地址
// p → 堆：[name=null, price=0.0, stock=0]
```

### 4.2 访问对象的属性和方法

用 `.` 操作符访问：

```java
Product p = new Product();
p.name = "Java 编程思想";
p.price = 99.0;
p.stock = 100;
p.showInfo();   // 商品：Java 编程思想，价格：99.0，库存：100
```

### 4.3 对象的内存图（呼应 02 篇）

```java
Product p1 = new Product();
p1.name = "书A";
Product p2 = p1;        // 把 p1 的地址赋给 p2
p2.name = "书B";
System.out.println(p1.name);  // 书B  ← p1、p2 指向同一个对象！
```

```
栈                          堆
┌──────────┐         ┌─────────────────┐
│ p1 ──────┼────────→│ name = "书B"    │  ← 只有一个对象
│ p2 ──────┼─────────┤ price = 0.0     │
└──────────┘         │ stock = 0       │
                     └─────────────────┘
```

> ⚠️ **引用传递是 Java 最核心的机制之一**：对象本身不会被复制，复制的只是「地址」。这也是为什么方法参数传对象时，方法内修改会影响外部——传的是地址的副本。

### 4.4 对象的 null 与空指针

```java
Product p = null;   // 引用不指向任何对象
System.out.println(p.name);  // ❌ NullPointerException 空指针异常
// 原因：p 没有指向任何对象，无法访问属性

Product p2 = new Product();
p2.name = "书";
System.out.println(p2.name);  // ✅ 书
```

> ⚠️ **空指针异常（NPE）是 Java 开发最常见的运行时异常**。任何引用变量都可能为 null，使用前务必判空（实际开发常用 `Optional` 或 `Objects.requireNonNull`）。

## 五、成员变量 vs 局部变量

这是呼应 [02-JVM内存模型](02-JVM内存模型.md) 的核心知识点，面试必考。

| 区别 | 成员变量（实例变量） | 局部变量 |
| :--- | :--- | :--- |
| **定义位置** | 类中、方法外 | 方法中、方法参数、代码块中 |
| **作用域** | 整个类 | 方法/代码块内部 |
| **内存位置** | 堆（随对象存在） | 栈（随方法栈帧存在） |
| **默认值** | 有（int→0、引用→null…） | **无**，必须先赋值才能用 |
| **生命周期** | 对象创建而生，对象回收而死 | 方法调用而生，方法结束而死 |

```java
public class Demo {
    int a;              // 成员变量，有默认值 0
    String name;        // 成员变量，默认值 null

    public void test(int param) {   // param 是局部变量
        int b;           // 局部变量，无默认值
        // System.out.println(b);  // ❌ 编译错误：可能尚未初始化变量 b
        b = 10;
        System.out.println(b);      // ✅ 10
        System.out.println(a);      // ✅ 0（成员变量有默认值）
        System.out.println(name);   // ✅ null
    }
}
```

> ⚠️ **为什么局部变量没有默认值？** 因为局部变量在栈上，栈帧频繁创建销毁，若每次都赋默认值会浪费性能。编译器强制你显式赋值，既安全又高效。

### 就近原则：同名变量时的查找顺序

当成员变量和局部变量同名时，方法内默认访问局部变量（就近原则）：

```java
public class Demo {
    int x = 10;          // 成员变量

    public void show(int x) {   // 参数 x 是局部变量
        System.out.println(x);  // 20，访问局部变量（就近）
        System.out.println(this.x);  // 10，用 this 强制访问成员变量
    }

    public static void main(String[] args) {
        new Demo().show(20);
    }
}
```

> 💡 这正是 `this` 关键字的核心用途之一——区分同名成员变量和局部变量。下面会详细讲。

## 六、封装

### 6.1 为什么需要封装

先看一段「不封装」的危险代码：

```java
public class Product {
    public double price;   // ❌ 公开属性，外部随意改
}

// 外部调用
Product p = new Product();
p.price = -100;     // ❌ 价格被改成负数！
p.price = 0;        // ❌ 白送
```

数据直接暴露，任何地方都能乱改，业务规则形同虚设。**封装**就是解决这个问题的。

### 6.2 private 关键字

`private` 修饰的成员**只能在本类中访问**，外部无法直接访问：

```java
public class Product {
    private double price;   // ✅ 私有化，外部不能直接改

    // 提供 getter/setter 间接访问
    public double getPrice() {
        return price;
    }

    public void setPrice(double price) {
        if (price < 0) {
            System.out.println("价格不能为负");   // ✅ 校验
            return;
        }
        this.price = price;   // this.price 是成员变量，price 是参数
    }
}
```

```java
Product p = new Product();
p.setPrice(99.0);    // ✅ 合法
p.setPrice(-100);    // ✅ 被拦截，价格保持 0.0
System.out.println(p.getPrice());  // 0.0
// p.price = -100;  // ❌ 编译错误：price 是 private，外部不可见
```

### 6.3 封装的意义

封装的三大价值：

1. **隐藏实现细节**：外部只管调 `setPrice`，不关心内部怎么校验、存哪
2. **保护数据安全**：在 setter 中加校验，杜绝非法数据
3. **统一访问入口**：将来改内部实现（如加日志、加锁），外部无感知

> 💡 **封装 = private 属性 + public getter/setter**，这是 JavaBean 的基本形态，也是所有 Java 框架（Spring、MyBatis）反射操作的基础。

### 6.4 访问权限修饰符一览

Java 有四种访问权限，从宽到严：

| 修饰符 | 本类 | 同包 | 子类 | 其他包 |
| :--- | :---: | :---: | :---: | :---: |
| `public` | ✅ | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| 默认（package-private，不写） | ✅ | ✅ | ❌ | ❌ |
| `private` | ✅ | ❌ | ❌ | ❌ |

> 📌 **实际开发规范**：成员变量一律 `private`，对外暴露的方法用 `public`。只有同包内部共用的工具方法才用默认权限。

## 七、this 关键字

### 7.1 this 代表「当前对象引用」

`this` 就是「当前正在调用这个方法的对象」的引用。谁调用这个方法，`this` 就是谁。

```java
public class Student {
    String name;

    public void show() {
        // this 代表「调用 show 的那个对象」
        System.out.println(this.name);
    }

    public static void main(String[] args) {
        Student s1 = new Student();
        s1.name = "张三";
        Student s2 = new Student();
        s2.name = "李四";

        s1.show();   // 张三，this == s1
        s2.show();   // 李四，this == s2
    }
}
```

### 7.2 this.成员变量——区分同名

这是 `this` 最常见的用法，解决「成员变量与参数/局部变量同名」的问题：

```java
public class Student {
    String name;
    int age;

    // ❌ 不用 this 的错误写法
    public void setName(String name) {
        name = name;   // 就近原则：两个 name 都是参数！成员变量没被赋值
    }

    // ✅ 用 this 区分
    public void setName2(String name) {
        this.name = name;   // this.name 是成员变量，name 是参数
    }
}
```

> ⚠️ `name = name` 是新手最隐蔽的 bug——不报错，但成员变量始终是 null。IDEA 会给出灰色警告「assignment has no effect」。

### 7.3 this.成员方法

```java
public class Student {
    public void study() {
        System.out.println("学习中...");
    }

    public void show() {
        this.study();   // ✅ 调用本类其他方法（this 可省略）
        study();        // ✅ 等价，编译器自动补 this
    }
}
```

### 7.4 this(...)——构造方法调用

`this(参数)` 可以在一个构造方法中调用本类的另一个构造方法，**必须放在第一行**：

```java
public class Student {
    String name;
    int age;

    // 无参构造
    public Student() {
        this("默认姓名", 18);   // ✅ 调用全参构造，必须放第一行
        System.out.println("无参构造执行");
    }

    // 全参构造
    public Student(String name, int age) {
        this.name = name;
        this.age = age;
        System.out.println("全参构造执行");
    }
}

// 测试
new Student();
// 输出：
// 全参构造执行
// 无参构造执行
```

> ⚠️ `this(...)` 必须是构造方法的第一条语句，否则编译错误。且不能形成循环调用（A 调 B，B 又调 A）。

## 八、构造方法

### 8.1 构造方法的特点

构造方法（Constructor）是创建对象时调用的特殊方法，用于初始化对象：

- 方法名与类名**完全相同**
- **没有返回值类型**（连 `void` 都不能写）
- 不能用 `return` 返回值（可以用 `return;` 提前结束）
- 通过 `new` 关键字调用

```java
public class Student {
    String name;
    int age;

    // 构造方法：与类同名、无返回值类型
    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

// 调用
Student s = new Student("张三", 20);   // new 时自动调用构造方法
```

> ⚠️ **构造方法 vs 普通方法**：构造方法没有返回值类型，普通方法即使不返回也必须写 `void`。`public void Student()` 是普通方法，不是构造方法！

### 8.2 无参构造与有参构造

```java
public class Student {
    String name;
    int age;

    // 无参构造
    public Student() {
        System.out.println("无参构造");
    }

    // 有参构造
    public Student(String name) {
        this.name = name;
        System.out.println("有参构造");
    }

    // 全参构造
    public Student(String name, int age) {
        this.name = name;
        this.age = age;
        System.out.println("全参构造");
    }
}

Student s1 = new Student();           // 无参构造
Student s2 = new Student("张三");      // 有参构造
Student s3 = new Student("张三", 20);  // 全参构造
```

### 8.3 默认构造方法

如果你**一个构造方法都不写**，编译器会自动给你一个无参构造方法（默认构造）：

```java
public class Student {
    String name;
    // 没写任何构造方法 → 编译器自动生成：public Student() {}
}

Student s = new Student();   // ✅ 调用默认的无参构造
```

> ⚠️ **新手大坑**：一旦你写了任何有参构造，编译器就**不再**给你生成无参构造。这时如果还用 `new Student()` 会编译错误：

```java
public class Student {
    String name;
    public Student(String name) {   // 写了有参构造
        this.name = name;
    }
}

// Student s = new Student();   // ❌ 编译错误：找不到无参构造
Student s = new Student("张三");   // ✅ 只能用有参
```

> 📌 **规范**：实际开发中，**无参构造一定要显式写出来**，不要依赖编译器默认生成。因为很多框架（Spring、MyBatis）通过反射调用无参构造创建对象，一旦丢了会报 `NoSuchMethodException`。

### 8.4 构造方法重载

构造方法可以重载（参数列表不同），提供多种创建对象的方式：

```java
public class Order {
    String orderId;
    double amount;
    String userId;

    public Order() {
        this("默认ID", 0, "匿名用户");
    }

    public Order(String orderId) {
        this(orderId, 0, "匿名用户");
    }

    public Order(String orderId, double amount, String userId) {
        this.orderId = orderId;
        this.amount = amount;
        this.userId = userId;
    }
}

Order o1 = new Order();
Order o2 = new Order("ORD001");
Order o3 = new Order("ORD002", 99.0, "U001");
```

## 九、标准类（JavaBean）规范

### 9.1 什么是 JavaBean

**JavaBean** 是一种标准的 Java 类规范，要求：

1. 所有成员变量用 `private` 修饰
2. 为每个变量提供 `public` 的 getter/setter
3. 提供**无参构造方法**（必须）
4. 提供**全参构造方法**（推荐）
5. 实现 `java.io.Serializable` 接口（序列化用，见下节）

```java
import java.io.Serializable;

public class Product implements Serializable {
    private static final long serialVersionUID = 1L;

    private Long id;
    private String name;
    private Double price;
    private Integer stock;

    // 无参构造
    public Product() {}

    // 全参构造
    public Product(Long id, String name, Double price, Integer stock) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.stock = stock;
    }

    // getter / setter
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public Double getPrice() { return price; }
    public void setPrice(Double price) { this.price = price; }
    public Integer getStock() { return stock; }
    public void setStock(Integer stock) { this.stock = stock; }
}
```

### 9.2 IDEA 快捷键生成代码

实际开发中，getter/setter/构造方法/toString 都不用手写，用 IDEA 快捷键：

| 操作 | 快捷键 |
| :--- | :--- |
| 生成 getter/setter | `Alt + Insert` → Getter/Setter |
| 生成构造方法 | `Alt + Insert` → Constructor |
| 生成 toString | `Alt + Insert` → toString |
| 生成 equals/hashCode | `Alt + Insert` → equals() and hashCode() |

> 💡 也可以用 Lombok 的 `@Data`、`@AllArgsConstructor`、`@NoArgsConstructor` 注解一键生成，但本篇以手写规范为准，Lombok 在后续框架篇章介绍。

### 9.3 JavaBean 在实际开发中的地位

JavaBean 不是语法要求，而是**生态约定**。几乎所有 Java 框架都依赖它：

- **Spring**：通过反射调用无参构造创建 Bean，通过 setter 注入依赖
- **MyBatis**：把数据库查询结果反射赋值到 JavaBean 的字段
- **JSON 序列化**（Jackson、Fastjson）：通过 getter/setter 读写属性
- **表单绑定**（Spring MVC）：HTTP 参数自动绑定到 JavaBean

```java
// Spring MVC 自动把表单参数绑定到 JavaBean
@PostMapping("/product")
public String add(Product product) {   // 表单字段自动映射到 product 的属性
    // product.getName()、product.getPrice() 已自动填充
    return "success";
}
```

> ⚠️ 这就是为什么无参构造和 getter/setter 不能省——框架靠反射和 getter/setter 操作对象，缺了就报错。

## 十、Serializable 与 serialVersionUID

### 10.1 序列化是什么

**序列化**：把对象转换成字节序列（可存文件、可网络传输）。
**反序列化**：把字节序列还原成对象。

典型场景：把用户对象存到 Redis、把订单对象通过 RPC 发给另一个服务。

```java
import java.io.*;

public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private int age;
    // 构造方法、getter/setter 省略
}
```

### 10.2 Serializable 标记接口

`Serializable` 是一个**标记接口**（没有任何方法），只是告诉 JVM「这个类可以被序列化」。实现了它，对象才能被 `ObjectOutputStream` 写出。

```java
User u = new User("张三", 20);

// 序列化到文件
ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("user.dat"));
oos.writeObject(u);
oos.close();

// 反序列化
ObjectInputStream ois = new ObjectInputStream(new FileInputStream("user.dat"));
User u2 = (User) ois.readObject();
ois.close();
```

### 10.3 serialVersionUID 的作用

```java
private static final long serialVersionUID = 1L;
```

它是**版本号**。反序列化时，JVM 会比较字节流里的 `serialVersionUID` 和当前类的 `serialVersionUID`：

- 一致 → 反序列化成功
- 不一致 → 抛 `InvalidClassException`

> ⚠️ **如果不显式声明**，编译器会根据类结构自动生成一个。一旦你改了类（加个字段），自动生成的 UID 就变了，旧的序列化数据就再也反序列化不回来了。所以**必须显式声明**，避免类改动导致反序列化失败。

> 📌 **规范**：所有要序列化的 JavaBean 都要 `implements Serializable` 并显式声明 `serialVersionUID`。这是阿里 Java 开发手册的强制要求。

## ⚠️ 重点

### 重点 1：成员变量有默认值，局部变量没有 ⭐

```java
public class Demo {
    int a;   // 成员变量，默认 0
    public void test() {
        int b;
        // System.out.println(b);  // ❌ 编译错误：未初始化
        b = 1;
        System.out.println(a);    // ✅ 0
        System.out.println(b);     // ✅ 1
    }
}
```

> 💡 根本原因：成员变量在堆上随对象分配，JVM 会清零；局部变量在栈上，JVM 不清零（性能考虑），所以强制你先赋值。

### 重点 2：写了有参构造就没了默认无参构造 ⭐⭐

```java
public class Student {
    String name;
    public Student(String name) {   // 写了有参
        this.name = name;
    }
}
// new Student();   // ❌ 编译错误
```

> ⚠️ 这是新手最常踩的坑之一。框架要求无参构造时，一定要显式写 `public Student() {}`。

### 重点 3：this(...) 必须在构造方法第一行 ⭐

```java
public Student() {
    System.out.println("hello");
    this("张三", 20);   // ❌ 编译错误：Call to this() must be first statement
}

public Student() {
    this("张三", 20);   // ✅ 必须第一行
    System.out.println("hello");
}
```

### 重点 4：封装的核心是 private + getter/setter ⭐⭐

```java
// ❌ 错误：公开属性，数据不安全
public class Account {
    public double balance;
}

// ✅ 正确：私有属性 + 校验
public class Account {
    private double balance;
    public double getBalance() { return balance; }
    public void setBalance(double balance) {
        if (balance < 0) throw new IllegalArgumentException("余额不能为负");
        this.balance = balance;
    }
}
```

### 重点 5：引用赋值是地址拷贝，不是对象拷贝 ⭐⭐

```java
Student s1 = new Student();
s1.name = "张三";
Student s2 = s1;        // s2 和 s1 指向同一个对象
s2.name = "李四";
System.out.println(s1.name);  // 李四 ← 改 s2 影响了 s1
```

> ⚠️ 想要「独立的副本」要用拷贝构造或克隆，不能直接 `=`。

### 重点 6：JavaBean 必须有无参构造 ⭐⭐

框架通过反射 `Class.newInstance()` 或 `Constructor.newInstance()` 调用无参构造创建对象。没有无参构造，反射创建对象会失败。

```java
// Spring 底层大致这样创建 Bean（简化）
Class<?> clazz = Class.forName("com.example.Product");
Object bean = clazz.newInstance();   // ❌ 没有无参构造会抛异常
```

## 💻 实战案例

### 案例 1：电商商品类——封装与价格校验 ⭐⭐

电商系统中，商品价格、库存必须严格校验，不能被随意改成负数：

```java
public class Product implements Serializable {
    private static final long serialVersionUID = 1L;

    private Long id;
    private String name;
    private Double price;       // 价格（分更精确，这里用元演示）
    private Integer stock;     // 库存
    private String category;   // 分类

    // 无参构造
    public Product() {}

    // 全参构造（带校验）
    public Product(Long id, String name, Double price, Integer stock, String category) {
        this.id = id;
        this.name = name;
        setPrice(price);        // 复用 setter 的校验逻辑
        setStock(stock);
        this.category = category;
    }

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }

    public String getName() { return name; }
    public void setName(String name) {
        if (name == null || name.trim().isEmpty()) {
            throw new IllegalArgumentException("商品名不能为空");
        }
        this.name = name.trim();
    }

    public Double getPrice() {
        return price;
    }

    public void setPrice(Double price) {
        if (price == null || price < 0) {
            throw new IllegalArgumentException("价格不能为负");
        }
        if (price > 999999.99) {
            throw new IllegalArgumentException("价格超出上限");
        }
        this.price = price;
    }

    public Integer getStock() { return stock; }
    public void setStock(Integer stock) {
        if (stock == null || stock < 0) {
            throw new IllegalArgumentException("库存不能为负");
        }
        this.stock = stock;
    }

    public String getCategory() { return category; }
    public void setCategory(String category) { this.category = category; }

    @Override
    public String toString() {
        return "Product{name='" + name + "', price=" + price + ", stock=" + stock + "}";
    }
}
```

```java
// 业务调用
public class ProductDemo {
    public static void main(String[] args) {
        // ✅ 正常创建
        Product p = new Product(1L, "Java 编程思想", 99.0, 100, "图书");
        System.out.println(p);

        // ❌ 价格为负，被拦截
        try {
            p.setPrice(-50.0);
        } catch (IllegalArgumentException e) {
            System.out.println("拦截：" + e.getMessage());  // 拦截：价格不能为负
        }

        // ❌ 库存为负
        try {
            new Product(2L, "坏品", 10.0, -5, "图书");
        } catch (IllegalArgumentException e) {
            System.out.println("拦截：" + e.getMessage());  // 拦截：库存不能为负
        }
    }
}
```

> 📌 **开发要点**：构造方法里也调用 setter 而不是直接赋值，这样校验逻辑只写一份，构造和修改都走同一道关卡。

### 案例 2：用户注册——手机号格式校验 ⭐

用户注册时，手机号、密码必须符合格式，在 setter 中统一校验：

```java
import java.util.regex.Pattern;

public class User implements Serializable {
    private static final long serialVersionUID = 1L;

    private String username;
    private String phone;       // 手机号
    private String password;

    public User() {}

    public User(String username, String phone, String password) {
        setUsername(username);
        setPhone(phone);
        setPassword(password);
    }

    public String getUsername() { return username; }
    public void setUsername(String username) {
        if (username == null || username.length() < 3 || username.length() > 20) {
            throw new IllegalArgumentException("用户名长度 3-20");
        }
        this.username = username;
    }

    public String getPhone() { return phone; }
    public void setPhone(String phone) {
        // 中国大陆手机号正则
        String regex = "^1[3-9]\\d{9}$";
        if (phone == null || !Pattern.matches(regex, phone)) {
            throw new IllegalArgumentException("手机号格式不合法");
        }
        this.phone = phone;
    }

    public String getPassword() { return password; }
    public void setPassword(String password) {
        if (password == null || password.length() < 6) {
            throw new IllegalArgumentException("密码至少 6 位");
        }
        this.password = password;
    }
}
```

```java
public class RegisterDemo {
    public static void main(String[] args) {
        // ✅ 合法注册
        User u1 = new User("zhangsan", "13800138000", "abc123");
        System.out.println("注册成功：" + u1.getUsername());

        // ❌ 手机号格式错
        try {
            new User("lisi", "12345", "abc123");
        } catch (IllegalArgumentException e) {
            System.out.println("注册失败：" + e.getMessage());  // 手机号格式不合法
        }

        // ❌ 密码太短
        try {
            new User("wangwu", "13900139000", "123");
        } catch (IllegalArgumentException e) {
            System.out.println("注册失败：" + e.getMessage());  // 密码至少 6 位
        }
    }
}
```

### 案例 3：银行账户——余额不可为负 ⭐

金融系统对数据合法性要求极高，封装是第一道防线：

```java
public class BankAccount {
    private String accountNo;
    private double balance;     // 余额
    private String owner;

    public BankAccount() {}

    public BankAccount(String accountNo, String owner) {
        this.accountNo = accountNo;
        this.owner = owner;
        this.balance = 0;      // 开户默认 0 元
    }

    // 存款
    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("存款金额必须大于 0");
        }
        this.balance += amount;
        System.out.println(owner + " 存入 " + amount + "，余额 " + balance);
    }

    // 取款
    public void withdraw(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("取款金额必须大于 0");
        }
        if (amount > balance) {
            throw new IllegalArgumentException("余额不足");
        }
        this.balance -= amount;
        System.out.println(owner + " 取出 " + amount + "，余额 " + balance);
    }

    public double getBalance() { return balance; }
    // 注意：没有 setBalance，余额只能通过存取款改变，不能直接改
}
```

```java
BankAccount acc = new BankAccount("622200001234", "张三");
acc.deposit(1000);    // 张三 存入 1000.0，余额 1000.0
acc.withdraw(300);    // 张三 取出 300.0，余额 700.0
// acc.withdraw(1000); // ❌ 余额不足
// acc.balance = 99999; // ❌ 编译错误，balance 是 private
```

> 💡 **只读属性**：余额只提供 getter 不提供 setter，外部只能读不能改。这是封装的高级用法——控制属性的可读可写性。

### 案例 4：订单类——构造方法初始化与业务规则 ⭐

```java
import java.time.LocalDateTime;

public class Order implements Serializable {
    private static final long serialVersionUID = 1L;

    private String orderId;
    private String userId;
    private Double totalAmount;
    private String status;          // PENDING / PAID / SHIPPED / DONE
    private LocalDateTime createTime;

    // 无参构造（框架反射用）
    public Order() {
        this.status = "PENDING";   // 默认待支付
        this.createTime = LocalDateTime.now();
    }

    // 业务构造：创建订单时只传 userId 和金额
    public Order(String userId, Double totalAmount) {
        this();                    // ✅ 先调无参，设置默认状态和时间
        if (totalAmount == null || totalAmount <= 0) {
            throw new IllegalArgumentException("订单金额必须大于 0");
        }
        this.orderId = "ORD" + System.currentTimeMillis();
        this.userId = userId;
        this.totalAmount = totalAmount;
    }

    public void pay() {
        if (!"PENDING".equals(status)) {
            throw new IllegalStateException("只有待支付订单才能支付");
        }
        this.status = "PAID";
        System.out.println("订单 " + orderId + " 已支付");
    }

    public void ship() {
        if (!"PAID".equals(status)) {
            throw new IllegalStateException("只有已支付订单才能发货");
        }
        this.status = "SHIPPED";
        System.out.println("订单 " + orderId + " 已发货");
    }

    // getter 省略，status 只读不能直接改
    public String getStatus() { return status; }
    public String getOrderId() { return orderId; }
}
```

```java
Order order = new Order("U001", 199.0);
System.out.println("订单号：" + order.getOrderId() + "，状态：" + order.getStatus());
order.pay();     // 订单已支付
order.ship();    // 订单已发货
// order.pay();  // ❌ 只有待支付订单才能支付（状态已变 PAID）
```

> 📌 **状态机模式雏形**：订单状态只能按 PENDING→PAID→SHIPPED→DONE 流转，封装让外部无法跳过步骤直接改成 DONE，保证业务安全。

### 案例 5：JavaBean 在框架中的真实地位 ⭐

演示 Spring/MyBatis 底层如何通过反射操作 JavaBean（简化版）：

```java
import java.lang.reflect.*;

public class ReflectDemo {
    // 模拟框架：通过反射创建对象并设置属性
    public static Object createAndFill(Class<?> clazz, java.util.Map<String, Object> data)
            throws Exception {
        // 1. 调用无参构造创建对象（这就是为什么必须有无参构造）
        Constructor<?> noArg = clazz.getDeclaredConstructor();
        Object obj = noArg.newInstance();

        // 2. 遍历数据，调用对应的 setter
        for (java.util.Map.Entry<String, Object> entry : data.entrySet()) {
            String fieldName = entry.getKey();
            String setterName = "set" + Character.toUpperCase(fieldName.charAt(0))
                               + fieldName.substring(1);
            Field f = clazz.getDeclaredField(fieldName);
            Method setter = clazz.getDeclaredMethod(setterName, f.getType());
            setter.invoke(obj, entry.getValue());   // 调用 setter
        }
        return obj;
    }

    public static void main(String[] args) throws Exception {
        java.util.Map<String, Object> data = new java.util.HashMap<>();
        data.put("name", "Java 书");
        data.put("price", 99.0);

        Product p = (Product) createAndFill(Product.class, data);
        System.out.println(p);   // Product{name='Java 书', price=99.0, ...}
    }
}
```

> 💡 这就是 Spring 的 `BeanWrapper`、MyBatis 的 `ResultSetHandler` 的核心原理——**反射 + 无参构造 + getter/setter**。理解了这一点，就明白 JavaBean 规范为什么是「强制」的。

## 🚀 新版本补充

### Java 9+：模块化对封装的影响

Java 9 引入模块系统（`module-info.java`），`public` 在模块间不再无条件公开，需要 `exports` 声明。这给封装增加了「模块级」的粒度：

```java
// module-info.java
module com.example.product {
    exports com.example.product;   // 只导出 product 包，内部实现包不导出
}
```

> 💡 模块化让「强封装」更进一步：即使 `public` 类，不在 `exports` 里也无法被其他模块访问。Java 8 环境下不适用，了解即可。

### Java 14：Record 类（预览）/ Java 16 正式

Java 14 预览、16 正式引入 `record`，用于简化「纯数据载体」类的编写，自动生成构造、getter、equals、hashCode：

```java
// Java 16+
public record Point(int x, int y) {}

// 等价于手写：private final int x; private final int y;
// 构造方法、x()、y()、equals、hashCode、toString 全自动生成
```

> ⚠️ Record 是**不可变**的（字段 final），适合做 DTO。Java 8 不可用，了解即可，后续篇章会详细讲。

### Java 16：局部类 record 与密封类预告

```java
// 密封类（Java 17 正式），限制谁可以继承它
public sealed class Shape permits Circle, Square {}
```

> 💡 这些都是 Java 9+ 特性，Java 8 环境下不可用。本篇以 Java 8 为基准，了解趋势即可。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 类与对象 | 类是模板，对象是实例；`new` 在堆中创建对象 |
| 成员变量 vs 局部变量 | 成员变量在堆有默认值，局部变量在栈无默认值 |
| 封装 | `private` 属性 + `public` getter/setter，保护数据 |
| this | 代表当前对象引用；`this.变量` 区分同名；`this(...)` 调构造 |
| 构造方法 | 与类同名、无返回值；无参/有参/重载；默认构造的丢失陷阱 |
| JavaBean 规范 | 私有字段 + getter/setter + 无参构造 + 全参构造 |
| Serializable | 标记接口，声明 `serialVersionUID` 防止反序列化失败 |
| 访问修饰符 | public > protected > 默认 > private |

## 学习建议

1. **手写一个完整的 JavaBean**：照着案例 1 把 Product 类完整敲一遍，包括私有字段、无参构造、全参构造、所有 getter/setter（带校验）、toString。不要用 IDEA 快捷键，先体会手写的繁琐，再享受快捷键的爽。
2. **画内存图理解引用**：拿案例 3 的 `Student s2 = s1` 画一张栈/堆内存图，亲眼看到「两个引用一个对象」，引用传递就彻底懂了。这是后续集合、参数传递的基础。
3. **刻意制造错误**：把无参构造删掉试试 `new Student()`、把 `this(...)` 放第二行试试、把 `private` 改成 `public` 试试外部乱改——亲手触发这些错误，记忆才深刻。
4. **理解 JavaBean 与框架的关系**：用案例 5 的反射代码跑一遍，体会「框架靠无参构造 + setter 注入」。理解了这一点，学 Spring 时就不会觉得「魔法」了。
5. **封装思维要贯穿始终**：写任何类时默认问自己三个问题——字段该不该公开？setter 要不要校验？这个属性该只读还是可写？养成封装习惯，代码质量立刻上一个台阶。
