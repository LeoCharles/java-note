# 注解

**注解（Annotation）** 是 Java 5 引入的「代码标记」：它给程序元素（类、方法、字段、参数）打上标签，本身不直接执行任何逻辑，而是由**编译器**或**第三方程序（通过反射）** 来读取并处理。从 `@Override` 的编译检查，到 Spring 的 `@Component`、`@RequestMapping`，再到 JUnit 的 `@Test`，注解已经成为现代 Java 开发的「配置语言」。理解注解，是看懂 Spring 全家桶、MyBatis、JUnit 的前提。

> 💡 阅读本篇前，建议先看 [44-反射](44-反射.md)——**注解的运行时读取完全依赖反射**。本篇所有「读取注解」的代码都建立在反射 API 之上。同时建议回顾 [13-接口](13-接口.md)，因为注解的本质就是一个特殊接口。

---

## 一、注解的概念

### 1.1 什么是注解

注解是代码里的**特殊标记**，用 `@注解名` 表示，可以放在类、方法、字段、参数等上面，用来携带额外信息。

```java
@Override              // 注解：标记方法重写
public String toString() { return "..."; }

@Deprecated            // 注解：标记过时
public void oldMethod() { }

@SuppressWarnings("unused")  // 注解：抑制警告
private int temp;
```

> 💡 **通俗理解**：注解像「便利贴」——你给某个方法贴一张「这是重写的」（`@Override`），贴一张「这个过时了」（`@Deprecated`）。便利贴本身不会改变方法的行为，但看到它的人（编译器、框架）会做出相应处理。

### 1.2 注解的本质：接口

注解在编译后，会变成一个继承 `java.lang.annotation.Annotation` 的接口：

```java
// 你写的注解
public @interface MyAnno {
    String value();
}

// 编译后等价于（伪代码）
public interface MyAnno extends Annotation {
    String value();   // 抽象方法
}
```

所以注解的「属性」本质是**抽象方法**，使用注解时赋值就是「实现」这些方法。这也是为什么注解不能有实现逻辑——它是接口，不是类。

> ⚠️ 注解本身**不执行任何代码**，它只是一个标记。真正让注解「起作用」的是读取它的程序：编译器（如 `@Override`）或第三方框架（如 Spring 通过反射读 `@Component`）。

### 1.3 注解的作用分类

| 作用 | 说明 | 代表 |
| :--- | :--- | :--- |
| **编译检查** | 让编译器在编译期检查语法约束 | `@Override` |
| **代码分析** | 抑制警告、辅助工具分析 | `@SuppressWarnings` |
| **编写文档** | 标记过时，生成 API 文档 | `@Deprecated` |
| **运行时处理** | 框架通过反射读取，执行逻辑 | `@Component`、`@Test`、`@RequestMapping` |

前三类是 JDK 内置注解的能力，第四类是现代框架让注解大放异彩的关键——**注解 + 反射 = 框架的配置中枢**。

## 二、JDK 预定义注解

### 2.1 @Override：检查方法重写

`@Override` 标记一个方法是否**重写**了父类方法（或实现接口方法）。只能用在方法上。

```java
class Animal {
    public void eat() {}
}

class Dog extends Animal {
    @Override   // ✅ 编译器检查：确实是重写父类 eat
    public void eat() {}

    // @Override
    // public void run() {}  // ❌ 编译错误：父类没有 run，不是重写
}
```

> 📌 **规范**：重写父类方法时**一律加 `@Override`**。这样万一方法名/参数写错了，编译器立刻报错，而不是等到运行时才发现方法没被调用。

### 2.2 @Deprecated：标记过时

`@Deprecated` 标记某个类、方法、字段已过时，不建议再使用。调用时编译器会给出警告（删除线）。

```java
class DateUtil {
    @Deprecated
    public static String formatOld(Date d) {   // 旧方法，已过时
        return new SimpleDateFormat("yyyy-MM-dd").format(d);
    }

    public static String format(Date d) {       // 新方法
        return new SimpleDateFormat("yyyy-MM-dd").format(d);
    }
}

class Test {
    public static void main(String[] args) {
        DateUtil.formatOld(new Date());   // ⚠️ 警告：使用已过时的方法
        DateUtil.format(new Date());      // ✅ 无警告
    }
}
```

> 💡 `@Deprecated` 可以加 `since` 和 `forRemoval` 属性（Java 9+）：
> ```java
> @Deprecated(since = "1.5", forRemoval = true)  // 1.5 起过时，未来将移除
> public void oldMethod() {}
> ```

### 2.3 @SuppressWarnings：抑制警告

`@SuppressWarnings` 让编译器对指定类型的警告「闭嘴」。常用值：

| 值 | 抑制的警告 |
| :--- | :--- |
| `"unused"` | 未使用的变量/方法 |
| `"unchecked"` | 泛型未检查（如裸用 `List`） |
| `"rawtypes"` | 使用了 raw 类型（没写泛型参数） |
| `"deprecation"` | 使用了过时方法 |
| `"all"` | 抑制所有警告 |
| `"serial"` | Serializable 缺少 serialVersionUID |

```java
@SuppressWarnings("unchecked")
List<String> list = new ArrayList();   // 泛型警告被抑制

@SuppressWarnings({"unused", "deprecation"})
public void test() {
    int x = 0;                        // unused 警告被抑制
    DateUtil.formatOld(new Date());   // deprecation 警告被抑制
}
```

> ⚠️ `@SuppressWarnings` 只是把警告**隐藏**，并没有真正解决问题。生产代码应尽量修复警告，而不是无脑抑制。

### 2.4 @FunctionalInterface：函数式接口（Java 8）

标记一个接口是**函数式接口**（有且只有一个抽象方法），这样它就能用 Lambda 创建实例。

```java
@FunctionalInterface
interface MyFunction {
    int apply(int a, int b);
    // int another();  // ❌ 加了 @FunctionalInterface 后，多一个抽象方法会编译报错
}

// ✅ 可以用 Lambda
MyFunction f = (a, b) -> a + b;
```

> 💡 这是 Java 8 配合 Lambda 引入的注解，作用类似 `@Override`——让编译器帮你检查「这个接口到底能不能用 Lambda」。

## 三、元注解 ⭐⭐⭐

**元注解**是「修饰注解的注解」——用在自定义注解的定义上，规定这个注解能用在哪、保留到什么阶段。自定义注解必先掌握元注解。

### 3.1 @Target：注解能用的位置

`@Target` 指定注解可以标注在哪些元素上。取值是 `ElementType` 枚举：

| 值 | 可标注位置 |
| :--- | :--- |
| `TYPE` | 类、接口、注解、枚举 |
| `FIELD` | 字段（含枚举常量） |
| `METHOD` | 方法 |
| `CONSTRUCTOR` | 构造方法 |
| `PARAMETER` | 方法参数 |
| `LOCAL_VARIABLE` | 局部变量 |
| `ANNOTATION_TYPE` | 注解类型本身 |
| `PACKAGE` | 包（package-info.java） |
| `TYPE_PARAMETER` | 类型参数 `<T>`（Java 8） |
| `TYPE_USE` | 任何类型使用处（Java 8） |

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Target;

// 只能用在方法上
@Target(ElementType.METHOD)
@interface MyMethod {}

// 可用在类或字段上
@Target({ElementType.TYPE, ElementType.FIELD})
@interface MyTypeOrField {}

@MyTypeOrField
class Demo {
    @MyTypeOrField
    private String name;

    // @MyTypeOrField   // ❌ 不能用在方法上
    public void run() {}
}
```

> 💡 不加 `@Target` 的注解可以用在任何位置。但**规范做法是显式限定**，避免误用。

### 3.2 @Retention：注解保留到什么阶段 ⭐⭐⭐

`@Retention` 决定注解存活多久，是自定义注解**最关键**的元注解。取值是 `RetentionPolicy` 枚举：

| 策略 | 保留阶段 | 能否反射读取 | 典型用途 |
| :--- | :--- | :---: | :--- |
| `SOURCE` | 仅源码，编译后丢弃 | ❌ | `@Override`、`@SuppressWarnings` |
| `CLASS` | 编译进 class，运行时不加载 | ❌ | 字节码工具用（默认值，很少显式用） |
| `RUNTIME` | 运行时仍存在 | ✅ | `@Component`、`@Test` 等框架注解 |

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.SOURCE)   // 编译后消失，反射读不到
@interface CompileOnly {}

@Retention(RetentionPolicy.RUNTIME)  // 运行时存在，反射可读
@interface RuntimeAnno {}
```

> ⚠️ **自定义注解默认是 CLASS**（不写 `@Retention` 时），反射读不到！**自定义注解一般都要显式写 `@Retention(RUNTIME)`**，否则反射读出来永远是 null。这是新手最常踩的坑。

### 3.3 @Documented：抽取到 API 文档

`@Documented` 表示这个注解会被 `javadoc` 工具抽取到 API 文档中。

```java
import java.lang.annotation.Documented;

@Documented
@interface MyAnno {}
```

加了 `@Documented` 后，用 `javadoc` 生成文档时，被 `@MyAnno` 标注的元素会在文档里显示该注解。纯文档作用，不影响运行。

### 3.4 @Inherited：子类继承

`@Inherited` 让注解具有继承性——父类的注解会自动加到子类上。**只对类有效，对接口/方法/字段无效**。

```java
import java.lang.annotation.Inherited;

@Inherited
@Retention(RetentionPolicy.RUNTIME)
@interface MyMark {}

@MyMark
class Parent {}

class Child extends Parent {}

// 测试
System.out.println(Child.class.isAnnotationPresent(MyMark.class));  // true，子类继承了
```

> 💡 `@Inherited` 只在「子类继承父类」时生效，**实现接口不生效**，方法重写也不生效。使用场景较少，了解即可。

### 3.5 @Repeatable：可重复（Java 8+）

`@Repeatable` 允许同一个注解在同一位置重复使用多次。需要配合一个「容器注解」。

```java
import java.lang.annotation.Repeatable;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

// 容器注解：包含一组 Schedules
@interface Schedules {
    Schedule[] value();
}

// 可重复注解
@Repeatable(Schedules.class)
@Retention(RetentionPolicy.RUNTIME)
@interface Schedule {
    String cron();
}

// 使用：同一方法上多个 @Schedule
class TaskService {
    @Schedule(cron = "0 0 6 * * ?")
    @Schedule(cron = "0 0 18 * * ?")
    public void run() {}
}
```

> 💡 Java 8 之前，同一位置只能写一个同类型注解，要多个得手动包进容器注解。`@Repeatable` 让语法更简洁，但底层仍是容器注解（反射读取时要注意）。

## 四、自定义注解 ⭐⭐⭐

### 4.1 定义注解：@interface

用 `@interface` 关键字定义注解（注意是 `@interface`，不是 `interface`）：

```java
import java.lang.annotation.*;

@Target(ElementType.METHOD)              // 只能用在方法上
@Retention(RetentionPolicy.RUNTIME)      // 运行时保留（反射可读）
public @interface MyTest {
    String value();                       // 注解属性
}
```

### 4.2 注解的属性（抽象方法）

注解里的「属性」本质是**抽象方法**，返回值类型**只能**是以下几种（及其数组）：

- 基本类型（`int`、`long`、`boolean`、`double`...）
- `String`
- 枚举（`enum`）
- `Class`
- 注解类型
- 以上任意一种的**数组**

> ⚠️ **不能用**包装类（`Integer`）、自定义类、集合（`List`/`Map`）作为属性类型。这是注解的硬性限制：

```java
@interface GoodAnno {
    String name();              // ✅ String
    int age() default 0;         // ✅ 基本类型
    Class<?> clazz();           // ✅ Class
    RetentionPolicy policy();   // ✅ 枚举
    String[] tags() default {}; // ✅ 数组
    GoodAnno nested();          // ✅ 注解嵌套
}

@interface BadAnno {
    // Integer num();           // ❌ 不允许包装类
    // List<String> list();     // ❌ 不允许集合
    // Object obj();            // ❌ 不允许 Object
}
```

### 4.3 default 默认值

属性可以用 `default` 给默认值，使用时可不赋值：

```java
@interface MyAnno {
    String name();
    int age() default 18;          // 有默认值，使用时可省略
    String[] tags() default {};    // 数组默认空
}

@MyAnno(name = "张三")              // age 用默认 18
class A {}

@MyAnno(name = "李四", age = 25)    // 显式赋值
class B {}
```

> ⚠️ **没有默认值的属性，使用时必须赋值**，否则编译报错：
> ```java
> @MyAnno   // ❌ name 没默认值，必须赋值
> class C {}
> ```

### 4.4 使用时属性赋值

```java
@interface MyAnno {
    String name();
    int age() default 18;
    String[] tags() default {};
}

@MyAnno(name = "张三", age = 20, tags = {"a", "b"})
class Demo {}

// 数组只有一个元素时，大括号可省略
@MyAnno(name = "李四", tags = "single")
class Demo2 {}
```

### 4.5 value 属性的省略规则 ⭐⭐

如果注解只有一个属性需要赋值，且该属性名为 `value`，则 `value =` 可以省略：

```java
@interface MyAnno {
    String value();
    int age() default 18;
}

@MyAnno("张三")           // ✅ 等价于 @MyAnno(value = "张三")
class A {}

@MyAnno(value = "李四", age = 20)  // age 也要赋值时，value 不能省略
class B {}

// @MyAnno("王五", 20)   // ❌ 两个属性都赋值时，value= 不能省略
```

> 💡 这就是为什么 `@SuppressWarnings("unchecked")` 能直接写字符串——它的属性就叫 `value`，且只有一个。Spring 的 `@Component("userService")`、`@RequestMapping("/api")` 同理。

### 4.6 属性的返回值与调用

注解的属性本质是方法，使用时赋值，读取时调用「方法名」取值：

```java
@Retention(RetentionPolicy.RUNTIME)
@interface MyAnno {
    String name();
    int age() default 18;
}

@MyAnno(name = "张三", age = 20)
class Demo {}

// 读取
MyAnno a = Demo.class.getAnnotation(MyAnno.class);
System.out.println(a.name());   // 张三
System.out.println(a.age());    // 20
```

## 五、反射读取注解 ⭐⭐⭐

注解的威力在于「运行时被读取」。读取注解完全依赖反射 API（见 [44-反射](44-反射.md)）。

### 5.1 判断注解是否存在：isAnnotationPresent

```java
boolean has = Demo.class.isAnnotationPresent(MyAnno.class);
// 等价于 Demo.class.getAnnotation(MyAnno.class) != null
```

### 5.2 获取注解：getAnnotation

```java
// 获取类上的注解
MyAnno a = Demo.class.getAnnotation(MyAnno.class);
if (a != null) {
    System.out.println(a.name() + ", " + a.age());
}

// 获取方法上的注解
Method m = Demo.class.getMethod("run");
MyAnno ma = m.getAnnotation(MyAnno.class);

// 获取字段上的注解
Field f = Demo.class.getDeclaredField("name");
MyAnno fa = f.getAnnotation(MyAnno.class);
```

### 5.3 获取所有注解：getAnnotations

```java
// 获取类上所有注解（含继承的 @Inherited 注解）
Annotation[] arr = Demo.class.getAnnotations();
for (Annotation a : arr) {
    System.out.println(a.annotationType().getSimpleName());
}

// 获取本类直接声明的注解（不含继承）
Annotation[] declared = Demo.class.getDeclaredAnnotations();
```

| 方法 | 说明 |
| :--- | :--- |
| `getAnnotation(Class)` | 获取指定类型注解（含继承的 @Inherited） |
| `getAnnotations()` | 获取所有注解（含继承） |
| `getDeclaredAnnotation(Class)` | 获取指定注解（不含继承，Java 8+） |
| `getDeclaredAnnotations()` | 本类直接声明的所有注解 |
| `isAnnotationPresent(Class)` | 是否存在指定注解 |
| `getAnnotationsByType(Class)` | 获取重复注解数组（配合 @Repeatable） |

### 5.4 读取注解属性的完整流程

```java
import java.lang.annotation.*;
import java.lang.reflect.Method;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface MyTest {
    String value();
    int timeout() default 1000;
}

class Task {
    @MyTest(value = "case1", timeout = 500)
    public void run() {}

    @MyTest("case2")   // value 省略
    public void walk() {}
}

public class Demo {
    public static void main(String[] args) throws Exception {
        for (Method m : Task.class.getDeclaredMethods()) {
            if (m.isAnnotationPresent(MyTest.class)) {
                MyTest t = m.getAnnotation(MyTest.class);
                System.out.println("方法：" + m.getName()
                    + "，描述：" + t.value()
                    + "，超时：" + t.timeout());
                // 执行方法（反射调用）
                m.invoke(new Task());
            }
        }
    }
}
```

输出：

```
方法：run，描述：case1，超时：500
方法：walk，描述：case2，超时：1000
```

> 💡 这就是 JUnit 的核心原理：扫描 `@Test` 注解的方法，反射调用执行。整个 JUnit 框架的入口就是这么几行代码的扩展。

### 5.5 读取 @Repeatable 重复注解

```java
@Repeatable(Schedules.class)
@Retention(RetentionPolicy.RUNTIME)
@interface Schedule { String cron(); }

@Retention(RetentionPolicy.RUNTIME)
@interface Schedules { Schedule[] value(); }

class Task {
    @Schedule(cron = "0 0 6 * * ?")
    @Schedule(cron = "0 0 18 * * ?")
    public void run() {}
}

// 读取方式一：通过容器注解
Schedules container = Task.class.getMethod("run").getAnnotation(Schedules.class);
for (Schedule s : container.value()) {
    System.out.println(s.cron());
}

// 读取方式二：getAnnotationsByType（Java 8+，自动展开容器）
Schedule[] arr = Task.class.getMethod("run").getAnnotationsByType(Schedule.class);
for (Schedule s : arr) {
    System.out.println(s.cron());
}
```

> 💡 `getAnnotationsByType` 会自动「拆开」容器注解，直接拿到重复注解数组，比手动取容器更方便。

## 六、注解处理器思路

注解本身不执行逻辑，真正让它「活」起来的是**注解处理器**——一段通过反射扫描并处理注解的代码。通用套路：

```
1. 反射获取目标元素（Class / Method / Field）
2. 判断是否有目标注解（isAnnotationPresent）
3. 获取注解（getAnnotation）
4. 读取注解属性（调用属性方法）
5. 根据属性值执行对应逻辑（反射创建对象、调用方法等）
```

```java
// 注解处理器模板
public static void process(Class<?> clazz) throws Exception {
    // 1. 处理类上的注解
    if (clazz.isAnnotationPresent(MyAnno.class)) {
        MyAnno a = clazz.getAnnotation(MyAnno.class);
        // 4. 读取属性
        String name = a.name();
        // 5. 执行逻辑
        System.out.println("处理类：" + name);
    }
    // 2. 处理方法上的注解
    for (Method m : clazz.getDeclaredMethods()) {
        if (m.isAnnotationPresent(MyTest.class)) {
            MyTest t = m.getAnnotation(MyTest.class);
            m.invoke(clazz.getDeclaredConstructor().newInstance());
        }
    }
    // 3. 处理字段上的注解
    for (Field f : clazz.getDeclaredFields()) {
        if (f.isAnnotationPresent(Column.class)) {
            Column c = f.getAnnotation(Column.class);
            System.out.println(f.getName() + " -> " + c.value());
        }
    }
}
```

> 📌 **记住这个套路**：所有基于注解的框架（Spring、MyBatis、JUnit）都是这个流程的扩展——扫描注解 → 读取属性 → 反射执行。掌握了它，框架源码就不再神秘。

## ⚠️ 重点

### 重点 1：@Retention 必须是 RUNTIME 才能反射读取 ⭐⭐⭐

```java
@Retention(RetentionPolicy.SOURCE)   // 编译后消失
@interface A {}

@Retention(RetentionPolicy.RUNTIME)  // 运行时存在
@interface B {}

@A @B class Demo {}

Demo.class.getAnnotation(A.class);   // null，读不到
Demo.class.getAnnotation(B.class);   // 有值，能读到
```

> ⚠️ **新手第一坑**：自定义注解忘了加 `@Retention(RUNTIME)`，反射读出来永远是 null，还以为反射用错了。**自定义注解默认是 CLASS，反射读不到，务必显式写 RUNTIME**。

### 重点 2：@Target 限定使用位置 ⭐⭐

```java
@Target(ElementType.METHOD)
@interface MethodOnly {}

@MethodOnly   // ❌ 编译错误：只能用在方法上
class Demo {}

class Demo2 {
    @MethodOnly   // ✅ 用在方法上
    public void run() {}
}
```

> 📌 规范：自定义注解**一定**要加 `@Target`，明确告诉使用者「这个注解能贴在哪」，避免误用。

### 重点 3：value 属性的省略规则 ⭐⭐

```java
@interface MyAnno {
    String value();
    int age() default 18;
}

@MyAnno("张三")                    // ✅ 只有 value 赋值，可省略 value=
@MyAnno(value = "李四", age = 20)  // ✅ 多属性赋值，value= 不能省略
// @MyAnno("王五", 20)            // ❌ 多属性时不能省略
```

### 重点 4：注解属性类型限制 ⭐⭐

```java
@interface Good {
    String s();           // ✅
    int i() default 0;    // ✅
    Class<?> c();         // ✅
    RetentionPolicy p();  // ✅ 枚举
    String[] arr();       // ✅ 数组
}

@interface Bad {
    // Integer i();      // ❌ 包装类
    // List<String> l(); // ❌ 集合
    // Object o();       // ❌ Object
}
```

> ⚠️ 只能是基本类型、String、枚举、Class、注解、以及它们的数组。需要传复杂对象时，只能传 `Class` 再反射创建。

### 重点 5：注解不执行任何逻辑 ⭐

```java
@Test   // 这个注解本身不会让方法自动执行
public void testCase() { ... }
```

> 💡 **注解只是标记**，真正执行的是读取它的程序。`@Test` 能跑测试，是因为 JUnit 框架在反射扫描 `@Test` 方法并调用它们。理解这一点，就不会困惑「为什么我加了注解却没效果」。

### 重点 6：元注解的位置——只能修饰注解 ⭐

```java
@Target(ElementType.METHOD)      // ✅ 用在注解定义上
@Retention(RetentionPolicy.RUNTIME)
@interface MyAnno {}

// @Target(ElementType.TYPE)     // ❌ 不能用在普通类上
// class Demo {}
```

> 💡 元注解（`@Target`、`@Retention` 等）只能修饰**注解的定义**，不能修饰普通类/方法。这是「元」的含义——修饰注解的注解。

### 案例 1：自定义 @Table/@Id/@Column 模拟 ORM ⭐⭐⭐

用注解描述对象与表的映射关系，反射读取生成 SQL——MyBatis/Hibernate 的核心思路。

```java
import java.lang.annotation.*;
import java.lang.reflect.Field;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Table { String value(); }

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Id { }

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Column {
    String value();
    String type() default "VARCHAR(255)";
}

@Table("t_order")
class Order {
    @Id
    @Column(value = "order_id", type = "INT")
    private Integer id;

    @Column("order_no")
    private String orderNo;

    @Column(value = "amount", type = "DECIMAL(10,2)")
    private Double amount;

    @Column(value = "status", type = "TINYINT")
    private Integer status;

    // 省略 getter/setter
}

public class OrmDemo {
    // 生成建表 SQL
    public static String createTableSQL(Class<?> clazz) {
        Table t = clazz.getAnnotation(Table.class);
        if (t == null) throw new RuntimeException("缺少 @Table");
        StringBuilder sb = new StringBuilder("CREATE TABLE ");
        sb.append(t.value()).append(" (\n");
        for (Field f : clazz.getDeclaredFields()) {
            Column c = f.getAnnotation(Column.class);
            if (c == null) continue;
            sb.append("  ").append(c.value()).append(" ").append(c.type());
            if (f.isAnnotationPresent(Id.class)) {
                sb.append(" PRIMARY KEY");
            }
            sb.append(",\n");
        }
        sb.delete(sb.length() - 2, sb.length()).append("\n)");
        return sb.toString();
    }

    // 生成查询 SQL：SELECT col1, col2 FROM table WHERE id_col = ?
    public static String findByIdSQL(Class<?> clazz) {
        Table t = clazz.getAnnotation(Table.class);
        StringBuilder cols = new StringBuilder();
        String idCol = null;
        for (Field f : clazz.getDeclaredFields()) {
            Column c = f.getAnnotation(Column.class);
            if (c == null) continue;
            cols.append(c.value()).append(", ");
            if (f.isAnnotationPresent(Id.class)) idCol = c.value();
        }
        cols.delete(cols.length() - 2, cols.length());
        return "SELECT " + cols + " FROM " + t.value()
             + " WHERE " + idCol + " = ?";
    }

    public static void main(String[] args) {
        System.out.println(createTableSQL(Order.class));
        System.out.println(findByIdSQL(Order.class));
    }
}
```

输出：

```
CREATE TABLE t_order (
  order_id INT PRIMARY KEY,
  order_no VARCHAR(255),
  amount DECIMAL(10,2),
  status TINYINT
)
SELECT order_id, order_no, amount, status FROM t_order WHERE order_id = ?
```

> 💡 这就是 MyBatis `@InsertProvider`、JPA `@Table`/`@Column` 的雏形。真实框架还处理了类型映射、关联关系、缓存等，但注解驱动的核心一致。

### 案例 2：@MyTest 注解实现测试方法执行 ⭐⭐⭐

模拟 JUnit：扫描带 `@MyTest` 的方法，自动执行。

```java
import java.lang.annotation.*;
import java.lang.reflect.Method;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface MyTest {
    String value() default "";
    boolean ignore() default false;
}

class CalculatorTest {
    @MyTest("加法测试")
    public void testAdd() {
        System.out.println("执行 testAdd：3+5=" + (3 + 5));
    }

    @MyTest("乘法测试")
    public void testMultiply() {
        System.out.println("执行 testMultiply：3*5=" + (3 * 5));
    }

    @MyTest(ignore = true)
    public void testSkip() {
        System.out.println("这行不该执行");
    }

    public void notATest() {
        System.out.println("普通方法，不执行");
    }
}

public class MyTestRunner {
    public static void run(Class<?> testClass) throws Exception {
        Object obj = testClass.getDeclaredConstructor().newInstance();
        int passed = 0, failed = 0, skipped = 0;
        for (Method m : testClass.getDeclaredMethods()) {
            if (!m.isAnnotationPresent(MyTest.class)) continue;
            MyTest t = m.getAnnotation(MyTest.class);
            if (t.ignore()) { skipped++; continue; }
            try {
                System.out.println("▶ " + (t.value().isEmpty() ? m.getName() : t.value()));
                m.invoke(obj);
                passed++;
            } catch (Exception e) {
                System.out.println("  ✗ 失败：" + e.getCause());
                failed++;
            }
        }
        System.out.println("\n通过：" + passed + "，失败：" + failed + "，跳过：" + skipped);
    }

    public static void main(String[] args) throws Exception {
        run(CalculatorTest.class);
    }
}
```

输出：

```
▶ 加法测试
执行 testAdd：3+5=8
▶ 乘法测试
执行 testMultiply：3*5=15

通过：2，失败：0，跳过：1
```

> 💡 这就是 JUnit 的核心。真实 JUnit 用 `@Test`、`@Before`、`@After` 等注解，加上生命周期管理、断言、参数化，但骨架就是「反射扫描注解方法 + invoke」。

### 案例 3：自定义校验注解 @NotNull / @Length ⭐⭐

电商系统表单校验：用注解标记字段约束，反射统一校验——Hibernate Validator 的思路。

```java
import java.lang.annotation.*;
import java.lang.reflect.Field;
import java.util.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotNull { String message() default "不能为空"; }

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Length {
    int min() default 0;
    int max() default 255;
    String message() default "长度不合法";
}

class UserForm {
    @NotNull(message = "用户名不能为空")
    @Length(min = 2, max = 20, message = "用户名长度 2-20")
    private String username;

    @Length(min = 6, max = 20, message = "密码长度 6-20")
    @NotNull(message = "密码不能为空")
    private String password;

    @NotNull(message = "手机号不能为空")
    @Length(max = 11, message = "手机号最多 11 位")
    private String phone;

    public UserForm(String u, String p, String ph) {
        this.username = u; this.password = p; this.phone = ph;
    }
}

public class Validator {
    // 通用校验：返回所有错误信息
    public static List<String> validate(Object obj) throws Exception {
        List<String> errors = new ArrayList<>();
        Class<?> clazz = obj.getClass();
        for (Field f : clazz.getDeclaredFields()) {
            f.setAccessible(true);
            Object value = f.get(obj);
            // @NotNull 校验
            if (f.isAnnotationPresent(NotNull.class)) {
                NotNull n = f.getAnnotation(NotNull.class);
                if (value == null || value.toString().isEmpty()) {
                    errors.add("[" + f.getName() + "] " + n.message());
                    continue;   // 已为空，无需再校验长度
                }
            }
            // @Length 校验
            if (f.isAnnotationPresent(Length.class) && value != null) {
                Length l = f.getAnnotation(Length.class);
                int len = value.toString().length();
                if (len < l.min() || len > l.max()) {
                    errors.add("[" + f.getName() + "] " + l.message()
                        + "（实际 " + len + "）");
                }
            }
        }
        return errors;
    }

    public static void main(String[] args) throws Exception {
        // 模拟表单提交：用户名为空，密码太短，手机号超长
        UserForm form = new UserForm("", "123", "1234567890123");
        List<String> errors = validate(form);
        if (errors.isEmpty()) {
            System.out.println("校验通过");
        } else {
            errors.forEach(System.out::println);
        }
    }
}
```

输出：

```
[username] 用户名不能为空
[password] 密码长度 6-20（实际 3）
[phone] 手机号最多 11 位（实际 13）
```

> 💡 这就是 `javax.validation`（Hibernate Validator）的核心：`@NotNull`、`@Size`、`@Pattern` 等注解 + 反射校验。Spring Boot 的 `@Valid` 底层正是这套机制。

### 案例 4：注解 + 反射实现简易 Spring MVC 路由 ⭐⭐⭐

模拟 `@Controller` + `@RequestMapping`：扫描类和方法上的路径注解，建立路由表。

```java
import java.lang.annotation.*;
import java.lang.reflect.Method;
import java.util.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Controller {}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface RequestMapping {
    String value();   // 路径
    String method() default "GET";
}

@Controller
class UserController {
    @RequestMapping(value = "/user/list", method = "GET")
    public String list() { return "用户列表"; }

    @RequestMapping(value = "/user/save", method = "POST")
    public String save() { return "保存成功"; }

    @RequestMapping("/user/delete")   // 默认 GET
    public String delete() { return "删除成功"; }
}

@Controller
class OrderController {
    @RequestMapping("/order/list")
    public String list() { return "订单列表"; }
}

// 路由表项
class Route {
    String path;
    String httpMethod;
    Object controller;
    Method method;
    public Route(String p, String m, Object c, Method me) {
        path = p; httpMethod = m; controller = c; method = me;
    }
}

public class SimpleDispatcher {
    private Map<String, Route> routes = new HashMap<>();

    // 注册一个 Controller
    public void register(Class<?> clazz) throws Exception {
        if (!clazz.isAnnotationPresent(Controller.class)) return;
        Object obj = clazz.getDeclaredConstructor().newInstance();
        for (Method m : clazz.getDeclaredMethods()) {
            if (!m.isAnnotationPresent(RequestMapping.class)) continue;
            RequestMapping r = m.getAnnotation(RequestMapping.class);
            String key = r.method() + " " + r.value();
            routes.put(key, new Route(r.value(), r.method(), obj, m));
        }
    }

    // 处理请求
    public String handle(String httpMethod, String path) throws Exception {
        String key = httpMethod + " " + path;
        Route route = routes.get(key);
        if (route == null) return "404 Not Found: " + path;
        return (String) route.method.invoke(route.controller);
    }

    public static void main(String[] args) throws Exception {
        SimpleDispatcher dispatcher = new SimpleDispatcher();
        dispatcher.register(UserController.class);
        dispatcher.register(OrderController.class);

        System.out.println(dispatcher.handle("GET", "/user/list"));    // 用户列表
        System.out.println(dispatcher.handle("POST", "/user/save"));   // 保存成功
        System.out.println(dispatcher.handle("GET", "/order/list"));   // 订单列表
        System.out.println(dispatcher.handle("GET", "/not/found"));     // 404
    }
}
```

> 💡 这就是 Spring MVC `DispatcherServlet` 的骨架：启动时扫描 `@Controller`，把 `@RequestMapping` 的路径映射到方法存进 Map，请求来了按 `method + path` 找到对应方法反射调用。真实 Spring 还处理了参数解析、视图渲染、拦截器等，但路由分发的核心就是这几行。

### 案例 5：配置注解替代 properties ⭐⭐

用注解把配置写在代码里，反射读取——类似 Spring Boot 的 `@ConfigurationProperties`。

```java
import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Config { String prefix() default ""; }

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Value { String value(); }

@Config(prefix = "db")
class DbConfig {
    @Value("db.url")
    private String url = "jdbc:mysql://localhost:3306/test";
    @Value("db.username")
    private String username = "root";
    @Value("db.maxConn")
    private int maxConn = 10;

    public String getUrl() { return url; }
    public String getUsername() { return username; }
    public int getMaxConn() { return maxConn; }
}

public class ConfigReader {
    public static void load(Object obj) throws Exception {
        Class<?> clazz = obj.getClass();
        if (!clazz.isAnnotationPresent(Config.class)) return;
        // 这里简化：直接用字段默认值（真实场景从 properties/环境变量读取覆盖）
        for (java.lang.reflect.Field f : clazz.getDeclaredFields()) {
            if (f.isAnnotationPresent(Value.class)) {
                Value v = f.getAnnotation(Value.class);
                System.out.println("配置项 " + v.value() + " = " + getFieldValue(obj, f));
            }
        }
    }

    private static Object getFieldValue(Object obj, java.lang.reflect.Field f) throws Exception {
        f.setAccessible(true);
        return f.get(obj);
    }

    public static void main(String[] args) throws Exception {
        DbConfig cfg = new DbConfig();
        load(cfg);
        // 输出：
        // 配置项 db.url = jdbc:mysql://localhost:3306/test
        // 配置项 db.username = root
        // 配置项 db.maxConn = 10
    }
}
```

> 💡 Spring Boot 的 `@Configuration`、`@Value`、`@ConfigurationProperties` 就是这个套路：注解标记配置项，启动时反射读取并注入。真实实现会从 `Environment`、配置文件、命令行参数等多源读取覆盖默认值。

### 案例 6：@Table + 反射实现通用 INSERT 语句 ⭐⭐

```java
import java.lang.annotation.*;
import java.lang.reflect.Field;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Table { String value(); }

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Column { String value(); }

@Table("t_product")
class Product {
    @Column("prod_id") private Integer id;
    @Column("prod_name") private String name;
    @Column("price") private Double price;
    @Column("stock") private Integer stock;

    public Product(Integer id, String name, Double price, Integer stock) {
        this.id = id; this.name = name; this.price = price; this.stock = stock;
    }
}

public class InsertBuilder {
    // 通用 INSERT 生成器
    public static String buildInsert(Object obj) {
        Class<?> clazz = obj.getClass();
        Table t = clazz.getAnnotation(Table.class);
        if (t == null) throw new RuntimeException("缺少 @Table");
        StringBuilder cols = new StringBuilder();
        StringBuilder vals = new StringBuilder();
        try {
            for (Field f : clazz.getDeclaredFields()) {
                Column c = f.getAnnotation(Column.class);
                if (c == null) continue;
                f.setAccessible(true);
                Object v = f.get(obj);
                cols.append(c.value()).append(", ");
                if (v instanceof String) {
                    vals.append("'").append(v).append("', ");
                } else {
                    vals.append(v).append(", ");
                }
            }
        } catch (Exception e) { throw new RuntimeException(e); }
        cols.delete(cols.length() - 2, cols.length());
        vals.delete(vals.length() - 2, vals.length());
        return "INSERT INTO " + t.value() + " (" + cols + ") VALUES (" + vals + ")";
    }

    public static void main(String[] args) {
        Product p = new Product(1, "Java书", 89.0, 100);
        System.out.println(buildInsert(p));
        // INSERT INTO t_product (prod_id, prod_name, price, stock)
        //   VALUES (1, 'Java书', 89.0, 100)
    }
}
```

> 💡 MyBatis 的 `@Insert`、Hibernate 的 `persist`，底层都是反射遍历字段 + 注解生成 SQL。这个案例是 ORM `save()` 方法的最小实现。

## 🚀 新版本补充

### Java 8：@Repeatable 可重复注解

Java 8 之前，同一位置不能写两个相同注解。Java 8 引入 `@Repeatable` 解决：

```java
// Java 8 之前：必须用容器包一层
@Schedules({@Schedule(cron="0 0 6 * * ?"), @Schedule(cron="0 0 18 * * ?")})
public void run() {}

// Java 8+：直接重复写
@Schedule(cron = "0 0 6 * * ?")
@Schedule(cron = "0 0 18 * * ?")
public void run() {}
```

读取时用 `getAnnotationsByType` 自动展开容器（见 5.5 节）。

### Java 8：类型注解（TYPE_USE）

Java 8 扩展了 `@Target`，新增 `TYPE_PARAMETER`（类型参数声明）和 `TYPE_USE`（类型使用处），让注解能标注在泛型上：

```java
@Target(ElementType.TYPE_USE)
@interface NonNull {}

class Box<@NonNull T> {                       // 类型参数声明处
    private @NonNull List<@NonNull String> items;  // 类型使用处
    void process(@NonNull String s) {}        // 参数类型使用处
}
```

> 💡 这为 Checker Framework 等静态检查工具提供了基础，但日常业务很少直接用。

### Java 8：@FunctionalInterface

Java 8 引入，标记函数式接口（见 2.4 节）。配合 Lambda 使用。

### Java 9+：注解的改进

- Java 9：`@Deprecated` 新增 `since` 和 `forRemoval` 属性，明确废弃时间表。
- Java 16+：记录类（Record）上的注解会被自动传播到组件（需配合 `@Target`）。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 注解本质 | 继承 Annotation 的接口，属性是抽象方法 |
| JDK 内置注解 | `@Override`、`@Deprecated`、`@SuppressWarnings`、`@FunctionalInterface` |
| 元注解 | `@Target`（位置）、`@Retention`（阶段）、`@Documented`、`@Inherited`、`@Repeatable` |
| @Retention 三策略 | SOURCE（编译丢弃）、CLASS（默认）、**RUNTIME（反射可读）** |
| 自定义注解 | `@interface` 定义，属性返回值限基本/String/枚举/Class/注解/数组 |
| value 省略 | 单属性且名为 value 时可省略 `value=` |
| 反射读取 | `isAnnotationPresent`、`getAnnotation`、`getAnnotationsByType` |
| 注解处理器套路 | 扫描注解 → 读属性 → 反射执行 |

## 学习建议

1. **务必手写一个自定义注解 + 处理器**：照着案例 2 写一个 `@MyTest`，扫描带注解的方法并执行。这一步做完，你会瞬间理解 JUnit、Spring `@Component` 是怎么「自动发现」的。
2. **牢记 @Retention(RUNTIME) 这条铁律**：自定义注解不加 `@Retention(RUNTIME)`，反射读出来永远是 null——这是新手最常踩的坑，写自定义注解时第一行就该加上。
3. **理解注解「不执行逻辑」的本质**：注解只是便利贴，真正干活的是读取它的处理器。带着这个视角去看 Spring 源码，你会发现 `@Component`、`@RequestMapping` 的处理逻辑都能在框架里找到对应的扫描代码。
4. **把案例 1（ORM）和案例 4（MVC 路由）完整跑一遍**：这两个案例覆盖了「类注解 + 字段注解 + 方法注解」的完整读取链路，跑通后你对注解的实际应用会有具象认识。
5. **结合反射一起学**：注解和反射是「配套技能」——注解负责标记，反射负责读取。建议把本篇和 [44-反射](44-反射.md) 对照着看，两篇的案例可以互相印证，理解会更深。
