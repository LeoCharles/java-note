# 包装类

Java 是一门**面向对象**的语言，但它的 8 种基本类型（`byte`/`short`/`int`/`long`/`float`/`double`/`char`/`boolean`）却不是对象——它们没有方法、没有属性，不能参与泛型、不能存进集合。为了让基本类型也能"享受"对象的待遇，Java 为每一个基本类型都设计了一个**包装类**（Wrapper Class），二者一一对应。理解包装类，不仅是理解集合与泛型的前置条件，更是理解自动装箱、`Integer` 缓存池陷阱、数据库实体设计的钥匙——很多诡异的 bug（`==` 比较失效、循环里莫名变慢、NPE）都根源于此。

> 💡 在阅读本篇前，建议先看 [04-数据类型与类型转换](04-数据类型与类型转换.md)，理解 8 种基本类型与引用类型的内存差异，再看 [02-JVM内存模型](02-JVM内存模型.md) 中"堆存对象、栈存基本类型值"的区别，会更容易理解装箱/拆箱的开销。

## 一、包装类概念

### 1.1 基本类型与包装类的对应关系

Java 为 8 种基本类型各提供了一个包装类，全部位于 `java.lang` 包下，无需 import：

| 基本类型 | 包装类 | 继承自 | 默认值（基本类型） | 默认值（包装类） |
| :---: | :---: | :---: | :---: | :---: |
| `byte` | `Byte` | Number | `0` | `null` |
| `short` | `Short` | Number | `0` | `null` |
| `int` | `Integer` | Number | `0` | `null` |
| `long` | `Long` | Number | `0L` | `null` |
| `float` | `Float` | Number | `0.0f` | `null` |
| `double` | `Double` | Number | `0.0d` | `null` |
| `char` | `Character` | Object | `' '` | `null` |
| `boolean` | `Boolean` | Object | `false` | `null` |

> 💡 **记忆口诀**：除了 `Integer`（对应 `int`）和 `Character`（对应 `char`）是全称外，其余 6 个包装类就是把基本类型名首字母大写：`Byte`、`Short`、`Long`、`Float`、`Double`、`Boolean`。

```java
// 包装类是引用类型，变量存的是对象地址
Integer a = Integer.valueOf(10);   // a 指向堆中的 Integer 对象
int b = 10;                        // b 直接存值 10

System.out.println(a.getClass());  // class java.lang.Integer
System.out.println(((Object)b).getClass());  // ❌ int 不是对象，编译报错
```

### 1.2 为什么需要包装类

基本类型"不够用"的场景，就是包装类存在的理由：

| 场景 | 基本类型的问题 | 包装类的解决方案 |
| :--- | :--- | :--- |
| 集合存元素 | `List<int>` 不合法，集合只能存对象 | `List<Integer>` 合法 |
| 泛型 | `Map<String, int>` 不合法 | `Map<String, Integer>` 合法 |
| 数据库字段 | 基本类型默认 0，无法表达"未填写" | 包装类默认 null，能区分"0"和"空" |
| 反射 | 基本类型无 Class 对象 | `Integer.class` 可用于反射 |
| 方法参数 | 基本类型传值，无法表达"可空" | 包装类可为 null，适配外部接口 |

```java
import java.util.*;

// ❌ 集合不能存基本类型
// List<int> list = new ArrayList<>();   // 编译错误

// ✅ 用包装类
List<Integer> list = new ArrayList<>();
list.add(1);    // 自动装箱：int → Integer
list.add(2);
System.out.println(list);   // [1, 2]

// 数据库实体：用包装类区分"0"和"未填写"
class User {
    private Integer age;      // null 表示未填写，0 不会和"未填写"混淆
    private Boolean vip;      // null 表示未知，false 表示明确非 VIP
}
```

> ⚠️ **数据库实体规范**：实体类的数值字段一律用包装类（`Integer`/`Long`），不要用基本类型。因为数据库字段可能为 `NULL`，若用 `int` 接收会被默认成 `0`，导致"未填写"被误判成"填了 0"。

## 二、装箱与拆箱

### 2.1 装箱：基本类型 → 包装类

把基本类型转成包装类，叫**装箱**（Boxing）。有两种方式：

```java
// 方式 1：构造方法（Java 9 起已标记 @Deprecated，不推荐）
Integer a = new Integer(10);     // ⚠️ 每次都新建对象，不进缓存

// 方式 2：valueOf 静态方法（推荐 ✅）
Integer b = Integer.valueOf(10); // 优先命中缓存池，不新建对象

// 方式 3：自动装箱（语法糖，编译期插入 valueOf）
Integer c = 10;                  // 等价于 Integer.valueOf(10)
```

> 📌 **开发规范**：装箱统一用 `valueOf()` 或自动装箱，**不要用 `new Integer()`**。一方面 `new` 永远新建对象，浪费内存；另一方面 Java 9 起构造方法已被标记 `@Deprecated`。

其余包装类的装箱方式相同：

```java
Long l = Long.valueOf(100L);
Double d = Double.valueOf(3.14);
Character ch = Character.valueOf('A');
Boolean flag = Boolean.valueOf(true);
```

### 2.2 拆箱：包装类 → 基本类型

把包装类转成基本类型，叫**拆箱**（Unboxing）。用 `xxxValue()` 方法：

```java
Integer a = Integer.valueOf(10);

// 拆箱：调用 intValue()
int b = a.intValue();         // ✅ 显式拆箱
long c = a.longValue();       // ✅ 也可以转成 long（跨类型）
double e = a.doubleValue();   // ✅ 转成 double

// 自动拆箱（语法糖，编译期插入 xxxValue）
int f = a;                    // 等价于 a.intValue()
```

各包装类的拆箱方法：

| 包装类 | 拆箱方法 | 说明 |
| :--- | :--- | :--- |
| `Integer` | `intValue()` | → int |
| `Long` | `longValue()` | → long |
| `Double` | `doubleValue()` | → double |
| `Float` | `floatValue()` | → float |
| `Byte` | `byteValue()` | → byte |
| `Short` | `shortValue()` | → short |
| `Character` | `charValue()` | → char |
| `Boolean` | `booleanValue()` | → boolean |

> 💡 所有 Number 子类（Byte/Short/Integer/Long/Float/Double）都有完整的 `xxxValue()` 方法，可以互相转换。例如 `Integer` 也能调 `longValue()`、`doubleValue()`，本质是先拆箱再走基本类型的自动转换。

### 2.3 自动装箱与拆箱

从 Java 5 开始，编译器会**自动**在基本类型和包装类之间插入 `valueOf` / `xxxValue`，这就是自动装箱拆箱——它只是**编译期语法糖**，运行时没有任何"自动"魔法。

```java
// 自动装箱：int → Integer
Integer a = 10;
// 编译后等价于：Integer a = Integer.valueOf(10);

// 自动拆箱：Integer → int
int b = a;
// 编译后等价于：int b = a.intValue();

// 运算时也会自动拆箱
Integer x = 100;
Integer y = 200;
int sum = x + y;   // 先拆箱成 int 相加，结果 300

// 方法参数也会自动装箱
List<Integer> list = new ArrayList<>();
list.add(5);       // 自动装箱：5 → Integer.valueOf(5)
int n = list.get(0); // 自动拆箱：Integer → int
```

> ⚠️ **自动拆箱的 NPE 陷阱**：当包装类变量为 `null` 时，自动拆箱会调用 `null.intValue()`，直接抛 `NullPointerException`。这是开发中极高频的崩溃点：

```java
Integer a = null;
int b = a;   // ❌ NullPointerException！等价于 a.intValue()，而 a 是 null

// ✅ 安全做法：先判空
if (a != null) {
    int c = a;
}
```

## 三、Integer 缓存池（IntegerCache）

### 3.1 缓存机制

`Integer.valueOf(int)` 在加载时会预先创建 **-128 到 127** 范围内的 Integer 对象并缓存起来。这个范围内的装箱，返回的是**同一个缓存对象**；范围外的装箱，才真正 `new` 一个新对象。

```java
Integer a = Integer.valueOf(127);
Integer b = Integer.valueOf(127);
System.out.println(a == b);    // true，命中缓存，a 和 b 是同一对象

Integer c = Integer.valueOf(128);
Integer d = Integer.valueOf(128);
System.out.println(c == d);   // false，超出缓存，c 和 d 是不同对象

System.out.println(a.equals(b));   // true，equals 比较的是值
System.out.println(c.equals(d));   // true
```

> 💡 **缓存原理**：`Integer` 内部有一个私有静态类 `IntegerCache`，类加载时在 `static` 块里循环创建 256 个 Integer 对象存进数组。`valueOf(i)` 判断 `i` 是否在 `[-128, 127]`，是则直接返回数组中的对象，否则 `new Integer(i)`。

### 3.2 自动装箱也走缓存

自动装箱本质就是 `valueOf`，所以也命中缓存：

```java
// 自动装箱
Integer a = 127;    // Integer.valueOf(127)，命中缓存
Integer b = 127;    // 同一缓存对象
System.out.println(a == b);   // true ✅

Integer c = 128;   // 超出缓存，new Integer(128)
Integer d = 128;   // 又 new Integer(128)
System.out.println(c == d);   // false ❌
```

### 3.3 缓存范围可调（了解）

`IntegerCache` 的高位（127）可以通过 JVM 参数 `-XX:AutoBoxCacheMax` 调整，下位固定为 -128。但实际开发中几乎不会去调，记住默认范围即可。

```java
// 启动参数加 -XX:AutoBoxCacheMax=1000，则缓存范围变成 [-128, 1000]
// 此时 Integer.valueOf(500) 也会命中缓存
// 但这是 JVM 实现 detail，不要在生产代码里依赖它
```

> ⚠️ **除 Integer 外**，`Byte`、`Short`、`Long` 也有缓存（范围都是 -128~127），`Character` 缓存 0~127，`Boolean` 缓存 TRUE/FALSE。但 `Float`、`Double` **没有缓存**——因为浮点数范围太大，缓存意义不大。

## 四、基本类型与 String 互转

### 4.1 基本类型 → String

三种方式，推荐 `String.valueOf()`：

```java
int n = 100;

// 方式 1：+ "" 拼接（最简单，但可读性差）
String s1 = n + "";              // "100"

// 方式 2：String.valueOf()（推荐 ✅，内部已处理 null）
String s2 = String.valueOf(n);   // "100"

// 方式 3：包装类.toString()
String s3 = Integer.toString(n); // "100"
String s4 = Integer.valueOf(n).toString(); // "100"
```

> 💡 `n + ""` 的底层是 `new StringBuilder().append(n).append("")`，会创建临时对象；`String.valueOf(n)` 直接调用 `Integer.toString(n)`，更高效。但绝大多数场景这点性能差异可忽略，可读性更重要。

**null 安全对比**：

```java
Integer num = null;

// ❌ 方式 1：+ "" 不会 NPE，但结果是 "null" 字符串，容易掩盖 bug
String s1 = num + "";              // "null"

// ❌ 方式 3：包装类.toString() 直接 NPE
// String s2 = num.toString();    // NullPointerException

// ✅ 方式 2：String.valueOf(null) 返回 "null" 字符串，不抛异常
String s3 = String.valueOf(num);  // "null"
```

### 4.2 String → 基本类型

用包装类的静态方法 `parseXxx(String)`：

```java
String s = "123";

int i = Integer.parseInt(s);        // ✅ 123
long l = Long.parseLong("9999999999"); // 9999999999
double d = Double.parseDouble("3.14"); // 3.14
boolean b = Boolean.parseBoolean("true"); // true

// Character 没有 parseChar，用 charAt 或 valueOf
char c = "A".charAt(0);             // 'A'
```

> ⚠️ **解析失败抛 NumberFormatException**：字符串不是合法数字格式时直接崩溃，这是开发中极高频的异常：

```java
int a = Integer.parseInt("abc");    // ❌ NumberFormatException
int b = Integer.parseInt("12.5");   // ❌ NumberFormatException（小数不是 int）
int c = Integer.parseInt("");       // ❌ NumberFormatException（空串）
int d = Integer.parseInt("12345678901234567890"); // ❌ 超出 int 范围

// ✅ 安全解析：try-catch
String input = "abc";
try {
    int n = Integer.parseInt(input);
    System.out.println("解析成功：" + n);
} catch (NumberFormatException e) {
    System.out.println("不是合法整数：" + input);
}
```

> 📌 **开发规范**：凡是接收外部输入（前端参数、配置文件、数据库）转数字，**必须 try-catch** `NumberFormatException`，否则一行脏数据就能让整个请求崩溃。

### 4.3 进制转换

`parseInt` / `toString` 支持进制：

```java
// 字符串按指定进制解析
int dec = Integer.parseInt("10");       // 10，十进制
int bin = Integer.parseInt("1010", 2);  // 10，二进制
int oct = Integer.parseInt("12", 8);    // 10，八进制
int hex = Integer.parseInt("A", 16);     // 10，十六进制

// 十进制转其他进制字符串
System.out.println(Integer.toString(255, 16));  // "ff"
System.out.println(Integer.toHexString(255));  // "ff"，快捷方法
System.out.println(Integer.toBinaryString(10)); // "1010"
System.out.println(Integer.toOctalString(10));  // "12"
```

## 五、包装类的常用方法

### 5.1 常量：MAX_VALUE / MIN_VALUE

每个数值包装类都有最大/最小值常量：

```java
System.out.println(Integer.MAX_VALUE);   // 2147483647（2^31 - 1）
System.out.println(Integer.MIN_VALUE);   // -2147483648（-2^31）
System.out.println(Long.MAX_VALUE);      // 9223372036854775807（2^63 - 1）
System.out.println(Double.MAX_VALUE);    // 1.7976931348623157E308
System.out.println(Double.MIN_VALUE);    // 4.9E-324（最小正数，不是负数！）

System.out.println(Character.MIN_VALUE); // ' '
System.out.println(Character.MAX_VALUE); // '￿'

System.out.println(Boolean.TRUE);        // true
System.out.println(Boolean.FALSE);       // false
```

> ⚠️ **`Double.MIN_VALUE` 的坑**：它是最小**正**值（4.9E-324），不是负的最大值。浮点数没有真正的"最小负值"常量，要用 `-Double.MAX_VALUE` 表示。

### 5.2 compare 比较方法

包装类提供静态 `compare` 方法，返回 -1/0/1，避免拆箱：

```java
int r1 = Integer.compare(10, 20);    // -1，10 < 20
int r2 = Integer.compare(20, 20);    // 0
int r3 = Integer.compare(30, 20);    // 1

// 实例方法 compareTo
Integer a = 10;
Integer b = 20;
System.out.println(a.compareTo(b));  // -1

// Boolean 的 compare
int r4 = Boolean.compare(true, false);  // 1
int r5 = Boolean.compare(false, true);  // -1
```

> 💡 `compare` 内部直接比较基本值，不触发拆箱，比 `a - b` 更安全（不会溢出），也比 `a > b ? 1 : ...` 更简洁。常用于 `Comparator` 排序。

### 5.3 toUnsignedString 无符号转换

Java 8 起包装类支持无符号运算：

```java
// 负数按无符号解析
System.out.println(Integer.parseUnsignedInt("4294967295")); // -1（按有符号输出）
System.out.println(Integer.toUnsignedString(-1));  // "4294967295"

// 无符号除法
System.out.println(Integer.divideUnsigned(-1, 2));  // 2147483647
System.out.println(Integer.remainderUnsigned(-1, 3)); // 0
```

### 5.4 位运算工具方法

```java
System.out.println(Integer.bitCount(15));    // 4，二进制 1111 有 4 个 1
System.out.println(Integer.highestOneBit(15)); // 8，最高位的 1
System.out.println(Integer.lowestOneBit(10));  // 2，最低位的 1
System.out.println(Integer.numberOfLeadingZeros(1));  // 31，前导 0 个数
System.out.println(Integer.reverse(1));       // 位反转
System.out.println(Integer.signum(-5));       // -1，符号函数
```

### 5.5 Character 的常用方法

```java
System.out.println(Character.isDigit('5'));    // true，是否数字
System.out.println(Character.isLetter('A'));    // true，是否字母
System.out.println(Character.isUpperCase('A')); // true，是否大写
System.out.println(Character.isLowerCase('a')); // true，是否小写
System.out.println(Character.isWhitespace(' ')); // true，是否空白
System.out.println(Character.toUpperCase('a')); // 'A'
System.out.println(Character.toLowerCase('A'));  // 'a'
System.out.println(Character.getNumericValue('A')); // 10
```

## 六、包装类的使用场景

### 6.1 集合元素

集合只能存对象，基本类型靠自动装箱进入集合：

```java
List<Integer> list = new ArrayList<>();
list.add(1);    // 自动装箱
list.add(2);
list.add(3);

int sum = 0;
for (Integer n : list) {
    sum += n;   // 自动拆箱
}
System.out.println(sum);  // 6
```

### 6.2 泛型与 Map

```java
// Map 的 key/value 是包装类
Map<String, Integer> scoreMap = new HashMap<>();
scoreMap.put("张三", 90);
scoreMap.put("李四", 85);

Integer score = scoreMap.get("张三");  // 90
Integer miss = scoreMap.get("王五");   // null，不存在
```

### 6.3 数据库实体可空字段

```java
// 实体类用包装类，区分"未填写"和"0"
public class Order {
    private Long id;              // 主键，未生成时为 null
    private Integer quantity;     // 数量，未填为 null，填了 0 表示明确买 0 个
    private BigDecimal amount;   // 金额
    private Boolean paid;         // 是否支付，null=未知，true=已付，false=未付

    // getter/setter 省略
}
```

### 6.4 方法返回值表达"无结果"

```java
// 用 Integer 返回值表达"找不到"
public Integer findUserId(String name) {
    // 查不到返回 null，而不是 -1（-1 可能是合法 ID）
    if ("张三".equals(name)) {
        return 1;
    }
    return null;   // 调用方必须判空
}

// 用 Optional 更优雅（Java 8+）
public Optional<Integer> findUserIdOpt(String name) {
    if ("张三".equals(name)) {
        return Optional.of(1);
    }
    return Optional.empty();
}
```

## ⚠️ 重点

### 重点 1：Integer 缓存池导致 == 比较失效 ⭐⭐⭐

这是包装类**最经典**的面试题和开发陷阱：

```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b);   // true ✅（命中缓存，同一对象）

Integer c = 128;
Integer d = 128;
System.out.println(c == d);   // false ❌（超出缓存，不同对象）
```

> ⚠️ **铁律**：包装类**永远用 `equals` 比较**，绝不用 `==`。`==` 比较的是对象地址，受缓存范围影响，结果时真时假，是埋雷。`equals` 比较的是值，稳定可靠。

```java
Integer x = 200;
Integer y = 200;
// ❌ 错误
if (x == y) { ... }       // false，看似相等实际不等
// ✅ 正确
if (x.equals(y)) { ... } // true
// ✅ 也可以先拆箱
if (x.intValue() == y.intValue()) { ... }
```

> 📌 **开发规范**：IDE 中可配置将 `Integer == Integer` 标红警告。生产代码里只要看到包装类用 `==`，一律视为可疑代码。

### 重点 2：自动拆箱的 NPE ⭐⭐⭐

包装类为 `null` 时自动拆箱，直接 NPE：

```java
Integer a = null;
int b = a;   // ❌ NullPointerException，等价于 a.intValue()

// 高发场景：从 Map/数据库取值后直接运算
Map<String, Integer> map = new HashMap<>();
int count = map.get("count");   // ❌ 若 key 不存在，get 返回 null，拆箱 NPE

// ✅ 安全写法
Integer countObj = map.get("count");
int count = (countObj != null) ? countObj : 0;
// 或用 getOrDefault（Java 8+）
int count2 = map.getOrDefault("count", 0);
```

> ⚠️ **三步排查法**：凡是看到 `NullPointerException` 且堆栈指向一行看似正常的赋值/运算，先怀疑是不是包装类自动拆箱——某个包装类变量为 `null` 了。

### 重点 3：循环中频繁装箱的性能陷阱 ⭐⭐

```java
// ❌ 错误：循环中反复装箱，产生大量临时对象
Long sum = 0L;   // 用了包装类 Long
for (int i = 0; i < 10000000; i++) {
    sum += i;    // 每次都自动拆箱→相加→再装箱，约 1000 万次 new Long
}
// 结果：慢得离谱，GC 压力大

// ✅ 正确：循环累加用基本类型
long sum2 = 0L;
for (int i = 0; i < 10000000; i++) {
    sum2 += i;   // 纯基本类型运算，无装箱
}
```

> ⚠️ **Effective Java 第 6 条**：循环和性能敏感代码中**优先用基本类型**。包装类适合"存"（集合、字段），不适合"算"（累加、密集运算）。把 `Long sum` 写成 `long sum` 是新手最常犯的性能错误。

### 重点 4：new Integer 已废弃 ⭐

```java
// ❌ Java 9 起标记 @Deprecated
Integer a = new Integer(10);   // 永远新建对象，不进缓存

// ✅ 用 valueOf 或自动装箱
Integer b = Integer.valueOf(10);  // 命中缓存
Integer c = 10;                   // 等价于 valueOf
```

> 📌 **规范**：Java 8 环境下 `new Integer()` 虽然没废弃标记，但也不推荐。统一用 `valueOf` 或自动装箱。

### 重点 5：parseXxx 必须处理 NumberFormatException ⭐⭐

```java
// ❌ 危险：外部输入直接解析
String input = request.getParameter("age");
int age = Integer.parseInt(input);   // 一行脏数据就崩

// ✅ 安全：try-catch + 默认值
int age;
try {
    age = Integer.parseInt(input);
} catch (NumberFormatException e) {
    age = 0;   // 或返回错误提示
}
```

### 重点 6：包装类不可变 ⭐

包装类都是**不可变**的（`final` 类，字段 `final`），运算返回新对象：

```java
Integer a = 10;
Integer b = a;     // a 和 b 指向同一对象
a = a + 5;         // 不是修改原对象，而是 a 指向了新的 Integer(15)
System.out.println(b);   // 10，b 不受影响
System.out.println(a);   // 15
```

> 💡 这和 `String` 的不可变性一致：包装类对象一旦创建，值不可改。所有"修改"操作都是创建新对象。所以包装类作为方法参数时，方法内对它"修改"不影响外部。

### 案例 1：Integer 缓存池面试题 ⭐⭐⭐

经典面试题，理解缓存池的试金石：

```java
public class CacheQuiz {
    public static void main(String[] args) {
        Integer a = 127;
        Integer b = 127;
        Integer c = 128;
        Integer d = 128;
        Integer e = new Integer(127);
        Integer f = Integer.valueOf(127);

        System.out.println(a == b);   // true，缓存池，同一对象
        System.out.println(c == d);   // false，超出缓存，不同对象
        System.out.println(a == e);   // false，new 永远新建对象，不进缓存
        System.out.println(a == f);   // true，都是 valueOf，命中缓存
        System.out.println(a.equals(b)); // true，equals 比值

        // 拆箱后比较
        int g = 127;
        System.out.println(a == g);   // true，a 自动拆箱成 int，再和 int 比
    }
}
```

> 💡 **面试要点**：
> - `==` 对包装类比较的是**对象地址**
> - 自动装箱用 `valueOf`，命中缓存（-128~127）返回同一对象
> - `new Integer()` 永远新建对象，绕过缓存
> - 包装类与基本类型用 `==` 比较时，会先**拆箱**再比基本值，结果恒正确

### 案例 2：数据库实体用包装类区分 null ⭐⭐

电商订单实体，区分"未填写"和"明确为 0"：

```java
public class Order {
    private Long id;              // 主键，未生成时为 null
    private Integer quantity;     // 数量，null=未填写，0=明确买 0 件
    private BigDecimal amount;   // 金额
    private Boolean paid;         // null=未知，true=已付，false=未付
    private Integer discountRate; // 折扣，null=无折扣，100=不打折

    // 模拟从数据库读取
    public static Order fromDb(Long id, Integer qty, Boolean paid) {
        Order o = new Order();
        o.id = id;
        o.quantity = qty;
        o.paid = paid;
        return o;
    }

    public static void main(String[] args) {
        // 数据库字段为 NULL 的场景
        Order o1 = fromDb(1L, null, null);
        if (o1.quantity == null) {
            System.out.println("数量未填写，需补全");   // 走这里
        }

        // 明确为 0 的场景
        Order o2 = fromDb(2L, 0, false);
        if (o2.quantity != null && o2.quantity == 0) {
            System.out.println("用户明确买了 0 件");   // 走这里
        }

        // ❌ 若实体用 int，无法区分
        // int quantity = 0;  // 既可能是"未填"也可能是"买 0 件"，歧义
    }
}
```

> 📌 **阿里规约**：所有 POJO（实体/DTO/VO）的数值字段必须用包装类，禁止用基本类型。原因就是区分数据库 `NULL` 和默认值 `0`。

### 案例 3：字符串转数字的解析校验 ⭐⭐

后台接口接收前端参数，必须做健壮的解析：

```java
public class NumberParser {

    // 安全解析 int，失败返回默认值
    public static int safeParseInt(String s, int defaultValue) {
        if (s == null || s.trim().isEmpty()) {
            return defaultValue;
        }
        try {
            return Integer.parseInt(s.trim());
        } catch (NumberFormatException e) {
            return defaultValue;
        }
    }

    // 安全解析 Long
    public static Long safeParseLong(String s) {
        if (s == null || s.trim().isEmpty()) {
            return null;   // 返回 null 表示解析失败
        }
        try {
            return Long.parseLong(s.trim());
        } catch (NumberFormatException e) {
            return null;
        }
    }

    public static void main(String[] args) {
        // 模拟前端传参
        String ageStr = " 25 ";
        String scoreStr = "abc";
        String emptyStr = "";

        System.out.println(safeParseInt(ageStr, 0));     // 25
        System.out.println(safeParseInt(scoreStr, 0));  // 0，非法返回默认
        System.out.println(safeParseInt(emptyStr, 0));   // 0，空串返回默认

        Long id = safeParseLong("99999999999");
        System.out.println(id);   // 99999999999
        System.out.println(safeParseLong("xyz"));  // null
    }
}
```

### 案例 4：金额用 Long 存分 ⭐⭐

支付系统常用做法——用 `Long` 存"分"避免浮点精度：

```java
public class AmountInCents {
    // 金额一律用 Long 存"分"，1 元 = 100 分
    // 好处：整数运算无精度问题，比 BigDecimal 轻量
    // 注意：超过 Long.MAX_VALUE（约 9.2 * 10^18 分 = 9.2 * 10^16 元）才溢出

    public static void main(String[] args) {
        Long priceCents = 19900L;   // 199.00 元
        Integer quantity = 3;

        // 总金额（分）
        long totalCents = priceCents * quantity;   // 59700
        System.out.println("总价：" + totalCents + " 分 = "
                         + totalCents / 100.0 + " 元");  // 597.0 元

        // 优惠：满 50000 分减 5000 分
        long discount = totalCents >= 50000 ? 5000 : 0;
        long payCents = totalCents - discount;
        System.out.println("实付：" + payCents + " 分 = "
                         + payCents / 100.0 + " 元");  // 547.0 元

        // ⚠️ 注意：priceCents 是 Long，quantity 是 Integer
        // 运算时都会拆箱成 long/int，结果提升为 long，无 NPE 风险（非 null 时）
    }
}
```

> 💡 **金额存储方案对比**：
> - `double` 存元：❌ 浮点精度问题
> - `Long` 存分：✅ 整数无精度问题，适合支付、对账
> - `BigDecimal` 存元：✅ 精确且语义清晰，适合复杂计算（利率、分期）
> - 实际项目里，支付金额常用 `Long` 分，财务计算用 `BigDecimal`，详见 [20-数学运算](20-数学运算：Math与BigDecimal.md)

### 案例 5：集合统计与自动装箱 ⭐

```java
import java.util.*;

public class ScoreStatistics {
    public static void main(String[] args) {
        // 学生成绩，用 List<Integer> 存储
        List<Integer> scores = Arrays.asList(85, 92, 78, 96, 88, 73, 91);

        // ❌ 性能差的写法：用 Integer 累加
        Integer badSum = 0;
        for (Integer s : scores) {
            badSum += s;   // 每次拆箱→相加→装箱
        }

        // ✅ 性能好的写法：拆箱成 int 累加
        int sum = 0;
        int max = Integer.MIN_VALUE;
        int min = Integer.MAX_VALUE;
        for (Integer s : scores) {
            int v = s;   // 一次性拆箱
            sum += v;
            if (v > max) max = v;
            if (v < min) min = v;
        }

        double avg = (double) sum / scores.size();
        System.out.println("总分：" + sum);    // 603
        System.out.println("最高：" + max);    // 96
        System.out.println("最低：" + min);    // 73
        System.out.println("平均：" + avg);    // 86.14...
    }
}
```

### 案例 6：Boolean 包装类的坑

```java
public class BooleanTrap {
    public static void main(String[] args) {
        // Boolean 缓存了 TRUE 和 FALSE 两个对象
        Boolean a = Boolean.valueOf(true);
        Boolean b = Boolean.valueOf(true);
        System.out.println(a == b);   // true，命中缓存

        // new Boolean 永远新建对象
        Boolean c = new Boolean(true);
        System.out.println(a == c);   // false
        System.out.println(a.equals(c)); // true

        // 自动拆箱 NPE
        Boolean flag = null;
        // if (flag) { }   // ❌ NPE，等价于 flag.booleanValue()
        if (Boolean.TRUE.equals(flag)) {   // ✅ 安全
            System.out.println("flag 为 true");
        }
    }
}
```

### 案例 7：包装类作为方法参数的不可变性

```java
public class ImmutableDemo {
    // 看似修改参数，实则无效
    public static void addOne(Integer n) {
        n = n + 1;   // n 指向了新对象，不影响外部
    }

    public static void main(String[] args) {
        Integer x = 10;
        addOne(x);
        System.out.println(x);   // 10，没变！
        // 原因：Integer 不可变，n = n + 1 是让局部变量 n 指向新对象
    }
}
```

> ⚠️ **新手常踩的坑**：以为方法内"修改"包装类参数会影响外部。实际上包装类不可变，所有"修改"都是新建对象，局部变量指向新对象，外部引用不变。要返回结果必须用返回值。

### 案例 8：Character 处理字符串字符

```java
public class CharProcessor {

    }
```

### 案例 9：Map 计数器与 getOrDefault

```java
import java.util.*;

public class WordCounter {
    public static void main(String[] args) {
        String[] words = {"java", "python", "java", "go", "python", "java"};

        // ❌ 老写法：手动判空，容易 NPE
        Map<String, Integer> counter1 = new HashMap<>();
        for (String w : words) {
            Integer cnt = counter1.get(w);
            if (cnt == null) {
                counter1.put(w, 1);
            } else {
                counter1.put(w, cnt + 1);
            }
        }

        // ✅ Java 8+ 写法：getOrDefault 避免 NPE
        Map<String, Integer> counter2 = new HashMap<>();
        for (String w : words) {
            counter2.put(w, counter2.getOrDefault(w, 0) + 1);
        }

        // ✅ 更简洁：merge
        Map<String, Integer> counter3 = new HashMap<>();
        for (String w : words) {
            counter3.merge(w, 1, Integer::sum);
        }

        System.out.println(counter3);  // {python=2, java=3, go=1}
    }
}
```

> 💡 这是包装类 + 集合的经典组合：`Map<K, Integer>` 做计数器。关键是避免 `get` 返回 `null` 后直接拆箱 NPE，用 `getOrDefault` 或 `merge` 更安全。

```java
import java.util.*;

public class ConfigParser {
    public static void main(String[] args) {
        // 模拟从 properties 文件读取配置
        Properties props = new Properties();
        props.setProperty("port", "8080");
        props.setProperty("timeout", "30000");
```

## 🚀 新版本补充

### Java 9：包装类构造方法废弃

Java 9 起，所有包装类的 `new Xxx()` 构造方法都被标记 `@Deprecated`：

```java
// Java 9+ 标记废弃
@Deprecated(since = "9")
public Integer(int value) { ... }

// 推荐用 valueOf
Integer a = Integer.valueOf(10);
```

> 💡 这是为了鼓励使用缓存。`new Integer(10)` 永远新建对象，`valueOf(10)` 命中缓存。Java 8 环境下虽无废弃标记，但也应避免 `new`。

### Java 8：Optional 与包装类

Java 8 引入 `Optional`，比包装类更优雅地表达"可能为空"：

```java
import java.util.Optional;

// 用 Optional 替代"返回 null 表示找不到"
public Optional<Integer> findUserId(String name) {
    if ("张三".equals(name)) {
        return Optional.of(1);
    }
    return Optional.empty();
}

// 调用方强制处理空的情况
Integer id = findUserId("李四").orElse(-1);   // 找不到返回 -1
```

> 💡 `Optional` 是包装类的"升级版"：包装类用 `null` 表示空，调用方容易忘记判空导致 NPE；`Optional` 用类型系统强制调用方处理空的情况。详见 [46-函数式编程](46-函数式编程.md)。

### Java 8：无符号运算 API

Java 8 给 `Integer`/`Long` 增加了无符号运算方法：

```java
// 把 int 当无符号 long 处理
int signed = -1;   // 二进制全 1
long unsigned = Integer.toUnsignedLong(signed);
System.out.println(unsigned);   // 4294967295

// 无符号除法
System.out.println(Integer.divideUnsigned(-1, 2));   // 2147483647
```

| 知识点 | 要点 |
| :--- | :--- |
| 8 个包装类 | Byte/Short/Integer/Long/Float/Double/Character/Boolean |

| 使用场景 | 集合元素、泛型、数据库可空字段、方法返回值 |

## 学习建议

1. **把 Integer 缓存池的面试题敲一遍**：亲手验证 `127==127` 为 true、`128==128` 为 false，看到这个"诡异"结果，比看十遍文字都管用。理解后形成肌肉记忆：包装类永远用 `equals`。
2. **养成判空习惯**：凡是 `Map.get()`、数据库取值、外部输入返回的包装类，用之前先想"它可能是 null 吗"。自动拆箱的 NPE 是开发中最高频的崩溃，判空能挡掉一半。
3. **区分"存"和"算"**：包装类适合存（集合、字段、参数），基本类型适合算（循环、密集运算）。看到循环里 `Long sum = 0L` 立刻警觉，改成 `long sum = 0L`。
4. **数据库实体一律用包装类**：这是行业规范（阿里规约明确要求）。用 `Integer` 而非 `int`，用 `Boolean` 而非 `boolean`，才能正确表达数据库的 `NULL`。养成习惯后再也不纠结字段类型。
5. **解析外部输入必加 try-catch**：`Integer.parseInt` 一行脏数据就崩，所有接收前端/配置/数据库字符串转数字的地方，都要包 `try-catch NumberFormatException`，给个默认值或返回错误提示，别让整个请求挂掉。
