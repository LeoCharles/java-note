# 权限修饰符与包

Java 通过**权限修饰符**控制类、方法、变量的可见范围，通过**包（package）**组织类的命名空间。两者配合实现「封装」——把该藏的藏起来、该暴露的暴露出去。理解权限范围是写出可维护、低耦合代码的基础：访问控制做不好，内部实现被人乱用，重构时处处是地雷。

> 💡 在阅读本篇前，建议先回顾 [10-面向对象基础](10-面向对象基础.md) 中「封装」的概念，权限修饰符正是封装的具体手段。

---

## 一、四种权限修饰符

Java 有四种权限修饰符，按可见范围从小到大依次是：`private` → `default`（默认/包级）→ `protected` → `public`。

> ⚠️ `default` 不是关键字！它表示**不写任何修饰符**时的默认权限，也叫「包级私有」（package-private）。Java 8 中没有 `default` 关键字用于访问控制（它只在接口的默认方法中是关键字，含义完全不同）。

### 1.1 权限范围总表

| 修饰符 | 同一个类 | 同一个包 | 不同包子类 | 不同包非子类 |
| :--- | :---: | :---: | :---: | :---: |
| `private` | ✅ | ❌ | ❌ | ❌ |
| `default`（默认） | ✅ | ✅ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| `public` | ✅ | ✅ | ✅ | ✅ |

> 💡 **记忆口诀**：private 只对自己，default 加上同包，protected 再加不同包子类，public 全放开。权限是**层层累加**的。

### 1.2 private：只在本类可见

`private` 修饰的成员只能在本类内部访问，是最严格的封装。

```java
public class User {
    private String name;        // 私有字段，外部不可见
    private int age;

    // 提供 public 的 getter/setter 控制访问
    public String getName() {
        return name;
    }
    public void setName(String name) {
        if (name == null || name.isEmpty()) {
            throw new IllegalArgumentException("姓名不能为空");  // ✅ 在 setter 里校验
        }
        this.name = name;
    }
}

// 测试
class TestPrivate {
    public static void main(String[] args) {
        User u = new User();
        // u.name = "张三";   // ❌ 编译错误：name 是 private
        u.setName("张三");     // ✅ 通过 public 方法访问
        System.out.println(u.getName());
    }
}
```

> 📌 **封装规范**：字段一律 `private`，通过 `getter/setter` 暴露访问，在 setter 中做参数校验。这是 JavaBean 的核心约定。

### 1.3 default：包级可见（默认权限）

不写修饰符就是默认权限，**同包内可访问，跨包不可见**。

```java
// 文件：com/example/model/User.java
package com.example.model;

public class User {
    String id;          // 默认权限：同包可访问
    String name;
}
```

```java
// 文件：com/example/model/UserService.java（同包）
package com.example.model;

public class UserService {
    public void test() {
        User u = new User();
        u.name = "张三";   // ✅ 同包，可访问默认权限成员
    }
}
```

```java
// 文件：com/example/controller/UserController.java（不同包）
package com.example.controller;

import com.example.model.User;

public class UserController {
    public void test() {
        User u = new User();
        // u.name = "张三";   // ❌ 不同包，默认权限不可见
    }
}
```

> 💡 默认权限常用于「包内工具方法」——只想给同包的类用，不对外暴露。比如 DAO 层的辅助方法。

### 1.4 protected：同包 + 不同包子类

`protected` 比 default 多了一项：**不同包的子类**也能访问（但只能通过子类自己的引用访问，不能通过父类引用）。

```java
// 文件：com/example/base/AbstractService.java
package com.example.base;

public abstract class AbstractService {
    protected void beforeProcess() {       // 受保护方法
        System.out.println("前置处理：记录日志");
    }
    protected void afterProcess() {
        System.out.println("后置处理：清理资源");
    }
}
```

```java
// 文件：com/example/order/OrderService.java（不同包，但是子类）
package com.example.order;

import com.example.base.AbstractService;

public class OrderService extends AbstractService {
    public void createOrder() {
        beforeProcess();    // ✅ 子类可访问父类的 protected 方法
        afterProcess();     // ✅
        System.out.println("创建订单");
    }
}
```

> ⚠️ **protected 的隐藏限制**：不同包子类访问 protected 成员时，只能通过**子类自己的引用**（或子类内部直接调用），不能用父类引用去访问。详见「重点」一节。

### 1.5 public：全部可见

`public` 修饰的成员在任何地方都可访问，是最开放的权限。

```java
public class StringUtils {
    public static boolean isEmpty(String s) {   // 公开静态方法
        return s == null || s.length() == 0;
    }
}

// 任意包都能调用
StringUtils.isEmpty("");   // ✅
```

> 📌 **暴露原则**：public 是 API 的契约，一旦发布就很难改。能用更小的权限就用更小的，**默认先用 private，确需暴露再升级权限**。

## 二、包的概念

### 2.1 什么是包

包是 Java 组织类的**命名空间**，类似于文件夹。作用有三：

1. **避免类名冲突**：两个 `User` 类可以分别放在 `com.example.model` 和 `com.example.dto` 中
2. **分类管理**：按功能、按层级组织类
3. **配合权限控制**：默认权限就是以包为边界

### 2.2 package 声明

`package` 语句必须是源文件的**第一条语句**（除注释外），一个文件只能有一个 package 声明。

```java
// 文件：com/example/model/User.java
package com.example.model;   // 声明包名，必须放在第一行

public class User {
    // ...
}
```

> ⚠️ **包名必须与文件夹结构一致**。`com.example.model.User` 类对应的物理路径是 `com/example/model/User.java`。不一致时编译能过，运行时找不到类。

### 2.3 域名倒写命名法

包名惯例是**互联网域名倒写**，保证全局唯一：

| 域名 | 包名前缀 |
| :--- | :--- |
| `apache.org` | `org.apache.xxx` |
| `google.com` | `com.google.xxx` |
| `alibaba.com` | `com.alibaba.xxx` |

> 💡 倒写域名是因为域名天然全局唯一，避免不同公司/组织的包名冲突。个人项目可用 `com.用户名.项目名`。

### 2.4 包名规范

- 全部**小写**，不用大写字母（避免与类名混淆）
- 用 `.` 分隔层级
- 不用 Java 关键字（如 `int`、`class`）

```java
package com.example.model;       // ✅ 全小写，域名倒写
package Com.Example.Model;       // ❌ 大写不规范
package com.example.int;         // ❌ int 是关键字
package com.example.user-service; // ❌ 不能用连字符
```

## 三、import 导入

### 3.1 导入单个类

```java
import java.util.List;        // 导入单个类
import java.util.ArrayList;

public class Demo {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();   // ✅ 直接用类名
    }
}
```

### 3.2 导入整个包

```java
import java.util.*;           // 导入 java.util 下所有类

public class Demo {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        Map<String, String> map = new HashMap<>();
        Set<String> set = new HashSet<>();
    }
}
```

> ⚠️ `import java.util.*` **不会递归**导入子包！`java.util.*` 只导入 `java.util` 包下的类，不会导入 `java.util.concurrent` 下的类。要导入子包必须单独写：`import java.util.concurrent.*`。

### 3.3 同名类冲突

当两个包有同名类时（如 `java.util.Date` 和 `java.sql.Date`），只能导入一个，另一个用**全限定名**（fully qualified name）：

```java
import java.util.Date;        // 导入 util 的 Date

public class Demo {
    public static void main(String[] args) {
        Date utilDate = new Date();                    // ✅ 用导入的 util.Date
        java.sql.Date sqlDate = new java.sql.Date(0); // ✅ 全限定名访问 sql.Date
    }
}
```

> 💡 全限定名 = `包名.类名`。冲突时对其中一个用全限定名，是开发中常见的处理方式。

### 3.4 静态导入

`import static` 可以直接导入类的**静态成员**（静态字段、静态方法），使用时不用加类名前缀：

```java
import static java.lang.Math.PI;        // 导入静态常量
import static java.lang.Math.*;        // 导入所有静态成员

public class Demo {
    public static void main(String[] args) {
        double r = 5.0;
        double area = PI * r * r;       // ✅ 直接用 PI，不用 Math.PI
        double v = sqrt(2);             // ✅ 直接用 sqrt，不用 Math.sqrt
    }
}
```

> ⚠️ **慎用静态导入**：过度使用会让代码看不出方法来自哪个类，降低可读性。推荐只在数学计算（`Math`）、断言（`Assert`）等场景少量使用。

## 四、常见包速览

JDK 自带的核心包：

| 包名 | 作用 | 是否自动导入 |
| :--- | :--- | :---: |
| `java.lang` | 语言核心：String、System、Math、Object、Thread | ✅ 自动 |
| `java.util` | 集合、日期、随机数、扫描器等工具 | ❌ |
| `java.io` | 输入输出流、文件操作 | ❌ |
| `java.net` | 网络编程：Socket、URL、ServerSocket | ❌ |
| `java.math` | 高精度数学：BigDecimal、BigInteger | ❌ |
| `java.sql` | JDBC 数据库访问 | ❌ |
| `java.text` | 文本格式化：DateFormat、MessageFormat | ❌ |
| `java.time` | Java 8 新日期时间 API | ❌ |

> 💡 **只有 `java.lang` 自动导入**，其他包都要手动 `import`。这也是为什么 `String`、`System` 不用导入就能直接用。

## 五、修饰符综合运用

### 5.1 类的修饰符

**外部类**只能用 `public` 或 `default` 两种权限，不能用 `private`/`protected`：

```java
public class PublicClass { }     // ✅ 任意包可访问
class DefaultClass { }          // ✅ 仅同包可访问（默认权限）
// private class Bad { }        // ❌ 外部类不能用 private
// protected class Bad2 { }     // ❌ 外部类不能用 protected
```

> 💡 **内部类**（嵌套在别的类里的类）四种权限都能用，因为它是成员级别。外部类不行。

### 5.2 成员的修饰符

类的成员（字段、方法）可用四种权限修饰符，还可叠加 `static`、`final`：

```java
public class UserService {
    private static final int MAX_RETRY = 3;     // 私有静态常量
    protected static Logger logger;             // 受保护静态字段
    public static final String VERSION = "1.0"; // 公开静态常量

    private String secret;                      // 私有实例字段
    public void execute() { }                   // 公开实例方法
    static void helper() { }                    // 包级静态方法（默认权限）
}
```

### 5.3 修饰符组合速查

| 位置 | 可用权限修饰符 | 常见叠加修饰符 |
| :--- | :--- | :--- |
| 外部类 | `public` / `default` | `final`、`abstract` |
| 内部类 | 四种均可 | `static`、`final`、`abstract` |
| 字段 | 四种均可 | `static`、`final` |
| 方法 | 四种均可 | `static`、`final`、`abstract`、`synchronized` |
| 构造方法 | 四种均可 | — |

> 📌 **最佳实践**：字段尽量 `private`，方法按需选择，工具方法放 `public static`，常量用 `public static final`。

## ⚠️ 重点

### 重点 1：protected 跨包访问的隐藏限制 ⭐⭐

这是最容易踩坑的点：不同包子类访问 protected 成员，**只能通过子类自己的类型引用**，不能用父类引用。

```java
// 包 A：父类
package com.example.a;
public class Parent {
    protected void hello() {
        System.out.println("Parent hello");
    }
}
```

```java
// 包 B：子类
package com.example.b;
import com.example.a.Parent;

public class Child extends Parent {
    public void test() {
        // ✅ 直接调用（子类内部）
        hello();

        // ✅ 通过子类自己的引用
        Child c = new Child();
        c.hello();

        // ❌ 不能通过父类引用访问！
        Parent p = new Parent();
        // p.hello();   // 编译错误：hello() 有 protected 访问限制
    }
}
```

> ⚠️ 原因：protected 的跨包权限是给「子类继承」用的，不是给「拿到父类实例随便调」用的。否则 protected 就退化成 public 了。

### 重点 2：默认权限不是关键字 ⭐

```java
public class Demo {
    String name;          // ✅ 默认权限（什么修饰符都不写）
    // default String name2;  // ❌ 编译错误：default 不是访问修饰符关键字
}
```

> 💡 Java 8 中 `default` 关键字只用于**接口的默认方法**（`default void method() {}`），与访问控制无关，别混淆。

### 重点 3：import 不递归 ⭐

```java
import java.util.*;              // 只导入 java.util 下的类
// java.util.concurrent.* 不会自动导入，要单独写
import java.util.concurrent.*;  // ✅ 显式导入子包

public class Demo {
    List<String> list = new ArrayList<>();         // java.util.List
    ConcurrentHashMap<String, String> map;          // java.util.concurrent
}
```

### 重点 4：类的权限与文件名的关系 ⭐

一个 `.java` 文件中只能有**一个 public 类**，且文件名必须与 public 类名一致：

```java
// 文件名必须是 UserService.java
public class UserService { }   // ✅ public 类，文件名匹配

class Helper { }              // ✅ 默认权限，可以有多个，文件名不要求
```

> ⚠️ 如果文件里有 `public class UserService`，文件名就必须是 `UserService.java`，否则编译错误。非 public 类不受此限制。

### 重点 5：private 不能被外部访问，但反射可以 ⭐

```java
public class Secret {
    private String password = "123456";

    public static void main(String[] args) throws Exception {
        Secret s = new Secret();
        // s.password;  // ❌ 编译错误

        // 反射可以突破 private 限制（不推荐）
        java.lang.reflect.Field f = Secret.class.getDeclaredField("password");
        f.setAccessible(true);                          // ✅ 突破访问检查
        System.out.println(f.get(s));                  // 123456
    }
}
```

> 💡 private 是**编译期**检查，不是运行时安全机制。反射可绕过，但生产代码不要依赖反射破坏封装。框架（如 Spring）内部大量用反射注入私有字段，那是框架的事。

## 💻 实战案例

### 案例 1：电商项目包结构分层设计 ⭐⭐

真实电商项目的标准包分层，每层权限严格管控：

```
com.shop.ecommerce
├── controller          // 控制层：接收请求（public 类，对外暴露接口）
│   └── OrderController.java
├── service             // 业务层：核心业务逻辑
│   ├── OrderService.java          // public 接口
│   └── impl
│       └── OrderServiceImpl.java  // public 实现类
├── dao                 // 数据访问层：操作数据库
│   ├── OrderDao.java
│   └── impl
│       └── OrderDaoImpl.java
├── entity              // 实体类：对应数据库表
│   └── Order.java
├── dto                 // 数据传输对象：层间传递
│   └── OrderDTO.java
├── vo                  // 视图对象：返回给前端
│   └── OrderVO.java
├── utils               // 工具类
│   ├── DateUtils.java
│   └── StringUtils.java
├── constant            // 常量
│   └── OrderConstant.java
├── exception           // 自定义异常
│   └── BusinessException.java
└── config              // 配置类
    └── AppConfig.java
```

权限设计要点：

```java
// 实体类：字段全部 private，通过 getter/setter 暴露
package com.shop.ecommerce.entity;

public class Order {
    private Long id;
    private String orderNo;        // 订单号
    private Integer status;        // 订单状态

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    // ... 其他 getter/setter
}
```

```java
// Service 接口公开，实现类方法用 public；辅助方法用 private
package com.shop.ecommerce.service.impl;

import com.shop.ecommerce.service.OrderService;

public class OrderServiceImpl implements OrderService {
    @Override
    public void createOrder(Long userId, Long productId) {   // public（实现接口）
        validateOrder(userId, productId);                    // private 辅助方法
        // 下单逻辑
    }

    private void validateOrder(Long userId, Long productId) {  // ✅ 内部校验，不暴露
        if (userId == null) throw new IllegalArgumentException("用户ID为空");
    }
}
```

```java
// 工具类：构造方法私有 + 静态方法，防止实例化
package com.shop.ecommerce.utils;

public class OrderNoUtils {
    private OrderNoUtils() { }   // ✅ 私有构造，防止 new

    public static String generateOrderNo() {
        return "ORD" + System.currentTimeMillis();
    }
}
```

> 📌 **分层规范**：controller 只调 service，service 只调 dao，dao 只操作 entity。跨层调用是代码坏味道。每层只暴露必要的 public 方法，内部逻辑 private 封装。

### 案例 2：protected 在模板方法模式中的运用 ⭐⭐

模板方法模式是 protected 最经典的用武之地：父类定义流程骨架（public），子类重写具体步骤（protected）。

```java
// 基础导出服务（抽象类，放 base 包）
package com.shop.ecommerce.base;

public abstract class AbstractExportService<T> {
    // 模板方法：public，定义导出流程骨架，不允许子类修改流程
    public final void export(String fileName, java.util.List<T> data) {
        beforeExport(fileName);           // 前置钩子
        byte[] content = doExport(data);  // 核心导出逻辑（子类实现）
        afterExport(fileName, content);   // 后置钩子
    }

    // 抽象方法：子类必须实现
    protected abstract byte[] doExport(java.util.List<T> data);

    // 钩子方法：子类可选重写
    protected void beforeExport(String fileName) {
        System.out.println("开始导出：" + fileName);
    }
    protected void afterExport(String fileName, byte[] content) {
        System.out.println("导出完成：" + fileName + "，大小：" + content.length + " 字节");
    }
}
```

```java
// 订单导出（子类，放 order 包，跨包继承）
package com.shop.ecommerce.order;

import com.shop.ecommerce.base.AbstractExportService;
import com.shop.ecommerce.entity.Order;

public class OrderExportService extends AbstractExportService<Order> {
    @Override
    protected byte[] doExport(java.util.List<Order> orders) {   // ✅ 跨包子类重写 protected
        StringBuilder sb = new StringBuilder("订单号,金额,状态\n");
        for (Order o : orders) {
            sb.append(o.getOrderNo()).append(",")
              .append(o.getId()).append(",")
              .append(o.getStatus()).append("\n");
        }
        return sb.toString().getBytes();
    }
}
```

```java
// 调用方
public class Client {
    public static void main(String[] args) {
        OrderExportService service = new OrderExportService();
        service.export("orders.csv", new java.util.ArrayList<>());  // ✅ 只能调 public 的 export
        // service.doExport(...);   // ❌ protected，跨包非子类不可见
    }
}
```

> 💡 **设计精髓**：`export` 是 public（对外稳定），`doExport` 是 protected（只给子类扩展），`beforeExport`/`afterExport` 是 protected 钩子（子类可选重写）。这就是「开放扩展、关闭修改」。

### 案例 3：工具类封装到 utils 包 ⭐

把通用方法抽成工具类，权限设计体现封装思想：

```java
package com.shop.ecommerce.utils;

import java.util.Collection;

/**
 * 集合工具类
 */
public final class CollectionUtils {       // final：不可继承
    private CollectionUtils() { }          // 私有构造：不可实例化

    public static boolean isEmpty(Collection<?> coll) {
        return coll == null || coll.isEmpty();
    }

    public static boolean isNotEmpty(Collection<?> coll) {
        return !isEmpty(coll);
    }

    // 包级私有：只给同包的其他工具类用
    static void checkNotNull(Object obj, String msg) {
        if (obj == null) throw new IllegalArgumentException(msg);
    }
}
```

```java
package com.shop.ecommerce.utils;

public class StringUtils {
    public static boolean isEmpty(String s) {
        return s == null || s.trim().isEmpty();
    }

    public static String trimToEmpty(String s) {
        return s == null ? "" : s.trim();
    }

    // 同包内可调 CollectionUtils 的包级方法
    public static void validate(String s) {
        CollectionUtils.checkNotNull(s, "字符串不能为空");  // ✅ 同包，可访问默认权限方法
    }
}
```

```java
package com.shop.ecommerce.controller;   // 不同包

import com.shop.ecommerce.utils.CollectionUtils;

public class OrderController {
    public void list() {
        // CollectionUtils.checkNotNull(...);  // ❌ 不同包，默认权限不可见
        boolean empty = CollectionUtils.isEmpty(null);  // ✅ public 可见
    }
}
```

> 📌 **工具类三件套**：`final` 类（防继承）+ `private` 构造（防实例化）+ `public static` 方法。这是 Java 工具类的标准写法。

### 案例 4：不同包下访问 protected 的限制演示 ⭐

```java
// 包：com.shop.ecommerce.pay
package com.shop.ecommerce.pay;

public class PaymentTemplate {
    protected void beforePay() {
        System.out.println("支付前置：风控检查");
    }

    protected void doPay(String orderId) {
        System.out.println("执行支付：" + orderId);
    }

    public void pay(String orderId) {     // 模板方法，public
        beforePay();
        doPay(orderId);
    }
}
```

```java
// 包：com.shop.ecommerce.pay.impl（不同包）
package com.shop.ecommerce.pay.impl;

import com.shop.ecommerce.pay.PaymentTemplate;

public class AlipayService extends PaymentTemplate {
    @Override
    protected void doPay(String orderId) {     // ✅ 子类重写 protected 方法
        System.out.println("支付宝支付：" + orderId);
    }

    public void test() {
        PaymentTemplate t = new PaymentTemplate();
        // t.beforePay();   // ❌ 不能通过父类引用访问 protected（跨包）
        // t.doPay("1");   // ❌ 同理

        AlipayService self = new AlipayService();
        self.beforePay();   // ✅ 通过子类自己的引用
        self.doPay("1");    // ✅
    }
}
```

## 🚀 新版本补充

### Java 9：模块化系统（Module）

Java 9 引入 `module-info.java`，在包之上再加一层「模块」控制：

```java
// module-info.java
module com.shop.ecommerce {
    requires java.sql;              // 依赖其他模块
    exports com.shop.ecommerce.controller;   // 只导出 controller 包
    exports com.shop.ecommerce.service;
    // 不导出 utils 包 → 其他模块完全访问不到
}
```

> 💡 模块化让权限控制更精细：即使包是 public 的类，如果所在包没被 `exports`，其他模块也访问不到。Java 8 没有模块化，了解即可。

### Java 9+：`var` 与包导入

Java 9 引入的 `import` 仍不支持「导入整个包的静态成员递归」，但模块化配合 `exports` 提供了更强的封装。Java 8 环境下这些特性不可用。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 四种修饰符 | `private` → `default` → `protected` → `public`，范围递增 |
| private | 仅本类可见 |
| default（默认） | 同包可见，不写修饰符即是 |
| protected | 同包 + 不同包子类可见 |
| public | 全部可见 |
| 包 | 命名空间，域名倒写，全小写 |
| import | 单类导入 / `包.*`（不递归）/ 同名用全限定名 |
| 静态导入 | `import static`，慎用 |
| 类的修饰符 | 外部类仅 `public`/`default` |
| 工具类规范 | `final` 类 + `private` 构造 + `public static` 方法 |

## 学习建议

1. **背熟权限范围表**：四种修饰符的四列范围（同类/同包/不同包子类/不同包非子类）是面试必考、开发必用，建议画几遍表格直到能默写。
2. **动手验证 protected 跨包限制**：建两个包，写一个父类一个子类，尝试用父类引用调 protected 方法，亲眼看到编译错误，理解「子类继承访问」与「实例访问」的区别。
3. **按分层组织包结构**：参照案例 1 的电商分层，在自己的练习项目里按 controller/service/dao/entity/utils 组织包，养成工程化习惯，别把所有类扔一个包。
4. **工具类写法刻进肌肉**：`final` + `private` 构造 + `public static`，这三件套是 Java 工具类的标配，写十遍形成条件反射。
5. **权限从最小开始**：写代码时默认用 `private`，确有需要再升级到 `default`/`protected`/`public`。暴露越少，重构越安全——这是封装的精髓。
