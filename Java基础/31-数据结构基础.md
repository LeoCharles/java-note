# 数据结构基础

集合类的底层不是凭空设计的——`ArrayList` 背后是数组，`LinkedList` 背后是链表，`HashMap` 背后是哈希表 + 红黑树。理解数据结构，才能真正理解集合为什么这么快、这么慢、什么时候该用哪个。本篇从栈、队列、数组、链表、树、哈希表逐一讲起，并对应到 Java 集合的实现，为后续深入 `HashMap` 源码打下地基。

> 💡 在阅读本篇前，建议先看 [28-集合框架体系](28-集合框架体系.md)，对 Collection/Map 的整体分类有印象，再来对照「每种集合底层是哪种数据结构」会更有针对性。

---

## 一、数据结构与集合实现的对应关系

Java 集合类本质上是经典数据结构的工程封装：

| 数据结构 | Java 集合实现 | 典型特点 |
| :--- | :--- | :--- |
| 数组 | `ArrayList` | 查询快、增删慢 |
| 链表 | `LinkedList` | 增删快、查询慢 |
| 哈希表（数组+链表+红黑树） | `HashMap` / `HashSet` | 增删查都快，无序 |
| 红黑树 | `TreeMap` / `TreeSet` | 自动排序，查询 O(log n) |
| 栈 | `Stack` / `LinkedList`（当栈用） | 后进先出 LIFO |
| 队列 | `LinkedList` / `ArrayDeque` | 先进先出 FIFO |

> 💡 学完本篇你会明白：选集合不是凭感觉，而是看场景需要哪种数据结构的时间复杂度。

## 二、栈 Stack（LIFO）

**栈**是「后进先出」（Last In First Out）的线性结构：只能在一端（栈顶）进出。

```
压栈 push  →  [C] [B] [A]  ← 栈顶（最后压入的最先弹出）
              ↑ 底部
```

### 2.1 核心操作

| 操作 | 说明 | 栈空时 |
| :--- | :--- | :--- |
| `push(e)` | 压入栈顶 | - |
| `pop()` | 弹出栈顶（删除并返回） | 抛 EmptyStackException |
| `peek()` | 查看栈顶（不删除） | 抛异常 |
| `empty()` | 是否为空 | - |

### 2.2 Java 中的栈

```java
import java.util.Stack;

Stack<Integer> stack = new Stack<>();
stack.push(1);
stack.push(2);
stack.push(3);
System.out.println(stack.peek());  // 3，查看栈顶
System.out.println(stack.pop());    // 3，弹出栈顶
System.out.println(stack.pop());    // 2
System.out.println(stack.pop());    // 1
// stack.pop();   // ❌ 栈空时抛 EmptyStackException
```

> ⚠️ `Stack` 继承自 `Vector`，所有方法都加 synchronized，**性能差**。官方文档推荐用 `ArrayDeque` 当栈：`Deque<Integer> stack = new ArrayDeque<>();`，方法名是 `push/pop/peek`，无锁、更快。

### 2.3 用 LinkedList 模拟栈

`LinkedList` 实现了 `Deque` 接口，天然可当栈用：

```java
import java.util.LinkedList;

LinkedList<String> stack = new LinkedList<>();
stack.push("A");   // 等价 addFirst
stack.push("B");
stack.push("C");
System.out.println(stack.pop());   // C
System.out.println(stack.pop());   // B
```

> 💡 栈的典型应用：方法调用栈、撤销/重做（Undo/Redo）、括号匹配、表达式求值、DFS 深度优先搜索。

## 三、队列 Queue（FIFO）

**队列**是「先进先出」（First In First Out）的线性结构：一端进（队尾），另一端出（队头）。

```
入队 offer → [A] [B] [C] → poll 出队
            ↑ 队尾          ↑ 队头
```

### 3.1 核心操作

`Queue` 接口的方法分两组：一组抛异常，一组返回特殊值（null/false）：

| 操作 | 抛异常版本 | 返回值版本 |
| :--- | :--- | :--- |
| 入队 | `add(e)` | `offer(e)` |
| 出队 | `remove()` | `poll()` |
| 查看队头 | `element()` | `peek()` |

### 3.2 Java 中的队列

```java
import java.util.LinkedList;
import java.util.Queue;

Queue<String> queue = new LinkedList<>();
queue.offer("A");   // 入队
queue.offer("B");
queue.offer("C");
System.out.println(queue.peek());  // A，查看队头
System.out.println(queue.poll());  // A，出队
System.out.println(queue.poll());  // B
System.out.println(queue.poll());  // C
System.out.println(queue.poll());  // null，队列空返回 null（不抛异常）
```

> 💡 队列的典型应用：任务调度（线程池任务队列）、消息队列、BFS 广度优先搜索、生产者-消费者模型。并发场景用 `BlockingQueue`（如 `ArrayBlockingQueue`、`LinkedBlockingQueue`）。

## 四、数组（连续内存）

**数组**是最基础的数据结构：在内存中**连续**存放相同类型元素，通过下标直接访问。

### 4.1 特点

- 内存**连续**分配
- 通过索引访问，查询 O(1)
- 增删需要移动元素，O(n)
- 大小固定（Java 数组创建后长度不可变）

### 4.2 时间复杂度

| 操作 | 复杂度 | 说明 |
| :--- | :---: | :--- |
| 按索引查询 | O(1) | 直接算地址：base + index * size |
| 按值查找 | O(n) | 需遍历 |
| 头部插入 | O(n) | 所有元素后移 |
| 尾部插入 | O(1) | 直接放末尾（未满时） |
| 中间删除 | O(n) | 删除后元素前移 |

```java
int[] arr = new int[5];   // 长度固定为 5
arr[0] = 10;
arr[4] = 50;
// arr[5] = 60;   // ❌ 数组越界 ArrayIndexOutOfBoundsException
System.out.println(arr.length);  // 5，长度是属性
```

> ⚠️ `ArrayList` 本质是「可扩容的数组」：内部维护一个 `Object[]`，满时按 1.5 倍扩容并复制元素。扩容是有开销的，所以预知大小时建议 `new ArrayList<>(capacity)` 指定初始容量。

## 五、链表（不连续内存）

**链表**用**节点**存储，每个节点含「数据 + 指向下一节点的指针」，内存**不连续**。

### 5.1 单向链表 vs 双向链表

```
单向链表：  [data|next] → [data|next] → [data|next] → null

双向链表：  null ← [prev|data|next] ⇄ [prev|data|next] ⇄ [prev|data|next] → null
```

| 对比项 | 单向链表 | 双向链表 |
| :--- | :--- | :--- |
| 指针数 | 1 个（next） | 2 个（prev + next） |
| 内存 | 更省 | 多一个指针 |
| 反向遍历 | ❌ 不支持 | ✅ 支持 |
| 删除某节点 | 需从头找前驱 O(n) | 已知节点可直接删 O(1) |

> 💡 Java 的 `LinkedList` 是**双向链表**，`LinkedList.Node` 源码就三个字段：`item`、`next`、`prev`。

### 5.2 时间复杂度

| 操作 | 复杂度 | 说明 |
| :--- | :---: | :--- |
| 按索引查询 | O(n) | 必须从头遍历 |
| 头/尾插入 | O(1) | 直接改指针 |
| 中间插入 | O(n) 查找 + O(1) 插入 | 查找慢，插入快 |
| 删除已知节点 | O(1)（双向） | 改前后指针即可 |

```java
// LinkedList 当链表用
LinkedList<String> list = new LinkedList<>();
list.add("A");      // 尾插
list.addFirst("Z"); // 头插 O(1)
list.addLast("Y");  // 尾插 O(1)
System.out.println(list);  // [Z, A, Y]
```

> ⚠️ **常见误区**：以为 `LinkedList` 查询比 `ArrayList` 快。恰恰相反——`list.get(index)` 在 `LinkedList` 是 O(n)，在 `ArrayList` 是 O(1)。随机访问多的场景务必用 `ArrayList`。

## 六、树

**树**是层次化的非线性结构，由节点组成。

### 6.1 基本概念

```
        A          ← 根节点（root）
       / \
      B   C        ← A 的子节点
     / \   \
    D   E   F      ← 叶子节点（leaf，无子节点）
```

| 术语 | 含义 |
| :--- | :--- |
| 根节点 | 最顶层节点 |
| 子节点 | 某节点下方的节点 |
| 父节点 | 子节点上方的节点 |
| 叶子节点 | 没有子节点的节点 |
| 深度 | 根到某节点的路径长度 |
| 高度 | 某节点到最深叶子的路径长度 |

### 6.2 二叉树

每个节点**最多两个子节点**（左、右）：

```
        A
       / \
      B   C
     / \
    D   E
```

### 6.3 二叉搜索树 BST（Binary Search Tree）

**左子树所有值 < 根 < 右子树所有值**，中序遍历得升序序列。

```
        8
       / \
      4   12
     / \  / \
    2  6 10 14
```

- 查找：从根开始，比根小往左走，比根大往右走，O(log n)（平衡时）
- 插入：先查找定位，再插入到叶子位置

> ⚠️ BST 的致命弱点：**插入有序数据会退化成链表**，查询变 O(n)。比如依次插入 1,2,3,4,5，会变成一条向右的链。所以需要「自平衡」。

### 6.4 平衡二叉树 AVL

AVL 树要求**任意节点的左右子树高度差不超过 1**，通过旋转保持平衡。查询极快，但插入/删除时频繁旋转，开销大，实际较少使用。

### 6.5 红黑树（重点⭐⭐）

红黑树是**自平衡二叉搜索树**，是 AVL 的「折中」：不追求绝对平衡，只追求「大致平衡」，插入删除时旋转次数少。Java 的 `TreeMap`、`TreeSet`、`HashMap`（链表过长时转红黑树）底层都用它。

**红黑树 5 条规则**：

1. 每个节点是**红色**或**黑色**
2. **根节点是黑色**
3. 每个叶子节点（NIL 空节点）是黑色
4. 红色节点的子节点必须是黑色（即**不能有连续两个红色节点**）
5. 从任一节点到其所有叶子节点的路径，包含**相同数目的黑色节点**（黑高相同）

```
        8B
       / \
      4R  12R
     / \   / \
    2B 6B 10B 14B
```

> 💡 **记忆要点**：红黑树保证「最长路径不超过最短路径的 2 倍」，因此查询稳定在 O(log n)。规则 4、5 是核心——4 防止红色扎堆，5 保证黑高一致。

### 6.6 红黑树 vs AVL

| 对比项 | AVL | 红黑树 |
| :--- | :--- | :--- |
| 平衡严格度 | 严格（高度差≤1） | 宽松（最长≤2倍最短） |
| 查询效率 | 略快 | 略慢 |
| 插入/删除旋转 | 多 | 少 |
| 适用场景 | 查询密集 | 增删查均衡 |
| Java 应用 | 几乎不用 | TreeMap、HashMap |

> 💡 Java 集合选红黑树而非 AVL，就是因为增删场景下旋转开销小，综合性能更好。

## 七、哈希表

**哈希表**通过「哈希函数」把 key 映射到数组下标，实现 O(1) 的增删查。`HashMap` 底层就是哈希表。

### 7.1 哈希函数与哈希冲突

```
key → 哈希函数 hash(key) → 数组下标 index → 存入数组[index]
```

理想情况：不同 key 映射到不同下标。但现实是不同 key 可能算出**相同下标**，这就是**哈希冲突**。

```java
// 简化版：HashMap 求 index
int hash = key.hashCode();           // 1. 调用 key 的 hashCode
int index = (n - 1) & hash;          // 2. 与数组长度做与运算定位下标
```

> ⚠️ 两个对象 `hashCode` 相同不代表它们 `equals` 相等，但 `equals` 相等的对象 `hashCode` 必须相同。这是重写 `hashCode` 的铁律。

### 7.2 拉链法解决冲突

冲突时，把相同下标的元素串成**链表**：

```
数组
[0] → null
[1] → [k1,v1] → [k2,v2] → null   ← 冲突，挂链表
[2] → null
[3] → [k3,v3] → null
```

查询时：先算下标 → 找到链表 → 遍历链表用 `equals` 比对 key。

### 7.3 Java 8 的优化：链表转红黑树

链表过长时查询退化为 O(n)。Java 8 的 `HashMap` 规定：

- 链表长度 ≥ **8** 且数组容量 ≥ **64** 时，链表转**红黑树**
- 红黑树节点数 ≤ **6** 时，退回链表

```
[1] → [k1,v1] → [k2,v2] → ... 6个节点 ... → [k8,v8]
                                              ↓ 长度到 8
[1] → 红黑树（查询 O(log n)）
```

> 💡 阈值 8 和 6 之间留了「缓冲」，避免在 7 附近反复转换抖动。源码注释说 8 是基于泊松分布算出的概率极低事件，正常情况下几乎不会触发。

### 7.4 HashMap 的扩容

当元素个数 > 容量 × 负载因子（默认 0.75）时扩容，容量翻倍：

```java
// 简化逻辑
if (size > capacity * 0.75) {
    capacity = capacity * 2;   // 扩容
    rehash();                  // 重新分配位置
}
```

> ⚠️ 扩容要 rehash，开销大。预知元素数量时，`new HashMap<>(expectedSize / 0.75 + 1)` 可避免扩容。

## 八、各数据结构时空复杂度对比

| 数据结构 | 查询 | 插入 | 删除 | 空间 | 特点 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| 数组 | O(1)（索引） | O(n) | O(n) | O(n) | 连续内存，固定大小 |
| 链表（双向） | O(n) | O(1) | O(1) | O(n) | 不连续，多存指针 |
| 栈 | O(n) | O(1) | O(1) | O(n) | LIFO |
| 队列 | O(n) | O(1) | O(1) | O(n) | FIFO |
| 哈希表 | O(1) 平均 | O(1) 平均 | O(1) 平均 | O(n) | 最坏退化 O(n) |
| BST（平衡） | O(log n) | O(log n) | O(log n) | O(n) | 有序 |
| 红黑树 | O(log n) | O(log n) | O(log n) | O(n) | 自平衡，稳定 |

> ⚠️ 哈希表的最坏情况是所有 key 都冲突，挂成一条长链表，退化为 O(n)。Java 8 引入红黑树优化后，最坏变 O(log n)。

## 九、数据结构与 Java 集合的对应

| 数据结构 | Java 集合 | 关键说明 |
| :--- | :--- | :--- |
| 数组 | `ArrayList` | 查询 O(1)，扩容 1.5 倍 |
| 双向链表 | `LinkedList` | 同时实现 List 和 Deque |
| 哈希表（数组+链表+红黑树） | `HashMap` / `HashSet` | 无序，O(1) 平均 |
| 红黑树 | `TreeMap` / `TreeSet` | 按 key 排序，O(log n) |
| 哈希表 + 链表 | `LinkedHashMap` | 保留插入顺序 |
| 栈 | `Stack`（旧）/ `ArrayDeque`（推荐） | LIFO |
| 队列 | `LinkedList` / `ArrayDeque` | FIFO |
| 数组+链表（线程安全） | `ConcurrentHashMap` | 分段锁/CAS |

```java
// 同样存 1~5，不同数据结构行为不同
List<Integer> arrayList = new ArrayList<>(Arrays.asList(3, 1, 4, 1, 5));
List<Integer> linkedList = new LinkedList<>(arrayList);
Set<Integer> hashSet = new HashSet<>(arrayList);      // 无序
Set<Integer> treeSet = new TreeSet<>(arrayList);      // 排序去重
System.out.println(hashSet);   // 顺序不定，如 [1, 3, 4, 5]
System.out.println(treeSet);   // [1, 3, 4, 5]，有序
```

## ⚠️ 重点

### 重点 1：ArrayList vs LinkedList 的选择 ⭐⭐

这是面试最高频的问题，务必记牢：

| 场景 | ArrayList | LinkedList |
| :--- | :---: | :---: |
| 随机访问 `get(i)` | ✅ O(1) | ❌ O(n) |
| 尾部增删 | ✅ 摊销 O(1) | ✅ O(1) |
| 头部插入 | ❌ O(n) | ✅ O(1) |
| 中间插入 | ❌ O(n) 移动 | O(n) 查找 + O(1) 插入 |
| 内存占用 | 小 | 大（每个节点多两个指针） |

> 📌 **结论**：90% 的业务场景用 `ArrayList`。频繁头部插入/删除才考虑 `LinkedList`，但实际中 `ArrayDeque` 往往更优。

### 重点 2：HashMap 的 key 必须正确重写 hashCode 和 equals ⭐⭐

```java
public class User {
    String name;
    int age;
    // 省略构造

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof User)) return false;
        User u = (User) o;
        return age == u.age && Objects.equals(name, u.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);   // ✅ 用到 equals 的所有字段
    }
}
```

> ⚠️ 不重写或写错，HashMap 会「找到同一个 key 却认为不相等」，导致同一个 key 存两份、get 返回 null。规则：**equals 用哪些字段，hashCode 就必须用哪些字段**。

### 重点 3：红黑树的 5 条规则 ⭐⭐

面试常考默写：

1. 节点是红或黑
2. 根是黑
3. 叶子（NIL）是黑
4. 红节点的子节点必黑（不能连续红）
5. 任一节点到叶子的所有路径，黑节点数相同

> 💡 推导记忆：规则 4 + 5 共同保证「没有一条路径比另一条长两倍」，所以高度始终 O(log n)。

### 重点 4：哈希冲突的拉链法 ⭐

```java
// 同一下标挂多个元素
HashMap<String, Integer> map = new HashMap<>();
map.put("Aa", 1);    // "Aa".hashCode() == 2112
map.put("BB", 2);    // "BB".hashCode() == 2112  ← 与 "Aa" 冲突！
// 两个 key 不同但 hashCode 相同，挂在同一桶里，靠 equals 区分
System.out.println(map.get("Aa"));  // 1
System.out.println(map.get("BB"));  // 2
```

### 重点 5：链表反转思路（面试常考）⭐

手写单向链表反转是经典面试题，核心是「三指针迭代」：

```java
class Node {
    int val;
    Node next;
    Node(int v) { val = v; }
}

// 迭代反转：prev/curr/next 三指针
public Node reverse(Node head) {
    Node prev = null;
    Node curr = head;
    while (curr != null) {
        Node next = curr.next;   // 1. 暂存下一个
        curr.next = prev;        // 2. 当前指向前一个（反转）
        prev = curr;             // 3. prev 前进
        curr = next;             // 4. curr 前进
    }
    return prev;   // 新头节点
}
```

> 💡 口诀：**存 next、转 curr、移 prev、移 curr**。务必能手写，面试现场默写。

## 💻 实战案例

### 案例 1：用 LinkedList 模拟栈和队列 ⭐

```java
import java.util.LinkedList;

public class StackAndQueueDemo {
    public static void main(String[] args) {
        // ✅ 当栈用（LIFO）
        LinkedList<String> stack = new LinkedList<>();
        stack.push("第一");
        stack.push("第二");
        stack.push("第三");
        System.out.println("栈弹出：" + stack.pop());   // 第三
        System.out.println("栈弹出：" + stack.pop());   // 第二

        // ✅ 当队列用（FIFO）
        LinkedList<String> queue = new LinkedList<>();
        queue.offer("任务1");
        queue.offer("任务2");
        queue.offer("任务3");
        System.out.println("队列出队：" + queue.poll());  // 任务1
        System.out.println("队列出队：" + queue.poll());  // 任务2
    }
}
```

> 📌 **真实场景**：线程池的任务队列就是 FIFO，用 `LinkedBlockingQueue`；浏览器的「后退/前进」是两个栈；编辑器的撤销用栈。

### 案例 2：手写单向链表反转 ⭐⭐

```java
public class LinkedListReverse {
    static class Node {
        int val;
        Node next;
        Node(int v) { val = v; }
    }

    // 打印链表
    static void print(Node head) {
        Node cur = head;
        while (cur != null) {
            System.out.print(cur.val + " -> ");
            cur = cur.next;
        }
        System.out.println("null");
    }

    public static void main(String[] args) {
        // 构造 1 -> 2 -> 3 -> 4 -> null
        Node head = new Node(1);
        head.next = new Node(2);
        head.next.next = new Node(3);
        head.next.next.next = new Node(4);

        print(head);   // 1 -> 2 -> 3 -> 4 -> null

        // ✅ 反转
        Node prev = null;
        Node curr = head;
        while (curr != null) {
            Node next = curr.next;
            curr.next = prev;
            prev = curr;
            curr = next;
        }
        head = prev;

        print(head);   // 4 -> 3 -> 2 -> 1 -> null
    }
}
```

> 💡 这是大厂面试高频手撕题。进阶版：递归反转、反转部分区间 [m,n]、K 个一组反转。掌握迭代版是基础。

### 案例 3：理解 HashMap 的哈希冲突 ⭐

```java
import java.util.HashMap;
import java.util.Map;

public class HashConflictDemo {
    static class Key {
        String name;
        Key(String name) { this.name = name; }

        @Override
        public int hashCode() {
            return 1;   // ✅ 故意让所有 key 哈希相同，模拟极端冲突
        }

        @Override
        public boolean equals(Object o) {
            if (this == o) return true;
            if (!(o instanceof Key)) return false;
            return name.equals(((Key) o).name);
        }

        @Override
        public String toString() { return name; }
    }

    public static void main(String[] args) {
        Map<Key, Integer> map = new HashMap<>();
        map.put(new Key("A"), 1);
        map.put(new Key("B"), 2);
        map.put(new Key("C"), 3);
        map.put(new Key("D"), 4);
        map.put(new Key("E"), 5);
        map.put(new Key("F"), 6);
        map.put(new Key("G"), 7);
        map.put(new Key("H"), 8);   // 第 8 个触发链表转红黑树

        System.out.println(map.get(new Key("H")));  // 8，仍能正确取到
        // 虽然全部冲突到同一桶，但 Java 8 转红黑树后查询仍是 O(log n)
    }
}
```

> ⚠️ 这个例子演示了「最坏情况」：所有 key 哈希相同，全挂在一个桶。Java 8 之前是 O(n) 链表，Java 8 转红黑树后变 O(log n)。生产中绝不要这样写 hashCode，这里仅为演示。

### 案例 4：用数组实现环形队列 ⭐

环形队列是固定大小、循环复用的队列，常用于缓冲区、生产消费场景：

```java
public class CircularQueue {
    private final int[] data;
    private int head;   // 队头
    private int tail;   // 队尾下一个待插入位置
    private int size;   // 当前元素数
    private final int capacity;

    public CircularQueue(int capacity) {
        this.capacity = capacity;
        this.data = new int[capacity];
        this.head = 0;
        this.tail = 0;
        this.size = 0;
    }

    public boolean offer(int val) {
        if (size == capacity) {
            System.out.println("队列满，无法入队 " + val);
            return false;   // ❌ 满
        }
        data[tail] = val;
        tail = (tail + 1) % capacity;   // ✅ 环形：取模回绕
        size++;
        return true;
    }

    public int poll() {
        if (size == 0) {
            throw new RuntimeException("队列空");
        }
        int val = data[head];
        head = (head + 1) % capacity;   // ✅ 环形：取模回绕
        size--;
        return val;
    }

    public static void main(String[] args) {
        CircularQueue q = new CircularQueue(3);
        q.offer(1); q.offer(2); q.offer(3);
        q.offer(4);          // 队列满，无法入队 4
        System.out.println(q.poll());  // 1
        q.offer(4);          // ✅ 复用位置 0
        System.out.println(q.poll());  // 2
        System.out.println(q.poll());  // 3
        System.out.println(q.poll());  // 4
    }
}
```

> 💡 **真实场景**：`ArrayBlockingQueue` 底层就是环形数组；操作系统生产者-消费者缓冲区、日志的 ring buffer 都是这个思路。取模回绕是核心。

### 案例 5：电商订单按时间栈式处理（撤销操作）

后台运营对订单做批量操作，需要支持「撤销上一步」，用栈记录操作历史：

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class OrderOperationHistory {
    public static void main(String[] args) {
        Deque<String> operationStack = new ArrayDeque<>();   // 当栈用

        // 模拟运营操作
        operationStack.push("批量改价：商品A 99→89");
        operationStack.push("批量上架：商品B/C/D");

    }
}
```

### 案例 6：任务调度队列（FIFO）

线程池把提交的任务放进 FIFO 队列，按顺序执行：

```java
import java.util.LinkedList;
import java.util.Queue;

public class TaskScheduler {
    public static void main(String[] args) {
        Queue<Runnable> taskQueue = new LinkedList<>();
        taskQueue.offer(() -> System.out.println("执行：发送邮件"));
        taskQueue.offer(() -> System.out.println("执行：生成报表"));
        taskQueue.offer(() -> System.out.println("执行：清理日志"));

        // 按提交顺序依次执行
        while (!taskQueue.isEmpty()) {
            taskQueue.poll().run();
        }
        // 执行：发送邮件
        // 执行：生成报表
        // 执行：清理日志
    }
}
```

> 📌 **真实场景**：`ThreadPoolExecutor` 内部用 `BlockingQueue<Runnable>` 存任务，工作线程从队头取任务执行。任务多时队列会堆积，需合理设置队列容量和拒绝策略。

## 本章小结

| 数据结构 | 特点 | 时间复杂度 | Java 集合 |
| :--- | :--- | :--- | :--- |
| 栈 | LIFO | 增删查 O(1)/O(n) | Stack、ArrayDeque |
| 队列 | FIFO | 增删 O(1) | LinkedList、ArrayDeque |
| 数组 | 连续内存，索引查询 | 查 O(1)，增删 O(n) | ArrayList |
| 链表 | 不连续，节点+指针 | 查 O(n)，增删 O(1) | LinkedList |
| 二叉搜索树 BST | 左<根<右 | O(log n)，退化 O(n) | - |
| 红黑树 | 自平衡 BST | O(log n) 稳定 | TreeMap、HashMap |
| 哈希表 | 数组+链表+红黑树 | 平均 O(1) | HashMap、HashSet |

| 核心知识点 | 要点 |
| :--- | :--- |
| 栈 vs 队列 | LIFO vs FIFO |
| 数组 vs 链表 | 查询快 vs 增删快 |
| BST 退化 | 插入有序数据变链表 O(n) |
| 红黑树 5 规则 | 红/黑、根黑、叶黑、红子黑、黑高同 |
| 哈希冲突 | 拉链法，Java 8 链表≥8 转红黑树 |
| HashMap key 规范 | 正确重写 hashCode + equals |

## 学习建议

1. **先画图再写代码**：栈、队列、链表、树这些结构，每学一个先在纸上画图理解「指针怎么指、元素怎么动」，再动手写代码。数据结构是「空间想象」的学问，画图比硬背有效十倍。
2. **手写链表反转**：这是大厂面试最高频的手撕题，务必能在白纸上默写「三指针迭代」版，再挑战递归版。能默写出来，说明你真正理解了链表。
3. **对比记忆复杂度**：把数组 vs 链表、BST vs 红黑树、哈希表平均 vs 最坏的复杂度做成对比表反复看，面试问「为什么用 ArrayList 不用 LinkedList」时才能答得有理有据。
4. **结合 HashMap 源码理解哈希表**：本篇是 HashMap 的「前置知识」。学完后去看 `HashMap.put` 源码，你会突然看懂「算 hash → 定下标 → 挂链表 → 转 8 转红黑树」整条链路，这是最有成就感的时刻。
5. **不要死记红黑树旋转**：红黑树的左右旋、变色规则极繁琐，面试通常只要求默写 5 条性质 + 理解「为什么能保证 O(log n)」。除非面底层岗，否则不必死磕旋转细节，把精力放在「什么场景用红黑树、为什么用」上更划算。
