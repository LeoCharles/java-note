# 基础语法

Java 语法是写 Java 代码的「交通规则」——注释怎么写、哪些词是系统保留的、变量怎么起名、字面量有哪些形态。这些内容看似简单，却是代码可读性、可维护性的根基。一个命名混乱、注释缺失的项目，维护成本会成倍增加。本篇系统梳理注释、关键字、标识符、命名规范与字面量，帮你打下扎实的语法底子。

> 💡 本篇是 Java 语法树的「叶子节点」，内容偏记忆型，但命名规范和注释习惯会贯穿整个开发生涯，建议结合 [04-数据类型与类型转换](04-数据类型与类型转换.md) 一起看。

## 一、注释

注释是写给开发者看的文字，编译器会忽略注释内容。Java 有三种注释：

### 1.1 单行注释

```java
// 这是单行注释，从 // 到行末都被忽略
int age = 18;  // 也可以写在代码右侧
```

### 1.2 多行注释

```java
/*
 * 这是多行注释
 * 可以写多行内容
 * 注意：多行注释不能嵌套（里面不能再包一个 /* ... */）
 */
int x = 10;
```

> ⚠️ 多行注释 `/* */` **不能嵌套**：第一个 `*/` 就会结束整个注释块，后面的内容会报编译错误。

```java
/*
/* 嵌套注释 */    // ❌ 第一个 */ 就结束了，这里开始报错
*/
```

### 1.3 文档注释（重点）

文档注释以 `/**` 开头、`*/` 结尾，配合 `javadoc` 工具可以自动生成 API 文档。这是 Java 区别于很多语言的特色功能。

```java
/**
 * 计算两个整数的和。
 * <p>这是一个示例方法，演示文档注释的写法。</p>
 *
 * @param a 第一个加数
 * @param b 第二个加数
 * @return 两数之和
 * @author Leo
 * @since 1.0
 * @deprecated 该方法已过时，请使用 {@link #addExact(int, int)}
 */
public int add(int a, int b) {
    return a + b;
}
```

常用 javadoc 标签：

| 标签 | 说明 | 用于 |
| :--- | :--- | :--- |
| `@param` | 方法参数说明 | 方法 |
| `@return` | 返回值说明 | 方法 |
| `@throws` / `@exception` | 可能抛出的异常 | 方法 |
| `@author` | 作者 | 类/接口 |
| `@version` | 版本号 | 类/接口 |
| `@since` | 从哪个版本开始有 | 类/方法 |
| `@see` | 参考另一个类/方法 | 通用 |
| `@deprecated` | 标记已过时 | 类/方法 |
| `{@link}` | 内联链接到某个类/方法 | 通用 |
| `{@code}` | 内联代码样式文本 | 通用 |

用命令行生成 API 文档：

```bash
# 生成 HTML 格式的 API 文档，输出到 doc 目录
javadoc -d doc -encoding UTF-8 -charset UTF-8 MyClass.java

# 对整个包生成文档
javadoc -d doc -encoding UTF-8 -sourcepath src com.example
```

> 💡 在 IDEA 中，输入 `/**` 后按回车，会自动生成文档注释模板（自动补全 `@param`、`@return` 等）。

> 📌 **开发规范**：公开的类和公共方法必须写文档注释。私有方法可以用普通注释。文档注释是团队协作的基础，也是 `javadoc` 生成接口文档的来源。

## 二、关键字

关键字是 Java 语言预定义的、有特殊含义的单词，全部**小写**。Java 8 约有 50 个关键字 + 3 个保留字。

### 2.1 关键字总览

| 分类 | 关键字 | 数量 |
| :--- | :--- | :---: |
| **数据类型** | `byte` `short` `int` `long` `float` `double` `char` `boolean` `void` | 9 |
| **流程控制** | `if` `else` `switch` `case` `default` `for` `while` `do` `break` `continue` `return` | 11 |
| **类与继承** | `class` `interface` `enum` `extends` `implements` `abstract` `final` `static` `import` `package` | 10 |
| **访问修饰** | `public` `protected` `private` | 3 |
| **异常处理** | `try` `catch` `finally` `throw` `throws` | 5 |
| **并发** | `synchronized` `volatile` | 2 |
| **其他修饰** | `native` `transient` `strictfp` `assert` `const`(保留) `goto`(保留) | 6 |
| **对象引用** | `new` `this` `super` `instanceof` | 4 |
| **保留字（字面量）** | `true` `false` `null` | 3 |

> 💡 **记忆技巧**：不用死记硬背。写代码用到的自然就记住了，重点是理解每个关键字的含义，避免拿它们当变量名。

### 2.2 保留字

`true`、`false`、`null` 是**字面量保留字**，严格来说不是关键字，但同样不能用作标识符：

```java
int true = 1;      // ❌ 编译错误：true 是保留字
String null = "x";  // ❌ 编译错误：null 是保留字
boolean false = true; // ❌ 编译错误
```

`goto` 和 `const` 是 C/C++ 保留但 Java 未使用的关键字，同样不能用作标识符：

```java
int goto = 1;   // ❌ 编译错误
int const = 2;  // ❌ 编译错误
```

### 2.3 易混淆关键字对比

| 关键字 | 用途 | 易混点 |
| :--- | :--- | :--- |
| `this` | 当前对象引用 | vs `super`（父类引用） |
| `final` | 不可变/不可继承/不可重写 | vs `finally`（异常必执行）vs `finalize`（GC 回收前调用，已废弃） |
| `throws` | 声明方法可能抛出的异常 | vs `throw`（实际抛出动作） |
| `abstract` | 抽象类/抽象方法 | vs `interface`（接口） |
| `static` | 静态成员，属于类 | vs 实例成员（属于对象） |
| `break` | 跳出循环/switch | vs `continue`（跳过本次，进入下次） |

```java
// throw vs throws
public void read(String path) throws IOException {  // throws 声明可能抛出的异常
    if (path == null) {
        throw new IllegalArgumentException("路径不能为空");  // throw 实际抛出
    }
}

// final vs finally
public void demo() {
    final int MAX = 100;   // final：常量，不可重新赋值
    try {
        // ...
    } finally {
        // finally：无论是否异常都会执行
        System.out.println("清理资源");
    }
}
```

## 三、标识符与命名规范

### 3.1 标识符命名规则

标识符是给类、方法、变量等起的名字。Java 标识符有**硬性规则**（违反则编译错误）：

| 规则 | 说明 | 示例 |
| :--- | :--- | :--- |
| 组成字符 | 字母、数字、下划线 `_`、美元符 `$` | `userName`、`$price` |
| 开头限制 | 不能以数字开头 | `name1` ✅ / `1name` ❌ |
| 不能是关键字 | 关键字/保留字不能做标识符 | `class` ❌ / `myClass` ✅ |
| 区分大小写 | `Name` 和 `name` 是不同的 | `int Name, name;` ✅ |
| 长度无限制 | 但实际不宜过长 | — |

```java
// ✅ 合法标识符
int userName = 1;
int _count = 2;
int $price = 3;
int 我的变量 = 4;   // ✅ Java 支持 Unicode，中文合法但不推荐

// ❌ 非法标识符
// int 1name = 1;      // 数字开头
// int class = 2;      // 关键字
// int my-name = 3;    // 含非法字符 -
// int a b = 4;        // 含空格
```

> ⚠️ 虽然 Java 允许用中文命名变量，但**强烈不推荐**——编码问题、团队协作障碍、工具兼容性都是隐患。坚持用英文。

### 3.2 命名规范（驼峰命名法）

命名规则是**编译器强制的**，命名规范是**行业约定的**。不遵守规范不会报错，但会被同事吐槽。

| 场景 | 规范 | 示例 |
| :--- | :--- | :--- |
| 包名 | 全小写，域名倒写 | `com.company.user` |
| 类名/接口名 | 大驼峰（UpperCamelCase） | `UserService`、`Runnable` |
| 方法名/变量名 | 小驼峰（lowerCamelCase） | `getUserName`、`maxAge` |
| 常量 | 全大写，下划线分隔 | `MAX_VALUE`、`DEFAULT_TIMEOUT` |
| 泛型类型参数 | 单个大写字母 | `T`、`E`、`K`、`V` |
| 枚举值 | 全大写，下划线分隔 | `RED`、`PAY_SUCCESS` |
| 抽象类 | 以 `Abstract` 开头或结尾 | `AbstractRepository` |
| 接口实现类 | 接口名 + `Impl` | `UserServiceImpl` |
| 测试类 | 被测类名 + `Test` | `UserServiceTest` |
| 异常类 | 以 `Exception` 结尾 | `BusinessException` |

```java
// ✅ 规范命名
package com.company.order;

public class OrderService {
    private static final int MAX_ORDER_COUNT = 100;   // 常量
    private String orderId;                            // 变量

    public String getOrderId() {                       // 方法
        return orderId;
    }
}

// ❌ 不规范命名
package Com.Company.Order;        // 包名不能大写
class orderservice { }            // 类名应大驼峰
class OrderService {
    String OrderId;               // 变量应小驼峰
    static final int maxcount = 100; // 常量应全大写
}
```

### 3.3 好的命名 vs 坏的命名

```java
// ❌ 坏命名：含义不明
int a = 18;
String s = "张三";
int[] arr = {1, 2, 3};
List list = new ArrayList();
void m1() { }
boolean f = false;

// ✅ 好命名：见名知意
int userAge = 18;
String userName = "张三";
int[] userIds = {1, 2, 3};
List<User> userList = new ArrayList<>();
void deleteUserById() { }
boolean isDeleted = false;
```

命名好坏的判断标准：

| 坏命名 | 问题 | 好命名 |
| :--- | :--- | :--- |
| `a`、`b`、`tmp` | 无业务含义 | `userName`、`tempFile` |
| `data` | 太泛 | `orderData` |
| `list` | 类型当名字 | `userList` |
| `flag` | 布尔值不知真假含义 | `isEnabled`、`hasPermission` |
| `getUserInfoByIdAndName` | 方法名过长 | `getUser`（参数已说明） |
| `sp` | 缩写不明 | `serviceProvider` 或 `sp`（团队约定后） |

> 📌 **布尔变量命名**：用 `is`/`has`/`can`/`should` 开头，如 `isLogin`、`hasPermission`、`canEdit`、`shouldRetry`。这样 `if (isLogin)` 读起来像自然语言。

> 📌 **方法命名**：动词开头。查询用 `get`/`find`，判断用 `is`/`has`，设置用 `set`，转换用 `to`，构建用 `build`，创建用 `create`，删除用 `delete`/`remove`。

## 四、字面量（常量）

字面量是源码中直接写出的数据值。Java 有 6 类字面量：

| 类型 | 示例 | 说明 |
| :--- | :--- | :--- |
| 整数 | `100`、`0xFF`、`0b1010`、`100L` | 默认 int，long 加 `L` |
| 小数 | `3.14`、`2.0F` | 默认 double，float 加 `F` |
| 字符 | `'A'`、`'中'`、`'\n'` | 单引号，单个字符 |
| 字符串 | `"hello"` | 双引号，可空 `""` |
| 布尔 | `true`、`false` | 只有两个值 |
| 空常量 | `null` | 引用类型才有，表示不指向任何对象 |

```java
// 整数
int decimal = 100;        // 十进制
int hex = 0xFF;          // 十六进制 = 255
int binary = 0b1010;     // 二进制 = 10（Java 7+）
long big = 10000000000L; // long 必须加 L

// 小数
double d = 3.14;         // 默认 double
float f = 3.14F;         // float 必须加 F
double sci = 1.23e4;     // 科学计数法 = 12300.0

// 字符
char c1 = 'A';
char c2 = '中';
char c3 = '\n';          // 转义字符：换行
char c4 = '\t';          // 转义字符：制表符
char c5 = '\\';          // 转义字符：反斜杠本身
char c6 = '\'';          // 转义字符：单引号

// 字符串
String s1 = "hello";
String s2 = "";           // 空字符串，合法
// char c = '';           // ❌ 字符不能为空，至少一个字符

// 布尔
boolean flag = true;

// 空常量
String ref = null;        // null 只能赋给引用类型
// int n = null;          // ❌ 基本类型不能赋 null
```

常用转义字符：

| 转义符 | 含义 | 转义符 | 含义 |
| :---: | :--- | :---: | :--- |
| `\n` | 换行 | `\t` | 制表符 |
| `\r` | 回车 | `\b` | 退格 |
| `\\` | 反斜杠 | `\'` | 单引号 |
| `\"` | 双引号 | `\uXXXX` | Unicode 字符 |

```java
System.out.println("第一行\n第二行");       // 换行
System.out.println("姓名\t年龄\t性别");      // 制表对齐
System.out.println("他说\"你好\"");          // 输出带引号
System.out.println("路径：C:\\Users\\Leo");  // 输出反斜杠
System.out.println("\u4e2d\u6587");          // 输出"中文"
```

## ⚠️ 重点

### 重点 1：文档注释 vs 普通注释 ⭐

```java
// 普通注释：只有开发者看
// 计算总价

/* 多行注释：编译器忽略 */
/* 仅供阅读，无法被 javadoc 提取 */

/**
 * 文档注释：能被 javadoc 工具提取生成 API 文档 ✅
 * @param price 单价
 * @return 总价
 */
public double calcTotal(double price) { return price; }
```

> 💡 只有 `/** */` 才能被 `javadoc` 解析。`//` 和 `/* */` 只是普通注释，不会出现在生成的文档中。

### 重点 2：关键字不能做标识符 ⭐

```java
int class = 1;       // ❌ class 是关键字
int return = 2;      // ❌ return 是关键字
int static = 3;      // ❌ static 是关键字
int true = 4;        // ❌ true 是保留字
int null = 5;        // ❌ null 是保留字
int myClass = 1;     // ✅ 大小写区分，myClass 不是关键字
```

### 重点 3：标识符区分大小写 ⭐

```java
int name = 1;
int Name = 2;   // ✅ name 和 Name 是两个不同的变量
int NAME = 3;   // ✅ 又是一个不同的变量
// 但这样写极不推荐，容易混淆
```

> ⚠️ Java 区分大小写，`name`、`Name`、`NAME` 是三个不同的标识符。但实际开发中不要仅靠大小写区分变量，可读性极差。

### 重点 4：驼峰命名法是行业铁律 ⭐⭐

```java
// ❌ 全大写当变量名（常量才全大写）
int USER_AGE = 18;

// ❌ 下划线当变量名（Python 风格，Java 不用）
int user_age = 18;

// ❌ 类名小写
class userservice { }

// ✅ 规范
int userAge = 18;          // 变量小驼峰
static final int MAX_AGE = 150;  // 常量全大写下划线
class UserService { }      // 类名大驼峰
```

> 📌 **团队规范优先**：如果公司有编码规范文档，以团队规范为准。但 99% 的 Java 团队都遵循驼峰命名法，这是 Java 圈的共识。

### 重点 5：见名知意比短命名重要 ⭐⭐

```java
// ❌ 为了短而短，丢失含义
void m(int a, int b) { }
List l = dao.q(1);

// ✅ 命名清晰，代码即文档
void deleteUser(int userId, int operatorId) { }
List<User> users = userDao.findById(1);
```

> 📌 **原则**：方法名应该能描述「做什么」，变量名应该能描述「是什么」。好的命名让代码不需要注释就能读懂。宁可名字长一点，也不要含义模糊。

### 重点 6：`null` 只能赋给引用类型 ⭐

```java
String s = null;        // ✅ String 是引用类型
int[] arr = null;       // ✅ 数组是引用类型
Object o = null;        // ✅

int n = null;           // ❌ int 是基本类型，不能赋 null
boolean b = null;       // ❌ boolean 是基本类型
// 基本类型有默认值：int=0, boolean=false，不存在 null
```

## 💻 实战案例

### 案例 1：见名知意——变量命名规范的重要性 ⭐⭐

实际项目中，糟糕的命名是维护噩梦。对比电商订单模块的命名：

```java
// ❌ 烂命名版：三个月后你自己都看不懂
class Svc {
    public int m(int a, int b, int c) {
        int d = a * b;
        int e = d - c;
        return e;
    }
}
// a 是什么？b 是什么？c 是什么？d 是什么？e 是什么？

// ✅ 好命名版：代码即文档，无需额外注释
class OrderService {
    /**
     * 计算订单实付金额。
     * @param unitPrice  商品单价（分）
     * @param quantity   购买数量
     * @param discount   优惠金额（分）
     * @return 实付金额（分）
     */
    public int calcPayableAmount(int unitPrice, int quantity, int discount) {
        int totalAmount = unitPrice * quantity;   // 商品总额
        int payableAmount = totalAmount - discount; // 实付金额
        return payableAmount;
    }
}
```

> 📌 **真实教训**：某电商项目因变量命名为 `a`、`b`、`tmp1`、`tmp2`，新人接手两周才理清业务逻辑，直接导致项目延期。命名规范不是小事，是工程效率问题。

### 案例 2：用 javadoc 生成接口文档 ⭐⭐

在前后端分离开发中，后端接口文档是前端联调的依据。除了 Swagger，`javadoc` 也能生成规范的 API 文档：

```java
package com.example.controller;

/**
 * 用户管理接口。
 * <p>提供用户的增删改查功能。</p>
 *
 * @author Leo
 * @version 1.0
 * @since 2024-01-01
 */
public class UserController {

    /**
     * 根据用户 ID 查询用户信息。
     * <p>示例请求：GET /user/1001</p>
     *
     * @param userId 用户 ID，必填，正整数
     * @return 用户信息对象
     * @throws IllegalArgumentException 用户 ID 为空或非正数
     * @throws UserNotFoundException    用户不存在
     * @see User
     */
    public User getUserById(Integer userId) {
        if (userId == null || userId <= 0) {
            throw new IllegalArgumentException("用户 ID 必须为正整数");
        }
        User user = userDao.findById(userId);
        if (user == null) {
            throw new UserNotFoundException("用户不存在: " + userId);
        }
        return user;
    }

    /**
     * 分页查询用户列表。
     *
     * @param pageNum  页码，从 1 开始，默认 1
     * @param pageSize 每页条数，默认 10，最大 100
     * @return 用户分页列表
     */
    public PageResult<User> listUsers(int pageNum, int pageSize) {
        return userDao.findByPage(pageNum, pageSize);
    }
}
```

生成文档命令：

```bash
# 生成 HTML 文档，指定编码避免中文乱码
javadoc -d apidoc -encoding UTF-8 -charset UTF-8 -docencoding UTF-8 ^
  -sourcepath src -subpackages com.example.controller
```

> 💡 在企业开发中，更常用的是 Swagger / SpringDoc（自动生成在线 API 文档），但 `javadoc` 生成的文档是 Java SDK、开源库的标准文档形式（如 JDK API 文档本身就是 `javadoc` 生成的）。

### 案例 3：常量定义——后台系统配置项 ⭐

后台系统中，魔法数字（magic number）是大忌。所有固定值都应定义为常量：

```java
// ❌ 魔法数字：散落在代码里，改一个要全局搜索
if (userType == 1) { }          // 1 是什么？
if (orderStatus == 5) { }       // 5 是什么？
if (retryCount > 3) { }        // 3 是什么？

// ✅ 常量定义：含义清晰，修改集中
public class Constants {
    // 用户类型
    public static final int USER_TYPE_ADMIN = 1;
    public static final int USER_TYPE_NORMAL = 2;
    public static final int USER_TYPE_VIP = 3;

    // 订单状态
    public static final int ORDER_STATUS_PENDING = 0;    // 待付款
    public static final int ORDER_STATUS_PAID = 1;       // 已付款
    public static final int ORDER_STATUS_SHIPPED = 2;    // 已发货

if (userType == Constants.USER_TYPE_ADMIN) { }
```

### 案例 4：注释的合理使用——金融系统风控规则 ⭐

注释不是越多越好，而是要解释「为什么」，而不是「是什么」：

```java
// ❌ 无用注释：复述代码，毫无价值
// 把价格乘以数量
int total = price * quantity;
// 返回结果
return total;

// ✅ 有价值注释：解释业务背景和「为什么」
public boolean checkRisk(Order order) {
    // 风控规则：单笔订单超过 10 万需人工审核（合规要求，见风控文档 R-003）
    if (order.getAmount() > 100000) {
        return needManualReview(order);
    }

    // 同一用户 1 小时内下单超过 5 次，疑似刷单（反欺诈策略 F-012）
    int recentOrders = orderDao.countByUserAndTime(order.getUserId(), 1);
    if (recentOrders > 5) {
        return needManualReview(order);
    }

    return true;  // 风控通过
}
```

> 📌 **注释原则**：好代码尽量自解释（靠命名），注释只用于解释「为什么这样做」（业务背景、合规要求、技术选型原因），而不是「在做什么」（代码本身已说明）。

## 🚀 新版本补充

### Java 9：javadoc HTML5 支持

Java 9 的 `javadoc` 支持生成 HTML5 格式文档，并增加了搜索功能：

```bash
# Java 9+ 生成 HTML5 文档，自带搜索框
javadoc -d apidoc -html5 -encoding UTF-8 MyClass.java
```

### Java 10：局部变量类型推断 `var`

`var` 让局部变量声明更简洁，但不影响命名规范（变量名仍要小驼峰）：

```java
// Java 8
Map<String, List<User>> userMap = new HashMap<>();
String userName = userService.getName(id);

// Java 10+ 用 var 简化（类型由编译器推断）
var userMap = new HashMap<String, List<User>>();
var userName = userService.getName(id);
```

> ⚠️ `var` 只是语法糖，编译后仍是强类型。不能用于成员变量、方法参数、返回值。Java 8 环境不可用。

### Java 16：Records（记录类）

Java 16 正式引入 `record`，用极简语法定义数据载体类，自动生成构造器、getter、equals 等：

```java
// Java 16+ 一行定义一个数据类
public record User(Integer id, String name, Integer age) {}

// 等价于传统写法几十行：构造器、getter、equals、hashCode、toString 全自动生成
// 适合 DTO、VO 等纯数据类，命名仍遵循大驼峰规范
```

> 💡 Records 是 Java 14 预览、16 正式的特性，Java 8 环境不可用，了解即可。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 三种注释 | 单行 `//`、多行 `/* */`、文档注释 `/** */` |
| 文档注释 | 配合 `javadoc` 生成 API 文档，公共方法必写 |
| 关键字 | 50 个左右，全小写，不能做标识符 |
| 保留字 | `true`、`false`、`null`、`goto`、`const` |
| 标识符规则 | 字母/`_`/`$` 开头，不能数字开头，不能是关键字 |
| 区分大小写 | `name` 和 `Name` 是不同标识符 |
| 包名 | 全小写，域名倒写 |
| 类名 | 大驼峰 `UserService` |
| 方法/变量名 | 小驼峰 `getUserName` |
| 常量 | 全大写下划线 `MAX_VALUE` |
| 字面量 | 整数、小数、字符、字符串、布尔、null |
| 命名核心 | 见名知意，宁可长不要模糊 |

## 学习建议

1. **立刻用 IDE 体验 javadoc**：写一个带 `@param`、`@return` 的方法，运行 `javadoc` 命令生成 HTML 文档，亲眼看到注释变成网页文档，你会理解文档注释的价值。
2. **检查自己代码的命名**：把之前写的代码翻出来，逐个检查变量名、方法名是否符合驼峰规范，是否有 `a`、`b`、`tmp` 这类无意义命名，全部改掉。
3. **不要背关键字表**：写代码自然就记住了。重点理解 `final`/`finally`/`finalize`、`throw`/`throws`、`this`/`super` 这几组易混淆的。
4. **养成「好命名」习惯**：每次写变量名前问自己「三个月后我还看得懂吗？同事看得懂吗？」。好命名是程序员的基本功，面试看代码质量时第一眼就是命名。
5. **注释写「为什么」不写「是什么」**：注释解释业务背景、技术决策原因，而不是复述代码逻辑。代码本身应该是最好的说明文档。
