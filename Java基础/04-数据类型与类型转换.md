# 数据类型与类型转换

Java 是**强类型语言**：每个变量在使用前必须声明类型，且类型在编译期就严格检查。理解数据类型是写出正确、健壮代码的起点——很多诡异的 bug（金额算错、整数溢出、精度丢失）都根源于此。

> 💡 在阅读本篇前，建议先看 [02-JVM内存模型](02-JVM内存模型.md)，理解「栈存基本类型值、堆存对象」的内存差异，会更容易理解下面的引用类型与参数传递。

---

## 一、数据类型总览

Java 数据类型分两大类：

```
Java 数据类型
├── 基本数据类型（8 种，存于栈/直接存值）
│   ├── 整型：byte、short、int、long
│   ├── 浮点型：float、double
│   ├── 字符型：char
│   └── 布尔型：boolean
└── 引用数据类型（存于堆，变量存的是地址）
    ├── 类（String、自定义类…）
    ├── 接口
    └── 数组
```

> 💡 **记忆口诀**：整型 4 个（byte/short/int/long）、浮点 2 个（float/double）、字符 1 个（char）、布尔 1 个（boolean），共 8 种基本类型。

## 二、基本数据类型

### 2.1 整数类型

| 类型 | 占用空间 | 取值范围 | 默认值 | 备注 |
| :--- | :---: | :--- | :---: | :--- |
| `byte` | 1 字节 | -128 ~ 127 | 0 | 字节流 IO 常用 |
| `short` | 2 字节 | -32768 ~ 32767 | 0 | 很少用 |
| `int` | 4 字节 | -2³¹ ~ 2³¹-1（约 ±21 亿） | 0 | **默认整型** |
| `long` | 8 字节 | -2⁶³ ~ 2⁶³-1 | 0 | 需加 `L` 后缀 |

```java
int i = 100;          // 整数字面量默认是 int
long l = 10000000000L; // 超出 int 范围必须加 L 后缀
long bad = 10000000000; // ❌ 编译错误：整数太大
```

### 2.2 浮点类型

| 类型 | 占用空间 | 取值范围 | 默认值 | 备注 |
| :--- | :---: | :--- | :---: | :--- |
| `float` | 4 字节 | 约 ±3.4E38（6~7 位有效数字） | 0.0f | 需加 `F` 后缀 |
| `double` | 8 字节 | 约 ±1.7E308（15 位有效数字） | 0.0d | **默认浮点型** |

```java
double d = 3.14;      // 浮点字面量默认是 double
float f = 3.14F;      // float 必须加 F 后缀
float bad = 3.14;     // ❌ 编译错误：从 double 转 float 可能损失精度
```

> ⚠️ **为什么 float 范围比 long 大，却只占 4 字节？**
> 浮点数用 IEEE 754 科学计数法存储（符号位 + 指数位 + 尾数位），指数位决定范围，尾数位决定精度。所以 `float` 表示范围远大于 `long`，但精度（有效数字）有限。

### 2.3 字符类型

`char` 是**无符号 16 位整数**，用 Unicode 编码存储，可存任意一个字符（含中文），也可当整数参与运算。

```java
char c1 = 'A';
char c2 = '中';        // 一个 char 可存一个汉字
char c3 = 65;          // ✅ 65 就是 'A' 的 Unicode 码
System.out.println(c1 + 0);   // 65，char 参与运算会提升为 int
System.out.println((char) (c1 + 32));  // 'a'，大小写转换常用
```

### 2.4 布尔类型

`boolean` 只有 `true` / `false` 两个值，默认 `false`。占用空间不明确（JVM 规范未定义精确大小，通常按 1 字节或 4 字节实现）。

```java
boolean flag = true;
// boolean b = 1;  // ❌ Java 不允许 0/1 当布尔用（与 C 不同）
```

## 三、引用数据类型

类、接口、数组都是引用类型。最常用的是 `String`：

```java
String s = "hello";   // String 是引用类型，不是基本类型！
String s2 = new String("hello");
```

> ⚠️ **新手最常踩的坑**：把 `String` 当基本类型。`String` 是类，比较内容要用 `.equals()`，不能用 `==`（详见 [18-字符串](18-字符串String与StringBuilder.md)）。

引用类型变量存的是对象在**堆**中的地址，基本类型变量存的是值本身：

```java
int a = 10;
int b = a;      // 值拷贝，b 改变不影响 a
b = 20;
System.out.println(a);  // 10

int[] arr1 = {1, 2, 3};
int[] arr2 = arr1;  // 地址拷贝，arr2 改变会影响 arr1
arr2[0] = 99;
System.out.println(arr1[0]);  // 99
```

## 四、类型转换

### 4.1 自动类型转换（隐式，小 → 大）

取值范围小的类型自动提升为大的类型，无需手动操作：

```
byte → short → int → long → float → double
                ↑
               char
```

```java
int i = 100;
long l = i;        // int → long，自动
double d = l;       // long → double，自动
System.out.println('A' + 1);  // 66，char → int 自动提升
```

### 4.2 强制类型转换（显式，大 → 小）

大范围转小范围**可能丢失精度/溢出**，必须显式强转：

```java
int i = (int) 3.99;   // 3，直接截断小数（不是四舍五入！）
int big = 300;
byte b = (byte) big;  // 44，溢出：300 超出 byte 范围，结果不可预期
```

> ⚠️ 强转的本质是**截断高位字节**。300 的二进制是 `100101100`，byte 只留低 8 位 `00101100` = 44。

## ⚠️ 重点

### 重点 1：`long` 字面量必须加 `L`

```java
long l1 = 10000000000L;   // ✅
long l2 = 10000000000;    // ❌ 编译错误：整数太大
// 原因：整数字面量默认是 int，10 后面 9 个 0 已超出 int 范围
```

> 💡 建议：**所有 long 字面量都加 L**，养成习惯，避免大数编译错误。注意是大写 `L`（小写 `l` 容易和 `1` 混淆）。

### 重点 2：`float` 字面量必须加 `F`

```java
float f = 3.14F;   // ✅
float f2 = 3.14;   // ❌ 编译错误：double 转 float 可能损失精度
```

### 重点 3：`byte`/`short` 运算会提升为 `int` ⭐

这是新手最常遇到的编译错误：

```java
byte a = 3;
byte b = 4;
byte c = a + b;          // ❌ 编译错误：a+b 结果是 int，不能直接赋给 byte
byte c2 = (byte)(a + b); // ✅ 强转
byte c3 = 3 + 4;         // ✅ 常量折叠：编译期算出 7，在 byte 范围内
```

> ⚠️ **规则**：`byte`、`short`、`char` 参与算术运算时，会**先提升为 `int`** 再计算，结果也是 `int`。只有「编译期常量」相加（如 `3 + 4`）才会被编译器折叠。

`char` 同理：

```java
char c = 'A';
int n = c + 1;    // 66，char 提升为 int
char c2 = c + 1;  // ❌ 编译错误：结果是 int
char c3 = (char)(c + 1);  // ✅ 'B'
```

### 重点 4：浮点数精度丢失（金额计算灾难）⭐⭐

```java
System.out.println(0.1 + 0.2);   // 0.30000000000000004  ❌
System.out.println(2.0 - 1.1);  // 0.8999999999999999   ❌
System.out.println(1.0 - 0.42); // 0.5800000000000001   ❌
```

> ⚠️ **这是浮点数最危险的坑**：`double` 用二进制无法精确表示十进制小数（类似十进制无法精确表示 1/3）。**凡是涉及金额、利率、计量的计算，绝对不能用 float/double！**

### 重点 5：`++` / `--` 的运算提升

```java
byte b = 10;
b = b + 1;   // ❌ b+1 是 int
b++;         // ✅ 自增有强制转换的隐藏动作，等价于 b = (byte)(b+1)
b += 1;      // ✅ 复合赋值也隐藏强转
```

> 💡 复合赋值（`+=`、`-=` 等）自带隐式强转，这是它与 `b = b + 1` 的关键区别。

### 重点 6：`boolean` 不参与数值转换

```java
boolean flag = true;
// int x = flag;     // ❌ boolean 不能转 int
// boolean b = 1;    // ❌ int 不能转 boolean
```

## 💻 实战案例

### 案例 1：金额计算必须用 BigDecimal ⭐⭐

这是开发中最典型的精度问题。电商、金融场景必考：

```java
import java.math.BigDecimal;

// ❌ 错误：用 double 算钱
double price = 0.1;
double total = price * 3;
System.out.println(total);  // 0.30000000000000004，账目对不上

// ✅ 正确：用 BigDecimal
// 注意：必须用 String 构造！
BigDecimal bd1 = new BigDecimal("0.1");
BigDecimal bd2 = new BigDecimal("0.2");
System.out.println(bd1.add(bd2));       // 0.3，精确
System.out.println(bd1.multiply(new BigDecimal("3")));  // 0.3

// ⚠️ 陷阱：用 double 构造 BigDecimal 仍会带进精度问题
BigDecimal wrong = new BigDecimal(0.1);
System.out.println(wrong);  // 0.1000000000000000055511151231257827021181583404541015625
BigDecimal right = BigDecimal.valueOf(0.1);  // ✅ valueOf 内部先转 String
System.out.println(right);  // 0.1
```

> 📌 **开发规范**：金额一律用 `BigDecimal` + `String` 构造；除法必须指定精度 `setScale(2, RoundingMode.HALF_UP)`，否则除不尽会抛 `ArithmeticException`。

### 案例 2：整数溢出——计算天数

```java
long millis = System.currentTimeMillis();         // 当前时间毫秒
int days = (int)(millis / 1000 / 60 / 60 / 24);   // ❌ 溢出！
// millis 约 1.7 万亿，除以 86400 后仍约 1900 万，看似在 int 范围内
// 但中间过程若先算乘法极易溢出

// ✅ 正确：全程用 long
long daysL = millis / 1000 / 60 / 60 / 24;
System.out.println(daysL);  // 约 20000 天
```

### 案例 3：char 当密码位移运算（凯撒密码）

```java
// 字符与整数的转换，常用于简单加密
char ch = 'H';
int shift = 3;
char encrypted = (char)(ch + shift);   // 'K'
char decrypted = (char)(encrypted - shift);  // 'H'
System.out.println(encrypted + " -> " + decrypted);
```

## 🚀 新版本补充

### Java 7：二进制字面量与下划线分隔

```java
int binary = 0b1010;          // 二进制，= 10
int big = 1_000_000_000;      // 下划线分隔，提高可读性，编译期忽略
long creditCard = 1234_5678_9012_3456L;
```

### Java 8+：无新增基本类型

Java 8 没有新增基本数据类型，但提供了 `OptionalInt`、`IntStream` 等对基本类型的流式封装（见 [46-函数式编程](46-函数式编程.md)）。

### Java 10：局部变量类型推断 `var`（补充了解）

```java
var i = 10;          // 编译期推断为 int，仍是强类型
var s = "hello";     // 推断为 String
// var 只是语法糖，编译后等价于显式声明类型，不是动态类型
```

> ⚠️ `var` 只能用于局部变量，不能用于成员变量、方法参数、返回值。Java 8 环境下不可用，了解即可。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 8 种基本类型 | byte/short/int/long、float/double、char、boolean |
| 默认类型 | 整型默认 int，浮点默认 double |
| 后缀 | long 加 `L`，float 加 `F` |
| 自动转换 | 小 → 大，隐式 |
| 强制转换 | 大 → 小，显式，可能丢精度/溢出 |
| 运算提升 | byte/short/char 运算 → int |
| 精度问题 | 金额用 BigDecimal(String 构造) |

## 学习建议

1. **动手验证每个易错点**：把上面 6 个易错点的代码原样敲进 IDE 运行一遍，亲眼看到编译错误和诡异输出，比看十遍文字都管用。
2. **牢记两个后缀**：`long` 加 `L`、`float` 加 `F`，从写第一行代码就养成习惯，能省掉一半编译错误。
3. **建立 BigDecimal 肌肉记忆**：金额计算是开发高频踩坑点，务必记住「String 构造 + 除法指定精度」这两条铁律，面试也常考。
4. **理解内存差异**：基本类型存值、引用类型存地址——这个区别会贯穿后续所有章节（参数传递、集合、== 比较），建议结合 [02-JVM内存模型](02-JVM内存模型.md) 一起理解，不要死记。
5. **不要背取值范围**：知道 `int` 约 21 亿、`long` 很大就够了，精确范围用时查表即可。重点是理解「范围大小关系」决定能否自动转换。
