# 接口

接口（Interface）是 Java 中最重要的抽象机制之一。如果说类是「对象的模板」，那么接口就是「行为的规范」——它只定义「能做什么」，不关心「谁来做、怎么做」。Java 的接口是 `has-a` 关系的体现（某物「具有」某能力），也是 Java 实现多态、解耦、策略模式的核心工具。掌握接口，是从「写能跑的代码」到「写可维护的架构」的关键一步。

> 💡 在阅读本篇前，建议先回顾 [12-抽象类](12-抽象类.md) 中关于抽象方法、继承的内容，理解了抽象类再来看接口，会事半功倍。

---

## 一、接口是什么

### 1.1 从现实生活理解接口

生活中到处是「接口」：

- USB 接口：只要插口形状符合标准，鼠标、U 盘、键盘都能用，不关心内部原理
- 电源插座：220V 两孔/三孔标准，任何符合标准的电器都能通电
- 驾照：定义了「能驾驶」这个能力，不区分你开的是轿车还是卡车

接口的本质就是**一套规范/标准**：定义了「该做什么」，但把「怎么做」留给实现者。

### 1.2 接口的基本语法

用 `interface` 关键字定义接口：

```java
// 定义接口：飞行能力
public interface Flyable {
    // 抽象方法（默认 public abstract，可省略）
    void fly();
}

// 定义接口：游泳能力
public interface Swimmable {
    void swim();
}
```

接口的命名规范：推荐用**形容词**（`Comparable`、`Runnable`、`Serializable`）或 `able` 后缀，表示「可……的」能力。

> 📌 **规范**：接口名用大驼峰，尽量用形容词或名词短语。JDK 中的接口如 `Comparable`（可比较的）、`Runnable`（可运行的）、`Iterable`（可迭代的）都是好范例。

### 1.3 接口是一种「引用类型」

接口和类一样，是一种引用数据类型。它不能直接 `new` 出对象（Java 8 的匿名内部类除外，本质仍是创建实现类对象）：

```java
Flyable f = new Flyable();  // ❌ 编译错误：接口不能直接实例化
Flyable f2 = new Flyable() {  // ✅ 匿名内部类，本质是创建了实现类对象
    public void fly() {
        System.out.println("我在飞");
    }
};
```

## 二、接口的内容（按版本演进）

接口里能写什么，是 Java 版本演进中最有故事的部分。从 Java 7 到 Java 9，接口的能力逐步增强：

| 版本 | 可包含的内容 | 关键字/修饰符 |
| :---: | :--- | :--- |
| Java 7 | 常量、抽象方法 | `public static final`、`public abstract`（均默认） |
| Java 8 | 新增 default 默认方法、static 静态方法 | `default`、`static` |
| Java 9 | 新增 private 私有方法 | `private` |

### 2.1 Java 7：常量与抽象方法

最「纯粹」的接口，只有两样东西：

```java
public interface Constants {
    // 常量：默认且必须是 public static final，可省略
    int MAX_SIZE = 100;               // 等价于 public static final int MAX_SIZE = 100;
    String DEFAULT_NAME = "默认";     // 等价于 public static final String DEFAULT_NAME = "默认";

    // 抽象方法：默认且必须是 public abstract，可省略
    void doSomething();              // 等价于 public abstract void doSomething();
}
```

> ⚠️ **重要**：接口中的变量**默认就是** `public static final`，即使你不写这三个修饰符。这意味着接口里的「变量」其实是**常量**，必须赋初值，且不可修改：
>
> ```java
> public interface Bad {
>     int count;              // ❌ 编译错误：常量必须初始化
> }
> public interface Good {
>     int count = 0;          // ✅ 实际是 public static final int count = 0
>     // count = 1;           // ❌ 编译错误：final 不可重新赋值
> }
> ```

> 💡 **为什么接口常量默认是 static final？**
> 接口不能实例化（没有对象），所以成员必须是 `static` 的，通过接口名访问；接口是规范，规范不应被实现者随意篡改，所以是 `final` 的。

### 2.2 Java 8：default 默认方法 ⭐

Java 8 之前，接口只能有抽象方法。这带来一个痛点：**接口升级灾难**。

假设你的 `List` 接口被 100 个类实现了，现在你想给 `List` 加一个 `stream()` 方法——按 Java 7 的规则，所有 100 个实现类都必须重写它，否则编译报错。这在 JDK 这种被广泛使用的库里根本无法推行。

Java 8 的 `default` 方法解决了这个问题：**接口可以提供默认实现，实现类不强制重写**。

```java
public interface Greetable {
    // 抽象方法：实现类必须重写
    String getName();

    // default 方法：有方法体，实现类可以不重写（也可重写覆盖）
    default void greet() {
        System.out.println("你好，" + getName() + "！");
    }
}

// 实现类：只重写抽象方法，greet() 直接用默认实现
public class Person implements Greetable {
    private String name;
    public Person(String name) { this.name = name; }

    @Override
    public String getName() { return name; }
    // 没有重写 greet()，但可以调用
}

Person p = new Person("张三");
p.greet();   // 输出：你好，张三！
```

> 💡 **default 方法的价值**：
> 1. **接口升级**：给老接口加方法而不破坏现有实现（JDK 8 给 `Collection` 加了 `stream()`、`forEach()` 等）。
> 2. **提供可选功能**：实现类按需重写，不重写也有默认行为。

### 2.3 Java 8：static 静态方法

Java 8 允许在接口中定义 `static` 方法，通过**接口名直接调用**，类似工具方法：

```java
public interface StringUtils {
    // static 方法：用接口名调用，不能被实现类继承
    static boolean isEmpty(String s) {
        return s == null || s.length() == 0;
    }

    static boolean isBlank(String s) {
        return s == null || s.trim().isEmpty();
    }
}

// 调用方式：接口名.方法名()
boolean b1 = StringUtils.isEmpty("");    // true
boolean b2 = StringUtils.isBlank("  ");   // true
```

> ⚠️ **static 方法与 default 方法的区别**：
> - `default` 方法是**实例方法**，通过实现类对象调用，可被重写
> - `static` 方法是**类方法**，通过接口名调用，**不能被实现类继承/重写**
>
> ```java
> public class MyString implements StringUtils {
>     // ❌ 不能重写接口的 static 方法，也不存在继承
> }
> // MyString.isEmpty("x");  // ❌ 编译错误，static 方法属于接口
> ```

> 💡 **设计意义**：以前工具方法要放在伴生类里（如 `Collection` 接口 + `Collections` 工具类）。Java 8 后可以直接放进接口，减少类爆炸。JDK 把 `Comparator.comparing()` 等工厂方法就放在了接口里。

### 2.4 Java 9：private 私有方法

当接口里有多个 `default`/`static` 方法存在重复逻辑时，Java 9 允许用 `private` 方法抽取公共代码：

```java
public interface Validator {

    default boolean isValidName(String name) {
        return checkNotEmpty(name) && name.length() <= 20;
    }

    default boolean isValidCode(String code) {
        return checkNotEmpty(code) && code.length() <= 10;
    }

    // Java 9 私有方法：抽取公共逻辑，仅供接口内部使用
    private boolean checkNotEmpty(String s) {
        return s != null && !s.trim().isEmpty();
    }

    // 也可以是 private static，供 static 方法调用
    private static String trim(String s) {
        return s == null ? "" : s.trim();
    }
}
```

> 💡 **private 方法解决什么**：让 `default`/`static` 方法之间能复用代码，又不把这些辅助方法暴露给实现类（保持接口简洁）。Java 8 没有这个能力，只能把公共逻辑写死在每个方法里，或放到外部工具类。

## 三、实现接口与多实现

### 3.1 implements 实现接口

类用 `implements` 关键字实现接口，**必须重写所有抽象方法**，否则该类要声明为 `abstract`：

```java
public interface Animal {
    void eat();
    void sleep();
}

// ✅ 完整实现：重写所有抽象方法
public class Dog implements Animal {
    @Override
    public void eat() { System.out.println("狗吃骨头"); }

    @Override
    public void sleep() { System.out.println("狗趴着睡"); }
}

// ❌ 不完整实现：必须声明为 abstract
public abstract class Cat implements Animal {
    @Override
    public void eat() { System.out.println("猫吃鱼"); }
    // sleep() 没重写，所以 Cat 必须是抽象类
}
```

> 📌 **规范**：重写接口方法时，访问修饰符**必须**是 `public`（接口方法默认 `public abstract`，子类重写不能降低可见性）。漏写 `public` 是新手最常见的编译错误：
>
> ```java
> public class Dog implements Animal {
>     void eat() { }   // ❌ 编译错误：eat() 无法实现 Animal 中的方法，访问权限更低
>     public void sleep() { }  // ✅ 必须 public
> }
> ```

### 3.2 一个类实现多个接口

Java 类**单继承**（只能 `extends` 一个父类），但可以**多实现**（`implements` 多个接口）。这是 Java 用接口弥补单继承限制的关键设计：

```java
public interface Flyable { void fly(); }
public interface Swimmable { void swim(); }
public interface Barkable { void bark(); }

// ✅ 一个类实现多个接口，用逗号分隔
public class Duck implements Flyable, Swimmable, Barkable {
    @Override
    public void fly() { System.out.println("鸭子飞"); }

    @Override
    public void swim() { System.out.println("鸭子游"); }

    @Override
    public void bark() { System.out.println("嘎嘎嘎"); }
}

Duck d = new Duck();
d.fly();   // 鸭子飞
d.swim();  // 鸭子游
d.bark();  // 嘎嘎嘎
```

> 💡 **为什么类是单继承、接口可多实现？**
> 类的继承带有**成员变量**和**实现代码**，多继承会引发「菱形问题」（两个父类有同名方法，子类不知继承谁的）。接口多实现之所以安全，是因为 Java 7 的接口没有实现体（抽象方法谁实现都行），Java 8 后虽有 default 方法，但通过**冲突解决规则**（见第四节）规避了菱形问题。

### 3.3 接口之间的多继承

接口之间用 `extends` 继承，且**可以多继承**（类不行）：

```java
public interface A { void methodA(); }
public interface B { void methodB(); }

// 接口可以多继承多个父接口
public interface C extends A, B {
    void methodC();
}

// 实现 C 的类，必须重写 A、B、C 三个接口的所有抽象方法
public class CImpl implements C {
    @Override public void methodA() { }
    @Override public void methodB() { }
    @Override public void methodC() { }
}
```

> 💡 接口多继承之所以安全：父接口都是抽象方法（或 default 方法有冲突规则），不会像类多继承那样产生「继承谁的实现」的歧义。

## 四、默认方法的冲突处理

Java 8 引入 default 方法后，多实现就可能产生冲突：两个接口有同名同参的 default 方法，实现类该用谁的？

### 4.1 多实现冲突：必须重写

```java
public interface A {
    default void hello() { System.out.println("A 的 hello"); }
}

public interface B {
    default void hello() { System.out.println("B 的 hello"); }
}

// ❌ 冲突：A 和 B 都有 default hello()，编译报错
public class C implements A, B {
}

// ✅ 解决：实现类必须重写 hello()，自己决定逻辑
public class C implements A, B {
    @Override
    public void hello() {
        System.out.println("C 自己的 hello");
    }
}

// ✅ 也可以显式调用某个父接口的默认实现：接口名.super.方法名
public class C implements A, B {
    @Override
    public void hello() {
        A.super.hello();   // 明确用 A 的默认实现
        B.super.hello();   // 明确用 B 的默认实现
    }
}
```

> ⚠️ **规则**：两个接口提供同名同参的 default 方法时，实现类**必须重写**该方法，否则编译错误。重写时可用 `接口名.super.方法名()` 显式选择某一边的默认实现。

### 4.2 父类方法优先于接口默认方法

当一个类既有父类（继承）又有接口（实现），且父类和接口有同名方法时，**父类优先**：

```java
public class Father {
    public void hello() { System.out.println("Father 的 hello"); }
}

public interface Greetable {
    default void hello() { System.out.println("Greetable 的 hello"); }
}

// 父类方法优先于接口默认方法
public class Son extends Father implements Greetable {
    // 不需要重写 hello()，直接用 Father 的
}

Son s = new Son();
s.hello();   // 输出：Father 的 hello（父类赢）
```

> 💡 **优先级规则**（记住这条线）：
> 1. **类（父类）的具体方法** > 接口的 default 方法
> 2. 子类重写的方法 > 一切
> 3. 多个接口冲突 → 必须重写
>
> 这保证了 Java 8 给接口加 default 方法（如 `Collection.stream()`）时，不会破坏那些父类已有同名方法的类——向后兼容。

### 4.3 两条冲突解决规则速记

| 场景 | 解决方式 |
| :--- | :--- |
| 两个接口有同名 default 方法 | 实现类**必须重写**，可用 `接口名.super.方法()` 选择 |
| 父类方法 vs 接口 default 方法 | **父类优先**，接口 default 被忽略 |
| 父接口与子接口有同名 default 方法 | **子接口优先**（更具体的赢） |

```java
public interface Parent {
    default void hello() { System.out.println("Parent"); }
}
public interface Child extends Parent {
    @Override
    default void hello() { System.out.println("Child"); }  // 子接口覆盖父接口
}

public class Impl implements Child { }
new Impl().hello();   // Child（子接口优先）
```

## 五、接口与抽象类的区别 ⭐⭐

这是面试必考、设计必思的核心问题。两者都能做抽象，但**设计意义不同**：

### 5.1 设计意义：is-a vs has-a

```java
// 抽象类：is-a（是一个）——模板式继承
public abstract class Animal {
    abstract void breathe();   // 所有动物都要呼吸
}
public class Dog extends Animal { }   // Dog「是一个」Animal

// 接口：has-a（有……能力）——行为规范
public interface Flyable { void fly(); }
public class Bird extends Animal implements Flyable { }  // Bird「有」飞行能力
```

| 对比项 | 抽象类 | 接口 |
| :--- | :--- | :--- |
| **设计意义** | `is-a`，是什么（模板） | `has-a`，能做什么（能力） |
| **关键字** | `abstract class` | `interface` |
| **继承关系** | 单继承（一个类只能 extends 一个抽象类） | 多实现（一个类可 implements 多个接口） |
| **成员变量** | 可有普通变量、可修改 | 只能是 `public static final` 常量 |
| **构造方法** | 有（供子类调用） | 无 |
| **代码块** | 可有静态块、实例块 | 无 |
| **方法** | 抽象 + 具体方法 | 抽象 + default + static +（Java 9）private |
| **访问修饰符** | 成员可用各种权限 | 默认且只能是 `public`（private 方法除外） |
| **使用场景** | 定义一族类的**共性模板** | 定义**跨类族的统一行为** |

### 5.2 什么时候用抽象类，什么时候用接口

```java
// ✅ 抽象类：当一组类有「强共性」——共享字段、共享实现
public abstract class Shape {
    protected String color;   // 共享字段
    public abstract double area();   // 抽象方法
    public void describe() {        // 共享实现
        System.out.println("颜色：" + color + "，面积：" + area());
    }
}

// ✅ 接口：当跨类族需要「统一行为」——不共享字段，只共享能力
public interface Comparable<T> {
    int compareTo(T o);   // 任何类都可以「可比较」，不必有共同父类
}
public interface Serializable { }   // 标记接口：任何类都可序列化
```

> 📌 **选择原则**：
> - 如果要**共享字段和实现代码**，用抽象类（如 `AbstractList` 把 `List` 的通用实现抽出来）
> - 如果只是**定义统一行为规范**，跨不同类族复用，用接口（如 `Comparable`、`Runnable`）
> - 实际开发中常**结合使用**：接口定义规范，抽象类提供骨架实现（JDK 的 `List` 接口 + `AbstractList` 抽象类就是典范）

## 六、函数式接口铺垫

如果一个接口**有且只有一个抽象方法**（default、static、private 方法不计），它就是「函数式接口」，可以用 Lambda 简化：

```java
// 函数式接口：只有一个抽象方法
@FunctionalInterface   // 可选注解，编译器会检查是否符合规范
public interface Calculator {
    int calc(int a, int b);
}

// 传统匿名内部类写法
Calculator c1 = new Calculator() {
    @Override
    public int calc(int a, int b) { return a + b; }
};

// ✅ Lambda 写法（Java 8，更简洁）
Calculator c2 = (a, b) -> a + b;
System.out.println(c2.calc(3, 4));   // 7
```

> 💡 `@FunctionalInterface` 注解是**可选**的，但建议加上：它让编译器帮你检查「是否只有一个抽象方法」，防止以后误加方法破坏函数式接口特性。JDK 内置的 `Runnable`、`Comparator`、`Callable` 都是函数式接口。Lambda 的详细用法见 [15-Lambda与函数式接口](15-Lambda与函数式接口.md)。

## ⚠️ 重点

### 重点 1：接口里的变量是常量，不是普通成员变量 ⭐

```java
public interface Config {
    int MAX = 100;          // 实际是 public static final int MAX = 100
    String NAME = "app";    // 实际是 public static final String NAME = "app"
}

// 通过接口名访问
System.out.println(Config.MAX);   // 100

// ❌ 不能修改
// Config.MAX = 200;   // 编译错误：final 不可重新赋值
```

> ⚠️ 新手常误以为接口里的变量可以像类成员变量那样修改。记住：接口里**没有真正的变量**，全是常量。

### 重点 2：实现接口方法必须用 public ⭐

```java
public interface Animal {
    void eat();   // 默认 public abstract
}

public class Dog implements Animal {
    // ❌ 错误：默认权限（包级）比 public 小，无法重写
    // void eat() { }

    // ✅ 正确：必须 public
    @Override
    public void eat() { }
}
```

> ⚠️ 接口方法默认 `public abstract`，重写时访问权限**不能更小**。漏写 `public` 是最常见的编译错误。

### 重点 3：接口不能有构造方法和普通成员变量 ⭐

```java
public interface Wrong {
    // int x;              // ❌ 常量必须初始化
    // public Wrong() { } // ❌ 接口不能有构造方法
    // { }                // ❌ 接口不能有实例初始化块
    // static { }         // ❌ 接口不能有静态初始化块（Java 8）
    int x = 0;             // ✅ 常量
    default void f() { }  // ✅ default 方法
}
```

### 重点 4：default 方法冲突必须重写 ⭐⭐

```java
interface A { default void hello() { System.out.println("A"); } }
interface B { default void hello() { System.out.println("B"); } }

// ❌ 编译错误：A、B 都有 default hello()
// class C implements A, B { }

// ✅ 必须重写
class C implements A, B {
    @Override
    public void hello() {
        A.super.hello();   // 选择 A 的实现
    }
}
```

### 重点 5：父类优先于接口默认方法 ⭐

```java
class Father { public void hello() { System.out.println("Father"); } }
interface Greetable { default void hello() { System.out.println("Greetable"); } }

class Son extends Father implements Greetable { }   // 不用重写
new Son().hello();   // Father（父类赢）
```

### 重点 6：接口的 static 方法不能被实现类继承 ⭐

```java
public interface Tool {
    static void help() { System.out.println("Tool.help"); }
}
public class MyTool implements Tool { }

// MyTool.help();   // ❌ 错误：static 方法属于接口，不被继承
Tool.help();        // ✅ 只能用接口名调用
```

> 💡 这和「类的 static 方法能被子类继承」不同，是接口 static 方法的特殊规则。

## 💻 实战案例

### 案例 1：电商促销策略模式（DiscountStrategy）⭐⭐

电商系统中，促销规则多变：满减、打折、优惠券、限时秒杀……用接口 + 策略模式，让规则可插拔、易扩展：

```java
// 策略接口：折扣计算
public interface DiscountStrategy {
    /**
     * 计算折扣后的价格
     * @param originalPrice 原价
     * @return 实付价
     */
    BigDecimal calculate(BigDecimal originalPrice);
}

// 满减策略：满 200 减 30
public class FullReductionDiscount implements DiscountStrategy {
    private BigDecimal threshold = new BigDecimal("200");
    private BigDecimal reduction = new BigDecimal("30");

    @Override
    public BigDecimal calculate(BigDecimal originalPrice) {
        if (originalPrice.compareTo(threshold) >= 0) {
            return originalPrice.subtract(reduction);
        }
        return originalPrice;
    }
}

// 打折策略：8 折
public class PercentageDiscount implements DiscountStrategy {
    private BigDecimal rate = new BigDecimal("0.8");

    @Override
    public BigDecimal calculate(BigDecimal originalPrice) {
        return originalPrice.multiply(rate).setScale(2, BigDecimal.ROUND_HALF_UP);
    }
}

// 优惠券策略：抵扣券
public class CouponDiscount implements DiscountStrategy {
    private BigDecimal couponValue;

    public CouponDiscount(BigDecimal couponValue) { this.couponValue = couponValue; }

    @Override
    public BigDecimal calculate(BigDecimal originalPrice) {
        BigDecimal result = originalPrice.subtract(couponValue);
        return result.compareTo(BigDecimal.ZERO) > 0 ? result : BigDecimal.ZERO;  // 不低于 0
    }
}

// 使用：根据用户选择的促销方式，传入不同策略
public class OrderService {
    public BigDecimal checkout(BigDecimal price, DiscountStrategy strategy) {
        return strategy.calculate(price);
    }
}

OrderService service = new OrderService();
// 满 250，满减后 220
System.out.println(service.checkout(new BigDecimal("250"), new FullReductionDiscount()));
// 满 250，8 折后 200
System.out.println(service.checkout(new BigDecimal("250"), new PercentageDiscount()));
// 满 250，用 50 元券，实付 200
System.out.println(service.checkout(new BigDecimal("250"), new CouponDiscount(new BigDecimal("50"))));
```

> 📌 **策略模式价值**：新增促销方式（如秒杀价）只需新增一个实现类，`OrderService` 一行不用改——符合开闭原则。这正是接口「行为规范」的威力。

### 案例 2：Comparable 接口实现自定义排序 ⭐

后台系统常需对商品/订单排序。实现 `Comparable` 定义自然顺序，用 `Comparator` 定义临时排序规则：

```java
public class Product implements Comparable<Product> {
    private String name;
    private BigDecimal price;
    private int sales;   // 销量

    public Product(String name, String price, int sales) {
        this.name = name;
        this.price = new BigDecimal(price);
        this.sales = sales;
    }

    // 实现 Comparable：按价格升序排
    @Override
    public int compareTo(Product o) {
        return this.price.compareTo(o.price);   // 升序；降序反过来
    }

    @Override
    public String toString() {
        return name + "(¥" + price + ", 销量" + sales + ")";
    }
}

Product[] products = {
    new Product("手机", "2999", 120),
    new Product("耳机", "199", 500),
    new Product("平板", "1999", 80)
};

// 自然排序：按价格升序（用 Comparable）
Arrays.sort(products);
System.out.println(Arrays.toString(products));
// [耳机(¥199, 销量500), 平板(¥1999, 销量80), 手机(¥2999, 销量120)]

// 临时排序：按销量降序（用 Comparator，匿名内部类）
Arrays.sort(products, new Comparator<Product>() {
    @Override
    public int compare(Product a, Product b) {
        return b.sales - a.sales;   // 降序
    }
});
System.out.println(Arrays.toString(products));
// [耳机(¥199, 销量500), 手机(¥2999, 销量120), 平板(¥1999, 销量80)]
```

> 💡 `Comparable` 定义「对象的自然顺序」，`Comparator` 定义「临时的、自定义的排序规则」。两者都是接口，体现了「排序能力」的抽象。

### 案例 3：回调机制（事件/异步通知）

接口是 Java 实现回调的标准方式。定义回调接口，调用方传入实现，被调用方在合适时机「回调」：

```java
// 回调接口：任务完成通知
public interface Callback {
    void onSuccess(String result);
    void onFailure(Exception e);
}

// 异步任务执行器
public class AsyncTask {
    public void execute(Callback callback) {
        new Thread(() -> {
            try {
                Thread.sleep(1000);   // 模拟耗时操作
                callback.onSuccess("任务完成，数据已生成");
            } catch (Exception e) {
                callback.onFailure(e);
            }
        }).start();
    }
}

// 调用方：匿名内部类实现回调
new AsyncTask().execute(new Callback() {
    @Override
    public void onSuccess(String result) {
        System.out.println("成功：" + result);
    }

    @Override
    public void onFailure(Exception e) {
        System.out.println("失败：" + e.getMessage());
    }
});
```

> 💡 这种回调模式在 Android 开发（点击监听 `OnClickListener`）、网络库（OkHttp 的 `Callback`）、Spring 的 `TransactionSynchronization` 中随处可见。

### 案例 4：接口在 Spring 中的地位

Spring 框架本身就是「面向接口编程」的教科书。几个核心接口：

```java
// BeanDefinition：描述一个 Bean 的元信息（接口，多种实现）
public interface BeanDefinition {
    String getBeanClassName();
    boolean isSingleton();
    // ...
}

// BeanFactory：IoC 容器的根接口
public interface BeanFactory {
    Object getBean(String name);
    <T> T getBean(Class<T> requiredType);
}

// 依赖 BeanFactory 接口编程，不依赖具体实现
public class OrderService {
    private BeanFactory factory;   // ✅ 面向接口

    public void process() {
        UserService userService = factory.getBean(UserService.class);
        // ...
    }
}
```

> 📌 **开发规范**：Spring 开发的铁律——**面向接口编程**。Service 层定义为接口（`UserService`），实现类（`UserServiceImpl`），Controller 依赖接口而非实现。这样便于 AOP 代理、Mock 测试、切换实现。

### 案例 5：接口做常量定义（后台系统配置）

后台系统常用接口集中管理常量（比 `static import` 更清晰）：

```java
public interface ErrorCode {
    int SUCCESS = 0;
    int PARAM_ERROR = 400;
    int UNAUTHORIZED = 401;
    int FORBIDDEN = 403;
    int SERVER_ERROR = 500;

    // Java 8+：用 static 方法做校验
    static boolean isError(int code) {
        return code != SUCCESS;
    }
}

// 使用
if (ErrorCode.isError(401)) {
    System.out.println("错误码：" + ErrorCode.UNAUTHORIZED);
}
```

> 💡 也可用 `enum` 定义常量（更类型安全），但接口常量在老项目和配置类中仍很常见。

### 案例 6：default 方法做接口升级（向后兼容）

模拟 JDK 给 `Collection` 加 `stream()` 的场景：

```java
// 老接口，已被很多类实现
public interface DataRepository {
    // 老方法
    Object findById(int id);
}

// 新需求：想加一个 findAll()，又不想破坏老实现类
public interface DataRepository {
    Object findById(int id);

    // ✅ 用 default 加新方法，老实现类不用改
    default java.util.List<Object> findAll() {
        return new java.util.ArrayList<>();   // 默认返回空列表
    }
}

// 老实现类：一个字不用改，照样能编译运行
public class UserRepository implements DataRepository {
    @Override
    public Object findById(int id) { return "用户" + id; }
    // 不重写 findAll()，用默认实现
}

UserRepository repo = new UserRepository();
System.out.println(repo.findAll());   // []，用默认实现
```

## 🚀 新版本补充

### Java 9：接口私有方法

Java 8 的 default/static 方法解决了接口升级，但当多个 default 方法有重复逻辑时，无法抽取私有方法。Java 9 补上了这块：

```java
public interface Logger {

    default void logInfo(String msg) {
        log("INFO", msg);   // 调用私有方法
    }

    default void logError(String msg) {
        log("ERROR", msg);   // 调用私有方法
    }

    // Java 9：私有方法，抽取公共逻辑，不暴露给实现类
    private void log(String level, String msg) {
        System.out.println("[" + level + "] " + msg);
    }

    // 也可以是 private static，供 static 方法调用
    private static String format(String s) {
        return s == null ? "" : s.trim();
    }
}
```

> ⚠️ Java 8 环境下接口**不能**有 private 方法，编译会报错。这是 Java 9 才引入的特性。

### Java 9：接口可以定义 private static 方法

配合接口的 `static` 方法使用，抽取 static 方法间的公共逻辑：

```java
public interface Calculator {
    static int add(int a, int b) { return normalize(a) + normalize(b); }
    static int sub(int a, int b) { return normalize(a) - normalize(b); }

    // private static：仅供上面的 static 方法复用
    private static int normalize(int x) {
        return x < 0 ? 0 : x;   // 负数归零
    }
}
```

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 接口本质 | 行为规范，`has-a` 关系，`interface` 关键字 |
| Java 7 内容 | 常量（默认 public static final）、抽象方法（默认 public abstract） |
| Java 8 新增 | default 默认方法（有方法体，解决升级）、static 静态方法（接口名调用） |
| Java 9 新增 | private 私有方法（抽取 default/static 的公共逻辑） |
| 实现接口 | `implements`，必须重写所有抽象方法，方法必须 public |
| 多实现 | 一个类可 implements 多个接口，弥补单继承 |
| 接口继承 | 接口 extends 接口，可多继承 |
| 冲突规则 | 多实现冲突必须重写；父类方法优先于接口 default；子接口优先于父接口 |
| 接口 vs 抽象类 | 接口=行为规范(has-a)，抽象类=模板继承(is-a) |
| 函数式接口 | 只有一个抽象方法，可用 Lambda |

## 学习建议

1. **先吃透「接口 vs 抽象类」的设计区别**：这是面向对象设计的分水岭。记住口诀「接口是 has-a 能力，抽象类是 is-a 模板」，遇到设计先问自己「这是共享能力还是共享模板」，答案决定了用哪个。
2. **动手验证 default 方法冲突**：把第四节的冲突代码敲进 IDE，亲眼看到编译错误，再练习用 `接口名.super.方法()` 解决——这是 Java 8 接口最易踩的坑，面试也常问。
3. **用策略模式写一个完整小例子**：照着案例 1，自己定义一个 `PaymentStrategy` 接口（微信/支付宝/银行卡三种实现），体会接口如何让代码「对扩展开放、对修改关闭」。这是理解设计模式的入门钥匙。
4. **多看 JDK 接口源码**：打开 `List`、`Comparator`、`Runnable`、`Callable` 看它们的抽象方法和 default 方法，这些都是工业级接口设计的范例，模仿它们的命名和方法划分。
5. **养成「面向接口编程」的习惯**：从现在起，凡是写 Service 类，先定义接口再写实现类，变量类型用接口而非实现（`List list = new ArrayList()` 而非 `ArrayList list = new ArrayList()`）。这个习惯会让你后续学 Spring 时如鱼得水。
