# 泛型

泛型（Generics）是 Java 5 引入的特性，它的本质是**参数化类型**——把「类型」当成参数传给类、方法、接口，让一份代码能安全地处理多种类型。没有泛型时，集合只能存 `Object`，取出来要强转，一不留神就 `ClassCastException`。泛型把类型检查从运行期提前到编译期，让错误在编译时就暴露，而不是上线后崩给用户看。掌握泛型，尤其是**通配符**和**泛型擦除**，是从「会用集合」到「能设计通用框架」的分水岭。

> 💡 在阅读本篇前，建议先看 [24-集合框架体系与Collection](24-集合框架体系与Collection.md) 和 [28-迭代器与增强for](28-迭代器与增强for.md)，理解集合存取元素的过程，再来理解泛型为什么必要，会顺畅得多。

## 一、泛型的由来

### 1.1 没有泛型的痛

Java 5 之前没有泛型，集合只能存 `Object`。这意味着你可以往一个 `List` 里塞任何东西：

```java
// 假装回到 Java 5 之前（没有泛型）
List list = new ArrayList();
list.add("张三");
list.add(100);        // ✅ 编译通过！Integer 也被当成 Object 存进去
list.add(new User());  // ✅ 什么都能塞

// 取出来要强转，因为 get 返回的是 Object
String name = (String) list.get(0);   // ✅ 没问题
String bad = (String) list.get(1);    // ❌ 运行时抛 ClassCastException：Integer 不能转 String
```

> ⚠️ **最大的问题**：编译期不报错，运行时才炸。`list.get(1)` 拿到的是 `Integer`，强转成 `String` 时抛 `ClassCastException`——这种 bug 在测试阶段可能根本发现不了，等用户操作到那条数据才暴露，排查极痛苦。

### 1.2 泛型带来的好处

有了泛型，集合能指定「只装某种类型」，编译器在编译期就帮你检查：

```java
List<String> list = new ArrayList<>();
list.add("张三");
list.add(100);        // ❌ 编译错误：不兼容的类型，Integer 不能加进 List<String>
list.add(new User()); // ❌ 编译错误

String name = list.get(0);  // ✅ 取出来直接是 String，不用强转
```

泛型三大好处：

| 好处 | 说明 |
| :--- | :--- |
| **类型安全** | 编译期检查，类型不匹配直接编译报错 |
| **避免强转** | 取出元素自动是声明类型，不用 `(String) list.get(0)` |
| **代码复用** | 一份泛型代码可处理多种类型，不用为每种类型写一份 |

> 💡 **泛型只作用于引用类型**：`List<int>` 是错的，必须用包装类 `List<Integer>`。因为泛型擦除后类型参数变成 `Object`，而基本类型不能赋给 `Object`——这点在泛型擦除一节会详讲。

## 二、泛型类

### 2.1 泛型类的定义

泛型类在类名后用 `<类型参数>` 声明，常用单字母大写做类型参数名：

```java
// 泛型类：<T> 是类型参数，代表「某种类型」，创建对象时确定
public class Box<T> {
    private T item;

    public void put(T item) {
        this.item = item;
    }

    public T get() {
        return item;
    }
}
```

> 📌 **命名约定**：类型参数用单个大写字母，常见命名：
> - `T`（Type）——通用类型
> - `E`（Element）——集合元素
> - `K`（Key）、`V`（Value）——键值
> - `R`（Result）——返回值
> - `N`（Number）——数字

### 2.2 泛型类的使用

创建对象时指定具体类型：

```java
Box<String> stringBox = new Box<>();
stringBox.put("hello");
String s = stringBox.get();   // ✅ 直接是 String，不用强转

Box<Integer> intBox = new Box<>();
intBox.put(100);
Integer n = intBox.get();     // ✅ 直接是 Integer

// ⚠️ 不指定类型参数也能用（裸类型 raw type），但失去泛型保护
Box rawBox = new Box();      // ⚠️ 警告，Box 当成 Box<Object>
rawBox.put("x");
Integer bad = (Integer) rawBox.get();  // ❌ 运行时 ClassCastException
```

> ⚠️ **裸类型（Raw Type）」**：`Box` 不带 `<>` 就是裸类型，是 Java 为兼容旧代码保留的写法。新代码**绝对不要**用裸类型，它会让编译器放弃泛型检查，所有错误推迟到运行期。

### 2.3 多类型参数的泛型类

一个泛型类可以有多个类型参数：

```java
public class Pair<K, V> {
    private K key;
    private V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() { return key; }
    public V getValue() { return value; }
}

// 使用
Pair<String, Integer> p = new Pair<>("年龄", 18);
String k = p.getKey();      // "年龄"
Integer v = p.getValue();   // 18
```

> 💡 JDK 的 `Map.Entry<K, V>`、`HashMap<K, V>` 就是多类型参数泛型类的典型代表。

### 2.4 泛型类型在创建时确定

泛型类的类型参数**在创建对象（`new`）时确定**，之后该对象的类型就固定了：

```java
Box<String> b1 = new Box<>();   // 这个 Box 只能装 String
b1.put("a");
// b1.put(1);  // ❌ 编译错误，类型已固定为 String

Box<String> b2 = new Box<>();  // 另一个对象，也是 String
```

> 💡 这一点和泛型方法不同——泛型方法的类型在**调用方法时**确定，下面讲。

## 三、泛型方法

### 3.1 泛型方法的定义

泛型方法是在**方法的返回值前**用 `<类型参数>` 声明，类型在调用方法时确定：

```java
// <T> 声明类型参数，T 是返回类型
// 注意：<T> 必须写在返回值类型前面
public <T> T identity(T arg) {
    return arg;
}
```

> ⚠️ **泛型方法 vs 泛型类**：泛型类的 `<T>` 写在类名后，作用于整个类；泛型方法的 `<T>` 写在返回值前，只作用于该方法。**即使所在类不是泛型类，方法也能是泛型方法**。

### 3.2 泛型方法的使用

调用时类型参数根据实参自动推断，也可以显式指定：

```java
// 自动推断：传入 String，T 推断为 String
String s = identity("hello");
Integer n = identity(100);

// 显式指定（很少用，一般让编译器推断）
String s2 = this.<String>identity("hello");
```

### 3.3 泛型方法的典型应用：数组转集合

```java
import java.util.ArrayList;
import java.util.List;

public class ArrayToList {
    // 泛型方法：把任意类型数组转成 List
    // <T> 声明类型参数，调用时由数组类型推断
    public static <T> List<T> toList(T[] arr) {
        List<T> list = new ArrayList<>();
        for (T t : arr) {
            list.add(t);
        }
        return list;
    }

    public static void main(String[] args) {
        String[] strs = {"a", "b", "c"};
        List<String> strList = toList(strs);   // T 推断为 String

        Integer[] nums = {1, 2, 3};
        List<Integer> numList = toList(nums);  // T 推断为 Integer
    }
}
```

> 💡 注意 `Arrays.asList(T...)` 本质也是个泛型方法，但它返回的 List 是**固定大小**的（不能 add/remove），这是常见坑点，详见 [24-集合框架体系与Collection](24-集合框架体系与Collection.md)。

### 3.4 泛型方法与泛型类的类型参数是独立的

```java
public class Container<T> {   // 类的类型参数 T
    // 这个方法用的是类的 T，不是泛型方法
    public T process(T t) {
        return t;
    }

    // 这个 <E> 是方法自己的类型参数，和类的 T 无关
    public <E> E transform(E e) {
        return e;
    }
}
```

> ⚠️ **新手易混淆**：`public T process(T t)` 看起来像泛型方法，其实不是——它用的是类的类型参数 `T`，方法返回值前没有 `<T>`，所以不是泛型方法。判断标准是「返回值前有没有 `<类型参数>`」。

## 四、泛型接口

### 4.1 泛型接口的定义

```java
// 泛型接口
public interface Repository<T> {
    void save(T t);
    T findById(int id);
    List<T> findAll();
}
```

### 4.2 两种实现方式

**方式一：实现类确定类型**（接口的泛型在实现时确定）：

```java
// 实现时指定 T = User
public class UserRepository implements Repository<User> {
    public void save(User u) { /* 存 User */ }
    public User findById(int id) { return new User(id); }
    public List<User> findAll() { return new ArrayList<>(); }
}
```

**方式二：实现类延续泛型**（实现类自己也是泛型类，把 T 往下传）：

```java
// 实现类也是泛型类，T 继续作为类型参数
public class BaseRepository<T> implements Repository<T> {
    private List<T> data = new ArrayList<>();

    public void save(T t) { data.add(t); }
    public T findById(int id) { return data.get(id); }
    public List<T> findAll() { return new ArrayList<>(data); }
}

// 使用时再确定 T
BaseRepository<User> userRepo = new BaseRepository<>();
BaseRepository<Order> orderRepo = new BaseRepository<>();
```

> 💡 **方式二就是泛型 DAO 模式的雏形**——一个 `BaseRepository<T>` 能同时服务 User、Order 等多种实体，是 Spring Data JPA 等框架的设计基础。实战案例会展开。

## 五、泛型通配符（重点⭐⭐）

通配符是泛型里最绕、也最常考的部分。核心问题是：**`List<String>` 是不是 `List<Object>` 的子类？** 答案是**不是**——泛型不协变。

### 5.1 泛型不协变

```java
List<String> strList = new ArrayList<>();
List<Object> objList = strList;   // ❌ 编译错误！List<String> 不是 List<Object> 的子类

// 为什么不协变？看这个反例：
// 假如上面成立，那么：
objList.add(100);                 // 往 objList 加 Integer（合法，它声明的是 Object）
String s = strList.get(0);        // ❌ strList 里现在有 100，强转 String 崩了
```

> ⚠️ **泛型不协变是为了类型安全**：如果 `List<String>` 能赋给 `List<Object>`，就能往里塞任何东西，原本的 `List<String>` 就被污染了。所以编译器直接禁止这种赋值。

### 5.2 无界通配符 `?`

`?` 表示「未知类型，但它是某种具体类型」。用 `List<?>` 可以接收**任何类型的 List**：

```java
// List<?> 能接收任意类型的 List
public static void printList(List<?> list) {
    for (Object o : list) {
        System.out.println(o);
    }
}

printList(new ArrayList<String>());   // ✅
printList(new ArrayList<Integer>());  // ✅
printList(new ArrayList<User>());     // ✅
```

**`?` 的限制：只能读，不能写（除了 null）**：

```java
List<?> list = new ArrayList<String>();
Object o = list.get(0);   // ✅ 可以读，读出来当 Object
list.add("x");            // ❌ 编译错误：不能添加元素（除了 null）
list.add(null);           // ✅ null 是所有引用类型的合法值
```

> 💡 **为什么不能写**：`List<?>` 里的 `?` 是「某种未知类型」，编译器不知道它到底是 `List<String>` 还是 `List<Integer>`，为了安全干脆禁止 add 任何具体值（除了 null，它对所有引用类型都合法）。

### 5.3 上限通配符 `? extends T`

`? extends T` 表示「T 或 T 的子类」。常用于**读取**场景：

```java
// 接收 Number 或其子类（Integer、Double...）的 List
public static double sum(List<? extends Number> list) {
    double total = 0;
    for (Number n : list) {   // ✅ 可以读，读出来当 Number
        total += n.doubleValue();
    }
    return total;
}

sum(new ArrayList<Integer>());   // ✅
sum(new ArrayList<Double>());    // ✅
sum(new ArrayList<Number>());    // ✅
```

**`? extends T` 的限制：只能读，不能写（除了 null）**：

```java
List<? extends Number> list = new ArrayList<Integer>();
Number n = list.get(0);   // ✅ 读出来当 Number
list.add(1);              // ❌ 编译错误：不能 add Integer
list.add(3.14);           // ❌ 编译错误：不能 add Double
list.add(null);          // ✅ 只能加 null
```

> ⚠️ **为什么不能写**：`list` 实际指向 `ArrayList<Integer>`，但声明类型是 `List<? extends Number>`，编译器只知道「是 Number 的某个子类」，不知道具体是 Integer 还是 Double。`add(1)` 万一它其实是 `ArrayList<Double>` 呢？所以禁止。

### 5.4 下限通配符 `? super T`

`? super T` 表示「T 或 T 的父类」。常用于**写入**场景：

```java
// 接收 Integer 或其父类（Number、Object）的 List
public static void addNumbers(List<? super Integer> list) {
    list.add(1);     // ✅ 可以写 Integer
    list.add(2);     // ✅
}

addNumbers(new ArrayList<Integer>());   // ✅
addNumbers(new ArrayList<Number>());    // ✅
addNumbers(new ArrayList<Object>());    // ✅
addNumbers(new ArrayList<Double>());    // ❌ 编译错误：Double 不是 Integer 的父类
```

**`? super T` 的限制：可以写，但读出来只能当 Object**：

```java
List<? super Integer> list = new ArrayList<Number>();
list.add(1);              // ✅ 可以写 Integer
Object o = list.get(0);   // ✅ 读出来只能当 Object
Integer n = list.get(0);  // ❌ 编译错误：不能当 Integer 读
```

> ⚠️ **为什么读出来只能当 Object**：`list` 可能指向 `ArrayList<Object>`，里面可能存着非 Integer 的东西，所以编译器不敢让你当 Integer 读，只敢当最顶层的 Object。

### 5.5 三种通配符对比

| 通配符 | 含义 | 读 | 写 | 适用场景 |
| :--- | :--- | :---: | :---: | :--- |
| `<?>` | 未知类型 | ✅（当 Object） | ❌（除 null） | 只读，不关心类型 |
| `<? extends T>` | T 及子类 | ✅（当 T） | ❌（除 null） | 从集合**读**数据 |
| `<? super T>` | T 及父类 | ✅（当 Object） | ✅（写 T 及子类） | 往集合**写**数据 |

> 💡 **记忆口诀**：`extends` 是「上限读」，`super` 是「下限写」。`extends` 限定的是「能读出来的类型上限」，`super` 限定的是「能写进去的类型下限」。

## 六、PECS 原则

### 6.1 Producer extends, Consumer super

PECS 是 Joshua Bloch 在《Effective Java》中提出的通配符使用原则：

- **Producer（生产者）用 extends**：如果你要从集合**读取**数据（集合是生产者，生产数据给你），用 `? extends T`
- **Consumer（消费者）用 super**：如果你要往集合**写入**数据（集合是消费者，消费你给的数据），用 `? super T`

```java
// 经典案例：把 src 的元素拷到 dest
// src 是生产者（被读），用 ? extends T
// dest 是消费者（被写），用 ? super T
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (T t : src) {       // ✅ 从 src 读，当 T
        dest.add(t);        // ✅ 往 dest 写 T
    }
}

// 使用
List<Number> dest = new ArrayList<>();
List<Integer> src = Arrays.asList(1, 2, 3);
copy(dest, src);   // ✅ dest 是 Integer 的父类 Number，src 是 Number 的子类 Integer
```

> 💡 `Collections.copy` 的签名就是 `copy(List<? super T> dest, List<? extends T> src)`，是 PECS 的教科书级示范。

### 6.2 什么时候用 `?` 而不是具体类型参数

- 方法只需要读、不需要写 → `? extends T`
- 方法只需要写、不需要按具体类型读 → `? super T`
- 方法既不关心类型也不读写具体值 → `<?>`
- 方法需要按同一类型既读又写 → 用类型参数 `T`

```java
// 既读又写，必须用 T，不能用通配符
public static <T> void swap(List<T> list, int i, int j) {
    T tmp = list.get(i);   // 读 T
    list.set(i, list.get(j));  // 写 T
    list.set(j, tmp);          // 写 T
}
```

> ⚠️ 通配符 `?` 是「只读或只写」的，一旦需要「同一类型既读又写」，通配符就力不从心，必须用类型参数 `T`。

## 七、泛型擦除（重点⭐⭐⭐）

### 7.1 泛型只在编译期有效

Java 的泛型是通过**擦除（Erasure）」实现的：编译器在编译时做类型检查，然后**把所有类型参数擦除」，运行时根本没有泛型信息。

```java
List<String> strList = new ArrayList<>();
List<Integer> intList = new ArrayList<>();

// 运行时它们的 class 是同一个！
System.out.println(strList.getClass() == intList.getClass());  // true ✅
System.out.println(strList.getClass().getName());  // java.util.ArrayList（没有 <String>）
```

> ⚠️ **关键认知**：`List<String>` 和 `List<Integer>` 在运行时是**同一个类** `ArrayList`。泛型只是编译期的「幻觉」，运行时被擦除成裸类型。

### 7.2 擦除后的类型

擦除规则：
- 无界类型参数 `<T>` → 擦除成 `Object`
- 有界类型参数 `<T extends Number>` → 擦除成 `Number`（上限类型）

```java
public class Box<T> {
    private T item;          // 擦除后：private Object item;
    public T get() { ... }   // 擦除后：public Object get();
}

public class NumberBox<T extends Number> {
    private T item;          // 擦除后：private Number item;
    public T get() { ... }   // 擦除后：public Number get();
}
```

编译器在调用处自动插入强转（桥接方法），所以你写 `String s = box.get()`，编译后其实是 `String s = (String) box.get()`——强转由编译器代劳，这就是「不用手动强转」的真相。

### 7.3 泛型擦除带来的限制

因为运行时没有泛型信息，以下操作**都不允许**：

**限制 1：不能 `new T()`**

```java
public class Box<T> {
    private T item = new T();   // ❌ 编译错误：不能 new T()
    // 原因：擦除后 T 变成 Object，new Object() 不是你要的 T
}
```

**变通方案**：传入 `Class<T>`，用反射创建：

```java
public class Box<T> {
    private T item;
    private Class<T> type;

    public Box(Class<T> type) {
        this.type = type;
        try {
            this.item = type.newInstance();   // ✅ 反射创建
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }
}

Box<User> box = new Box<>(User.class);
```

**限制 2：不能 `new T[]`**

```java
public class Box<T> {
    private T[] arr = new T[10];   // ❌ 编译错误：不能 new T[]
}
```

> ⚠️ **数组协变 + 泛型擦除会破坏类型安全**，所以禁止 `new T[]`。变通方案：用 `Object[]` 或 `List<T>`，或反射 `Array.newInstance`：

```java
// 用 List 替代数组（推荐）
public class Box<T> {
    private List<T> arr = new ArrayList<>();
}

// 或反射创建数组
T[] arr = (T[]) java.lang.reflect.Array.newInstance(type, 10);
```

**限制 3：基本类型不能做泛型参数**

```java
List<int> list = new ArrayList<>();      // ❌ 编译错误
List<Integer> list2 = new ArrayList<>(); // ✅ 用包装类
```

原因：擦除后 `T` 变 `Object`，而 `int` 不是 `Object`（基本类型不是引用类型）。

**限制 4：`instanceof` 不能用泛型类型参数**

```java
public <T> void check(Object obj) {
    if (obj instanceof T) { }          // ❌ 编译错误：instanceof 不能用 T
    if (obj instanceof List<String>) { }  // ❌ 编译错误：泛型类型不能用于 instanceof
    if (obj instanceof List) { }       // ✅ 只能用裸类型
}
```

**限制 5：静态成员不能使用类的类型参数**

```java
public class Box<T> {
    private static T instance;   // ❌ 编译错误：静态成员不能用类的 T
    // 原因：T 在创建对象时确定，但静态成员属于类，对象还没创建时 T 是什么？
}
```

### 7.4 重载的陷阱

因为擦除，`List<String>` 和 `List<Integer>` 在运行时是同一个类型，所以这两个方法签名**冲突**，不能重载：

```java
// ❌ 编译错误：两个方法擦除后签名相同，都是 method(List)
public void method(List<String> list) { }
public void method(List<Integer> list) { }
```

> ⚠️ **这是泛型擦除最直观的体现**：你以为参数类型不同是重载，编译器一看擦除后都是 `method(List)`，就报「方法签名重复」。要区分它们，只能改方法名或加额外参数。

### 7.5 桥接方法

泛型方法重写时，子类的方法签名可能和父类擦除后的不一致，编译器会自动生成「桥接方法」来保证多态正确：

```java
class Parent {
    public void set(T t) { }   // 擦除后：set(Object)
}

class Child extends Parent<String> {
    @Override
    public void set(String t) { }   // 子类用具体类型 String
}
```

编译器会为 `Child` 生成一个桥接方法：

```java
// 编译器自动生成（你看不到源码，反编译能看到）
public void set(Object t) {
    this.set((String) t);   // 转调真正的 set(String)
}
```

> 💡 桥接方法是泛型擦除的「补救措施」，让基于裸类型的父类方法和基于具体类型的子类方法能多态调用。日常开发不用关心，但理解它有助于看懂反射时的奇怪方法签名。

## 八、泛型限定在方法中的应用

### 8.1 类型参数的上限

泛型方法和泛型类都能给类型参数加**上限**（`extends`），限定必须是某类或其子类：

```java
// 泛型方法：<T extends Number> 限定 T 必须是 Number 或其子类
public static <T extends Number> double sum(T[] arr) {
    double total = 0;
    for (T n : arr) {
        total += n.doubleValue();   // ✅ 能调用 Number 的方法，因为 T 一定是 Number 的子类
    }
    return total;
}

sum(new Integer[]{1, 2, 3});   // ✅
sum(new Double[]{1.0, 2.0});   // ✅
// sum(new String[]{"a"});     // ❌ String 不是 Number 的子类
```

> 💡 **上限的好处**：限定后，方法内可以安全调用上限类型（`Number`）的方法。没有上限的话 `T` 擦除成 `Object`，只能调 `Object` 的方法。

### 8.2 多重上限

`T` 必须同时满足多个条件（类 + 接口），用 `&` 连接：

```java
// T 必须是 Number 的子类，且实现 Comparable 接口
public static <T extends Number & Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}

max(1, 2);          // ✅ Integer 是 Number 且实现 Comparable
max(1.0, 2.0);      // ✅ Double 同理
// max("a", "b");   // ❌ String 不是 Number
```

> ⚠️ **多重上限的规则**：如果有类，类必须放第一个（Java 单继承），后面接接口。`<T extends ClassA & InterfaceB & InterfaceC>`。

### 8.3 泛型上限 vs 通配符上限

```java
// 泛型方法的上限：<T extends Number>
public static <T extends Number> double sumA(List<T> list) { ... }

// 通配符的上限：<? extends Number>
public static double sumB(List<? extends Number> list) { ... }
```

两者功能相似，但有区别：
- 泛型上限 `<T extends Number>`：方法内可以用 `T` 这个类型（比如返回 `T`、参数间关联）
- 通配符上限 `<? extends Number>`：`?` 不能当类型名用，只能表示「某种 Number 子类」

> 💡 **选择标准**：需要在方法内用「T 这个类型」（返回值、多个参数同类型、方法内变量）→ 用 `<T extends>`；只是接收参数、不关心具体类型 → 用 `<? extends>`。

## ⚠️ 重点

### 重点 1：泛型不协变 ⭐⭐

```java
List<String> strList = new ArrayList<>();
List<Object> objList = strList;   // ❌ 编译错误
Object[] objArr = new String[10]; // ✅ 数组是协变的
```

> ⚠️ 数组协变、泛型不协变，这是 Java 设计上的差异。数组协变其实有缺陷（运行时类型检查），泛型为了编译期安全选择不协变。

### 重点 2：通配符的读写规则 ⭐⭐

| 通配符 | 读 | 写 |
| :--- | :---: | :---: |
| `<?>` | ✅（Object） | ❌（除 null） |
| `<? extends T>` | ✅（T） | ❌（除 null） |
| `<? super T>` | ✅（Object） | ✅（T 及子类） |

> 💡 **PECS 一句话总结**：读用 extends，写用 super，既读又写用 T。

### 重点 3：泛型擦除 ⭐⭐⭐

- 泛型只在编译期检查，运行时擦除
- `List<String>` 和 `List<Integer>` 运行时是同一个类
- 不能 `new T()`、不能 `new T[]`、不能用基本类型做参数、不能 `instanceof T`
- 不能用泛型类型区分重载方法

```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());  // true，擦除后都是 ArrayList
```

### 重点 4：裸类型不要用 ⭐

```java
List list = new ArrayList();   // ⚠️ 裸类型，失去泛型保护
list.add("a");
list.add(1);
String s = (String) list.get(1);  // ❌ 运行时 ClassCastException
```

> 📌 **规范**：新代码一律带类型参数 `List<String>`。裸类型只为兼容 Java 5 之前的旧代码保留。

### 重点 5：泛型不能继承异常 ⭐

```java
// ❌ 不能这样写：泛型类不能继承 Throwable
class MyException<T> extends Exception { }   // 编译错误

// ❌ catch 不能用泛型类型
try { } catch (T e) { }   // 编译错误：不能 catch 泛型类型
```

> ⚠️ 因为擦除，`catch (T e)` 在运行时无法区分异常类型，所以 Java 直接禁止泛型异常。

## 💻 实战案例

### 案例 1：泛型 DAO 设计（BaseDao<T>）⭐⭐

后台系统中，User、Order、Product 等实体都有 CRUD 操作，代码高度重复。用泛型 `BaseDao<T>` 抽象公共逻辑，子类只需指定类型：

```java
import java.util.ArrayList;
import java.util.List;

// 实体基类
abstract class BaseEntity {
    protected int id;
    public int getId() { return id; }
    public void setId(int id) { this.id = id; }
}

class User extends BaseEntity {
    String name;
    User(int id, String name) { this.id = id; this.name = name; }
    public String toString() { return "User[" + id + "," + name + "]"; }
}

class Order extends BaseEntity {
    double amount;
    Order(int id, double amount) { this.id = id; this.amount = amount; }
    public String toString() { return "Order[" + id + "," + amount + "]"; }
}

// 泛型 DAO 基类：T 必须是 BaseEntity 的子类，这样能调用 getId()
abstract class BaseDao<T extends BaseEntity> {
    protected List<T> data = new ArrayList<>();

    public void save(T t) { data.add(t); }
    public T findById(int id) {
        for (T t : data) {
            if (t.getId() == id) return t;   // ✅ 有上限才能调 getId()
        }
        return null;
    }
    public List<T> findAll() { return new ArrayList<>(data); }
    public void delete(int id) {
        data.removeIf(t -> t.getId() == id);   // ✅ 安全删除
    }
    // 留给子类实现的业务方法
    public abstract List<T> findByName(String name);
}

// UserDao：确定 T = User
class UserDao extends BaseDao<User> {
    public List<User> findByName(String name) {
        List<User> result = new ArrayList<>();
        for (User u : data) {
            if (u.name.equals(name)) result.add(u);
        }
        return result;
    }
}

// OrderDao：确定 T = Order
class OrderDao extends BaseDao<Order> {
    public List<Order> findByName(String name) { return new ArrayList<>(); }
}

public class DaoDemo {
    public static void main(String[] args) {
        UserDao userDao = new UserDao();
        userDao.save(new User(1, "张三"));
        userDao.save(new User(2, "李四"));
        System.out.println(userDao.findById(1));   // User[1,张三]
        userDao.delete(1);
        System.out.println(userDao.findAll());     // [User[2,李四]]

        OrderDao orderDao = new OrderDao();
        orderDao.save(new Order(101, 99.9));
        System.out.println(orderDao.findById(101));  // Order[101,99.9]
    }
}
```

> 💡 这就是 Spring Data JPA 的 `JpaRepository<T, ID>` 的设计思想：一个泛型基类搞定所有实体的公共 CRUD，子类只写差异部分。泛型 + 继承 = 代码复用的利器。

### 案例 2：泛型方法实现数组转集合 ⭐

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class ArrayUtils {
    // 泛型方法：安全的数组转 List（可增删，不像 Arrays.asList 那样固定大小）
    @SafeVarargs
    public static <T> List<T> toList(T... arr) {
        List<T> list = new ArrayList<>(Arrays.asList(arr));
        return list;
    }

    public static void main(String[] args) {
        List<String> strs = toList("a", "b", "c");
        strs.add("d");   // ✅ 可以增删
        System.out.println(strs);  // [a, b, c, d]

        List<Integer> nums = toList(1, 2, 3);
        nums.removeIf(n -> n == 2);
        System.out.println(nums);  // [1, 3]
    }
}
```

> ⚠️ **`@SafeVarargs` 注解**：泛型可变参数 `T... arr` 底层是 `T[]`，而泛型数组有类型安全警告（擦除导致）。`@SafeVarargs` 告诉编译器「我保证这里不会污染堆」，抑制警告。只能用在 static/finnal 方法上。

### 案例 3：通配符做方法参数（接收 List<? extends Number> 求和）⭐⭐

金融系统：一个方法要能接收 `List<Integer>`、`List<Double>`、`List<BigDecimal>` 等各种数字列表求和：

```java
import java.math.BigDecimal;
import java.util.Arrays;
import java.util.List;

public class SumUtils {
    // ✅ 用 ? extends Number，能接收所有数字子类的 List
    public static double sum(List<? extends Number> list) {
        double total = 0;
        for (Number n : list) {       // ✅ 读出来当 Number
            total += n.doubleValue();
        }
        return total;
    }

    public static void main(String[] args) {
        List<Integer> ints = Arrays.asList(1, 2, 3);
        List<Double> doubles = Arrays.asList(1.5, 2.5);
        List<BigDecimal> bigs = Arrays.asList(new BigDecimal("1.1"), new BigDecimal("2.2"));

        System.out.println(sum(ints));     // 6.0
        System.out.println(sum(doubles));  // 4.0
        System.out.println(sum(bigs));     // 3.3
    }
}
```

> 💡 如果不用通配符，写 `sum(List<Number> list)`，那 `sum(ints)` 会编译错误——因为 `List<Integer>` 不是 `List<Number>` 的子类（泛型不协变）。通配符 `? extends` 正是解决这个问题的工具。

### 案例 4：泛型擦除的坑（金融：配置解析）⭐⭐

一个「从配置读 List」的工具，想支持 `List<String>` 和 `List<Integer>` 两种返回：

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class ConfigReader {
    // ❌ 想用泛型区分返回类型——擦除导致重载失败
    // public List<String> getList(String key) { ... }
    // public List<Integer> getList(String key) { ... }  // 编译错误：擦除后签名相同

    // ✅ 方案 1：传入 Class 区分
    @SuppressWarnings("unchecked")
    public static <T> List<T> getList(String key, Class<T> type) {
        String raw = "a,b,c";   // 假装从配置读
        String[] parts = raw.split(",");
        List<T> result = new ArrayList<>();
        for (String p : parts) {
            if (type == Integer.class) {
                result.add((T) Integer.valueOf(p.length()));   // 演示，实际按业务解析
            } else {
                result.add((T) p);
            }
        }
        return result;
    }

    public static void main(String[] args) {
        List<String> strs = getList("keys", String.class);
        List<Integer> nums = getList("counts", Integer.class);
        System.out.println(strs);  // [a, b, c]
        System.out.println(nums);  // [1, 1, 1]

        // ⚠️ 擦除的坑：运行时不检查类型，强转可能埋雷
        List<String> bad = getList("x", Integer.class);  // 编译通过！但里面是 Integer
        String s = bad.get(0);   // ❌ 运行时 ClassCastException：Integer 转 String
    }
}
```

> ⚠️ **擦除的代价**：`getList("x", Integer.class)` 声明成 `List<String>` 也能编译通过，因为运行时 `List` 不带类型信息。强转的雷在 `get` 时才爆。这就是泛型擦除最危险的副作用——类型安全是「编译期尽力而为」，运行时靠强转兜底。

### 案例 5：泛型单例工厂（不可变容器）⭐

设计一个「空 List」单例，避免到处 `new ArrayList<>()` 浪费内存：

```java
import java.util.Collections;
import java.util.List;

public class EmptyListFactory {
    // 泛型方法返回单例空 List，类型安全
    @SuppressWarnings("unchecked")
    public static <T> List<T> emptyList() {
        return (List<T>) EMPTY_LIST;   // 同一个对象，所有类型共用
    }

    // 全局唯一一个空 List 实例
    private static final List<?> EMPTY_LIST = Collections.emptyList();

    public static void main(String[] args) {
        List<String> strs = emptyList();
        List<Integer> nums = emptyList();
        System.out.println(strs == nums);   // true，同一个对象！
        // strs.add("x");  // ❌ 不可变，抛 UnsupportedOperationException
    }
}
```

> 💡 这就是 `Collections.emptyList()` 的实现原理——一个不可变空 List 单例，靠泛型擦除让所有类型共用。因为不可变（不能 add），所以类型安全：你拿到的 `List<String>` 永远不会被塞进 Integer。

### 案例 6：PECS 实战——拷贝集合（电商：合并购物车）⭐

把多个用户的购物车合并到一个总购物车，元素类型有继承关系：

```java
import java.util.ArrayList;
import java.util.List;

class CartItem { double price; CartItem(double p) { price = p; } }
class BookItem extends CartItem { BookItem(double p) { super(p); } }
class ElectronicItem extends CartItem { ElectronicItem(double p) { super(p); } }

public class CartMerger {
    // PECS：dest 是消费者（被写）用 super，src 是生产者（被读）用 extends
    public static <T> void mergeCart(List<? super T> dest, List<? extends T> src) {
        for (T item : src) {
            dest.add(item);
        }
    }

    public static void main(String[] args) {
        List<CartItem> totalCart = new ArrayList<>();           // 总购物车
        List<BookItem> books = new ArrayList<>();               // 书籍子类
        books.add(new BookItem(50));
        List<ElectronicItem> electronics = new ArrayList<>();   // 电子子类
        electronics.add(new ElectronicItem(2000));

        // ✅ 把 BookItem、ElectronicItem 都合并进 CartItem 购物车
        mergeCart(totalCart, books);
        mergeCart(totalCart, electronics);
        System.out.println("合并后商品数：" + totalCart.size());  // 2
    }
}
```

> 💡 如果把 `mergeCart` 写成 `mergeCart(List<T> dest, List<T> src)`，那 `mergeCart(totalCart, books)` 会编译错误——`List<BookItem>` 不是 `List<CartItem>`。PECS 正是为这种「父子类型集合互操作」设计的。

## 🚀 新版本补充

### Java 9：匿名内部类使用菱形语法（`<>`）

Java 7 引入菱形语法 `new Box<>()`，但匿名内部类不能用。Java 9 放宽了这个限制：

```java
// Java 8：匿名内部类不能用菱形
Box<String> b = new Box<>() { };   // ❌ Java 8 编译错误

// Java 9+：匿名内部类也能用菱形
Box<String> b = new Box<>() { };   // ✅ Java 9 通过
```

### Java 10：局部变量类型推断 `var` 与泛型

`var` 让泛型实例化更简洁，但类型推断仍受泛型擦除影响：

```java
// Java 10+
var list = new ArrayList<String>();   // 推断为 ArrayList<String>
// var list2 = new ArrayList<>();      // 推断为 ArrayList<Object>，丢失泛型信息！
```

> ⚠️ 用 `var` 时如果右边不带类型参数，会推断成 `ArrayList<Object>`，失去泛型保护。所以 `var` + 泛型时，右边最好带具体类型。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 泛型由来 | 集合存 Object 需强转，ClassCastException 风险 |
| 泛型好处 | 类型安全、避免强转、代码复用 |
| 泛型类 | `class Box<T>`，类型在 `new` 时确定 |
| 泛型方法 | `<T> T method(T param)`，类型在调用时确定 |
| 泛型接口 | 实现类确定类型或延续泛型 |
| 无界通配符 `<?>` | 只读（当 Object），不能写 |
| 上限 `<? extends T>` | T 及子类，只读（当 T），不能写 |
| 下限 `<? super T>` | T 及父类，可写 T 及子类，读当 Object |
| PECS 原则 | 读 extends，写 super |
| 泛型擦除 | 只编译期有效，运行时擦除成 Object/上限 |
| 擦除限制 | 不能 new T、new T[]、基本类型参数、instanceof T |
| 重载陷阱 | `List<String>` 和 `List<Integer>` 不能区分重载 |
| 裸类型 | `List` 不带 `<>`，失去泛型保护，禁用 |

---

## 学习建议

1. **先吃透「泛型不协变」」：`List<String>` 不能赋给 `List<Object>` 是泛型最反直觉的点，务必理解「为什么不协变」（否则能往里塞 Integer 污染 String 列表），再学通配符就有了基础。
2. **把通配符读写规则画成表贴墙上**：`extends` 只读、`super` 只写、`?` 只读不写——这是泛型面试必考、开发高频用的知识点。结合 PECS 口诀（生产者 extends、消费者 super）记忆。
3. **动手验证泛型擦除**：写 `list1.getClass() == list2.getClass()` 看 `List<String>` 和 `List<Integer>` 运行时是不是同一个类；尝试 `new T()`、`instanceof T` 看编译错误。亲眼看到擦除的限制，比看十遍文字都深刻。
4. **实现一个泛型 DAO**：`BaseDao<T extends BaseEntity>` 是泛型最经典的实战应用，自己写一遍 CRUD，体会「类型参数 + 上限」如何让一份代码服务多种实体。理解了它，看 Spring Data JPA 的源码就不会陌生。
5. **警惕擦除的运行时陷阱」：泛型的类型安全是「编译期尽力而为」，运行时靠强转兜底。用反射、`@SuppressWarnings` 绕过编译检查时，要清楚强转的雷可能延迟到 `get` 时才爆。涉及泛型 + 反射的代码，务必做好运行时类型校验。
