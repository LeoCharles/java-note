# 字节流与字符流

IO（Input/Output）是 Java 与外界交换数据的通道：读文件、写日志、上传下载、网络通信，底层都是 IO 流。Java 的 IO 体系庞大但脉络清晰——所有流都从四大抽象基类派生：字节流 `InputStream` / `OutputStream` 处理任意文件，字符流 `Reader` / `Writer` 处理文本。本篇聚焦最基础的字节流与字符流，掌握它们你就拿下了 Java IO 的半壁江山。

> 💡 本篇是 [32-File 类与 NIO.2](32-File类与NIO.2.md) 的延续——File 解决「文件在哪」，IO 流解决「文件内容怎么读写」。建议先读上一篇。

---

## 一、IO 概述

**IO = Input / Output**，以**内存**为基准：

- **输入（Input）**：数据从外部（磁盘、网络）进入内存 = **读**
- **输出（Output）**：数据从内存写出到外部 = **写**

```
        输入流（读）          输出流（写）
外部 ────────────────→ 内存 ────────────────→ 外部
（磁盘/网络）              （磁盘/网络）
```

> ⚠️ 方向判断永远以内存为基准。新手常把「写到文件」当成输入——从内存角度看，写文件是**输出**。

---

## 二、IO 流的分类

### 2.1 按流向分

| 类型 | 方向 | 基类 | 记忆 |
| :--- | :--- | :--- | :--- |
| 输入流 | 外部 → 内存 | `InputStream` / `Reader` | 读 |
| 输出流 | 内存 → 外部 | `OutputStream` / `Writer` | 写 |

### 2.2 按数据类型分

| 类型 | 单位 | 适用场景 | 基类 |
| :--- | :--- | :--- | :--- |
| 字节流 | 字节（byte，8 位） | 所有文件（二进制、图片、视频、文本） | `InputStream` / `OutputStream` |
| 字符流 | 字符（char，Java 内部 UTF-16） | 纯文本文件 | `Reader` / `Writer` |

> ⚠️ **核心区别**：字节流读 1 个字节（1 byte），字符流读 1 个字符（可能 1~3 字节，取决于编码）。中文在 UTF-8 下占 3 字节，用字节流逐字节读会**截断汉字导致乱码**。

### 2.3 按角色分

| 类型 | 作用 | 举例 |
| :--- | :--- | :--- |
| 节点流 | 直接连接数据源 | `FileInputStream`、`FileReader` |
| 处理流 | 包装节点流，增强功能 | `BufferedInputStream`、`InputStreamReader` |

```
程序 ←→ 处理流（缓冲、转换） ←→ 节点流（直接连文件） ←→ 文件
```

> 💡 处理流套在节点流外面，像「套娃」一样层层增强。本篇先讲节点流，缓冲流等处理流在后续章节展开。

---

## 三、四大抽象基类

| 抽象基类 | 字节/字符 | 输入/输出 | 核心方法 |
| :--- | :---: | :---: | :--- |
| `InputStream` | 字节 | 输入 | `read()`、`read(byte[])`、`close()` |
| `OutputStream` | 字节 | 输出 | `write(int)`、`write(byte[])`、`flush()`、`close()` |
| `Reader` | 字符 | 输入 | `read()`、`read(char[])`、`close()` |
| `Writer` | 字符 | 输出 | `write(int)`、`write(char[])`、`write(String)`、`flush()`、`close()` |

> 💡 记忆口诀：**字节流以 byte 为单位，字符流以 char 为单位；输入读、输出写；close 必须调。**

## 四、字节流：FileOutputStream

`FileOutputStream` 是文件字节输出流，用于把字节写出到文件。**任何文件都能写**（文本、图片、视频）。

### 4.1 构造方法（覆盖 vs 追加）

```java
import java.io.FileOutputStream;
import java.io.IOException;

// 1. 覆盖模式（默认）：每次 new 都清空原文件
FileOutputStream fos1 = new FileOutputStream("a.txt");

// 2. 追加模式：第二个参数 true，在文件末尾追加
FileOutputStream fos2 = new FileOutputStream("a.txt", true);

// 3. 用 File 对象构造
FileOutputStream fos3 = new FileOutputStream(new java.io.File("a.txt"));

fos1.close();  // ✅ 用完必须关
```

> ⚠️ **覆盖模式是默认行为**，打开文件瞬间原内容就被清空。生产环境写日志一定要用追加模式 `new FileOutputStream("log.txt", true)`，否则日志会被覆盖丢失！

### 4.2 写出数据

```java
// 写单个字节（只写低 8 位）
fos.write(65);    // 写入 'A'（ASCII 65）
fos.write(97);    // 写入 'a'

// 写字节数组
byte[] data = "hello".getBytes();
fos.write(data);

// 写字节数组的一部分
fos.write(data, 0, 2);  // 只写 "he"
```

### 4.3 换行与关闭

```java
FileOutputStream fos = new FileOutputStream("log.txt", true);
fos.write("第一行".getBytes());
fos.write("\r\n".getBytes());  // 换行
fos.write("第二行".getBytes());
fos.close();
```

> ⚠️ 换行符跨平台：Windows 是 `\r\n`，Linux/Mac 是 `\n`。硬编码 `\r\n` 在 Linux 上会产生奇怪的 `^M` 字符。推荐用 `System.lineSeparator()` 或 `Files.write` 自动处理。

> ⚠️ `write(int)` 只写出参数的**低 8 位**（一个字节）。`write(300)` 写出的不是 300，而是 `300 & 0xFF = 44`。

## 五、字节流：FileInputStream

`FileInputStream` 是文件字节输入流，从文件读字节到内存。

### 5.1 逐字节读取

```java
import java.io.FileInputStream;
import java.io.IOException;

FileInputStream fis = new FileInputStream("a.txt");
int b;
// read() 返回 0~255，读到末尾返回 -1
while ((b = fis.read()) != -1) {
    System.out.print((char) b);
}
fis.close();
```

> ⚠️ 逐字节读取效率极低（每次 read 都要系统调用），只适合演示。实际开发必须用 `read(byte[])` 缓冲数组。

### 5.2 用 byte[] 缓冲读取

```java
FileInputStream fis = new FileInputStream("a.txt");
byte[] buffer = new byte[1024];  // 1KB 缓冲区
int len;
// read(byte[]) 返回实际读取的字节数，读到末尾返回 -1
while ((len = fis.read(buffer)) != -1) {
    System.out.write(buffer, 0, len);  // 只输出实际读到的部分
}
fis.close();
```

> ⚠️ **经典 bug**：`System.out.write(buffer)` 而非 `write(buffer, 0, len)`。最后一次读取 buffer 可能没填满，残留旧数据会重复输出。必须用 `0` 和 `len` 限定有效范围。

### 5.3 读取中文的乱码问题

```java
// 假设 a.txt 用 UTF-8 保存了 "你好"（6 字节）
FileInputStream fis = new FileInputStream("a.txt");
byte[] buffer = new byte[1024];
int len = fis.read(buffer);
fis.close();

// ❌ 直接 new String：用平台默认编码，可能乱码
String wrong = new String(buffer, 0, len);  // 若平台是 GBK 就乱码

// ✅ 指定编码（与文件编码一致）
String right = new String(buffer, 0, len, "UTF-8");  // 你好
```

> ⚠️ 字节流读中文乱码的根因：UTF-8 下一个汉字 3 字节，若 buffer 大小不当可能把汉字**截断**在边界，产生不可恢复的乱码。**读文本文件请用字符流**。

## 六、字符流：FileWriter

`FileWriter` 是文件字符输出流，专为文本设计，内部自带编码（默认平台编码或指定编码）。

```java
import java.io.FileWriter;
import java.io.IOException;

// 覆盖模式
FileWriter fw1 = new FileWriter("b.txt");
// 追加模式
FileWriter fw2 = new FileWriter("b.txt", true);

// 写单个字符
fw1.write('A');
fw1.write('中');  // ✅ 一个字符一个字符写，不会截断汉字

// 写字符数组
char[] chars = {'你', '好', '!'};
fw1.write(chars);

// 写字符串（最常用）
fw1.write("Hello 世界");

// 写字符串一部分
fw1.write("Hello", 0, 3);  // "Hel"

// append（链式）
fw1.append("追加").append("内容");

fw1.flush();  // 冲刷缓冲区到文件
fw1.close();
```

> 💡 `FileWriter` 构造时可指定编码（Java 11+ 支持 `new FileWriter(file, Charset)`）。Java 8 的 `FileWriter` 只能用平台默认编码，要指定编码需用 `OutputStreamWriter`（见第八节）。

---

## 七、字符流：FileReader

`FileReader` 是文件字符输入流，按字符读取文本。

```java
import java.io.FileReader;
import java.io.IOException;

FileReader fr = new FileReader("b.txt");

// 逐字符读取
int ch;
while ((ch = fr.read()) != -1) {
    System.out.print((char) ch);
}

// 用 char[] 缓冲读取
char[] buffer = new char[1024];
int len;
while ((len = fr.read(buffer)) != -1) {
    System.out.print(new String(buffer, 0, len));
}

fr.close();
```

> 💡 字符流的 `read(char[])` 返回的是**字符数**，不是字节数。一个汉字算 1 个字符。

## 八、字节流 vs 字符流的选择

| 对比项 | 字节流 | 字符流 |
| :--- | :--- | :--- |
| 单位 | byte（1 字节） | char（2 字节，UTF-16） |
| 适用 | 所有文件 | 纯文本 |
| 中文处理 | 需手动指定编码，易乱码 | 自带编码，安全 |
| 典型场景 | 图片/视频/二进制复制 | 配置文件/日志/文本读写 |
| 基类 | InputStream / OutputStream | Reader / Writer |

> 📌 **选择原则**：
> - **非文本文件**（图片、视频、压缩包、exe）→ **字节流**
> - **纯文本文件**（.txt、.log、.csv、.properties、.xml、.json）→ **字符流**
> - **需要指定编码** → 字节流 + `InputStreamReader` / `OutputStreamWriter`，或直接用 NIO.2 的 `Files.newBufferedReader(path, charset)`

### 8.1 转换流：InputStreamReader / OutputStreamWriter

字节流与字符流的桥梁，可指定编码：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

// 字节流 → 字符流，指定 UTF-8
InputStreamReader isr = new InputStreamReader(
    new FileInputStream("a.txt"), StandardCharsets.UTF_8);
int ch;
while ((ch = isr.read()) != -1) {
    System.out.print((char) ch);
}
isr.close();

// 字符流 → 字节流，指定 GBK
OutputStreamWriter osw = new OutputStreamWriter(
    new FileOutputStream("b.txt"), "GBK");
osw.write("你好");
osw.close();
```

> 💡 `FileReader` / `FileWriter` 本质就是 `InputStreamReader` / `OutputStreamWriter` 包了 `FileInputStream` / `FileOutputStream`，只是不支持指定编码（Java 8）。要指定编码就用转换流。

## 九、JDK 7 try-with-resources 自动关闭流 ⭐⭐

流用完必须 `close()`，否则**文件句柄泄漏**——Windows 上文件被占用无法删除，Linux 上 fd 耗尽导致 `Too many open files`。但手动 close 有两个坑：

1. **忘记关闭**：代码一长容易漏写。
2. **异常屏蔽**：close 自己也抛异常，会覆盖业务异常。

### 9.1 传统写法（繁琐且易错）

```java
FileInputStream fis = null;
try {
    fis = new FileInputStream("a.txt");
    int b = fis.read();
} catch (IOException e) {
    e.printStackTrace();
} finally {
    // ❌ 繁琐：要判空、要单独 try-catch
    if (fis != null) {
        try {
            fis.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

### 9.2 try-with-resources（Java 7+，推荐）

把流对象写在 `try(...)` 里，**无论是否异常都会自动关闭**：

```java
// ✅ 自动关闭单个流
try (FileInputStream fis = new FileInputStream("a.txt")) {
    int b = fis.read();
} catch (IOException e) {
    e.printStackTrace();
}
// 这里 fis 已自动关闭

// ✅ 自动关闭多个流（用分号分隔）
try (FileInputStream fis = new FileInputStream("src.txt");
     FileOutputStream fos = new FileOutputStream("dst.txt")) {
    byte[] buffer = new byte[1024];
    int len;
    while ((len = fis.read(buffer)) != -1) {
        fos.write(buffer, 0, len);
    }
} catch (IOException e) {
    e.printStackTrace();
}
// 两个流都自动关闭，关闭顺序与声明顺序相反
```

> ⚠️ **关闭顺序**：try-with-resources 按**声明逆序**关闭（后声明的先关）。对于「先读后写」的场景，先关输出流（冲刷缓冲）再关输入流，顺序正确。

### 9.3 原理：AutoCloseable 接口

```java
public interface AutoCloseable {
    void close() throws Exception;
}
```

任何实现了 `AutoCloseable`（或子接口 `Closeable`）的类都能放进 try-with-resources。所有 IO 流都实现了它。编译器会把它展开成等价的 `try-finally`，并保留**业务异常不被 close 异常屏蔽**（用 `addSuppressed` 把 close 异常挂到业务异常上）。

> 📌 **规范**：从 Java 7 起，**所有流操作一律用 try-with-resources**，禁止手写 finally close。这是现代 Java 的硬性规范。

## 十、读写大文件：缓冲数组

逐字节读写每次都要系统调用，性能极差。用缓冲数组可大幅减少 IO 次数：

```java
// ❌ 慢：逐字节复制 100MB 文件，可能要几十秒
try (FileInputStream fis = new FileInputStream("big.zip");
     FileOutputStream fos = new FileOutputStream("copy.zip")) {
    int b;
    while ((b = fis.read()) != -1) {
        fos.write(b);
    }
}

// ✅ 快：8KB 缓冲，100MB 文件几秒搞定
try (FileInputStream fis = new FileInputStream("big.zip");
     FileOutputStream fos = new FileOutputStream("copy.zip")) {
    byte[] buffer = new byte[8192];  // 8KB
    int len;
    while ((len = fis.read(buffer)) != -1) {
        fos.write(buffer, 0, len);
    }
}
```

> 💡 缓冲数组大小一般 4KB~64KB，常用 8KB（`8192`）。再大收益递减。更优雅的方案是用 `BufferedInputStream` / `BufferedReader` 处理流（后续章节）。

## 十一、编码与乱码

### 11.1 常见编码

| 编码 | 字节数 | 说明 |
| :--- | :--- | :--- |
| ASCII | 1 字节 | 英文，0~127 |
| ISO-8859-1 | 1 字节 | 西欧语言，不能表示中文 |
| GBK | 1~2 字节 | 中文，英文 1 字节、汉字 2 字节 |
| UTF-8 | 1~4 字节 | 变长，英文 1 字节、汉字 3 字节 |
| UTF-16 | 2~4 字节 | Java char 内部用 UTF-16 |

### 11.2 编码与解码

```java
// 编码：String → byte[]
String s = "你好";
byte[] gbk = s.getBytes("GBK");          // 4 字节
byte[] utf8 = s.getBytes("UTF-8");      // 6 字节
byte[] def = s.getBytes();               // 平台默认编码

// 解码：byte[] → String
String s1 = new String(gbk, "GBK");      // ✅ 你好
String s2 = new String(gbk, "UTF-8");     // ❌ 乱码（编码解码不一致）
String s3 = new String(utf8, "UTF-8");    // ✅ 你好

// 用 StandardCharsets 常量（推荐，避免拼写错误）
byte[] bytes = s.getBytes(StandardCharsets.UTF_8);
String decoded = new String(bytes, StandardCharsets.UTF_8);
```

> ⚠️ **乱码根因**：编码与解码用了**不同的字符集**。解决乱码就是让两端字符集一致。

### 11.3 乱码修复思路

```java
// 假设：用 GBK 编码，却被 UTF-8 解码产生乱码
String wrong = "ä½ å¥½";  // 乱码字符串

// 思路：先用错误编码「还原」回字节，再用正确编码「重新解码」
byte[] bytes = wrong.getBytes(StandardCharsets.UTF_8);  // 用错误编码还原
String right = new String(bytes, "GBK");  // 用正确编码重新解码
System.out.println(right);  // 你好
```

> 💡 这是「乱码修复」的经典套路：**乱码字符串 → 用当时的解码方式反向编码回字节 → 用正确编码重新解码**。前提是乱码过程中没有丢失字节（ISO-8859-1 是单字节编码，常用于「中转」不丢字节）。

## ⚠️ 重点

### 重点 1：流必须关闭，且必须用 try-with-resources ⭐⭐

```java
// ❌ 危险：忘记 close，文件句柄泄漏
FileInputStream fis = new FileInputStream("a.txt");
int b = fis.read();
// 没有 close()，文件被占用

// ✅ try-with-resources 自动关闭
try (FileInputStream fis = new FileInputStream("a.txt")) {
    int b = fis.read();
}
```

> 📌 **铁律**：所有流（InputStream、OutputStream、Reader、Writer 及其子类）都实现了 `AutoCloseable`，**一律放进 try-with-resources**。这是 Java 7+ 的强制规范，没有例外。

### 重点 2：write(buffer) vs write(buffer, 0, len) ⭐⭐

```java
byte[] buffer = new byte[1024];
int len = fis.read(buffer);

// ❌ 错误：输出整个 buffer，含上次残留的旧数据
fos.write(buffer);

// ✅ 正确：只输出实际读到的部分
fos.write(buffer, 0, len);
```

> ⚠️ 这是文件复制最常见的 bug。最后一次读取通常读不满 buffer，`write(buffer)` 会把残留的旧字节写进去，导致目标文件末尾多出垃圾数据、文件损坏。

### 重点 3：字节流读中文易乱码 ⭐⭐

```java
// ❌ 字节流逐字节读中文，汉字被截断
FileInputStream fis = new FileInputStream("chinese.txt");
int b;
while ((b = fis.read()) != -1) {
    System.out.print((char) b);  // 乱码：3 字节的汉字被拆开
}

// ✅ 读文本用字符流
try (FileReader fr = new FileReader("chinese.txt")) {
    int ch;
    while ((ch = fr.read()) != -1) {
        System.out.print((char) ch);  // 正确
    }
}

// ✅ 或用字节流 + 指定编码一次性读取
byte[] bytes = java.nio.file.Files.readAllBytes(
    java.nio.file.Paths.get("chinese.txt"));
String text = new String(bytes, StandardCharsets.UTF_8);
```

### 重点 4：覆盖 vs 追加模式 ⭐⭐

```java
// ❌ 默认覆盖：每次运行清空日志，历史记录丢失
new FileOutputStream("app.log")

// ✅ 追加模式：保留历史日志
new FileOutputStream("app.log", true)

// ✅ FileWriter 同理
new FileWriter("app.log", true)
```

> ⚠️ 写日志、写数据文件务必用追加模式。覆盖模式只在「每次重新生成」场景用（如导出报表覆盖旧文件）。

### 重点 5：flush() 的作用 ⭐

```java
FileWriter fw = new FileWriter("log.txt");
fw.write("hello");
// 此时数据可能在内存缓冲区，文件里还没有
fw.flush();  // ✅ 强制把缓冲区数据写到磁盘
fw.close();  // close 内部会先 flush
```

> 💡 `close()` 会自动调用 `flush()`，所以正常关闭流时无需手动 flush。但处理流（如 `BufferedWriter`）有缓冲区，若想在关闭前看到数据落盘，需手动 flush。`FileOutputStream` / `FileWriter` 本身缓冲较小，但仍建议养成 flush 习惯。

### 重点 6：read() 返回 -1 表示读完 ⭐

```java
// ❌ 死循环：忘记判断 -1
while (true) {
    int b = fis.read();
    System.out.print((char) b);
}

// ✅ 标准写法
int b;
while ((b = fis.read()) != -1) {
    System.out.print((char) b);
}
```

> ⚠️ `read()` 读到文件末尾返回 `-1`（不是 0，也不是抛异常）。这是判断读完的唯一信号。`read(byte[])` 同理，返回 -1 表示读完。

## 💻 实战案例

### 案例 1：文件复制（字节流）⭐⭐

最经典的 IO 案例：复制任意文件（图片、视频、文档）：

```java
import java.io.*;

public class FileCopier {
    public static void copy(String src, String dst) throws IOException {
        // ✅ try-with-resources 同时管理两个流
        try (FileInputStream fis = new FileInputStream(src);
             FileOutputStream fos = new FileOutputStream(dst)) {
            byte[] buffer = new byte[8192];  // 8KB 缓冲
            int len;
            while ((len = fis.read(buffer)) != -1) {
                fos.write(buffer, 0, len);  // ✅ 必须 0, len
            }
        }  // 两个流自动关闭
    }

    public static void main(String[] args) throws IOException {
        long start = System.currentTimeMillis();
        copy("D:/data/video.mp4", "D:/backup/video_copy.mp4");
        long cost = System.currentTimeMillis() - start;
        System.out.println("复制完成，耗时 " + cost + " ms");
    }
}
```

> 💡 这是「万能复制」——字节流能复制任何文件。字符流只能复制文本，复制图片会损坏文件。

### 案例 2：文本文件读写（字符流）⭐⭐

读取配置文件、写入日志：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class TextFileDemo {
    // 写文本（追加模式）
    public static void appendLog(String file, String msg) throws IOException {
        try (FileWriter fw = new FileWriter(file, true)) {  // ✅ 追加
            fw.write(msg);
            fw.write(System.lineSeparator());  // ✅ 跨平台换行
        }
    }

    // 读文本（指定编码，避免乱码）
    public static String readText(String file) throws IOException {

        try (InputStreamReader isr = new InputStreamReader(
                new FileInputStream(file), StandardCharsets.UTF_8)) {
            StringBuilder sb = new StringBuilder();
            char[] buffer = new char[1024];
            int len;
            while ((len = isr.read(buffer)) != -1) {
                sb.append(buffer, 0, len);
            }
            return sb.toString();
        }
    }

    public static void main(String[] args) throws IOException {
        appendLog("app.log", "[INFO] 服务启动");
        appendLog("app.log", "[ERROR] 数据库连接超时");
        System.out.println(readText("app.log"));
    }
}
```

### 案例 3：读取 properties 配置文件 ⭐⭐

    }

    public static void main(String[] args) throws IOException {
        Properties props = load("config.properties");
        String url = props.getProperty("db.url");
        String user = props.getProperty("db.user");

### 案例 5：文件上传保存（模拟）⭐⭐

Web 接口接收文件字节流并保存到服务器：

```java
import java.io.*;

public class FileUploader {
    // 模拟：从输入流读取并保存到磁盘
    public static String saveFile(InputStream input, String saveDir, String fileName)
            throws IOException {
        // 确保目录存在
        File dir = new File(saveDir);
        if (!dir.exists()) {
            dir.mkdirs();  // ✅ 多级创建
        }

        // 防止文件名冲突：加时间戳
        String savedName = System.currentTimeMillis() + "_" + fileName;
        File savedFile = new File(dir, savedName);

        // ✅ try-with-resources 关闭输出流（输入流由调用方管理）
        try (FileOutputStream fos = new FileOutputStream(savedFile)) {
            byte[] buffer = new byte[8192];
            int len;
            while ((len = input.read(buffer)) != -1) {
                fos.write(buffer, 0, len);
            }
        }
        return savedFile.getAbsolutePath();
    }
}
```

> 💡 这里 `InputStream` 来自 HTTP 请求（如 `request.getInputStream()`），由容器管理关闭，不放进 try-with-resources。只关自己创建的 `FileOutputStream`。

### 案例 6：处理中文乱码 ⭐⭐

读取 GBK 编码的旧文件并转存为 UTF-8：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class EncodingConverter {
    // GBK 文件 → UTF-8 文件
    public static void convert(String srcFile, String dstFile) throws IOException {
        try (InputStreamReader isr = new InputStreamReader(
                new FileInputStream(srcFile), "GBK");  // ✅ 用 GBK 读
             OutputStreamWriter osw = new OutputStreamWriter(
                new FileOutputStream(dstFile), StandardCharsets.UTF_8)) {  // ✅ 用 UTF-8 写
            char[] buffer = new char[1024];
            int len;
            while ((len = isr.read(buffer)) != -1) {
                osw.write(buffer, 0, len);
            }
        }
    }

    public static void main(String[] args) throws IOException {
        convert("D:/data/legacy_gbk.txt", "D:/data/converted_utf8.txt");
        System.out.println("编码转换完成");
    }
}
```

> ⚠️ 老项目迁移常遇到 GBK → UTF-8 转换。关键：**读取时用文件原始编码，写入时用目标编码**。转换流 `InputStreamReader` / `OutputStreamWriter` 正是为此设计。

### 案例 7：try-with-resources 关闭多个流 ⭐⭐

文件复制 + 日志记录，同时管理多个资源：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class MultiStreamDemo {
    public static void copyAndLog(String src, String dst, String logFile) throws IOException {
        // ✅ 三个流同时管理，自动逆序关闭
        try (FileInputStream fis = new FileInputStream(src);
             FileOutputStream fos = new FileOutputStream(dst);
             OutputStreamWriter logWriter = new OutputStreamWriter(
                 new FileOutputStream(logFile, true), StandardCharsets.UTF_8)) {

            byte[] buffer = new byte[8192];
            int len;
            long total = 0;
            while ((len = fis.read(buffer)) != -1) {
                fos.write(buffer, 0, len);
                total += len;
            }
            // 写日志
            logWriter.write(String.format("复制 %s → %s, 大小: %d 字节%n",
                src, dst, total));
        }  // 关闭顺序：logWriter → fos → fis（逆序）
    }

    public static void main(String[] args) throws IOException {
        copyAndLog("a.zip", "b.zip", "copy.log");
    }
}
```

### 案例 8：按行读取日志并统计错误数 ⭐

运维分析日志：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class LogAnalyzer {
    public static int countErrors(String logFile) throws IOException {
        int count = 0;
        try (BufferedReader br = new BufferedReader(
                new InputStreamReader(new FileInputStream(logFile), StandardCharsets.UTF_8))) {
            String line;
            while ((line = br.readLine()) != null) {  // ✅ 按行读
                if (line.contains("[ERROR]")) {
                    count++;
                }
            }
        }
        return count;
    }

    public static void main(String[] args) throws IOException {
        int errors = countErrors("app.log");
        System.out.println("错误日志数: " + errors);
    }
}
```

> 💡 `BufferedReader.readLine()` 按行读取，自动处理换行符，是处理文本日志的最佳选择。它本质是处理流，包在 `InputStreamReader` 外面。

## 🚀 新版本补充

### Java 8：Files.lines() 流式读文件

```java
import java.nio.file.*;
import java.util.stream.Stream;

// ✅ Java 8：按行返回 Stream，惰性加载，适合大文件
try (Stream<String> lines = Files.lines(Paths.get("app.log"))) {
    long errorCount = lines.filter(l -> l.contains("ERROR"))
                           .count();
    System.out.println("错误数: " + errorCount);
}
```

> 💡 `Files.lines` 是 Java 8 引入的函数式读文件方式，配合 Stream API 可声明式处理。但返回的 Stream 仍需关闭（用 try-with-resources）。

### Java 11：FileReader 支持指定 Charset

```java
// Java 8：FileReader 不支持指定编码，要用 InputStreamReader
InputStreamReader isr = new InputStreamReader(new FileInputStream("a.txt"), "UTF-8");

// Java 11+：FileReader 直接支持 Charset
FileReader fr = new FileReader("a.txt", StandardCharsets.UTF_8);
```

### Java 11：Files.readString / writeString

```java
// Java 11+：一行读写字符串
String content = Files.readString(Paths.get("a.txt"));  // 默认 UTF-8
Files.writeString(Paths.get("b.txt"), "hello", StandardOpenOption.CREATE);
```

> ⚠️ Java 8 环境下这些方法不可用。等价写法：`new String(Files.readAllBytes(path), UTF_8)` 和 `Files.write(path, "hello".getBytes(UTF_8))`。

### Java 9：InputStream.transferTo

```java
// Java 9+：一行完成流复制
try (InputStream in = new FileInputStream("src.txt");
     OutputStream out = new FileOutputStream("dst.txt")) {
    in.transferTo(out);  // ✅ 内部用缓冲，简洁高效
}
```

> 💡 Java 8 需手写 while 循环 + buffer。`transferTo` 是 Java 9 对字节流复制的简化，底层实现与手写缓冲循环等价。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| IO 方向 | 以内存为基准：输入=读，输出=写 |
| 四大基类 | InputStream/OutputStream（字节）、Reader/Writer（字符） |
| 字节流 | 任意文件，FileInputStream/FileOutputStream |
| 字符流 | 纯文本，FileReader/FileWriter |
| 选择原则 | 二进制用字节流，文本用字符流 |
| 覆盖/追加 | 构造第二参数 true 为追加，默认覆盖 |
| 缓冲数组 | read(byte[])/read(char[])，必须用 0, len |
| 乱码根因 | 编码与解码字符集不一致 |
| 转换流 | InputStreamReader/OutputStreamWriter 指定编码 |
| try-with-resources | 自动关闭流，Java 7+ 强制规范 |
| flush | 强制刷缓冲到磁盘，close 会自动 flush |
| read 返回值 | -1 表示读完，不是 0 |

---

## 学习建议

1. **先理解方向再写代码**：IO 的「输入/输出」永远以内存为基准。把「读=输入=外部到内存」「写=输出=内存到外部」刻进脑子，方向搞反是最常见的低级错误。
2. **try-with-resources 写到肌肉记忆**：从今天起，所有流都放进 `try(...)` 里，禁止手写 finally close。这能消灭 90% 的资源泄漏 bug。多流场景用分号分隔，关闭顺序自动逆序。
3. **字节流字符流别混用**：复制文件用字节流，读写文本用字符流。用字节流读中文一定乱码，用字符流复制图片一定损坏。把「字节流=万能但中文不友好」「字符流=文本专用」记牢。
4. **乱码要会诊断**：遇到乱码别慌，先查文件实际编码（用编辑器看），再让读取编码与之一致。掌握「乱码字符串 → 反编码回字节 → 正编码重新解码」的修复套路，能解决 80% 的乱码问题。
5. **动手写文件复制**：把案例 1 的文件复制敲一遍，分别用逐字节、byte[] 缓冲、Java 9 的 transferTo 三种方式，对比耗时。你会直观感受到缓冲数组的威力——这是理解「处理流为什么快」的钥匙。
