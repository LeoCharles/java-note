# 多态

**多态**（Polymorphism）是面向对象三大特性中最灵活、最强大的一个。同一个父类引用，指向不同的子类对象，调用同一个方法却表现出不同的行为——这就是多态。它是开闭原则（对扩展开放、对修改关闭）的底层支撑，也是策略模式、工厂模式、模板方法模式等设计模式的基础。掌握多态，你就能写出「新增功能不改老代码」的高扩展性程序。

> 💡 本篇是 [11-继承与final](11-继承与final.md) 的延续，涉及方法重写、向上/向下转型等内容，建议先掌握继承相关知识再看本篇。

---

## 一、多态的前提

多态不是凭空产生的，需要三个前提条件，缺一不可：

1. **继承或实现关系**：必须有父类和子类（或接口和实现类）
2. **方法重写**：子类必须重写父类的方法，否则多态没有意义
3. **父类引用指向子类对象**：`父类 变量 = new 子类()`

```java
// 前提 1：继承
class Animal {
    public void eat() {
        System.out.println("动物吃东西");
    }
}

class Cat extends Animal {
    // 前提 2：方法重写
    @Override
    public void eat() {
        System.out.println("猫吃鱼");
    }
}

class Dog extends Animal {
    @Override
    public void eat() {
        System.out.println("狗吃肉");
    }
}

// 前提 3：父类引用指向子类对象
Animal a1 = new Cat();   // 父类引用指向猫对象
Animal a2 = new Dog();   // 父类引用指向狗对象
a1.eat();   // 猫吃鱼（多态：同一调用，不同表现）
a2.eat();   // 狗吃肉
```

> 💡 **多态的本质**：编译时类型（左边的声明类型）和运行时类型（右边的实际对象类型）不一致，运行时根据对象的**真实类型**执行对应的方法。

## 二、多态的体现

### 2.1 父类引用指向子类对象

这是多态最直接的体现形式：

```java
Animal a = new Cat();   // ✅ 父类引用指向子类对象（向上转型，隐式）
a.eat();                // 猫吃鱼
```

等号左边 `Animal a` 是**编译时类型**（编译器认为 `a` 是 Animal），右边 `new Cat()` 是**运行时类型**（实际对象是 Cat）。

### 2.2 方法调用：编译看左，运行看右

```java
Animal a = new Cat();
a.eat();   // ✅ 编译时检查 Animal 有没有 eat()（有），运行时执行 Cat 的 eat()
// a.catchMouse();  // ❌ 编译错误：Animal 类没有 catchMouse()，编译看左
```

> ⚠️ **编译看左**：编译器只看左边类型有没有这个方法，没有就报错。这是为什么父类引用不能调用子类特有方法的原因。

### 2.3 多态的多种形式

多态不限于「直接 new 子类」，以下场景都体现多态：

```java
// 形式 1：直接赋值
Animal a = new Cat();

// 形式 2：方法参数——父类做参数，可接收任意子类
void feed(Animal a) {     // 参数是父类类型
    a.eat();
}
feed(new Cat());   // ✅ 传入猫
feed(new Dog());   // ✅ 传入狗

// 形式 3：方法返回值——父类做返回，可返回任意子类
Animal create(int type) {
    if (type == 1) return new Cat();
    return new Dog();
}
```

## 三、多态中成员访问特点

这是多态最核心、最容易出错的知识点。记住口诀：**成员变量和静态方法看左边，非静态方法编译看左运行看右**。

### 3.1 成员变量：编译看左，运行也看左 ⭐

```java
class Father {
    int num = 10;
}

class Son extends Father {
    int num = 20;
}

Father f = new Son();
System.out.println(f.num);   // 10（看左边 Father）
```

> ⚠️ 成员变量**不存在动态绑定**！`f.num` 编译时绑定到 `Father` 类的 `num`，运行时也是 10。这是因为成员变量不参与多态机制。

### 3.2 成员方法：编译看左，运行看右 ⭐⭐

```java
class Father {
    void show() {
        System.out.println("Father show");
    }
}

class Son extends Father {
    @Override
    void show() {
        System.out.println("Son show");
    }
}

Father f = new Son();
f.show();   // Son show（编译看左有 show()，运行看右执行 Son 的）
```

这就是**动态绑定**（Dynamic Binding）：JVM 在运行时根据对象的实际类型，找到并执行子类重写的方法。

### 3.3 静态方法：编译看左，运行也看左

```java
class Father {
    static void staticMethod() {
        System.out.println("Father static");
    }
}

class Son extends Father {
    static void staticMethod() {
        System.out.println("Son static");
    }
}

Father f = new Son();
f.staticMethod();        // Father static（看左边）
Son.staticMethod();      // Son static
```

> 💡 静态方法属于类，不属于对象，不参与动态绑定。`f.staticMethod()` 实际等价于 `Father.staticMethod()`。实际开发中应避免用引用调用静态方法，直接用类名调用。

### 3.4 总结对比表

| 成员类型 | 编译看 | 运行看 | 说明 |
| :--- | :---: | :---: | :--- |
| 成员变量 | 左 | **左** | 不参与动态绑定 |
| 非静态方法 | 左 | **右** | 动态绑定，多态核心 |
| 静态方法 | 左 | **左** | 属于类，不参与动态绑定 |

```java
class Father {
    int num = 10;
    void method() { System.out.println("Father method, num=" + num); }
    static void staticMethod() { System.out.println("Father static"); }
}

class Son extends Father {
    int num = 20;
    @Override
    void method() { System.out.println("Son method, num=" + num); }
    static void staticMethod() { System.out.println("Son static"); }
}

Father f = new Son();
System.out.println(f.num);       // 10（变量看左）
f.method();                      // Son method, num=20（方法运行看右，方法内 num 是 Son 的）
f.staticMethod();                // Father static（静态看左）
```

## 四、多态的好处

### 4.1 扩展性——新增子类不改老代码 ⭐⭐

```java
class Payment {
    public void pay(double amount) {
        System.out.println("支付：" + amount);
    }
}

class WechatPay extends Payment {
    @Override
    public void pay(double amount) {
        System.out.println("微信支付：" + amount + " 元");
    }
}

class Alipay extends Payment {
    @Override
    public void pay(double amount) {
        System.out.println("支付宝支付：" + amount + " 元");
    }
}

// 统一支付方法：参数是父类，可接收任意子类
class PaymentService {
    public void process(Payment payment, double amount) {
        System.out.println("开始处理支付...");
        payment.pay(amount);    // 多态：根据传入对象执行不同逻辑
        System.out.println("支付完成");
    }
}

// 使用
PaymentService service = new PaymentService();
service.process(new WechatPay(), 99.9);   // 微信支付
service.process(new Alipay(), 199.0);      // 支付宝支付

// ✅ 新增银行卡支付：不改 PaymentService 任何代码！
class BankCardPay extends Payment {
    @Override
    public void pay(double amount) {
        System.out.println("银行卡支付：" + amount + " 元");
    }
}
service.process(new BankCardPay(), 500.0); // 银行卡支付
```

> 💡 **这就是开闭原则**：新增银行卡支付，只需新增一个类，`PaymentService` 一行代码都不用改。如果没有多态，每加一种支付方式就要改 `if-else`。

### 4.2 统一参数类型——父类做参数接收所有子类

```java
// 不用多态：每种商品写一个方法
void calcBook(Book b) { ... }
void calcElectronics(Electronics e) { ... }
void calcClothing(Clothing c) { ... }

// 用多态：一个方法搞定
void calcPrice(Product p) {       // 父类做参数
    System.out.println(p.getName() + " 价格：" + p.getPrice());
}

calcPrice(new Book(...));        // ✅
calcPrice(new Electronics(...)); // ✅
calcPrice(new Clothing(...));    // ✅
```

### 4.3 统一返回值——灵活性

```java
class PaymentFactory {
    // 父类做返回值，内部根据条件返回不同子类
    public static Payment create(String type) {
        switch (type) {
            case "wechat": return new WechatPay();
            case "alipay": return new Alipay();
            case "bank":   return new BankCardPay();
            default: throw new IllegalArgumentException("未知支付方式");
        }
    }
}

Payment p = PaymentFactory.create("alipay");
p.pay(100);   // 支付宝支付：100.0 元
```

> 💡 这就是**简单工厂模式**的雏形，调用方不需要知道具体子类，只面向父类编程。

## 五、多态的弊端

### 5.1 不能使用子类特有方法

```java
class Cat extends Animal {
    @Override
    void eat() { System.out.println("猫吃鱼"); }

    void catchMouse() {     // 子类特有方法
        System.out.println("抓老鼠");
    }
}

Animal a = new Cat();
a.eat();           // ✅ 猫吃鱼（父类有，子类重写）
// a.catchMouse();  // ❌ 编译错误：Animal 没有 catchMouse()
```

> ⚠️ 编译器只认左边类型 `Animal`，`Animal` 没有 `catchMouse()`，所以编译报错。这是多态的代价——为了统一处理，牺牲了子类特有方法的访问能力。

### 5.2 解决方案：向下转型

如果确实需要调用子类特有方法，要先**向下转型**还原成子类类型（见下文第七节）。

---

## 六、向上转型（隐式，安全）

**向上转型**：子类对象赋值给父类引用，即 `父类 变量 = new 子类()`。这是隐式的、自动的，因为子类 *是一种* 父类（`is-a` 关系），一定安全。

```java
class Animal { void eat() {} }
class Cat extends Animal { void catchMouse() {} }

Cat c = new Cat();
Animal a = c;          // ✅ 向上转型：隐式，安全
Animal a2 = new Cat(); // ✅ 直接向上转型

a.eat();               // ✅ 能用父类方法
// a.catchMouse();     // ❌ 不能用子类特有方法（丢失了子类特有功能）
```

> 💡 **类比理解**：把猫当作「动物」来看，这是安全的（猫一定是动物）。但当作动物后，你只能调用动物有的功能，猫特有的「抓老鼠」就用不了了。

向上转型是安全的，因为：
- 子类一定拥有父类的所有成员（继承关系保证）
- 不会出现类型不匹配

---

## 七、向下转型（显式，有风险）

**向下转型**：父类引用还原回子类类型，即 `子类 变量 = (子类) 父类引用`。这是显式的强转，有风险。

### 7.1 基本用法

```java
Animal a = new Cat();      // 向上转型（隐式）
Cat c = (Cat) a;           // ✅ 向下转型（显式强转）
c.catchMouse();            // ✅ 现在能调用子类特有方法了
```

### 7.2 转型风险——ClassCastException ⭐⭐

向下转型的前提是：**对象本来就是这个子类类型**。如果对象的真实类型和强转的目标类型不匹配，运行时会抛 `ClassCastException`。

```java
Animal a = new Dog();      // 实际对象是 Dog
Cat c = (Cat) a;           // ❌ 运行时抛 ClassCastException：Dog 不能转成 Cat
```

> ⚠️ **这是多态中最常见的运行时异常**。编译器检查不出来（因为 `a` 声明是 `Animal`，编译器认为强转 `Cat` 有可能），但运行时 JVM 发现对象真实是 `Dog`，无法变成 `Cat`，就抛异常。

### 7.3 安全的向下转型——先 instanceof 判断

```java
Animal a = new Cat();

if (a instanceof Cat) {        // 先判断真实类型
    Cat c = (Cat) a;           // ✅ 安全强转
    c.catchMouse();
}
```

> 📌 **规范**：向下转型前**必须**用 `instanceof` 判断，这是避免 `ClassCastException` 的标准做法。

---

## 八、ClassCastException 异常

`ClassCastException` 是 `RuntimeException` 的子类，发生在**向下转型类型不匹配**时。

```java
class Animal {}
class Cat extends Animal {}
class Dog extends Animal {}

Animal a1 = new Cat();
Animal a2 = new Dog();

Cat c1 = (Cat) a1;   // ✅ a1 真实是 Cat
Cat c2 = (Cat) a2;   // ❌ ClassCastException: Dog cannot be cast to Cat
```

常见触发场景：

```java
Object obj = "hello";        // obj 真实类型是 String
// Integer num = (Integer) obj;  // ❌ ClassCastException: String → Integer

Object obj2 = new ArrayList<>();
// String s = (String) obj2;     // ❌ ClassCastException: ArrayList → String
```

> ⚠️ **教训**：`Object` 是所有类的父类，从 `Object` 强转时一定要先 `instanceof` 判断，否则极易抛异常。这在反序列化、JSON 解析（如 `ObjectMapper`）中非常常见。

---

## 九、instanceof 关键字

`instanceof` 用于在运行时判断对象的**真实类型**，是向下转型前的安全检查。

### 9.1 基本语法

```java
对象 instanceof 类型    // 返回 boolean
```

```java
Animal a = new Cat();
System.out.println(a instanceof Cat);     // true（a 真实是 Cat）
System.out.println(a instanceof Animal);  // true（Cat 是 Animal 的子类）
System.out.println(a instanceof Dog);     // false（a 不是 Dog）

Object obj = "hello";
System.out.println(obj instanceof String);    // true
System.out.println(obj instanceof Integer);   // false
```

### 9.2 instanceof 的继承判断特性 ⭐

`instanceof` 判断的是 `is-a` 关系，子类对象 `instanceof` 父类永远返回 `true`：

```java
Cat c = new Cat();
System.out.println(c instanceof Animal);   // true（猫是一种动物）
System.out.println(c instanceof Object);    // true（所有对象都是 Object）

List<String> list = new ArrayList<>();
System.out.println(list instanceof List);        // true
System.out.println(list instanceof ArrayList);    // true
System.out.println(list instanceof Collection);  // true（ArrayList 是 Collection 子接口）
```

### 9.3 用 instanceof 做类型分发 ⭐⭐

实际开发中，常在多态场景下用 `instanceof` 做类型分发，调用子类特有方法：

```java
class Product {
    public void display() { System.out.println("商品"); }
}
class Book extends Product {
    public void showAuthor() { System.out.println("显示作者"); }
}
class Electronics extends Product {
    public void showWarranty() { System.out.println("显示保修"); }
}

// 统一处理商品，但需要调用子类特有方法时用 instanceof 分发
void processProduct(Product p) {
    p.display();   // ✅ 多态调用，所有商品都有

    if (p instanceof Book) {
        Book b = (Book) p;
        b.showAuthor();      // ✅ 安全调用子类特有方法
    } else if (p instanceof Electronics) {
        Electronics e = (Electronics) p;
        e.showWarranty();
    }
}

processProduct(new Book());          // 商品 + 显示作者
processProduct(new Electronics());   // 商品 + 显示保修
```

> 💡 **注意**：如果 `if-else` 分发太多，说明设计可能有问题，应考虑把行为下放到子类（用多态替代条件分发）。但有些场景（如处理第三方库对象）确实需要 `instanceof`。

### 9.4 instanceof 对 null 的处理

```java
String s = null;
System.out.println(s instanceof String);   // false（null 不是任何类型的实例）
```

> 💡 `null instanceof 任何类型` 都是 `false`，所以 `instanceof` 天然处理了 null，不用额外判空。

## ⚠️ 重点

### 重点 1：成员访问特点口诀 ⭐⭐

**「变量看左，方法运行看右，静态看左」**——这是多态最核心的规则，面试必考。

```java
class Father {
    int num = 10;
    void method() { System.out.println("Father"); }
    static void staticMethod() { System.out.println("Father static"); }
}

class Son extends Father {
    int num = 20;
    @Override
    void method() { System.out.println("Son"); }
    static void staticMethod() { System.out.println("Son static"); }
}

Father f = new Son();
System.out.println(f.num);     // 10（变量看左）
f.method();                    // Son（方法运行看右）
f.staticMethod();              // Father static（静态看左）
```

> ⚠️ 成员变量不参与多态！很多人以为 `f.num` 是 20，实际是 10。这是因为变量在编译期就绑定了，没有动态绑定机制。

### 重点 2：向下转型必须先 instanceof ⭐⭐

```java
Animal a = new Cat();

// ❌ 危险：不判断直接强转
// Dog d = (Dog) a;   // ClassCastException

// ✅ 安全：先判断再强转
if (a instanceof Dog) {
    Dog d = (Dog) a;
    d.guard();
}
```

### 重点 3：多态不能调用子类特有方法 ⭐

```java
Animal a = new Cat();
a.eat();              // ✅ 父类有的
// a.catchMouse();    // ❌ 子类特有的，编译报错
```

> ⚠️ 这是多态的代价。如果一定要调用子类特有方法，必须向下转型。

### 重点 4：多态只对非静态方法有效 ⭐

```java
Father f = new Son();
f.method();        // Son（非静态方法，动态绑定）
f.staticMethod();  // Father static（静态方法，不动态绑定）
```

> 💡 静态方法属于类，绑定在编译期，不参与运行时多态。实际开发中静态方法用类名调用，不要用引用调用。

### 重点 5：多态的扩展性价值 ⭐⭐

```java
// 父类做参数，接收所有子类
void pay(Payment p, double amount) {
    p.pay(amount);
}

// 新增支付方式，不改这个方法
pay(new WechatPay(), 100);
pay(new Alipay(), 200);
pay(new BankCardPay(), 500);   // 新增，老代码零修改
```

> 💡 这就是「对扩展开放，对修改关闭」——多态是开闭原则的底层实现。

## 💻 实战案例

### 案例 1：电商支付统一处理 ⭐⭐

电商系统中，支付方式多样（微信、支付宝、银行卡、余额），用多态统一处理，新增支付方式不改老代码。

```java
// 父类：支付方式
abstract class Payment {
    protected String name;     // 支付方式名称

    public Payment(String name) {
        this.name = name;
    }

    // 抽象方法：子类必须实现具体支付逻辑
    public abstract boolean pay(double amount);

    // 通用方法：记录支付日志
    public void log(double amount, boolean success) {
        System.out.println("[" + name + "] 支付 " + amount + " 元，结果：" + (success ? "成功" : "失败"));
    }
}

// 子类：微信支付
class WechatPay extends Payment {
    public WechatPay() { super("微信支付"); }

    @Override
    public boolean pay(double amount) {
        System.out.println("调用微信支付 SDK，金额：" + amount);
        log(amount, true);
        return true;
    }
}

// 子类：支付宝支付
class Alipay extends Payment {
    public Alipay() { super("支付宝"); }

    @Override
    public boolean pay(double amount) {
        System.out.println("调用支付宝 SDK，金额：" + amount);
        log(amount, true);
        return true;
    }
}

// 子类：银行卡支付
class BankCardPay extends Payment {
    private String cardNumber;

    public BankCardPay(String cardNumber) {
        super("银行卡");
        this.cardNumber = cardNumber;
    }

    @Override
    public boolean pay(double amount) {
        System.out.println("从卡号 " + cardNumber + " 扣款 " + amount + " 元");
        if (amount > 50000) {
            System.out.println("超过单笔限额");
            log(amount, false);
            return false;
        }
        log(amount, true);
        return true;
    }
}

// 支付服务：面向父类编程，不关心具体子类
class PaymentService {
    // 多态：父类做参数，接收所有子类
    public void checkout(Payment payment, double amount) {
        System.out.println("====== 开始支付 ======");
        boolean success = payment.pay(amount);
        if (success) {
            System.out.println("订单支付成功");
        } else {
            System.out.println("支付失败，请重试");
        }
        System.out.println();
    }
}

// 使用
PaymentService service = new PaymentService();

service.checkout(new WechatPay(), 99.9);
// ====== 开始支付 ======
// 调用微信支付 SDK，金额：99.9
// [微信支付] 支付 99.9 元，结果：成功
// 订单支付成功

service.checkout(new Alipay(), 199.0);
// ====== 开始支付 ======
// 调用支付宝 SDK，金额：199.0
// [支付宝] 支付 199.0 元，结果：成功
// 订单支付成功

service.checkout(new BankCardPay("622848"), 60000);
// ====== 开始支付 ======
// 从卡号 622848 扣款 60000.0 元
```

### 案例 2：策略模式雏形——不同折扣策略 ⭐⭐

电商促销活动有多种折扣策略（满减、打折、无优惠），用多态实现策略切换，不修改计算逻辑。

```java
// 策略接口（父类角色）
interface DiscountStrategy {
    double calculate(double originalPrice);
}

// 策略1：无折扣
class NoDiscount implements DiscountStrategy {
    @Override
    public double calculate(double originalPrice) {
        return originalPrice;
    }
}

// 策略2：打 8 折
class PercentageDiscount implements DiscountStrategy {
    private double rate;
    public PercentageDiscount(double rate) { this.rate = rate; }
    @Override
    public double calculate(double originalPrice) {
        return originalPrice * rate;
    }
}

// 策略3：满 200 减 50
class FullReductionDiscount implements DiscountStrategy {
    private double threshold;
    private double reduction;
    public FullReductionDiscount(double threshold, double reduction) {
        this.threshold = threshold;
        this.reduction = reduction;
    }
    @Override
    public double calculate(double originalPrice) {
        if (originalPrice >= threshold) {
            return originalPrice - reduction;
        }
        return originalPrice;
    }
}

// 上下文：面向接口编程，不关心具体策略
class PriceCalculator {
    private DiscountStrategy strategy;   // 持有策略接口引用

    public PriceCalculator(DiscountStrategy strategy) {
        this.strategy = strategy;
    }

    public double calc(double originalPrice) {
        return strategy.calculate(originalPrice);   // 多态调用
    }
}

// 使用
PriceCalculator c1 = new PriceCalculator(new NoDiscount());
System.out.println(c1.calc(100));    // 100.0

PriceCalculator c2 = new PriceCalculator(new PercentageDiscount(0.8));
System.out.println(c2.calc(100));    // 80.0

PriceCalculator c3 = new PriceCalculator(new FullReductionDiscount(200, 50));
System.out.println(c3.calc(250));    // 200.0
System.out.println(c3.calc(150));    // 150.0（不满 200 不减）

// ✅ 新增「新人立减 10 元」策略，不改 PriceCalculator
class NewUserDiscount implements DiscountStrategy {
    @Override
    public double calculate(double originalPrice) {
        return Math.max(0, originalPrice - 10);
    }
}
PriceCalculator c4 = new PriceCalculator(new NewUserDiscount());
System.out.println(c4.calc(30));     // 20.0
```

> 💡 这就是**策略模式**的核心：将算法封装成独立类，通过多态在运行时切换。Spring 中 `@Autowired` 注入不同实现类就是这种模式。

### 案例 3：用 instanceof 做类型分发——处理不同类型商品 ⭐

后台系统中，不同类型商品有不同的额外处理逻辑，用 `instanceof` 分发。

```java
class Product {
    private String name;
    private double price;
    public Product(String name, double price) { this.name = name; this.price = price; }
    public String getName() { return name; }
    public double getPrice() { return price; }
    public void showBasic() { System.out.println(name + " ￥" + price); }
}

class Book extends Product {
    private String author;
    public Book(String name, double price, String author) { super(name, price); this.author = author; }
    public String getAuthor() { return author; }
    public void showAuthor() { System.out.println("作者：" + author); }
}

class Electronics extends Product {
    private int warranty;
    public Electronics(String name, double price, int warranty) { super(name, price); this.warranty = warranty; }
    public int getWarranty() { return warranty; }
    public void showWarranty() { System.out.println("保修：" + warranty + " 个月"); }
}

class Clothing extends Product {
    private String size;
    public Clothing(String name, double price, String size) { super(name, price); this.size = size; }
    public String getSize() { return size; }
    public void showSize() { System.out.println("尺码：" + size); }
}

// 商品详情页渲染：统一入口，按类型分发
class ProductRenderer {
    public void render(Product p) {
        p.showBasic();   // ✅ 多态调用，所有商品都有

        // 按真实类型分发，调用子类特有方法
        if (p instanceof Book) {
            Book b = (Book) p;
            b.showAuthor();
        } else if (p instanceof Electronics) {
            Electronics e = (Electronics) p;
            e.showWarranty();
        } else if (p instanceof Clothing) {
            Clothing c = (Clothing) p;
            c.showSize();
        }
        System.out.println("---");
    }
}

// 使用
ProductRenderer renderer = new ProductRenderer();
renderer.render(new Book("Java核心", 89.0, "Cay Horstmann"));
// Java核心 ￥89.0
// 作者：Cay Horstmann
// ---

renderer.render(new Electronics("蓝牙耳机", 299.0, 12));
// 蓝牙耳机 ￥299.0
// 保修：12 个月
// ---

renderer.render(new Clothing("T恤", 59.0, "XL"));
// T恤 ￥59.0
// 尺码：XL
// ---
```

> ⚠️ **设计提醒**：`instanceof` 分发虽然能用，但如果类型频繁增加，`if-else` 会越来越长。更好的做法是把 `showDetail()` 下放到父类（抽象方法），让子类各自实现，用多态替代 `instanceof`。上面案例展示的是「无法修改父类」时的妥协方案。

### 案例 4：多态统一处理商品计算——结算系统

```java
abstract class Product {
    protected String name;
    protected double price;
    public Product(String name, double price) { this.name = name; this.price = price; }
    public String getName() { return name; }
    // 抽象方法：不同商品有不同的最终价格计算
    public abstract double calcFinalPrice(int quantity);
}

class Book extends Product {
    public Book(String name, double price) { super(name, price); }
    @Override
    public double calcFinalPrice(int quantity) {
        return price * quantity;   // 图书不打折
    }
}

class Electronics extends Product {
    public Electronics(String name, double price) { super(name, price); }
    @Override
    public double calcFinalPrice(int quantity) {
        double total = price * quantity;
        if (quantity >= 3) total *= 0.9;   // 电子产品满3件9折
        return total;
    }
}

class Clothing extends Product {
    public Clothing(String name, double price) { super(name, price); }
    @Override
    public double calcFinalPrice(int quantity) {
        double total = price * quantity;
        if (total >= 500) total -= 50;   // 服装满500减50
        return total;
    }
}

// 购物车结算：多态统一处理，不关心具体商品类型
class ShoppingCart {
    private java.util.List<Product> items = new java.util.ArrayList<>();

    public void add(Product p) { items.add(p); }

    public double checkout() {
        double total = 0;
        for (Product p : items) {
            // ✅ 多态：p 可能是 Book、Electronics、Clothing
            // 运行时自动调用对应子类的 calcFinalPrice
            double subTotal = p.calcFinalPrice(1);
            System.out.println(p.getName() + " 小计：" + subTotal);
            total += subTotal;
        }
        System.out.println("总计：" + total);
        return total;
    }
}

// 使用
ShoppingCart cart = new ShoppingCart();
cart.add(new Book("Java编程思想", 99.0));
cart.add(new Electronics("机械键盘", 399.0));
cart.add(new Clothing("外套", 550.0));
cart.checkout();
// Java编程思想 小计：99.0
// 机械键盘 小计：399.0
// 外套 小计：500.0（550 - 50）
// 总计：998.0
```

> 💡 注意 `for (Product p : items)` 这一行——`p` 的编译类型是 `Product`，但运行时可能是任意子类。`p.calcFinalPrice(1)` 自动调用子类重写的方法，这就是多态的威力。新增商品类型，`ShoppingCart` 不用改一行代码。

### 案例 5：日志系统——多态 + instanceof 结合

```java
interface Logger {
    void log(String message);
}

class ConsoleLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[CONSOLE] " + message);
    }
}

class FileLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[FILE] 写入文件：" + message);
    }
}

class DatabaseLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[DB] 写入数据库：" + message);
    }
}

// 日志管理器：多态统一处理
class LogManager {
    private java.util.List<Logger> loggers = new java.util.ArrayList<>();

    public void addLogger(Logger logger) { loggers.add(logger); }

    public void log(String message) {
        for (Logger l : loggers) {
            l.log(message);   // ✅ 多态：每个 logger 输出到不同地方
        }
    }
}

// 使用
LogManager manager = new LogManager();
manager.addLogger(new ConsoleLogger());
manager.addLogger(new FileLogger());
manager.addLogger(new DatabaseLogger());
manager.log("用户下单成功");
// [CONSOLE] 用户下单成功
// [FILE] 写入文件：用户下单成功
// [DB] 写入数据库：用户下单成功

// ✅ 新增「邮件日志」，不改 LogManager
class EmailLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[EMAIL] 发送邮件：" + message);
    }
}
manager.addLogger(new EmailLogger());
manager.log("库存预警");
```

## 🚀 新版本补充

### Java 16：instanceof 模式匹配（预览）

Java 16 引入了 `instanceof` 的模式匹配语法，**判断和强转一步到位**，告别冗余的强转代码：

```java
// Java 8 写法：先判断再强转，两步
Object obj = "hello";
if (obj instanceof String) {
    String s = (String) obj;      // 还要再强转一次
    System.out.println(s.length());
}

// Java 16+ 写法：模式匹配，判断即绑定变量
if (obj instanceof String s) {   // ✅ 如果是 String，自动绑定到变量 s
    System.out.println(s.length());
}
```

### Java 21：switch 模式匹配（正式版）

结合 `instanceof` 模式匹配，`switch` 也能做类型分发，比 `if-else instanceof` 更优雅：

```java
// Java 21+
String format(Object obj) {
    return switch (obj) {
        case Integer i -> "整数：" + i;
        case String s  -> "字符串：" + s;
        case Double d  -> "小数：" + d;
        case null      -> "空值";
        default        -> "其他：" + obj;
    };
}

System.out.println(format(42));      // 整数：42
System.out.println(format("hi"));    // 字符串：hi
System.out.println(format(3.14));    // 小数：3.14
System.out.println(format(null));    // 空值
```

> ⚠️ 以上特性 Java 8 不支持。Java 8 中只能用传统 `instanceof` + 强转的方式。但理解模式匹配有助于阅读现代 Java 代码（如 Spring 6 源码）。

### Java 14：Record 类（预览，Java 16 正式）

Record 类天然适合做多态的值载体，配合密封类使用：

```java
// Java 16+
sealed interface Shape permits Circle, Rectangle {}

record Circle(double radius) implements Shape {}
record Rectangle(double width, double height) implements Shape {}

// Java 21 switch 模式匹配 + record 解构
double area(Shape s) {
    return switch (s) {
        case Circle(double r) -> Math.PI * r * r;
        case Rectangle(double w, double h) -> w * h;
    };
}
```

> 💡 这是 Java 未来多态的发展方向：密封类 + record + 模式匹配，实现类似函数式语言的代数数据类型。Java 8 环境了解即可。

## 学习建议

1. **牢记成员访问口诀**：「变量看左，方法运行看右，静态看左」。把第三节的对比表代码敲一遍运行，亲眼看到 `f.num` 是 10 而不是 20，这个印象会比看十遍文字都深。
2. **用多态重构一段 if-else**：找一段你写过的 `if (type == 1) ... else if (type == 2)` 代码，尝试用多态重构（定义父类、子类各自实现），体会「新增类型不改老代码」的扩展性。这是理解设计模式的第一步。
3. **向下转型务必先 instanceof**：养成「强转前先判断」的肌肉记忆，能避免 90% 的 `ClassCastException`。在 JSON 解析、反序列化场景中尤其重要。
4. **对比向上/向下转型**：向上转型是安全的（子类一定是父类），向下转型有风险（父类引用的真实类型不确定）。理解为什么一个安全一个危险，关键在于「真实类型」和「声明类型」的差异。
5. **策略模式练手**：用多态实现一个「排序策略」系统（冒泡、快排、归并），通过传入不同策略对象切换算法。这是策略模式的标准实现，也是 Spring 依赖注入的底层思想——面向接口编程，运行时注入具体实现。
