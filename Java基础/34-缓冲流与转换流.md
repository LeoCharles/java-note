# 缓冲流与转换流

前面几篇我们学了基本字节流（`FileInputStream`/`FileOutputStream`）和基本字符流（`FileReader`/`FileWriter`）。它们能完成读写，但有两个明显短板：**效率低**（每次 read/write 都直接操作磁盘，频繁 IO）和**中文乱码**（字节流读中文时字符集不匹配）。缓冲流解决效率问题，转换流解决字节与字符、字符集之间的桥梁问题——这两者都是「处理流」，套在基本流外面使用，是实际开发中 IO 的标配写法。

> 💡 在阅读本篇前，建议先看 [32-字节流与字符流](32-字节流与字符流.md)，理解节点流（直接读写文件）和处理流（套接增强）的区别，本篇的缓冲流、转换流都属于处理流。

---

## 一、缓冲流：提高读写效率

### 1.1 为什么需要缓冲流

基本字节流每次调用 `read()`/`write()` 都会直接访问磁盘。磁盘 IO 是非常慢的操作（比内存慢几万倍），如果一次只读 1 个字节，读 1MB 文件就要做 100 万次磁盘 IO。

缓冲流的核心思想：**在内存中开一个缓冲区（默认 8192 字节 / 8KB）**，读写先操作缓冲区，缓冲区满了再一次性刷到磁盘，把「多次小 IO」合并成「一次大 IO」，效率大幅提升。

```
基本流：       内存 ←→ 磁盘（每次 1 字节，频繁 IO）
缓冲流：       内存 ←→ 缓冲区(8KB) ←→ 磁盘（攒满一批再走，减少 IO 次数）
```

> 💡 缓冲流是**处理流**，不能独立存在，必须套在一个节点流外面：`new BufferedInputStream(new FileInputStream(file))`。

### 1.2 BufferedOutputStream：缓冲输出

`BufferedOutputStream` 内部维护一个 8192 字节的 `byte[]` 缓冲区。`write()` 写入的数据先进缓冲区，缓冲区满后自动刷新到底层流。

```java
import java.io.*;

public class BufferedOutputDemo {
    public static void main(String[] args) throws IOException {
        // 基本流套缓冲流
        FileOutputStream fos = new FileOutputStream("a.txt");
        BufferedOutputStream bos = new BufferedOutputStream(fos);

        bos.write("Hello".getBytes());   // 数据先进缓冲区，不一定立刻落盘
        bos.write("World".getBytes());

        bos.flush();   // ✅ 手动刷新：把缓冲区剩余数据强制写出
        bos.close();   // close() 内部会先调 flush()，再关流
    }
}
```

> ⚠️ **忘记 flush/close 会导致数据丢失**：缓冲区没满时数据还留在内存，程序直接退出，文件里就少内容。所以缓冲输出流**一定要 close**（close 内部会自动 flush）。

### 1.3 BufferedInputStream：缓冲读取

`BufferedInputStream` 同样内部有一个 8192 字节缓冲区，`read()` 一次性读一批到缓冲区，后续 read 从缓冲区取，取完再读下一批。

```java
import java.io.*;

public class BufferedInputDemo {
    public static void main(String[] args) throws IOException {
        BufferedInputStream bis = new BufferedInputStream(new FileInputStream("a.txt"));

        // 方式一：逐字节读（实际从缓冲区取，效率高）
        int b;
        while ((b = bis.read()) != -1) {
            System.out.print((char) b);
        }

        // 方式二：批量读到字节数组
        byte[] buf = new byte[1024];
        int len;
        while ((len = bis.read(buf)) != -1) {
            System.out.println(new String(buf, 0, len));
        }

        bis.close();
    }
}
```

### 1.4 BufferedWriter：newLine() 跨平台换行

`BufferedWriter` 提供了 `newLine()` 方法，会根据当前操作系统输出对应的换行符（Windows 是 `\r\n`，Linux 是 `\n`，Mac 是 `\r`），避免硬编码换行符的跨平台问题。

```java
import java.io.*;

public class BufferedWriterDemo {
    public static void main(String[] args) throws IOException {
        BufferedWriter bw = new BufferedWriter(new FileWriter("lines.txt"));

        bw.write("第一行");
        bw.newLine();        // ✅ 跨平台换行，比写 "\r\n" 更规范
        bw.write("第二行");
        bw.newLine();
        bw.write("第三行");

        bw.flush();
        bw.close();
    }
}
```

> 📌 **规范**：换行不要写死 `"\r\n"` 或 `"\n"`，用 `BufferedWriter.newLine()` 或 `System.lineSeparator()`，保证程序在不同系统下生成的文件都能正确显示。

### 1.5 BufferedReader：readLine() 读一行

`BufferedReader` 最常用的方法是 `readLine()`：一次读一行文本，返回字符串（**不含换行符**），读到末尾返回 `null`。这是按行处理文本文件的最佳选择。

```java
import java.io.*;

public class BufferedReaderDemo {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new FileReader("lines.txt"));

        String line;
        while ((line = br.readLine()) != null) {  // ✅ 经典按行读
            System.out.println(line);
        }

        br.close();
    }
}
```

> ⚠️ `readLine()` 返回的字符串**不包含换行符**，如果需要保留换行，要自己补 `System.lineSeparator()`。

### 1.6 缓冲流性能对比

我们用一个实际例子对比基本流和缓冲流复制文件的耗时：

```java
import java.io.*;

public class PerformanceTest {
    // 基本字节流：逐字节复制
    public static long copyBasic(String src, String dest) throws IOException {
        long start = System.currentTimeMillis();
        FileInputStream fis = new FileInputStream(src);
        FileOutputStream fos = new FileOutputStream(dest);
        int b;
        while ((b = fis.read()) != -1) {
            fos.write(b);
        }
        fis.close(); fos.close();
        return System.currentTimeMillis() - start;
    }

    // 缓冲流：逐字节复制（缓冲区加持）
    public static long copyBuffered(String src, String dest) throws IOException {
        long start = System.currentTimeMillis();
        BufferedInputStream bis = new BufferedInputStream(new FileInputStream(src));
        BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream(dest));
        int b;
        while ((b = bis.read()) != -1) {
            bos.write(b);
        }
        bis.close(); bos.close();
        return System.currentTimeMillis() - start;
    }

    public static void main(String[] args) throws IOException {
        // 假设 src.mp4 是一个 10MB 的文件
        long t1 = copyBasic("src.mp4", "dest1.mp4");
        long t2 = copyBuffered("src.mp4", "dest2.mp4");
        System.out.println("基本流耗时：" + t1 + " ms");   // 可能几千毫秒
        System.out.println("缓冲流耗时：" + t2 + " ms");   // 通常几十毫秒
    }
}
```

> 💡 **结论**：即使都是「逐字节读写」，缓冲流也比基本流快几十倍。实际开发中复制文件**必用缓冲流**，且推荐用「批量读字节数组 + 缓冲流」组合，效率最高。

## 二、转换流：字节与字符的桥梁

### 2.1 为什么需要转换流

`FileReader`/`FileWriter` 的坑在于：**它们使用系统默认字符集**（中文 Windows 默认 GBK，Linux 默认 UTF-8）。如果文件是 UTF-8 编码，而你的程序跑在 GBK 系统上，用 `FileReader` 读就会乱码。

转换流 `InputStreamReader` / `OutputStreamWriter` 的作用：**把字节流转换成字符流，并且可以在构造时显式指定字符集**，彻底解决乱码问题。

```
字节流（InputStream） ──InputStreamReader(指定字符集)──→ 字符流（Reader）
字符流（Writer） ──OutputStreamWriter(指定字符集)──→ 字节流（OutputStream）
```

### 2.2 InputStreamReader：字节输入 → 字符输入

```java
import java.io.*;

public class InputStreamReaderDemo {
    public static void main(String[] args) throws IOException {
        // ✅ 显式指定 UTF-8，无论程序跑在哪个系统都不会乱码
        FileInputStream fis = new FileInputStream("utf8.txt");
        InputStreamReader isr = new InputStreamReader(fis, "UTF-8");
        BufferedReader br = new BufferedReader(isr);   // 再套缓冲流

        String line;
        while ((line = br.readLine()) != null) {
            System.out.println(line);
        }
        br.close();
    }
}
```

> ⚠️ 字符集名字大小写不敏感，`"UTF-8"`、`"utf-8"`、`"UTF8"` 都行，但建议统一写 `"UTF-8"`。如果写错字符集名会抛 `UnsupportedEncodingException`。

### 2.3 OutputStreamWriter：字符输出 → 字节输出

```java
import java.io.*;

public class OutputStreamWriterDemo {
    public static void main(String[] args) throws IOException {
        // ✅ 指定 UTF-8 写出，保证其他程序按 UTF-8 读不乱码
        FileOutputStream fos = new FileOutputStream("out.txt");
        OutputStreamWriter osw = new OutputStreamWriter(fos, "UTF-8");
        BufferedWriter bw = new BufferedWriter(osw);

        bw.write("你好，世界");
        bw.newLine();
        bw.write("Hello World");

        bw.flush();
        bw.close();
    }
}
```

### 2.4 解决字节流读中文的乱码问题

对比用基本字节流和转换流读取中文文件：

```java
import java.io.*;

public class ChineseEncodingTest {
    public static void main(String[] args) throws IOException {
        // 假设 a.txt 是 UTF-8 编码，内容："你好Java"

        // ❌ 错误：用字节流直接转 String，依赖系统默认字符集
        // 在 GBK 系统上会乱码（UTF-8 中文 3 字节，GBK 中文 2 字节）
        FileInputStream fis = new FileInputStream("a.txt");
        byte[] buf = new byte[1024];
        int len = fis.read(buf);
        System.out.println(new String(buf, 0, len));  // 可能乱码
        fis.close();

        // ✅ 正确：用转换流指定 UTF-8
        InputStreamReader isr = new InputStreamReader(
                new FileInputStream("a.txt"), "UTF-8");
        char[] cbuf = new char[1024];
        int len2 = isr.read(cbuf);
        System.out.println(new String(cbuf, 0, len2));  // 正确显示
        isr.close();
    }
}
```

> ⚠️ **乱码的本质**：编码（写字）和解码（读字）用了**不同的字符集**。只要读写用同一个字符集，就不会乱码。转换流的价值就是让你能**显式指定**这个字符集。

### 2.5 装饰模式：缓冲流 + 转换流组合

实际开发中，读文本文件的标准写法是「三层套娃」：

```java
// 经典写法：文件字节流 → 转换流(指定字符集) → 缓冲流(提高效率)
BufferedReader reader = new BufferedReader(
        new InputStreamReader(
                new FileInputStream("data.txt"), "UTF-8"));

String line;
while ((line = reader.readLine()) != null) {
    // 处理每一行
}
reader.close();
```

```java
// 写文件同理
BufferedWriter writer = new BufferedWriter(
        new OutputStreamWriter(
                new FileOutputStream("out.txt"), "UTF-8"));
writer.write("内容");
writer.close();
```

> 💡 这种「层层套接」就是**装饰模式（Decorator Pattern）**：转换流装饰字节流（加上字符集能力），缓冲流再装饰转换流（加上缓冲能力）。每套一层就多一个功能，但对外接口都是 Reader/Writer。

## 三、字符集 Charset

### 3.1 常见字符集

| 字符集 | 中文名 | 中文编码 | 特点 |
| :--- | :--- | :--- | :--- |
| `ISO-8859-1` | Latin-1 | 不支持中文 | 单字节，Tomcat 默认（老版本） |
| `GBK` | 国标码 | 2 字节 | 中文 Windows 默认 |
| `UTF-8` | Unicode 变长 | 3 字节 | 国际通用，推荐 |
| `UTF-16` | Unicode 定长 | 2/4 字节 | Java 内部 String 用的编码 |

### 3.2 StandardCharsets 常量

Java 7 起提供了 `StandardCharsets` 类，用常量代替字符串，避免拼写错误：

```java
import java.nio.charset.StandardCharsets;
import java.nio.charset.Charset;

// ✅ 用常量，编译期检查，不会拼错
InputStreamReader isr = new InputStreamReader(
        new FileInputStream("a.txt"), StandardCharsets.UTF_8);

// ❌ 用字符串，容易拼错（运行时才报错）
InputStreamReader isr2 = new InputStreamReader(
        new FileInputStream("a.txt"), "UFT-8");  // 拼错，抛异常
```

> 📌 **规范**：指定字符集优先用 `StandardCharsets.UTF_8` 等常量，不用字符串 `"UTF-8"`。常量是类型安全的，IDE 有提示，不会拼错。

### 3.3 查看默认字符集

```java
import java.nio.charset.Charset;

// 查看当前 JVM 默认字符集
System.out.println(Charset.defaultCharset());  // 中文 Windows 上通常是 GBK，Linux 上是 UTF-8

// 这就是 FileReader 默认使用的字符集——也是它容易乱码的根源
```

> ⚠️ `Charset.defaultCharset()` 受 JVM 启动参数 `-Dfile.encoding` 影响。生产环境通常统一设为 `-Dfile.encoding=UTF-8`，避免因系统不同导致行为不一致。

## 四、标准输入输出流的转换

### 4.1 System.in 是 InputStream

`System.in` 是一个 `InputStream`（字节流），直接读键盘输入要手动处理字节转字符，很麻烦。用 `InputStreamReader` 包装后就能按字符读，再套 `BufferedReader` 就能按行读。

```java
import java.io.*;

public class KeyboardInput {
    public static void main(String[] args) throws IOException {
        // System.in 是 InputStream，转换成字符流再按行读
        BufferedReader br = new BufferedReader(
                new InputStreamReader(System.in));

        System.out.print("请输入用户名：");
        String username = br.readLine();
        System.out.print("请输入年龄：");
        String age = br.readLine();

        System.out.println("你好，" + username + "，年龄 " + age);
    }
}
```

> 💡 这是 Java 5 之前读键盘输入的标准方式。Java 5+ 提供了更简洁的 `java.util.Scanner`（内部也是包装了 System.in），但理解转换流的原理对阅读老代码、处理网络流很重要。

### 4.2 System.out 是 PrintStream

`System.out` 本质是 `PrintStream`（打印流，下一篇详讲），它继承了 `FilterOutputStream`，可以包装使用：

```java
import java.io.*;

public class SystemOutTest {
    public static void main(String[] args) {
        // System.out 是 PrintStream 的实例
        PrintStream ps = System.out;
        ps.println("直接用 PrintStream 打印");
        ps.printf("格式化：%s，%d%n", "字符串", 100);
    }
}
```

## ⚠️ 重点

### 重点 1：缓冲流必须 flush 或 close ⭐⭐

```java
BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream("a.txt"));
bos.write("hello".getBytes());
// 程序异常退出，没 close → ❌ 文件可能为空，数据还在缓冲区没落盘

bos.write("world".getBytes());
bos.flush();   // ✅ 手动刷新，确保数据落盘
bos.close();  // ✅ close 内部会 flush，所以只 close 也行
```

> ⚠️ **最佳实践**：用 try-with-resources（Java 7+）自动关流，既保证 flush 又防止忘关：
> ```java
> try (BufferedOutputStream bos = new BufferedOutputStream(
>         new FileOutputStream("a.txt"))) {
>     bos.write("hello".getBytes());
> }  // 自动 close，内部自动 flush
> ```

### 重点 2：readLine() 不含换行符 ⭐

```java
BufferedReader br = new BufferedReader(new FileReader("a.txt"));
String line = br.readLine();  // "第一行"，不含 \n
// 如果原样写回，要自己补换行
BufferedWriter bw = new BufferedWriter(new FileWriter("b.txt"));
bw.write(line);
bw.newLine();  // ✅ 必须手动补，否则所有行挤成一行
```

### 重点 3：FileReader 不能指定字符集（Java 8）⭐⭐

这是 Java 8 中 `FileReader` 最大的坑：

```java
// ❌ Java 8 的 FileReader 构造方法不支持传字符集
// FileReader fr = new FileReader("a.txt", "UTF-8");  // 编译错误！Java 8 没有这个构造

// ✅ Java 8 必须用转换流来指定字符集
Reader reader = new InputStreamReader(new FileInputStream("a.txt"), "UTF-8");
```

> ⚠️ **注意**：Java 11 才给 `FileReader` 加了带 `Charset` 参数的构造方法。Java 8 环境下要指定字符集，只能用 `InputStreamReader`。这是 Java 8 开发中必记的坑。

### 重点 4：字符集拼写错误运行时才报错 ⭐

```java
// ❌ 字符串拼错，编译期不报错，运行时抛 UnsupportedEncodingException
InputStreamReader isr = new InputStreamReader(fis, "UTF-8-");  // 运行时异常

// ✅ 用 StandardCharsets 常量，编译期就能发现
InputStreamReader isr2 = new InputStreamReader(fis, StandardCharsets.UTF_8);
```

### 重点 5：装饰模式的套接顺序 ⭐

转换流和缓冲流的套接顺序不能乱：

```java
// ✅ 正确：字节流 → 转换流 → 缓冲流
BufferedReader br = new BufferedReader(
        new InputStreamReader(new FileInputStream("a.txt"), "UTF-8"));

// ❌ 错误：缓冲流套在字节流上，无法指定字符集
// BufferedReader br2 = new BufferedReader(new FileInputStream("a.txt"));  // 编译错误，类型不匹配

// ❌ 错误：转换流不能套在缓冲字符流外面
// InputStreamReader isr = new InputStreamReader(new BufferedReader(...));  // 逻辑反了
```

> 💡 **记忆**：转换流是「字节↔字符」的桥，必须紧贴字节流；缓冲流是最外层增强，套在最外面。

## 💻 实战案例

### 案例 1：大文件高效复制（缓冲流 + 批量读写）⭐⭐

电商系统需要把用户上传的商品图片复制到备份目录，文件可能上百 MB，必须高效：

```java
import java.io.*;

public class FileCopy {
    public static void copyFile(String src, String dest) throws IOException {
        // 缓冲流 + 批量字节数组，最高效的复制方式
        try (BufferedInputStream bis = new BufferedInputStream(new FileInputStream(src));
             BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream(dest))) {

            byte[] buf = new byte[8192];   // 8KB 缓冲区
            int len;
            while ((len = bis.read(buf)) != -1) {
                bos.write(buf, 0, len);
            }
            // try-with-resources 自动 close + flush
        }
    }

    public static void main(String[] args) throws IOException {
        long start = System.currentTimeMillis();
        copyFile("product.jpg", "product_backup.jpg");
        System.out.println("复制耗时：" + (System.currentTimeMillis() - start) + " ms");
    }
}
```

> 📌 **规范**：文件复制用「`BufferedInputStream` + `BufferedOutputStream` + 8KB 字节数组」，这是 JDK 中效率最高的纯 IO 复制方式（Java 7+ 也可用 `Files.copy`，内部实现类似）。

### 案例 2：读取 UTF-8 文本防乱码（转换流）⭐⭐

后台系统读取用户提交的 UTF-8 编码的 CSV 文件，解析每行数据：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class CsvReader {
    public static void readCsv(String path) throws IOException {
        // ✅ 显式指定 UTF-8，跨平台不乱码
        try (BufferedReader br = new BufferedReader(
                new InputStreamReader(new FileInputStream(path), StandardCharsets.UTF_8))) {

            String line;
            boolean header = true;
            while ((line = br.readLine()) != null) {
                if (header) { header = false; continue; }  // 跳过表头
                String[] cols = line.split(",");
                // cols[0]=商品名 cols[1]=价格 cols[2]=库存
                System.out.println("商品：" + cols[0] + "，价格：" + cols[1]);
            }
        }
    }
}
```

> ⚠️ 如果这里用 `new FileReader(path)`，在 GBK 系统上读 UTF-8 文件，中文商品名会全部乱码，导致数据解析失败。**读文本文件一律用转换流指定字符集**。

### 案例 3：GBK 转 UTF-8 文件转换 ⭐⭐

老系统导出的数据是 GBK 编码，新系统要求 UTF-8，需要批量转换：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class EncodingConverter {
    public static void convert(String srcFile, String destFile) throws IOException {
        // 用 GBK 读老文件
        try (BufferedReader br = new BufferedReader(
                new InputStreamReader(new FileInputStream(srcFile), "GBK"));
             // 用 UTF-8 写新文件
             BufferedWriter bw = new BufferedWriter(
                new OutputStreamWriter(new FileOutputStream(destFile), StandardCharsets.UTF_8))) {

            String line;
            while ((line = br.readLine()) != null) {
                bw.write(line);
                bw.newLine();   // 跨平台换行
            }
        }
    }

    public static void main(String[] args) throws IOException {
        convert("old_data_gbk.txt", "new_data_utf8.txt");
        System.out.println("转换完成");
    }
}
```

> 💡 这是数据迁移中常见的需求：一边按源字符集读，一边按目标字符集写，转换流天然支持这种「读时解码、写时编码」的模式。

### 案例 4：按行读取日志文件并过滤 ⭐

运维场景：读取应用日志，找出所有 ERROR 级别的行，写入错误日志文件：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class LogFilter {
    public static void filterError(String logFile, String errorFile) throws IOException {
        try (BufferedReader br = new BufferedReader(
                new InputStreamReader(new FileInputStream(logFile), StandardCharsets.UTF_8));
             BufferedWriter bw = new BufferedWriter(
                new OutputStreamWriter(new FileOutputStream(errorFile), StandardCharsets.UTF_8))) {

            String line;
            int count = 0;
            while ((line = br.readLine()) != null) {
                if (line.contains("ERROR")) {
                    bw.write(line);
                    bw.newLine();
                    count++;
                }
            }
            System.out.println("共筛选出 " + count + " 条错误日志");
        }
    }
}
```

> 💡 `BufferedReader.readLine()` 是处理日志这类「按行组织」文本的最佳工具，配合转换流指定字符集，能稳定处理各种编码的日志文件。

### 案例 5：键盘输入菜单（System.in + 转换流）⭐

后台管理系统的命令行交互菜单，读取用户键盘输入：

```java
import java.io.*;

public class ConsoleMenu {
    public static void main(String[] args) throws IOException {
        // System.in（字节流）→ InputStreamReader → BufferedReader
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        while (true) {
            System.out.println("===== 订单管理系统 =====");
            System.out.println("1. 查询订单");
            System.out.println("2. 创建订单");
            System.out.println("3. 退出");
            System.out.print("请选择：");

            String input = br.readLine();   // 读整行
            switch (input) {
                case "1":
                    System.out.println(">> 查询订单功能");
                    break;
                case "2":
                    System.out.println(">> 创建订单功能");
                    break;
                case "3":
                    System.out.println(">> 再见");
                    return;
                default:
                    System.out.println(">> 无效输入：" + input);
            }
        }
    }
}
```

> 💡 虽然 Java 5+ 更推荐用 `Scanner`，但 `BufferedReader.readLine()` 读取整行的行为更可控（Scanner 的 nextInt 等会留换行符在缓冲区，容易导致后续 nextLine 读到空串），理解转换流包装 System.in 的原理很重要。

### 案例 6：合并多个日志文件（缓冲流批量处理）⭐

运维需要把按天分割的多个日志文件合并成一个总日志：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.List;

public class LogMerger {
    public static void merge(List<String> srcFiles, String destFile) throws IOException {
        try (BufferedWriter bw = new BufferedWriter(
                new OutputStreamWriter(new FileOutputStream(destFile), StandardCharsets.UTF_8))) {

            for (String src : srcFiles) {
                try (BufferedReader br = new BufferedReader(
                        new InputStreamReader(new FileInputStream(src), StandardCharsets.UTF_8))) {
                    String line;
                    while ((line = br.readLine()) != null) {
                        bw.write(line);
                        bw.newLine();
                    }
                }
                bw.write("---- 上面来自 " + src + " ----");
                bw.newLine();
            }
        }
    }

    public static void main(String[] args) throws IOException {
        List<String> logs = new ArrayList<>();
        logs.add("app-2024-01-01.log");
        logs.add("app-2024-01-02.log");
        logs.add("app-2024-01-03.log");
        merge(logs, "app-all.log");
    }
}
```

> 📌 **规范**：每个源文件用独立的 try-with-resources 打开和关闭，避免打开过多流导致资源泄漏。合并写入的目标流只开一个，复用缓冲区。

## 🚀 新版本补充

### Java 11：FileReader/FileWriter 支持指定字符集

Java 11 给 `FileReader` 和 `FileWriter` 增加了带 `Charset` 参数的构造方法，可以替代转换流简化代码：

```java
// Java 11+ 写法（更简洁）
FileReader fr = new FileReader("a.txt", StandardCharsets.UTF_8);
FileWriter fw = new FileWriter("b.txt", StandardCharsets.UTF_8);

// 等价于 Java 8 的转换流写法
InputStreamReader isr = new InputStreamReader(new FileInputStream("a.txt"), StandardCharsets.UTF_8);
```

> ⚠️ Java 8 环境下 `FileReader` 没有这个构造方法，只能用转换流。升级到 Java 11 后可以简化，但底层实现完全一样。

### Java 8：Files.lines() 按行读取（Stream）

Java 8 的 NIO `Files.lines()` 可以直接按行读取文件返回 `Stream<String>`，内部也是用转换流 + 缓冲流：

```java
import java.nio.file.*;
import java.nio.charset.StandardCharsets;

// Java 8+ 一行代码按行读（指定 UTF-8）
Files.lines(Paths.get("a.txt"), StandardCharsets.UTF_8)
     .filter(line -> line.contains("ERROR"))
     .forEach(System.out::println);
```

> 💡 这是 Java 8 函数式风格写法，底层封装了 `BufferedReader`。但理解了本篇的转换流原理，再看 `Files.lines` 就一目了然。

### Java 8：BufferedReader.lines() 返回 Stream

`BufferedReader` 在 Java 8 新增了 `lines()` 方法，返回 `Stream<String>`：

```java
BufferedReader br = new BufferedReader(
        new InputStreamReader(new FileInputStream("a.txt"), StandardCharsets.UTF_8));
br.lines().filter(s -> s.length() > 10).forEach(System.out::println);
br.close();
```

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 缓冲流作用 | 内部 8KB 缓冲区，减少磁盘 IO，提高效率 |
| BufferedOutputStream | 写缓冲区，满则刷盘，需 flush/close |
| BufferedInputStream | 读到缓冲区，read 从缓冲区取 |
| BufferedWriter | `newLine()` 跨平台换行 |
| BufferedReader | `readLine()` 读一行，返回不含换行符 |
| 转换流作用 | 字节↔字符桥梁，可指定字符集 |
| InputStreamReader | 字节输入 → 字符输入，构造指定字符集 |
| OutputStreamWriter | 字符输出 → 字节输出，构造指定字符集 |
| FileReader 的坑 | Java 8 不能指定字符集，要用转换流 |
| StandardCharsets | 用常量代替字符串，避免拼错 |
| 装饰模式 | 缓冲流套转换流套字节流：`new BufferedReader(new InputStreamReader(new FileInputStream(file), UTF_8))` |
| System.in | 是 InputStream，用 InputStreamReader 包装读键盘 |

## 学习建议

1. **务必手写性能对比**：自己写一个「基本流逐字节复制」和「缓冲流逐字节复制」的对比程序，复制一个 10MB 文件，亲眼看到几十倍的速度差异，比看文字印象深刻得多。
2. **牢记标准套接写法**：读文本文件的标准写法 `new BufferedReader(new InputStreamReader(new FileInputStream(file), StandardCharsets.UTF_8))` 要背下来，这是 Java 8 中最规范的文本读取方式，面试和工作中天天用。
3. **理解乱码本质**：乱码 = 编码和解码用了不同字符集。不要死记「用 UTF-8 就行」，要理解「读写用同一字符集就不乱码」这个原理，遇到任何乱码问题都能分析。
4. **用 try-with-resources 管理流**：缓冲流忘记 close 会导致数据丢失，从第一天起就用 try-with-resources 语法，既安全又简洁，彻底告别手动 close 的繁琐和遗漏。
5. **区分 Java 8 和 Java 11 的差异**：Java 8 的 `FileReader` 不能指定字符集（必须用转换流），Java 11 才能。写代码时要清楚自己用的 JDK 版本，避免用了高版本 API 在低版本上报错。
