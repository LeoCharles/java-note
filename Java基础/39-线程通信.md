# 线程通信

线程同步解决的是「多线程抢资源」的问题，而线程通信解决的是「多线程协作」的问题——一个线程干完活要通知另一个线程继续，生产者生产了数据要通知消费者来取。`wait/notify`、`Condition`、`LockSupport` 是 Java 线程间协作的三大手段。

> 💡 在阅读本篇前，建议先看 [38-线程同步](38-线程同步.md)，理解 `synchronized` 与 `Lock` 的用法，因为线程通信的 `wait/notify` 必须在锁内使用。

---

## 一、为什么需要线程通信

多个线程协作完成任务时，需要「等待—通知」机制：

- **生产者消费者**：生产者生产数据放入队列，队列满了要等消费者取走；队列空了消费者要等生产者生产。
- **任务队列**：工作线程从队列取任务执行，队列空就阻塞等待，有新任务就唤醒执行。
- **异步回调**：主线程提交任务后等待结果，子线程完成后通知主线程。

```java
// ❌ 错误做法：用 sleep 轮询，浪费 CPU
while (queue.isEmpty()) {
    Thread.sleep(100);  // 反复检查，既浪费 CPU 又有延迟
}
// ✅ 正确做法：用 wait/notify，队列空就阻塞，有数据自动唤醒
```

> ⚠️ 通信的核心思想：**让线程在条件不满足时主动阻塞（释放锁），条件满足时被唤醒**，而不是忙等待。

## 二、wait/notify/notifyAll

`wait/notify/notifyAll` 是 `Object` 类的方法，所有对象都能调用。

### 2.1 基本用法

```java
public class WaitNotifyDemo {
    private static final Object lock = new Object();
    private static boolean ready = false;

    public static void main(String[] args) throws InterruptedException {
        // 等待线程
        Thread waiter = new Thread(() -> {
            synchronized (lock) {           // ✅ 必须先持有锁
                while (!ready) {
                    try {
                        System.out.println("等待中...");
                        lock.wait();         // ✅ 释放锁并阻塞，被唤醒后重新获取锁
                    } catch (InterruptedException e) {}
                }
                System.out.println("条件满足，继续执行");
            }
        });
        waiter.start();

        Thread.sleep(1000);
        // 通知线程
        synchronized (lock) {
            ready = true;
            lock.notify();   // ✅ 唤醒一个等待的线程
            // lock.notifyAll();  // 唤醒所有等待的线程
            System.out.println("已发送通知");
        }
    }
}
```

### 2.2 三个方法的语义

| 方法 | 作用 | 调用要求 |
| :--- | :--- | :--- |
| `wait()` | 释放锁，当前线程进入等待队列，阻塞 | 必须持有对象锁 |
| `notify()` | 唤醒等待队列中**一个**线程（随机） | 必须持有对象锁 |
| `notifyAll()` | 唤醒等待队列中**所有**线程 | 必须持有对象锁 |

> ⚠️ **铁律**：`wait/notify/notifyAll` 必须在 `synchronized` 块内，由**同一个锁对象**调用，否则抛 `IllegalMonitorStateException`。

```java
synchronized (lock) {
    lock.wait();    // ✅ 持有 lock 锁，用 lock 调用 wait
}
synchronized (lock) {
    lock.notify();  // ✅ 持有 lock 锁，用 lock 调用 notify
}

// ❌ 错误：没在 synchronized 块内
lock.wait();   // IllegalMonitorStateException
// ❌ 错误：锁对象和调用对象不一致
synchronized (other) {
    lock.wait();  // IllegalMonitorStateException
}
```

### 2.3 wait() 的执行流程

```java
synchronized (lock) {
    // ① 当前线程持有 lock 锁
    lock.wait();
    // ② 释放 lock 锁，进入 lock 的等待队列
    // ③ 被 notify 唤醒后，重新竞争 lock 锁
    // ④ 拿到锁后，从 wait() 处继续往下执行
}
```

> 💡 `wait()` 会**释放锁**（这是它和 `sleep` 的关键区别），让其他线程能进入同步块。被唤醒后要**重新竞争锁**，拿到锁才从 `wait()` 返回。

### 2.4 虚假唤醒：用 while 不用 if ⭐⭐⭐

这是线程通信最隐蔽的坑。`wait()` 可能在没有 `notify` 的情况下被「虚假唤醒」，所以**判断条件必须用 `while` 而不是 `if`**。

```java
// ❌ 错误：用 if 判断
synchronized (lock) {
    if (!ready) {
        lock.wait();   // 被唤醒后不会重新判断 ready，直接往下走
    }
    // 如果是虚假唤醒，ready 仍是 false，却继续执行了 → 出 bug
}

// ✅ 正确：用 while 判断
synchronized (lock) {
    while (!ready) {
        lock.wait();   // 被唤醒后重新检查条件，不满足就继续等
    }
    // 只有 ready 真为 true 才往下走
}
```

> ⚠️ **官方文档明确要求**：`wait` 的条件判断**永远用 while**。即使没有虚假唤醒，`notifyAll` 唤醒所有线程后，只有一个能拿到锁，其余的拿到锁时条件可能已被改变，必须重新判断。

```java
// 经典场景：多个消费者，notifyAll 唤醒所有，但只有一个能消费
synchronized (lock) {
    while (queue.isEmpty()) {   // ✅ while：拿到锁后发现还是空，继续等
        lock.wait();
    }
    String item = queue.poll();  // 安全消费
}
```

### 2.5 wait(long)：带超时等待

```java
synchronized (lock) {
    lock.wait(3000);  // 最多等 3 秒，超时自动唤醒
    lock.wait(3000, 500000);  // 3 秒 + 50 万纳秒
}
```

> 💡 `wait(0)` 等价于 `wait()`（无限等待）。超时后线程被自动唤醒，但**仍需重新竞争锁**才能继续。

## 三、生产者消费者模型

生产者消费者是线程通信最经典的应用。

### 3.1 基础版：wait/notify 实现

```java
import java.util.LinkedList;
import java.util.Queue;

public class BaoziShop {
    private final Queue<String> warehouse = new LinkedList<>();
    private final int capacity = 5;

    // 生产者
    public synchronized void produce(String baozi) throws InterruptedException {
        while (warehouse.size() == capacity) {  // ✅ while 判断
            System.out.println("仓库满了，生产者等待");
            this.wait();   // 锁是 this，用 this.wait()
        }
        warehouse.add(baozi);
        System.out.println("生产 " + baozi + "，库存 " + warehouse.size());
        this.notifyAll();  // ✅ 唤醒所有等待的消费者
    }

    // 消费者
    public synchronized String consume() throws InterruptedException {
        while (warehouse.isEmpty()) {   // ✅ while 判断
            System.out.println("仓库空了，消费者等待");
            this.wait();
        }
        String baozi = warehouse.poll();
        System.out.println("消费 " + baozi + "，库存 " + warehouse.size());
        this.notifyAll();  // ✅ 唤醒所有等待的生产者
        return baozi;
    }

    public static void main(String[] args) {
        BaoziShop shop = new BaoziShop();
        new Thread(() -> {
            for (int i = 1; i <= 20; i++) {
                try { shop.produce("包子" + i); } catch (InterruptedException e) {}
            }
        }, "包子铺老板").start();

        new Thread(() -> {
            for (int i = 0; i < 10; i++) {
                try { shop.consume(); } catch (InterruptedException e) {}
            }
        }, "顾客A").start();
        new Thread(() -> {
            for (int i = 0; i < 10; i++) {
                try { shop.consume(); } catch (InterruptedException e) {}
            }
        }, "顾客B").start();
    }
}
```

> 💡 这里用 `notifyAll` 而非 `notify`：因为生产者和消费者都在等同一个锁，`notify` 可能唤醒同类线程（如生产者唤醒生产者），导致死等。`notifyAll` 保证一定有异类被唤醒。

### 3.2 wait vs sleep 对比 ⭐⭐⭐

| 对比项 | wait() | sleep() |
| :--- | :--- | :--- |
| 所属类 | `Object` | `Thread` |
| 释放锁 | ✅ 释放 | ❌ 不释放 |
| 使用位置 | 必须在 synchronized 块内 | 任意位置 |
| 唤醒方式 | notify/notifyAll/超时/中断 | 超时/中断 |
| 用途 | 线程间通信 | 暂停当前线程 |

```java
synchronized (lock) {
    lock.wait(2000);   // ✅ 释放锁，2 秒后或被 notify 唤醒
    Thread.sleep(2000); // ❌ 不释放锁，其他线程进不来同步块
}
```

> ⚠️ **核心区别**：`wait` 释放锁、`sleep` 不释放。这是面试高频题，务必牢记。

## 四、LockSupport

`LockSupport` 是 Java 5 引入的更灵活的线程阻塞/唤醒工具，**不需要 synchronized**，且支持「先唤醒后等待」。

### 4.1 park/unpark 基本用法

```java
import java.util.concurrent.locks.LockSupport;

public class LockSupportDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            System.out.println("子线程开始");
            LockSupport.park();   // ✅ 阻塞当前线程（类似 wait，但不需要锁）
            System.out.println("子线程被唤醒");
        });
        t.start();

        Thread.sleep(1000);
        System.out.println("主线程唤醒子线程");
        LockSupport.unpark(t);   // ✅ 唤醒指定线程（类似 notify，但指定目标）
    }
}
```

| 方法 | 作用 |
| :--- | :--- |
| `LockSupport.park()` | 阻塞当前线程 |
| `LockSupport.unpark(Thread t)` | 唤醒指定线程 |

### 4.2 先 unpark 后 park：不会阻塞 ⭐⭐

这是 `LockSupport` 与 `wait/notify` 的关键差异：

```java
// ✅ 先 unpark 后 park：不会阻塞
Thread t = new Thread(() -> {
    System.out.println("子线程准备 park");
    LockSupport.park();   // 虽然先调了 unpark，这里不会阻塞！
    System.out.println("子线程继续");
});
t.start();
Thread.sleep(100);
LockSupport.unpark(t);  // 先发"许可"
// 即使 unpark 在 park 之前调用，park 也不会阻塞
```

> 💡 **原理**：`unpark` 给目标线程发一个「许可」（permit），`park` 时如果有许可就消费并立即返回；没有许可才阻塞。许可最多只有一个，多次 `unpark` 也不会累积。

```java
// 对比 wait/notify：先 notify 后 wait 会永久阻塞 ❌
synchronized (lock) {
    lock.notify();  // 此时没有等待线程，通知丢失
    lock.wait();    // 永久阻塞，因为 notify 已经过去了
}
```

> ⚠️ `wait/notify` 是「通知可能丢失」的，`park/unpark` 是「许可不丢失」的——这是 `LockSupport` 更可靠的原因。

### 4.3 park 支持中断与超时

```java
// 带超时阻塞（纳秒）
LockSupport.parkNanos(2_000_000_000L);  // 最多等 2 秒

// 带超时阻塞（毫秒，到 deadline）
LockSupport.parkUntil(System.currentTimeMillis() + 2000);

// park 可被 interrupt 唤醒（不会抛异常，但会返回）
Thread.currentThread().interrupt();
LockSupport.park();  // 不会阻塞，立即返回
// 检查中断状态
if (Thread.interrupted()) {
    System.out.println("被中断唤醒");
}
```

> 💡 `park` 被 `interrupt` 唤醒后**不会抛 `InterruptedException`**，需要自己检查 `Thread.interrupted()`。这点和 `sleep/wait` 不同。

### 4.4 park/unpark vs wait/notify 对比

| 对比项 | wait/notify | park/unpark |
| :--- | :--- | :--- |
| 是否需要锁 | ✅ 必须 synchronized | ❌ 不需要 |
| 先唤醒后等待 | ❌ 通知丢失，永久阻塞 | ✅ 许可不丢，正常返回 |
| 唤醒目标 | 随机/全部 | 指定线程 |
| 中断响应 | 抛 InterruptedException | 静默返回，需自查 |
| 灵活度 | 较低 | 较高 |

## 五、Condition：配合 Lock 的通信

`Condition` 是 `Lock` 接口提供的通信工具，功能等价于 `wait/notify`，但支持**多个等待队列**，能精准唤醒「对方」而非同类。

### 5.1 基本用法

```java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

public class ConditionBasic {
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition cond = lock.newCondition();
    private boolean ready = false;

    public void waitForReady() throws InterruptedException {
        lock.lock();
        try {
            while (!ready) {
                cond.await();   // ✅ 释放锁并等待（类似 wait）
            }
            System.out.println("条件满足");
        } finally { lock.unlock(); }
    }

    public void setReady() {
        lock.lock();
        try {
            ready = true;
            cond.signal();   // ✅ 唤醒一个等待线程（类似 notify）
            // cond.signalAll();  // 唤醒所有
        } finally { lock.unlock(); }
    }
}
```

> ⚠️ `await/signal` 也必须在 `lock` 持有期间调用，否则抛 `IllegalMonitorStateException`，和 `wait/notify` 一样。

### 5.2 多条件等待：精准唤醒 ⭐⭐

这是 `Condition` 相比 `wait/notify` 的最大优势——可以有多个等待队列，分别唤醒。

```java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

public class MultiConditionDemo {
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition condA = lock.newCondition();  // A 等待队列
    private final Condition condB = lock.newCondition();  // B 等待队列

    public void waitForA() throws InterruptedException {
        lock.lock();
        try {
            System.out.println("A 开始等待");
            condA.await();          // ✅ 只在 condA 队列等
            System.out.println("A 被唤醒");
        } finally { lock.unlock(); }
    }

    public void waitForB() throws InterruptedException {
        lock.lock();
        try {
            System.out.println("B 开始等待");
            condB.await();          // ✅ 只在 condB 队列等
            System.out.println("B 被唤醒");
        } finally { lock.unlock(); }
    }

    public void signalA() {
        lock.lock();
        try { condA.signal(); }    // ✅ 只唤醒 condA 队列
        finally { lock.unlock(); }
    }

    public void signalB() {
        lock.lock();
        try { condB.signal(); }    // ✅ 只唤醒 condB 队列
        finally { lock.unlock(); }
    }

    public static void main(String[] args) throws InterruptedException {
        MultiConditionDemo demo = new MultiConditionDemo();
        new Thread(demo::waitForA, "A线程").start();
        new Thread(demo::waitForB, "B线程").start();
        Thread.sleep(1000);
        demo.signalA();   // ✅ 只唤醒 A，B 继续等
    }
}
```

> 💡 用 `wait/notifyAll` 时，所有等待线程挤在一个队列，`notifyAll` 会唤醒所有人（含同类），效率低。`Condition` 把不同角色的等待分开，`signal` 时只唤醒目标角色。

### 5.3 Condition 的方法一览

| 方法 | 等价于 | 说明 |
| :--- | :--- | :--- |
| `await()` | `wait()` | 释放锁并等待 |
| `await(long, TimeUnit)` | `wait(long)` | 带超时等待 |
| `awaitNanos(long)` | — | 纳秒级超时 |
| `awaitUninterruptibly()` | — | 不可中断等待（wait 做不到） |
| `signal()` | `notify()` | 唤醒一个 |
| `signalAll()` | `notifyAll()` | 唤醒所有 |

```java
// awaitUninterruptibly：不可中断等待（wait/await 都会被 interrupt 打断）
cond.awaitUninterruptibly();  // ✅ 即使被 interrupt 也不返回，只能被 signal 唤醒
```

## 六、管程（Monitor）模型

`wait/notify` 和 `Condition` 的底层都是**管程（Monitor）**。管程是一种同步机制，本质是「一个锁 + 一个或多个等待队列」。

```
管程（Monitor）结构：
┌─────────────────────────────────┐
│  入口队列（竞争锁的线程）        │
├─────────────────────────────────┤
│  同步队列（持有锁的线程执行区）  │
├─────────────────────────────────┤
│  等待队列1（wait/await 的线程）  │
│  等待队列2（多条件时）           │
└─────────────────────────────────┘
```

- `synchronized` 的管程：**一个锁 + 一个等待队列**（所有 `wait` 的线程都在这里）。
- `Lock + Condition` 的管程：**一个锁 + 多个等待队列**（每个 `Condition` 一个队列）。

> 💡 `notify` 唤醒时从等待队列移一个到入口队列（重新竞争锁）；`notifyAll` 把等待队列全部移到入口队列。

## ⚠️ 重点

### 重点 1：wait/notify 必须在 synchronized 内 ⭐⭐⭐

```java
synchronized (lock) {
    while (!cond) lock.wait();   // ✅ 锁对象与调用对象一致
}
synchronized (lock) {
    lock.notify();              // ✅
}
// lock.wait();  // ❌ IllegalMonitorStateException
```

> ⚠️ **锁对象和调用 wait/notify 的对象必须是同一个**，否则运行时抛异常。这是新手最常犯的错。

### 重点 2：条件判断永远用 while ⭐⭐⭐

```java
// ❌ if：虚假唤醒或 notifyAll 后条件已变，仍会继续执行
if (queue.isEmpty()) lock.wait();

// ✅ while：唤醒后重新检查，不满足继续等
while (queue.isEmpty()) lock.wait();
```

> ⚠️ 这是线程通信最隐蔽的 bug 源。官方文档明确要求用 `while`，面试也常考。

### 重点 3：wait 释放锁，sleep 不释放 ⭐⭐⭐

```java
synchronized (lock) {
    lock.wait(2000);    // ✅ 释放锁，其他线程能进来
    Thread.sleep(2000);  // ❌ 不释放锁，其他线程进不来
}
```

> 📌 这是 `wait` 和 `sleep` 最本质的区别，面试必问。

### 重点 4：notify 可能唤醒同类线程 ⭐⭐

```java
// 多生产者多消费者，用 notify 可能死等
synchronized (lock) {
    // 生产者满了 → wait
    // 另一个生产者 notify → 唤醒的还是生产者 → 消费者永远等不到 → 死等
}
// ✅ 解决：用 notifyAll，或用 Condition 分队列
```

> 💡 **多生产者多消费者场景，永远用 `notifyAll`**，或改用 `Condition` 精准唤醒。

### 重点 5：LockSupport 先 unpark 后 park 不阻塞 ⭐⭐

```java
LockSupport.unpark(t);  // 先发许可
// ... 稍后
LockSupport.park();     // ✅ 有许可，立即返回，不阻塞
```

> 💡 这是 `park/unpark` 相比 `wait/notify` 的最大优势——通知不会丢失，适合「不确定先后顺序」的协作场景。

### 重点 6：Condition 必须在 lock 内调用 ⭐⭐

```java
lock.lock();
try {
    cond.await();    // ✅
    cond.signal();   // ✅
} finally { lock.unlock(); }

// cond.await();  // ❌ 没 hold lock，IllegalMonitorStateException
```

## 💻 实战案例

### 案例 1：包子铺——生产者消费者 ⭐⭐⭐

早餐店做包子，顾客吃包子，库存有上限。

```java
import java.util.LinkedList;
import java.util.Queue;

public class BaoziShop {
    private final Queue<String> warehouse = new LinkedList<>();
    private final int capacity = 5;

    public synchronized void produce() throws InterruptedException {
        while (warehouse.size() == capacity) {  // ✅ while
            System.out.println(Thread.currentThread().getName()
                    + "：仓库满了，歇会儿");
            this.wait();
        }
        String baozi = "包子" + System.currentTimeMillis() % 1000;
        warehouse.add(baozi);
        System.out.println(Thread.currentThread().getName()
                + " 做了 " + baozi + "，库存 " + warehouse.size());
        this.notifyAll();  // ✅ 通知消费者
    }

    public synchronized void consume() throws InterruptedException {
        while (warehouse.isEmpty()) {  // ✅ while
            System.out.println(Thread.currentThread().getName()
                    + "：没包子了，等会儿");
            this.wait();
        }
        String baozi = warehouse.poll();
        System.out.println(Thread.currentThread().getName()
                + " 吃了 " + baozi + "，库存 " + warehouse.size());
        this.notifyAll();  // ✅ 通知生产者
    }

    public static void main(String[] args) {
        BaoziShop shop = new BaoziShop();
        // 2 个厨师
        for (int i = 1; i <= 2; i++) {
            new Thread(() -> {
                for (int j = 0; j < 10; j++) {
                    try { shop.produce(); } catch (InterruptedException e) {}
                }
            }, "厨师" + i).start();
        }
        // 3 个顾客
        for (int i = 1; i <= 3; i++) {
            new Thread(() -> {
                for (int j = 0; j < 7; j++) {
                    try { shop.consume(); } catch (InterruptedException e) {}
                }
            }, "顾客" + i).start();
        }
    }
}
```

### 案例 2：阻塞队列雏形 ⭐⭐⭐

后台系统任务队列：工作线程从队列取任务，队列空就阻塞。

```java
import java.util.LinkedList;
import java.util.Queue;
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

public class BlockingQueueDemo<T> {
    private final Queue<T> queue = new LinkedList<>();
    private final int capacity;
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notFull = lock.newCondition();   // 队列未满
    private final Condition notEmpty = lock.newCondition();  // 队列非空

    public BlockingQueueDemo(int capacity) { this.capacity = capacity; }

    public void put(T item) throws InterruptedException {
        lock.lock();
        try {
            while (queue.size() == capacity) {
                notFull.await();   // ✅ 满了，等消费者取走
            }
            queue.add(item);
            System.out.println("入队 " + item + "，大小 " + queue.size());
            notEmpty.signal();     // ✅ 通知消费者有货
        } finally { lock.unlock(); }
    }

    public T take() throws InterruptedException {
        lock.lock();
        try {
            while (queue.isEmpty()) {
                notEmpty.await();  // ✅ 空了，等生产者放入
            }
            T item = queue.poll();
            System.out.println("出队 " + item + "，大小 " + queue.size());
            notFull.signal();      // ✅ 通知生产者有空位
            return item;
        } finally { lock.unlock(); }
    }

    public static void main(String[] args) {
        BlockingQueueDemo<String> queue = new BlockingQueueDemo<>(3);
        // 生产者
        new Thread(() -> {
            for (int i = 1; i <= 10; i++) {
                try { queue.put("任务" + i); } catch (InterruptedException e) {}
            }
        }, "生产者").start();
        // 消费者
        new Thread(() -> {
            for (int i = 0; i < 10; i++) {
                try { queue.take(); } catch (InterruptedException e) {}
            }
        }, "消费者").start();
    }
}
```

> 💡 这就是 JUC `ArrayBlockingQueue`/`LinkedBlockingQueue` 的简化原型，实际开发直接用 JUC 的阻塞队列即可。

### 案例 3：任务队列——线程池雏形 ⭐⭐

```java
import java.util.LinkedList;
import java.util.Queue;

public class SimpleThreadPool {
    private final Queue<Runnable> taskQueue = new LinkedList<>();
    private final Object monitor = new Object();

    public SimpleThreadPool(int n) {
        for (int i = 0; i < n; i++) {
            new Thread(() -> {
                while (true) {
                    Runnable task;
                    synchronized (monitor) {
                        while (taskQueue.isEmpty()) {  // ✅ while
                            try { monitor.wait(); }    // 没任务就等
                            catch (InterruptedException e) { return; }
                        }
                        task = taskQueue.poll();
                    }
                    task.run();  // ✅ 执行任务（不在锁内，提升并发）
                }
            }, "worker-" + i).start();
        }
    }

    public void submit(Runnable task) {
        synchronized (monitor) {
            taskQueue.add(task);
            monitor.notify();  // ✅ 通知一个工作线程
        }
    }

    public static void main(String[] args) {
        SimpleThreadPool pool = new SimpleThreadPool(2);
        for (int i = 1; i <= 5; i++) {
            final int n = i;
            pool.submit(() -> System.out.println(
                    Thread.currentThread().getName() + " 执行任务 " + n));
        }
    }
}
```

> 💡 这是 `ThreadPoolExecutor` 的极简雏形，真实线程池用 `ReentrantLock + Condition` 实现，原理一致。

### 案例 4：LockSupport 实现先唤醒后等待 ⭐⭐

```java
import java.util.concurrent.locks.LockSupport;

public class LockSupportOrderDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            System.out.println("子线程：先做点事");
            try { Thread.sleep(500); } catch (InterruptedException e) {}
            System.out.println("子线程：准备 park");
            LockSupport.park();   // ✅ 即使主线程已 unpark，也不会阻塞
            System.out.println("子线程：park 返回，继续");
        }, "子线程");
        t.start();

        Thread.sleep(100);
        System.out.println("主线程：先 unpark");
        LockSupport.unpark(t);  // ✅ 先发许可，子线程 park 时直接返回
        t.join();
    }
}
```

> 💡 这种「不确定谁先执行」的协作场景，`wait/notify` 会因通知丢失而卡死，`LockSupport` 则万无一失。

### 案例 5：Condition 实现多条件等待 ⭐⭐

电商场景：订单系统，付款后通知发货，发货后通知物流。

```java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

public class OrderFlowDemo {
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition paidCond = lock.newCondition();    // 等付款
    private final Condition shippedCond = lock.newCondition(); // 等发货
    private boolean paid = false;
    private boolean shipped = false;

    // 付款线程
    public void pay() throws InterruptedException {
        lock.lock();
        try {
            paid = true;
            System.out.println("已付款");
            paidCond.signal();   // ✅ 只通知等付款的线程
        } finally { lock.unlock(); }
    }

    // 发货线程：等付款后再发货
    public void ship() throws InterruptedException {
        lock.lock();
        try {
            while (!paid) {
                System.out.println("发货线程：等付款");
                paidCond.await();   // ✅ 在 paidCond 队列等
            }
            shipped = true;
            System.out.println("已发货");
            shippedCond.signal();   // ✅ 只通知等发货的线程
        } finally { lock.unlock(); }
    }

    // 物流线程：等发货后通知
    public void logistics() throws InterruptedException {
        lock.lock();
        try {
            while (!shipped) {
                System.out.println("物流线程：等发货");
                shippedCond.await();  // ✅ 在 shippedCond 队列等
            }
            System.out.println("物流已通知");
        } finally { lock.unlock(); }
    }

    public static void main(String[] args) throws InterruptedException {
        OrderFlowDemo flow = new OrderFlowDemo();
        new Thread(flow::logistics, "物流").start();
        new Thread(flow::ship, "发货").start();
        Thread.sleep(500);
        new Thread(flow::pay, "付款").start();
    }
}
```

> 💡 用 `wait/notifyAll` 也能实现，但会唤醒所有等待线程（含无关角色），效率低。`Condition` 把不同阶段的等待分开，精准唤醒。

### 案例 6：超时等待——限时抢购 ⭐⭐

```java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;
import java.util.concurrent.TimeUnit;

public class FlashSaleDemo {
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition stockCond = lock.newCondition();
    private int stock = 0;

    // 等待补货，最多等 5 秒
    public boolean buyWithTimeout() throws InterruptedException {
        lock.lock();
        try {
            long deadline = System.nanoTime()
                    + TimeUnit.SECONDS.toNanos(5);
            while (stock <= 0) {
                long remaining = deadline - System.nanoTime();
                if (remaining <= 0) {
                    System.out.println(Thread.currentThread().getName()
                            + "：5 秒内没货，放弃");
                    return false;   // ✅ 超时返回
                }
                stockCond.awaitNanos(remaining);  // ✅ 带超时等待
            }
            stock--;
            System.out.println(Thread.currentThread().getName()
                    + "：抢到，剩余 " + stock);
            return true;
        } finally { lock.unlock(); }
    }

    public void restock(int n) {
        lock.lock();
        try {
            stock += n;
            System.out.println("补货 " + n + "，库存 " + stock);
            stockCond.signalAll();  // ✅ 通知所有等待的买家
        } finally { lock.unlock(); }
    }

    public static void main(String[] args) throws InterruptedException {
        FlashSaleDemo sale = new FlashSaleDemo();
        // 3 个买家限时抢购
        for (int i = 1; i <= 3; i++) {
            new Thread(() -> {
                try { sale.buyWithTimeout(); }
                catch (InterruptedException e) {}
            }, "买家" + i).start();
        }
        Thread.sleep(2000);
        sale.restock(1);  // 2 秒后补 1 件货，只有 1 个买家能抢到
    }
}
```

> 💡 `awaitNanos` / `await(time, unit)` 是实现「限时等待」的标准手段，比 `wait(long)` 精度更高。

// Java 21 引入虚拟线程，线程通信模型不变，但线程创建成本极低
Thread.startVirtualThread(() -> {

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| wait/notify | Object 方法，必须在 synchronized 内，锁对象调用 |
| wait | 释放锁并阻塞，被唤醒后重新竞争锁 |
| notify/notifyAll | 唤醒一个/所有等待线程 |
| 虚假唤醒 | 条件判断用 while 不用 if |
| wait vs sleep | wait 释放锁、sleep 不释放；wait 在锁内、sleep 任意 |
| LockSupport.park/unpark | 不需要锁，先 unpark 后 park 不阻塞 |
| Condition | 配合 Lock，await/signal，支持多条件队列 |
| 管程 Monitor | 一个锁 + 一个或多个等待队列 |
| 超时等待 | wait(long) / await(time) / awaitNanos |

## 学习建议

1. **手写生产者消费者**：这是线程通信的「Hello World」，务必用 `wait/notify` 和 `Condition` 各写一遍，对比体会 `notifyAll` 和多 `Condition` 的差异。
2. **验证虚假唤醒**：把 `while` 改成 `if`，多线程跑生产者消费者，观察是否出现「库存为负」或「空队列 poll 返回 null」——亲眼看到 bug 才会记住用 `while`。
3. **对比 wait 与 sleep**：写两段代码，一段 `wait` 一段 `sleep`，观察 `sleep` 期间其他线程能否进入同步块，理解「释放锁」的本质。
4. **LockSupport 的许可机制要理解透**：记住「许可不丢失」是它相比 `notify` 的核心优势，适合不确定先后顺序的协作。可以自己写「先 unpark 后 park」和「先 notify 后 wait」对比，后者会卡死。
5. **Condition 多条件是进阶利器**：实际开发中 `ReentrantLock + 多 Condition` 比 `synchronized + notifyAll` 更精准高效，建议用订单流转、阻塞队列等案例练手，建立肌肉记忆。
