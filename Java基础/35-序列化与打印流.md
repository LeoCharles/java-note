# 序列化与打印流

前面学的流都是读写「数据」（字节、字符、文本）。但开发中经常需要把**对象**存到文件或通过网络传给另一台机器——比如把用户会话对象写到磁盘、把订单对象通过 Socket 发给支付服务。这就需要**序列化**：把对象转换成字节序列。本篇讲序列化流（`ObjectOutputStream`/`ObjectInputStream`）和打印流（`PrintStream`/`PrintWriter`），前者负责对象的持久化与传输，后者是日志输出和格式化打印的利器。

> 💡 在阅读本篇前，建议先看 [34-缓冲流与转换流](34-缓冲流与转换流.md)，理解处理流（套在节点流外面）的概念，本篇的序列化流和打印流都是处理流。

---

## 一、序列化：对象 ↔ 字节序列

### 1.1 什么是序列化

**序列化（Serialization）**：把 Java 对象转换成字节序列（可以写入文件或通过网络发送）。
**反序列化（Deserialization）**：把字节序列恢复成 Java 对象。

```
序列化：   Java 对象  ──ObjectOutputStream──→  字节序列（文件/网络）
反序列化： 字节序列   ──ObjectInputStream───→  Java 对象
```

应用场景：
- **持久化**：把对象存到磁盘，下次启动程序再读回来（如缓存、会话）
- **网络传输**：把对象通过 Socket 发给远程服务（RPC 的基础）
- **深拷贝**：序列化再反序列化，得到一个完全独立的新对象

### 1.2 Serializable 标记接口

要序列化的类必须实现 `java.io.Serializable` 接口。这个接口**没有抽象方法**，只是一个「标记」——告诉 JVM「这个类可以被序列化」。

```java
import java.io.Serializable;

public class User implements Serializable {
    private String name;
    private int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return "User{name='" + name + "', age=" + age + "}";
    }

    // 省略 getter/setter
}
```

> ⚠️ **不实现 Serializable 就序列化会抛 `NotSerializableException`**。这个接口没有任何方法要实现，纯粹是个标记，但必须写上。

### 1.3 ObjectOutputStream：writeObject()

`ObjectOutputStream` 是处理流，套在 `OutputStream` 外面，用 `writeObject(obj)` 把对象写成字节序列。

```java
import java.io.*;

public class SerializeDemo {
    public static void main(String[] args) throws IOException {
        User user = new User("张三", 25);

        // 序列化到文件
        ObjectOutputStream oos = new ObjectOutputStream(
                new FileOutputStream("user.dat"));
        oos.writeObject(user);   // ✅ 把对象写成字节序列
        oos.close();

        System.out.println("序列化完成");
    }
}
```

### 1.4 ObjectInputStream：readObject()

`ObjectInputStream` 用 `readObject()` 把字节序列读回对象。返回的是 `Object`，需要强转。

```java
import java.io.*;

public class DeserializeDemo {
    public static void main(String[] args) throws IOException, ClassNotFoundException {
        // 反序列化
        ObjectInputStream ois = new ObjectInputStream(
                new FileInputStream("user.dat"));
        Object obj = ois.readObject();   // ✅ 读回对象，返回 Object
        User user = (User) obj;           // 强转回具体类型
        ois.close();

        System.out.println(user);   // User{name='张三', age=25}
    }
}
```

> ⚠️ `readObject()` 会抛两个异常：
> - `IOException`：文件读取出错
> - `ClassNotFoundException`：找不到类（字节序列里的对象，JVM 找不到对应的 Class）——这在网络传输中很常见：发送方有这个类，接收方没有。

## 二、transient 关键字：不参与序列化

### 2.1 transient 的作用

被 `transient` 修饰的成员变量**不参与序列化**——序列化时跳过它，反序列化时它会是默认值（引用类型是 `null`，基本类型是 `0`/`false`）。

```java
import java.io.Serializable;

public class Account implements Serializable {
    private String username;
    private transient String password;   // ✅ 密码不参与序列化
    private transient int tempCode;       // ✅ 临时数据不参与序列化

    public Account(String username, String password, int tempCode) {
        this.username = username;
        this.password = password;
        this.tempCode = tempCode;
    }

    @Override
    public String toString() {
        return "Account{username='" + username + "', password='" + password
                + "', tempCode=" + tempCode + "}";
    }
}
```

测试序列化与反序列化：

```java
import java.io.*;

public class TransientTest {
    public static void main(String[] args) throws IOException, ClassNotFoundException {
        Account acc = new Account("admin", "123456", 8888);

        // 序列化
        ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("acc.dat"));
        oos.writeObject(acc);
        oos.close();

        // 反序列化
        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("acc.dat"));
        Account back = (Account) ois.readObject();
        ois.close();

        System.out.println(back);
        // Account{username='admin', password='null', tempCode=0}
        // ✅ username 正常恢复
        // ❌ password 是 null（transient 不参与序列化）
        // ❌ tempCode 是 0（transient 不参与序列化）
    }
}
```

> 💡 **transient 的典型用途**：
> - **敏感数据**：密码、身份证号、银行卡号，不希望明文存到文件
> - **临时数据**：缓存、计算中间结果，没必要持久化
> - **不可序列化的成员**：某个成员对象的类没实现 Serializable，用 transient 跳过它避免报错

### 2.2 transient vs static

`static` 修饰的成员也**不参与序列化**（因为 static 属于类，不属于对象）：

```java
public class Config implements Serializable {
    static String version = "1.0";        // static 不参与序列化
    transient String tempToken;           // transient 不参与序列化
    String name = "default";              // 普通成员，参与序列化
}
```

```java
Config c = new Config();
c.name = "自定义";
c.tempToken = "token123";
// 假设 version 被改成 "2.0"

// 序列化后反序列化
Config back = (Config) ois.readObject();
// back.name = "自定义"      ✅ 普通成员恢复
// back.tempToken = null     ❌ transient 跳过
// back.version = "2.0"      ❌ static 不参与序列化，读的是当前类的值（不是序列化时的值）
```

> ⚠️ **关键区别**：
> - `transient`：反序列化后是**默认值**（null/0）
> - `static`：反序列化后是**当前 JVM 中该类的 static 值**（因为 static 属于类，不随对象走）
>
> 所以序列化对象时，static 字段的值不会被保存，反序列化读到的 static 是运行时类的当前值，**不是序列化时的值**。这就是为什么序列化通常只存对象的状态（实例字段），不存类状态（static 字段）。

## 三、serialVersionUID：序列化版本号 ⭐⭐

### 3.1 什么是 serialVersionUID

`Serializable` 接口建议每个可序列化的类都声明一个 `serialVersionUID`（序列化版本号），它是类的「版本标识」。

```java
public class User implements Serializable {
    private static final long serialVersionUID = 1L;   // ✅ 显式声明版本号
    private String name;
    private int age;
}
```

### 3.2 不定义版本号的后果

如果不显式定义 `serialVersionUID`，**编译器会自动根据类的结构（字段、方法）计算一个**。问题来了：一旦你修改了类（加个字段、改个方法名），自动计算的版本号就变了。

```
序列化时：类版本号 = A，写入文件
↓ 修改了类（加了个字段）
反序列化时：类版本号 = B（变了！）
↓
❌ 抛 InvalidClassException：local class incompatible
```

```java
// 场景：先用 User{name, age} 序列化，然后给 User 加了个 email 字段
// 如果没定义 serialVersionUID，反序列化会失败：

import java.io.*;

public class VersionFailTest {
    public static void main(String[] args) throws Exception {
        // 第一次运行：序列化 User(name, age)
        // ObjectOutputStream oos = ...; oos.writeObject(new User("张三", 25));

        // 然后给 User 类加了 email 字段，重新编译
        // 第二次运行：反序列化
        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("user.dat"));
        User user = (User) ois.readObject();   // ❌ InvalidClassException
        // 报错：stream classdesc serialVersionUID = X, local class serialVersionUID = Y
    }
}
```

> ⚠️ **这是序列化最常踩的坑**：类升级（加字段）后，旧数据反序列化失败。根本原因就是没定义 `serialVersionUID`，导致编译器自动算的版本号变了。

### 3.3 显式定义版本号解决兼容问题

显式定义 `serialVersionUID` 后，**只要版本号不变，JVM 就认为类是兼容的**，即使加了字段也能反序列化（新字段取默认值）：

```java
public class User implements Serializable {
    private static final long serialVersionUID = 1L;   // ✅ 固定版本号
    private String name;
    private int age;
    // 后来加的字段
    private String email;   // 反序列化时是 null，但不会报错
}
```

```
序列化时：版本号 = 1（显式定义），写入文件
↓ 加了 email 字段
反序列化时：版本号 = 1（还是显式定义的那个，没变！）
↓
✅ 兼容，反序列化成功，email 取默认值 null
```

> 📌 **规范**：**所有实现 Serializable 的类，必须显式声明 `serialVersionUID`**。这是阿里、Google 等大厂 Java 规范的硬性要求。IDE（如 IDEA）可以配置检查，没定义会报警告。

### 3.4 版本兼容规则

| 类的修改 | 是否兼容（版本号相同前提下） |
| :--- | :--- |
| 加字段 | ✅ 兼容，新字段取默认值 |
| 删字段 | ✅ 兼容，多余数据被忽略 |
| 改字段类型 | ❌ 不兼容，类型不匹配 |
| 改类名/包名 | ❌ 不兼容，找不到类 |
| 改父类结构 | ❌ 可能不兼容 |

> 💡 **总结**：`serialVersionUID` 是序列化的「保险丝」。显式定义后，小改动（加删字段）能平滑兼容，避免 `InvalidClassException`。

## 四、序列化的进阶用法

### 4.1 序列化引用类型成员

如果类的某个成员是引用类型（另一个对象），那个成员的类也必须实现 `Serializable`，否则抛 `NotSerializableException`：

```java
import java.io.Serializable;

class Address implements Serializable {   // ✅ 成员类也要实现
    private String city;
    public Address(String city) { this.city = city; }
    @Override public String toString() { return city; }
}

class Employee implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private Address address;   // ✅ 引用类型成员，Address 也实现了 Serializable

    public Employee(String name, Address address) {
        this.name = name;
        this.address = address;
    }
    @Override public String toString() { return name + " @ " + address; }
}
```

```java
// 序列化 Employee 时，会递归序列化里面的 Address
Employee emp = new Employee("李四", new Address("北京"));
ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("emp.dat"));
oos.writeObject(emp);   // ✅ Employee 和 Address 都被序列化
oos.close();
```

> ⚠️ 如果 `Address` 没实现 `Serializable`，序列化 `Employee` 时会抛 `NotSerializableException`。**整个对象图（对象及其所有引用对象）都必须可序列化**。

### 4.2 序列化集合

集合（如 `ArrayList`）本身实现了 `Serializable`，只要里面的元素也可序列化，就能整体序列化：

```java
import java.io.*;
import java.util.ArrayList;
import java.util.List;

public class ListSerializeDemo {
    public static void main(String[] args) throws Exception {
        List<User> users = new ArrayList<>();
        users.add(new User("张三", 25));
        users.add(new User("李四", 30));
        users.add(new User("王五", 28));

        // ✅ 直接序列化整个集合
        ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("users.dat"));
        oos.writeObject(users);   // 序列化 ArrayList 及其中所有元素
        oos.close();

        // ✅ 反序列化读回集合
        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("users.dat"));
        List<User> back = (List<User>) ois.readObject();   // 强转回 List
        ois.close();

        for (User u : back) {
            System.out.println(u);
        }
    }
}
```

> 💡 **注意 unchecked 警告**：`readObject()` 返回 `Object`，强转到 `List<User>` 会有泛型 unchecked 警告（因为运行时泛型擦除，JVM 无法校验元素类型）。这是序列化集合的固有特点，加 `@SuppressWarnings("unchecked")` 即可。

### 4.3 反序列化的类型转换与 ClassNotFoundException

```java
Object obj = ois.readObject();

// ✅ 用 instanceof 先判断再转，更安全
if (obj instanceof User) {
    User user = (User) obj;
    // 使用 user
}

// ❌ 直接强转，类型不匹配会抛 ClassCastException
// User user = (User) obj;   // 如果 obj 实际是 List，这里就崩了
```

> ⚠️ **网络传输场景的坑**：发送方序列化了 `com.company.User`，接收方的 classpath 里没有这个类，`readObject()` 会抛 `ClassNotFoundException`。这就是为什么 RPC 框架（如 Dubbo）要求双方共享相同的 API jar 包。

## 五、打印流：PrintStream 与 PrintWriter

### 5.1 PrintStream：System.out 的本质

`PrintStream` 是打印流，提供 `print()`/`println()`/`printf()`/`format()` 方法。我们一直在用的 `System.out` 就是 `PrintStream` 的实例：

```java
import java.io.PrintStream;

PrintStream ps = System.out;   // System.out 就是 PrintStream
ps.println("Hello");            // 等价于 System.out.println("Hello")
ps.print("不换行");
ps.printf("格式化：%s，%d%n", "字符串", 100);
```

### 5.2 PrintWriter：更通用的打印流

`PrintWriter` 比 `PrintStream` 更常用，可以接受 `Writer`、`OutputStream`、`File` 等多种数据源，且支持自动刷新：

```java
import java.io.*;

public class PrintWriterDemo {
    public static void main(String[] args) throws IOException {
        // 直接写文件
        PrintWriter pw = new PrintWriter(new FileWriter("log.txt"));
        pw.println("第一行");
        pw.print("不换行");
        pw.printf("格式化：%s，%d%n", "字符串", 100);
        pw.close();
    }
}
```

### 5.3 print / println / printf / format

```java
PrintWriter pw = new PrintWriter(System.out);  // 打印到控制台

pw.print("不换行");        // 打印不换行
pw.println("换行");        // 打印并换行
pw.printf("姓名：%s，年龄：%d%n", "张三", 25);   // 格式化打印
pw.format("价格：%.2f，数量：%d%n", 19.9, 3);   // format 和 printf 完全等价

pw.close();
```

常用格式化占位符：

| 占位符 | 含义 | 示例 |
| :--- | :--- | :--- |
| `%s` | 字符串 | `"张三"` |
| `%d` | 十进制整数 | `25` |
| `%f` | 浮点数 | `19.900000` |
| `%.2f` | 浮点数保留 2 位 | `19.90` |
| `%n` | 换行（跨平台） | 换行 |
| `%x` | 十六进制 | `1f` |
| `%o` | 八进制 | `37` |

> 💡 `printf` 和 `format` 是**完全等价**的（`printf` 内部调 `format`），用哪个都行。`%n` 是跨平台换行，比 `\n` 更规范。

### 5.4 自动刷新（autoFlush）

`PrintWriter` 有个构造方法可以开启自动刷新：当调用 `println`/`printf`/`format` 时自动 flush：

```java
import java.io.*;

public class AutoFlushDemo {
    public static void main(String[] args) throws IOException {
        // 第二个参数 autoFlush = true
        PrintWriter pw = new PrintWriter(
                new FileWriter("log.txt"), true);   // ✅ 开启自动刷新

        pw.println("这条会立刻写入文件");   // println 触发自动 flush
        pw.print("这条不会自动 flush");     // print 不触发（只有 println/printf/format 触发）

        // 即使不 close，前面 println 的内容也已落盘
    }
}
```

> ⚠️ **注意**：自动刷新**只对 `println`/`printf`/`format` 生效**，对 `print` 和 `write` 不生效。所以日志场景推荐用 `println` 而非 `print`。

### 5.5 打印流不抛 IOException

`PrintStream` 和 `PrintWriter` 的方法**不抛 `IOException`**——内部捕获了异常，改用 `checkError()` 检查：

```java
PrintWriter pw = new PrintWriter(new FileWriter("log.txt"));
pw.println("内容");   // ✅ 不用 try-catch，方法签名没有 throws IOException

if (pw.checkError()) {   // ✅ 检查是否发生过异常
    System.err.println("写入时出错了");
}
pw.close();
```

> 💡 **设计原因**：打印流常用于日志输出，不希望 IO 异常打断业务逻辑。所以它「吞掉」异常，用 `checkError()` 让调用方按需检查。这也是为什么 `System.out.println()` 从不抛异常。

## ⚠️ 重点

### 重点 1：transient 保护敏感数据 ⭐⭐

```java
public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private String username;
    private transient String password;   // ✅ 密码不序列化，反序列化后是 null
    private transient String idCard;     // ✅ 身份证号不序列化
}
```

> 📌 **规范**：密码、身份证号、银行卡号等敏感字段，一律用 `transient` 修饰，避免明文写入文件或传输。需要传输时应该先加密再序列化。

### 重点 2：serialVersionUID 必须显式定义 ⭐⭐

```java
// ❌ 不定义，编译器自动算，类一改版本号就变，旧数据反序列化失败
public class User implements Serializable {
    private String name;
}

// ✅ 显式定义，类升级（加字段）后仍能兼容旧数据
public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private String email;   // 后加的字段，旧数据反序列化时为 null，不报错
}
```

> ⚠️ **这是序列化最常出问题的点**：生产环境序列化了数据到磁盘，后来升级代码加了字段，没定义版本号就导致旧数据读不回来，业务中断。**第一行就要写 `serialVersionUID`**。

### 重点 3：static 不参与序列化 ⭐

```java
public class Counter implements Serializable {
    private static final long serialVersionUID = 1L;
    private static int count = 0;      // static 不参与序列化
    private String name;
}
// 序列化时 count 的值不会被保存
// 反序列化时 count 是当前类里 static 的值（不是序列化时的值）
```

> 💡 **记忆**：序列化只存「对象的状态」（实例字段），不存「类的状态」（static 字段）。static 属于类，不属于对象，自然不随对象序列化。

### 重点 4：引用类型成员必须也可序列化 ⭐

```java
class Order implements Serializable {
    private static final long serialVersionUID = 1L;
    private User user;          // ✅ User 也实现了 Serializable
    private Connection conn;    // ❌ Connection 没实现 Serializable，序列化会报错
    // 解决：用 transient 跳过
    private transient Connection conn2;   // ✅ 跳过不可序列化的成员
}
```

> ⚠️ 遇到成员对象不可序列化（如数据库连接、Socket、线程），用 `transient` 跳过它。反序列化后该成员是 null，需要重新初始化。

### 重点 5：打印流吞异常，要用 checkError 检查 ⭐

```java
PrintWriter pw = new PrintWriter(new FileWriter("log.txt"));
pw.println("重要日志");
// pw.println 不抛异常，但如果磁盘满了，写不进去也不会报错
if (pw.checkError()) {
    // ✅ 主动检查是否出错
    System.err.println("日志写入失败！");
}
pw.close();
```

> ⚠️ 打印流「不抛异常」是双刃剑：方便是方便，但出错了你不知道。关键日志场景要养成调用 `checkError()` 的习惯。

### 重点 6：序列化的对象图必须完整可序列化 ⭐

```java
class Order implements Serializable {
    private static final long serialVersionUID = 1L;
    private User user;           // User 要可序列化
    private List<Item> items;    // List 和 Item 都要可序列化
    private Address address;    // Address 要可序列化
}
// 序列化 Order 时，会递归序列化 user、items、address 及它们引用的所有对象
// 整条引用链上任何一个对象不可序列化，都会抛 NotSerializableException
```

## 💻 实战案例

### 案例 1：对象序列化到文件 ⭐

电商系统把用户会话对象持久化到磁盘，服务重启后恢复登录状态：

```java
import java.io.*;
import java.io.Serializable;

class UserSession implements Serializable {
    private static final long serialVersionUID = 1L;
    private long userId;
    private String username;
    private String loginToken;
    private long loginTime;

    public UserSession(long userId, String username, String loginToken, long loginTime) {
        this.userId = userId;
        this.username = username;
        this.loginToken = loginToken;
        this.loginTime = loginTime;
    }

    @Override
    public String toString() {
        return "UserSession{userId=" + userId + ", username='" + username
                + "', loginTime=" + loginTime + "}";
    }

    public String getLoginToken() { return loginToken; }
}

public class SessionPersist {
    // 持久化会话
    public static void saveSession(UserSession session, String file) throws IOException {
        try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream(file))) {
            oos.writeObject(session);
        }
    }

    // 恢复会话
    public static UserSession loadSession(String file) throws IOException, ClassNotFoundException {
        try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream(file))) {
            return (UserSession) ois.readObject();
        }
    }

    public static void main(String[] args) throws Exception {
        UserSession session = new UserSession(1001, "张三", "token_abc", System.currentTimeMillis());
        saveSession(session, "session.dat");
        System.out.println("会话已持久化");

        UserSession back = loadSession("session.dat");
        System.out.println("恢复会话：" + back);
    }
}
```

### 案例 2：transient 保护密码 ⭐⭐

金融系统的账户对象要序列化传输，但密码字段绝不能被序列化：

```java
import java.io.*;

class BankAccount implements Serializable {
    private static final long serialVersionUID = 1L;
    private String accountNo;
    private String holderName;
    private transient String password;      // ✅ 密码不参与序列化
    private transient String payPassword;  // ✅ 支付密码不参与序列化
    private double balance;

    public BankAccount(String accountNo, String holderName, String password, double balance) {
        this.accountNo = accountNo;
        this.holderName = holderName;
        this.password = password;
        this.payPassword = "888888";
        this.balance = balance;
    }

    @Override
    public String toString() {
        return "BankAccount{accountNo='" + accountNo + "', holder='" + holderName
                + "', password='" + password + "', payPassword='" + payPassword
                + "', balance=" + balance + "}";
    }
}

public class TransientPasswordTest {
    public static void main(String[] args) throws Exception {
        BankAccount acc = new BankAccount("6228480012345678", "李四", "mySecret123", 10000.0);

        // 序列化
        try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("account.dat"))) {
            oos.writeObject(acc);
        }

        // 反序列化
        try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("account.dat"))) {
            BankAccount back = (BankAccount) ois.readObject();
            System.out.println(back);
            // BankAccount{accountNo='6228480012345678', holder='李四',
            //   password='null', payPassword='null', balance=10000.0}
            // ✅ 密码和支付密码都是 null，没有泄露
            // ✅ 余额正常恢复（balance 不是 transient）
        }
    }
}
```

> 📌 **安全规范**：密码、密钥、身份证号等敏感字段必须用 `transient`。即使对象被序列化到磁盘或网络传输，这些字段也不会以明文形式出现。需要更高安全性时，应先加密再序列化。

### 案例 3：serialVersionUID 版本兼容 ⭐⭐

演示类升级后，有版本号 vs 无版本号的差异：

```java
// ===== 第一版 User 类 =====
class User implements Serializable {
    private static final long serialVersionUID = 1L;   // ✅ 显式定义
    private String name;
    private int age;
    public User(String name, int age) { this.name = name; this.age = age; }
    @Override public String toString() { return name + "," + age; }
}

// 先序列化
// ObjectOutputStream oos = ...; oos.writeObject(new User("张三", 25));

// ===== 升级：加了 email 字段 =====
class User implements Serializable {
    private static final long serialVersionUID = 1L;   // 版本号没变
    private String name;
    private int age;
    private String email;   // 新增字段
    public User(String name, int age, String email) { ... }
}

// 反序列化旧数据
ObjectInputStream ois = ...;
User back = (User) ois.readObject();   // ✅ 成功！email 为 null，不报错
```

```java
// ❌ 反面教材：没定义版本号
class User implements Serializable {   // 没写 serialVersionUID
    private String name;
    private int age;
}
// 序列化后，给类加 email 字段，重新编译
// 反序列化 → InvalidClassException：版本号不匹配
```

> ⚠️ **生产事故场景**：线上服务用对象序列化做缓存，发版时改了类结构，没定义版本号，导致缓存数据全部反序列化失败，缓存雪崩。**`serialVersionUID` 是序列化的生命线**。

### 案例 4：序列化 ArrayList（批量持久化）⭐

订单系统每天把当天所有订单序列化存档，便于离线分析：

```java
import java.io.*;
import java.util.ArrayList;
import java.util.List;

class Order implements Serializable {
    private static final long serialVersionUID = 1L;
    private long orderId;
    private String productName;
    private double amount;

    public Order(long orderId, String productName, double amount) {
        this.orderId = orderId;
        this.productName = productName;
        this.amount = amount;
    }

    @Override
    public String toString() {
        return "Order{" + orderId + ", " + productName + ", " + amount + "}";
    }
}

public class OrderArchive {
    // 序列化整个订单列表
    public static void saveOrders(List<Order> orders, String file) throws IOException {
        try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream(file))) {
            oos.writeObject(orders);   // ✅ 直接序列化集合
        }
    }

    // 反序列化读回订单列表
    @SuppressWarnings("unchecked")
    public static List<Order> loadOrders(String file) throws IOException, ClassNotFoundException {
        try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream(file))) {
            return (List<Order>) ois.readObject();
        }
    }

    public static void main(String[] args) throws Exception {
        List<Order> orders = new ArrayList<>();
        orders.add(new Order(1001, "iPhone", 5999.0));
        orders.add(new Order(1002, "MacBook", 12999.0));
        orders.add(new Order(1003, "AirPods", 999.0));

        saveOrders(orders, "orders_20240101.dat");
        System.out.println("订单已归档");

        List<Order> back = loadOrders("orders_20240101.dat");
        for (Order o : back) {
            System.out.println(o);
        }
    }
}
```

> 💡 序列化集合时，集合本身和所有元素都必须可序列化。`ArrayList` 已实现 `Serializable`，只要 `Order` 也实现了，就能整体序列化。反序列化时强转回 `List<Order>`（注意泛型 unchecked 警告）。

### 案例 5：日志输出重定向到文件（PrintStream）⭐⭐

后台服务要把日志输出到文件而不是控制台，用 `System.setOut` 重定向标准输出流：

```java
import java.io.*;
import java.time.LocalDateTime;

public class LogRedirect {
    public static void main(String[] args) throws IOException {
        // 把 System.out 重定向到文件
        PrintStream fileOut = new PrintStream(
                new BufferedOutputStream(new FileOutputStream("app.log", true)), true);  // autoFlush
        System.setOut(fileOut);   // ✅ 重定向标准输出

        // 之后所有 System.out.println 都写入文件
        System.out.println("[" + LocalDateTime.now() + "] 服务启动");
        System.out.println("[" + LocalDateTime.now() + "] 处理订单 1001");
        System.out.println("[" + LocalDateTime.now() + "] 订单处理完成");

        // 恢复到控制台（如果需要）
        // System.setOut(new PrintStream(new FileOutputStream(FileDescriptor.out)));
    }
}
```

> 💡 `System.setOut(PrintStream)` 可以把标准输出重定向到任意 `PrintStream`——文件、网络、甚至内存（`ByteArrayOutputStream`）。这是日志框架（如 Log4j）底层重定向输出的原理。`setErr` 同理可重定向错误流。

### 案例 6：System.out.printf 格式化报表 ⭐

生成销售报表，用 `printf` 格式化对齐输出：

```java
import java.io.PrintStream;

public class SalesReport {
    public static void main(String[] args) {
        PrintStream out = System.out;

        // 表头
        out.printf("%-12s %-10s %8s %10s%n", "商品名称", "类别", "销量", "销售额");
        out.printf("%-12s %-10s %8s %10s%n", "------------", "----------", "--------", "----------");

        // 数据行
        out.printf("%-12s %-10s %8d %10.2f%n", "iPhone", "手机", 150, 899850.0);
        out.printf("%-12s %-10s %8d %10.2f%n", "MacBook", "电脑", 80, 1039920.0);
        out.printf("%-12s %-10s %8d %10.2f%n", "AirPods", "配件", 300, 299700.0);

        // 合计
        out.printf("%-12s %-10s %8s %10s%n", "------------", "----------", "--------", "----------");
        out.printf("%-12s %-10s %8d %10.2f%n", "合计", "", 530, 2239470.0);
    }
}
```

输出效果（`-` 表示左对齐，数字表示宽度）：
```
商品名称     类别           销量       销售额
------------ ----------  -------- ----------
iPhone       手机             150  899850.00
MacBook      电脑              80 1039920.00
AirPods      配件             300  299700.00
------------ ----------  -------- ----------
合计                          530 2239470.00
```

> 💡 `printf` 格式化是生成报表、对齐输出的利器。`%-12s` 表示左对齐占 12 字符的字符串，`%10.2f` 表示右对齐占 10 字符保留 2 位小数的浮点数。掌握这些占位符，输出格式化数据事半功倍。

### 案例 7：网络传输对象序列化 ⭐

模拟客户端把订单对象通过 Socket 序列化传给服务端：

```java
import java.io.*;
import java.net.*;

class Order implements Serializable {
    private static final long serialVersionUID = 1L;
    private long orderId;
    private String product;
    private double amount;
    public Order(long orderId, String product, double amount) {
        this.orderId = orderId; this.product = product; this.amount = amount;
    }
    @Override public String toString() { return "Order{" + orderId + "," + product + "," + amount + "}"; }
}

// 服务端
class Server {
    public static void main(String[] args) throws Exception {
        ServerSocket server = new ServerSocket(8888);
        System.out.println("服务端启动，等待连接...");
        try (Socket socket = server.accept();
             ObjectInputStream ois = new ObjectInputStream(socket.getInputStream())) {
            Order order = (Order) ois.readObject();   // ✅ 反序列化接收对象
            System.out.println("收到订单：" + order);
        }
        server.close();
    }
}

// 客户端
class Client {
    public static void main(String[] args) throws Exception {
        Order order = new Order(2001, "iPhone", 5999.0);
        try (Socket socket = new Socket("localhost", 8888);
             ObjectOutputStream oos = new ObjectOutputStream(socket.getOutputStream())) {
            oos.writeObject(order);   // ✅ 序列化发送对象
            oos.flush();
            System.out.println("订单已发送");
        }
    }
}
```

> 📌 **RPC 基础**：这就是远程方法调用（RPC）的雏形——客户端序列化对象通过网络发给服务端，服务端反序列化后处理。实际框架（Dubbo、gRPC）在此基础上加了协议、序列化优化（如 Protobuf 替代 Java 序列化，因为 Java 原生序列化体积大、效率低、有安全漏洞）。

## 🚀 新版本补充

### Java 9：序列化过滤 ObjectInputFilter

Java 9 引入 `ObjectInputFilter`，可以在反序列化前检查数据，防止反序列化漏洞（恶意构造的字节序列导致执行任意代码）：

```java
import java.io.*;

// Java 9+ 设置反序列化过滤器
ObjectInputStream ois = new ObjectInputStream(new FileInputStream("user.dat"));
ois.setObjectInputFilter(info -> {
    // 只允许反序列化 User 类
    if (info.serialClass() != null && info.serialClass() != User.class) {
        return ObjectInputFilter.Status.REJECTED;
    }
    return ObjectInputFilter.Status.ALLOWED;
});
User user = (User) ois.readObject();
```

> ⚠️ **安全提示**：Java 原生序列化存在反序列化漏洞（CVE-2015-4852 等），攻击者可构造恶意对象导致 RCE。生产环境不要反序列化不可信来源的数据。Java 9 的 `ObjectInputFilter` 是缓解措施，但更推荐用 JSON（Jackson/Gson）替代 Java 序列化。

### Java 14：Records（记录类，预览）/ Java 16 正式

Java 14+ 的 `Record` 类天生适合做数据载体，也实现了 `Serializable`：

```java
// Java 16+ Record，自动实现 Serializable 相关方法
public record UserDto(String name, int age) implements Serializable {
    // 自动生成构造、getter、equals、hashCode、toString
}
```

> 💡 Record 是不可变数据类的语法糖，比手写 POJO 简洁，适合做 DTO（数据传输对象）。但 Java 8 环境不可用，了解即可。

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| 序列化 | 对象 → 字节序列，用于持久化/网络传输 |
| Serializable | 标记接口，无方法，必须实现才能序列化 |
| ObjectOutputStream | `writeObject(obj)` 序列化 |
| ObjectInputStream | `readObject()` 反序列化，返回 Object 需强转 |
| transient | 修饰的成员不参与序列化，反序列化后为默认值 |
| static | static 不参与序列化（属于类不属于对象） |
| serialVersionUID | 序列化版本号，必须显式定义，保证类升级兼容 |
| 引用成员 | 成员对象的类也必须实现 Serializable |
| 序列化集合 | 集合和元素都可序列化即可整体序列化 |
| PrintStream | print/println/printf，System.out 的本质 |
| PrintWriter | 更通用的打印流，支持 autoFlush |
| 自动刷新 | autoFlush=true，仅对 println/printf/format 生效 |
| 打印流异常 | 不抛 IOException，用 checkError() 检查 |
| 重定向 | System.setOut(new PrintStream(...)) 重定向输出 |

## 学习建议

1. **手写 transient 实验**：创建一个带 transient 字段和非 transient 字段的类，序列化后反序列化，打印各字段值，亲眼看到 transient 字段变成 null/0，比看十遍文字都管用。
2. **模拟版本兼容场景**：写一个类（定义 serialVersionUID），序列化后存文件；然后给类加个字段，重新编译，再反序列化——验证能成功读取（新字段为 null）。再删掉 serialVersionUID 试一次，对比 `InvalidClassException` 的报错。
3. **serialVersionUID 是铁律**：从写第一个可序列化类的第一行起，就加上 `private static final long serialVersionUID = 1L;`。IDEA 可在 Inspections 里开启检查，没定义会报警告，强制养成习惯。
4. **理解打印流的设计**：`PrintStream` 不抛异常、用 `checkError()` 检查——这种「吞异常+延迟检查」的设计是为了日志场景不被 IO 异常打断。理解这个设计后，再看 `System.out.println()` 为什么从不报错就豁然开朗。
5. **生产环境慎用 Java 原生序列化**：原生序列化体积大、效率低、有安全漏洞。学习它是为了理解原理和读老代码，新项目做网络传输优先用 JSON（Jackson/Gson）或 Protobuf，做缓存优先用 Redis 的序列化方案。理解了本篇，再学这些框架会非常轻松。
