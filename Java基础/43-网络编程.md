# 网络编程

如果说前几篇讲的是「单机内的并发」，那么网络编程就是让**不同机器之间能够通信**。从你打开浏览器访问一个网页，到即时通讯软件收发消息，背后都是网络编程在支撑。Java 在 `java.net` 包中封装了一套完整的网络通信 API，本篇将从 TCP/UDP 基础讲到 Socket 编程，再到多线程服务端与 B/S 模拟，把网络通信的骨架搭起来。

> 💡 阅读本篇前，建议先掌握 [40-多线程基础](40-多线程基础与线程安全.md) 的线程创建，因为网络服务端几乎都是「每个客户端一个线程」的模型，多线程是网络编程的必备前置。

## 一、网络通信三要素

任何一次网络通信，都离不开三个要素：

| 要素 | 说明 | 举例 |
| :--- | :--- | :--- |
| **IP 地址** | 标识网络中一台主机 | `192.168.1.100`、`127.0.0.1` |
| **端口号** | 标识主机上的一个程序（进程） | `80`（HTTP）、`3306`（MySQL） |
| **协议** | 通信双方约定的规则 | TCP、UDP |

> 💡 **通俗理解**：IP 地址是「小区地址」，端口号是「门牌号」，协议是「交流用的语言」。三者缺一不可——光有 IP 找到机器，没端口找不到程序；找到程序了，没协议双方听不懂。

### 1.1 IP 地址

- **IPv4**：4 字节，32 位，分 4 段十进制表示，如 `192.168.1.1`。全球已近枯竭。
- **IPv6**：16 字节，128 位，如 `fe80::1%lo0`，地址空间几乎无限。
- **127.0.0.1**：本机回环地址，只能访问自己，常用于本地测试。

### 1.2 端口号

- 取值范围 `0 ~ 65535`（2 字节）。
- `0 ~ 1023`：系统保留端口（知名端口），如 HTTP=80、HTTPS=443、FTP=21、MySQL=3306。
- `1024 ~ 49151`：注册端口，应用可申请使用。
- `49152 ~ 65535`：动态/私有端口，程序临时分配。

> ⚠️ 一个端口同一时刻只能被一个程序监听。启动两个程序抢占同一端口会报 `BindException: Address already in use`。

### 1.3 协议

| 协议 | 特点 | 适用场景 |
| :--- | :--- | :--- |
| **TCP** | 面向连接、可靠、有序、字节流 | 文件传输、网页、邮件 |
| **UDP** | 无连接、不可靠、快、数据报 | 直播、语音、DNS 查询 |

## 二、软件架构：C/S 与 B/S

| 架构 | 全称 | 特点 | 举例 |
| :--- | :--- | :--- | :--- |
| **C/S** | Client/Server | 需安装客户端，性能好，开发成本高 | QQ、微信桌面版、网游客户端 |
| **B/S** | Browser/Server | 浏览器即客户端，免安装，跨平台 | 淘宝网页、后台管理系统 |

> 💡 B/S 本质是 C/S 的特例——客户端固定成了浏览器，通信协议固定成了 HTTP。本篇最后会模拟一个简易的 B/S 服务端。

## 三、InetAddress 类

Java 用 `InetAddress` 表示 IP 地址，没有公开构造方法，通过静态方法获取：

```java
import java.net.InetAddress;

// getByName：根据主机名或 IP 字符串获取
InetAddress addr = InetAddress.getByName("www.baidu.com");
System.out.println(addr);   // www.baidu.com/110.242.68.66

// getHostAddress：获取 IP 字符串
System.out.println(addr.getHostAddress());  // 110.242.68.66

// getHostName：获取主机名
System.out.println(addr.getHostName());      // www.baidu.com

// getLocalHost：获取本机
InetAddress local = InetAddress.getLocalHost();
System.out.println(local.getHostAddress());  // 192.168.1.100

// 127.0.0.1 回环
InetAddress loop = InetAddress.getByName("127.0.0.1");
System.out.println(loop.getHostName());      // localhost
```

> 💡 `InetAddress` 内部会做 DNS 解析，`getByName("www.baidu.com")` 会联网查询，可能阻塞。生产环境注意设超时。

## 四、TCP 与 UDP 对比（重点 ⭐⭐）

### 4.1 TCP：面向连接的可靠协议

TCP 在通信前必须**三次握手**建立连接，通信结束**四次挥手**断开：

```
三次握手（建立连接）：
客户端 → SYN → 服务端        （我要连你了）
服务端 → SYN+ACK → 客户端    （收到，我也准备好了）
客户端 → ACK → 服务端        （好，开始吧）

四次挥手（断开连接）：
客户端 → FIN → 服务端        （我说完了）
服务端 → ACK → 客户端        （收到，我还没说完）
服务端 → FIN → 客户端        （我也说完了）
客户端 → ACK → 服务端        （好，再见）
```

TCP 的特点：
- **面向连接**：通信前先建链，通信后断链。
- **可靠传输**：丢包会重传、按序到达、无差错。
- **面向字节流**：数据以字节流形式传输，无边界。
- **开销大**：要维护连接状态、确认重传。

适用：文件上传下载、网页、邮件、数据库连接——**不能丢、不能乱**的场景。

### 4.2 UDP：无连接的不可靠协议

UDP 不建连接，直接把数据报扔出去，不管对方收没收到：

```
发送端 → 数据报（含目标地址+端口）→ 接收端
（不握手、不确认、不重传）
```

UDP 的特点：
- **无连接**：不握手，直接发。
- **不可靠**：可能丢包、乱序。
- **面向数据报**：每个包独立，有边界。
- **快**：无连接维护开销，延迟低。

适用：直播、语音/视频通话、DNS 查询、游戏实时位置同步——**允许偶尔丢包，但要求低延迟**的场景。

> ⚠️ **选型关键**：要可靠选 TCP，要快选 UDP。直播用 UDP 是因为偶尔丢一帧画面无所谓，但延迟卡顿体验极差；而文件传输用 TCP 是因为丢一个字节文件就坏了。

## 五、TCP 编程（重点 ⭐⭐⭐）

Java 用 `Socket` 表示客户端，`ServerSocket` 表示服务端。

### 5.1 Socket（客户端）

```java
import java.net.Socket;
import java.io.*;

// 构造：指定服务端 IP 和端口
Socket socket = new Socket("127.0.0.1", 8888);

// 获取输入输出流，与服务端通信
OutputStream out = socket.getOutputStream();
out.write("hello server".getBytes());

InputStream in = socket.getInputStream();
byte[] buf = new byte[1024];
int len = in.read(buf);
System.out.println(new String(buf, 0, len));   // 服务端返回的消息

// 关闭
socket.close();
```

### 5.2 ServerSocket（服务端）

```java
import java.net.ServerSocket;
import java.io.*;

// 构造：监听 8888 端口
ServerSocket server = new ServerSocket(8888);

// accept：阻塞等待客户端连接，返回 Socket
System.out.println("服务端启动，等待连接...");
Socket socket = server.accept();   // ⚠️ 阻塞！有客户端连进来才返回

// 通过返回的 Socket 与客户端通信
InputStream in = socket.getInputStream();
byte[] buf = new byte[1024];
int len = in.read(buf);
System.out.println("收到：" + new String(buf, 0, len));

OutputStream out = socket.getOutputStream();
out.write("hello client".getBytes());

socket.close();
server.close();
```

> 💡 **通信模型**：服务端 `accept` 阻塞等连接 → 客户端 `new Socket` 发起连接 → 三次握手成功后双方各拿到一个 `Socket`，通过它的 IO 流互相收发字节。**真正的通信是 Socket 与 Socket 之间**，ServerSocket 只负责「接待」。

### 5.3 通信流程图

```
   客户端                              服务端
     │                                   │
     │        new Socket(host,port)       │  new ServerSocket(port)
     │ ──────────── 连接 ──────────────→  │  accept() 阻塞等待
     │        （三次握手）                │ ← 返回 Socket
     │                                   │
     │  socket.getOutputStream()         │  socket.getInputStream()
     │ ──────────── 发数据 ────────────→ │  read
     │                                   │
     │  socket.getInputStream()          │  socket.getOutputStream()
     │ ←──────────── 回数据 ──────────── │  write
     │  read                             │
     │                                   │
     │  close / shutdownOutput           │  close
```

### 5.4 shutdownOutput：标记输出结束

TCP 是字节流，没有边界，接收方 `read` 不知道对方发完了没。调用 `shutdownOutput()` 表示「我发完了」，对端 `read` 会返回 -1：

```java
// 客户端：发完数据后关闭输出流（不关 Socket）
socket.getOutputStream().write("全部数据".getBytes());
socket.shutdownOutput();   // ✅ 标记输出结束，服务端 read 返回 -1

// 服务端：能读到 -1 知道客户端发完了
int len;
while ((len = in.read(buf)) != -1) {   // ✅ 遇到 shutdownOutput 后返回 -1
    System.out.println(new String(buf, 0, len));
}
```

> ⚠️ `shutdownOutput()` 只关输出方向，还能继续读。直接 `close()` 会把输入输出都关掉，无法再收响应。文件上传场景常用 shutdownOutput 告诉服务端「文件传完了」。

## 六、UDP 编程（重点 ⭐⭐）

UDP 用 `DatagramSocket` 收发，数据封装在 `DatagramPacket`（数据报包）里。

### 6.1 DatagramPacket：数据报包

一个数据报包包含：**数据 + 目标地址 + 目标端口**（发送时）或 **数据缓冲区 + 长度**（接收时）。

```java
import java.net.*;

// 发送包：数据 + 目标地址 + 端口
byte[] data = "hello udp".getBytes();
InetAddress addr = InetAddress.getByName("127.0.0.1");
DatagramPacket sendPacket = new DatagramPacket(data, data.length, addr, 9999);

// 接收包：空缓冲区，等待填充
byte[] buf = new byte[1024];
DatagramPacket recvPacket = new DatagramPacket(buf, buf.length);
```

### 6.2 DatagramSocket：收发端

```java
// 发送端
DatagramSocket sendSocket = new DatagramSocket();   // 随机端口
sendSocket.send(sendPacket);
sendSocket.close();

// 接收端
DatagramSocket recvSocket = new DatagramSocket(9999); // 绑定 9999 端口
recvSocket.receive(recvPacket);   // ⚠️ 阻塞，直到收到数据报
System.out.println(new String(recvPacket.getData(), 0, recvPacket.getLength()));
recvSocket.close();
```

> 💡 UDP 不需要先建连接，发送端直接 `send`，接收端 `receive` 阻塞等。没有 ServerSocket 的概念，双方都是 DatagramSocket。

## ⚠️ 重点

### 重点 1：TCP 是字节流，没有消息边界 ⭐⭐⭐

```java
// ❌ 错误认知：以为一次 write 对应一次 read
out.write("hello".getBytes());
out.write("world".getBytes());
// 服务端可能一次 read 收到 "helloworld"，也可能分两次
// TCP 是流式传输，不保留 write 的边界！
```

> ⚠️ 这是 TCP 编程最常踩的坑。解决办法：① 用 `shutdownOutput` 标记结束；② 自定义协议（长度前缀、换行符分隔）；③ 用 `BufferedReader.readLine()` 按行读。

### 重点 2：accept 是阻塞的 ⭐⭐⭐

```java
// 单线程服务端：accept 阻塞等连接，处理一个客户端时无法接待下一个
while (true) {
    Socket socket = server.accept();   // 阻塞
    handle(socket);                    // 处理期间，其他客户端连不上 ❌
}
```

> 💡 解决：每个客户端开一个线程处理（见实战案例 3），或用 NIO Selector（进阶内容）。

### 重点 3：read 也是阻塞的 ⭐⭐

```java
// 客户端没发数据时，服务端 in.read() 会一直阻塞
int len = in.read(buf);   // 阻塞直到有数据或连接关闭
// 若客户端断开，read 返回 -1；若客户端崩溃未正常关闭，可能一直阻塞
```

> ⚠️ 生产环境要设 `setSoTimeout` 读超时，避免恶意客户端连上不发数据耗尽线程。

### 重点 4：用完要 close，否则端口泄漏 ⭐⭐

```java
Socket socket = null;
try {
    socket = new Socket("127.0.0.1", 8888);
    // 通信
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (socket != null) {
        try { socket.close(); } catch (IOException ignored) {}  // ✅ 必须关
    }
}
```

> 📌 Socket、ServerSocket、DatagramSocket 都是资源，用完必须 close，否则文件描述符和端口泄漏，最终 `Too many open files`。

### 重点 5：UDP 不保证送达 ⭐⭐

```java
// UDP 发出去不管对方收没收到，可能丢包、乱序
sendSocket.send(packet);   // 不抛异常不代表对方收到了
```

> 💡 需要可靠性的应用层协议要自己实现确认重传（如 QUIC 协议），或干脆用 TCP。

## 💻 实战案例

### 案例 1：TCP 基础收发——客户端发消息服务端回显 ⭐⭐

最简单的 TCP 通信，先跑通基本流程：

```java
import java.io.*;
import java.net.*;

// 服务端
class TcpServer {
    public static void main(String[] args) throws IOException {
        ServerSocket server = new ServerSocket(8888);
        System.out.println("服务端启动...");
        Socket socket = server.accept();           // 阻塞等连接

        InputStream in = socket.getInputStream();
        OutputStream out = socket.getOutputStream();

        byte[] buf = new byte[1024];
        int len = in.read(buf);                    // 读客户端消息
        String msg = new String(buf, 0, len);
        System.out.println("收到：" + msg);

        out.write(("echo: " + msg).getBytes());    // 回显
        socket.shutdownOutput();

        socket.close();
        server.close();
    }
}

// 客户端
class TcpClient {
    public static void main(String[] args) throws IOException {
        Socket socket = new Socket("127.0.0.1", 8888);
        OutputStream out = socket.getOutputStream();
        out.write("你好服务端".getBytes());
        socket.shutdownOutput();                  // ✅ 标记发完

        InputStream in = socket.getInputStream();
        byte[] buf = new byte[1024];
        int len = in.read(buf);
        System.out.println("服务端回复：" + new String(buf, 0, len));

        socket.close();
    }
}
```

### 案例 2：文件上传到服务器 ⭐⭐⭐

客户端读本地文件按字节发给服务端，服务端接收写盘。核心难点是「怎么知道传完了」——用 `shutdownOutput`。

```java
import java.io.*;
import java.net.*;
import java.util.UUID;

// 服务端：接收文件写盘
class FileUploadServer {
    public static void main(String[] args) throws IOException {
        ServerSocket server = new ServerSocket(8888);
        System.out.println("上传服务启动...");
        while (true) {
            Socket socket = server.accept();       // 循环接待
            new Thread(() -> {
                try (InputStream in = socket.getInputStream()) {
                    // 用 UUID 防止文件名冲突
                    String fileName = "upload_" + UUID.randomUUID() + ".jpg";
                    try (FileOutputStream fos = new FileOutputStream("D:/uploads/" + fileName)) {
                        byte[] buf = new byte[1024];
                        int len;
                        while ((len = in.read(buf)) != -1) {  // 读到 -1 表示客户端 shutdownOutput
                            fos.write(buf, 0, len);
                        }
                    }
                    System.out.println("已保存：" + fileName);

                    // 回复上传成功
                    OutputStream out = socket.getOutputStream();
                    out.write("上传成功".getBytes());
                    socket.shutdownOutput();
                } catch (IOException e) {
                    e.printStackTrace();
                } finally {
                    try { socket.close(); } catch (IOException ignored) {}
                }
            }).start();
                }
        }
    }
}

// 客户端：读本地文件发送
class FileUploadClient {
    public static void main(String[] args) throws IOException {
        Socket socket = new Socket("127.0.0.1", 8888);
        OutputStream out = socket.getOutputStream();

        try (FileInputStream fis = new FileInputStream("D:/photo.jpg")) {
            byte[] buf = new byte[1024];
            int len;
            while ((len = fis.read(buf)) != -1) {
                out.write(buf, 0, len);            // 边读边发
            }
        }
        socket.shutdownOutput();                  // ✅ 告诉服务端文件发完了

        // 读服务端回复
        InputStream in = socket.getInputStream();
        byte[] buf = new byte[1024];
        int len = in.read(buf);
        System.out.println("服务端回复：" + new String(buf, 0, len));

        socket.close();
    }
}
```

> 📌 这是文件上传的雏形。真实 Web 上传用 multipart 协议，但底层字节流传输的思路一致。注意大文件要分块读写，不能一次性 `read` 全部。

### 案例 3：TCP 聊天室（多客户端+服务端转发）⭐⭐⭐

聊天室核心：服务端为每个客户端开一个线程，收到消息后转发给所有其他客户端。

```java
import java.io.*;
import java.net.*;
import java.util.*;

// 服务端
class ChatServer {
    // 所有在线客户端的输出流
    private static final List<PrintWriter> clients =
        Collections.synchronizedList(new ArrayList<>());

    public static void main(String[] args) throws IOException {
        ServerSocket server = new ServerSocket(9999);
        System.out.println("聊天服务器启动，端口 9999");
        while (true) {
            Socket socket = server.accept();
            System.out.println("新用户上线：" + socket.getRemoteSocketAddress());
            new Thread(new ClientHandler(socket)).start();
        }
    }

    static class ClientHandler implements Runnable {
        private Socket socket;
        private PrintWriter out;

        ClientHandler(Socket socket) { this.socket = socket; }

        public void run() {
            try {
                BufferedReader in = new BufferedReader(
                    new InputStreamReader(socket.getInputStream(), "UTF-8"));
                out = new PrintWriter(
                    new OutputStreamWriter(socket.getOutputStream(), "UTF-8"), true);
                clients.add(out);

                String msg;
                while ((msg = in.readLine()) != null) {   // 按行读，有边界 ✅
                    String broadcast = socket.getRemoteSocketAddress() + " 说：" + msg;
                    System.out.println(broadcast);
                    // 转发给所有客户端
                    synchronized (clients) {
                        for (PrintWriter pw : clients) {
                            pw.println(broadcast);          // ✅ 转发
                        }
                    }
                }
            } catch (IOException e) {
                System.out.println("用户下线");
            } finally {
                if (out != null) clients.remove(out);      // 移除离线客户端
                try { socket.close(); } catch (IOException ignored) {}
            }
        }
    }
}

// 客户端
class ChatClient {
    public static void main(String[] args) throws IOException {
        Socket socket = new Socket("127.0.0.1", 9999);
        // 读服务端消息的线程
        new Thread(() -> {
            try (BufferedReader in = new BufferedReader(
                    new InputStreamReader(socket.getInputStream(), "UTF-8"))) {
                String line;
                while ((line = in.readLine()) != null) {
                    System.out.println(line);
                }
            } catch (IOException e) {
                System.out.println("连接断开");
            }
        }).start();

        // 主线程读键盘输入发给服务端
        BufferedReader keyboard = new BufferedReader(new InputStreamReader(System.in, "UTF-8"));
        PrintWriter out = new PrintWriter(
            new OutputStreamWriter(socket.getOutputStream(), "UTF-8"), true);
        String input;
        while ((input = keyboard.readLine()) != null) {
            out.println(input);   // ✅ 按行发送，与服务端 readLine 对应
        }
        socket.close();
    }
}
```

> 💡 这里用 `readLine()` 按行读解决 TCP 无边界问题（重点 1 的方案②）。真实 IM 还要处理用户列表、私聊、群组、心跳保活等，但「每客户端一线程 + 转发」是核心骨架。

### 案例 4：UDP 简单通信 ⭐⭐

```java
import java.net.*;

// 接收端（先启动）
class UdpReceiver {
    public static void main(String[] args) throws Exception {
        DatagramSocket socket = new DatagramSocket(9999);
        System.out.println("接收端启动，等待数据...");
        while (true) {
            byte[] buf = new byte[1024];
            DatagramPacket packet = new DatagramPacket(buf, buf.length);
            socket.receive(packet);   // 阻塞接收
            String msg = new String(packet.getData(), 0, packet.getLength());
            System.out.println("收到：" + msg + " 来自 " + packet.getAddress());
        }
    }
}

// 发送端
class UdpSender {
    public static void main(String[] args) throws Exception {
        DatagramSocket socket = new DatagramSocket();   // 随机端口
        byte[] data = "你好 UDP".getBytes();
        DatagramPacket packet = new DatagramPacket(
            data, data.length, InetAddress.getByName("127.0.0.1"), 9999);
        socket.send(packet);   // ✅ 直接发，不建连接
        System.out.println("已发送");
        socket.close();
    }
}
```

> 💡 UDP 适合做心跳检测、服务发现、局域网广播。真实直播用 UDP 是因为偶尔丢帧无所谓，但延迟卡顿体验极差。

### 案例 5：模拟 Tomcat 返回静态资源（B/S 服务端）⭐⭐⭐

浏览器访问 `http://127.0.0.1:8080/index.html`，服务端读取文件返回。核心是解析 HTTP 请求行 + 拼装 HTTP 响应：

```java
import java.io.*;
import java.net.*;

class MiniTomcat {
    public static void main(String[] args) throws IOException {
        ServerSocket server = new ServerSocket(8080);
        System.out.println("MiniTomcat 启动：http://127.0.0.1:8080");
        while (true) {
            Socket socket = server.accept();
            new Thread(() -> handle(socket)).start();   // 每请求一线程
        }
    }

    static void handle(Socket socket) {
        try (BufferedReader reader = new BufferedReader(
                new InputStreamReader(socket.getInputStream()));
             OutputStream out = socket.getOutputStream()) {

            // 1. 解析 HTTP 请求行：GET /index.html HTTP/1.1
            String requestLine = reader.readLine();
            if (requestLine == null) { socket.close(); return; }
            System.out.println(Thread.currentThread().getName() + " " + requestLine);

            String[] parts = requestLine.split(" ");
            String method = parts[0];      // GET
            String path = parts[1];        // /index.html

            // 读空请求头直到空行（简化处理，不解析 header）
            while (reader.readLine() != null && !reader.readLine().isEmpty()) {}

            // 2. 根据路径读文件
            File file = new File("D:/webapps" + path);
            if (file.exists() && file.isFile()) {
                String contentType = guessContentType(path);
                // 3. 拼装 HTTP 响应
                StringBuilder header = new StringBuilder();
                header.append("HTTP/1.1 200 OK\r\n");
                header.append("Content-Type: ").append(contentType).append("\r\n");
                header.append("Content-Length: ").append(file.length()).append("\r\n");
                header.append("\r\n");   // 空行分隔 header 和 body
                out.write(header.toString().getBytes());

                // 4. 输出文件内容
                try (FileInputStream fis = new FileInputStream(file)) {
                    byte[] buf = new byte[1024];
                    int len;
                    while ((len = fis.read(buf)) != -1) {
                        out.write(buf, 0, len);
                    }
                }
            } else {
                // 404
                String body = "<h1>404 Not Found</h1>";
                StringBuilder header = new StringBuilder();
                header.append("HTTP/1.1 404 Not Found\r\n");
                header.append("Content-Type: text/html; charset=UTF-8\r\n");
                header.append("Content-Length: ").append(body.getBytes().length).append("\r\n");
                header.append("\r\n");
                out.write(header.toString().getBytes());
                out.write(body.getBytes());
            }
            out.flush();
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            try { socket.close(); } catch (IOException ignored) {}
        }
    }

    static String guessContentType(String path) {
        if (path.endsWith(".html")) return "text/html; charset=UTF-8";
        if (path.endsWith(".css"))   return "text/css";
        if (path.endsWith(".js"))    return "application/javascript";
        if (path.endsWith(".jpg") || path.endsWith(".jpeg")) return "image/jpeg";
        if (path.endsWith(".png"))   return "image/png";
        return "application/octet-stream";
    }
}
```

> 📌 浏览器访问 `http://127.0.0.1:8080/index.html` 即可看到页面。这就是 Tomcat 的雏形——真实 Tomcat 还要处理动态请求（Servlet）、会话、过滤器、连接池等，但「监听端口 → 解析 HTTP → 返回资源」的骨架完全一致。

### 案例 6：多线程并发服务端（每客户端一线程）⭐⭐

把案例 1 的单线程服务端改造成多线程，能同时接待多个客户端：

```java
import java.io.*;
import java.net.*;

class ConcurrentServer {
    public static void main(String[] args) throws IOException {
        ServerSocket server = new ServerSocket(8888);
        System.out.println("并发服务端启动...");
        while (true) {
            Socket socket = server.accept();
            System.out.println(socket.getRemoteSocketAddress() + " 上线");
            // 每个客户端一个线程 ✅
            new Thread(new ClientTask(socket)).start();
        }
    }

    static class ClientTask implements Runnable {
        private Socket socket;
        ClientTask(Socket socket) { this.socket = socket; }

        public void run() {
            try (InputStream in = socket.getInputStream();
                 OutputStream out = socket.getOutputStream()) {
                BufferedReader reader = new BufferedReader(
                    new InputStreamReader(in, "UTF-8"));
                PrintWriter writer = new PrintWriter(
                    new OutputStreamWriter(out, "UTF-8"), true);

                String line;
                while ((line = reader.readLine()) != null) {   // 循环读
                    System.out.println(Thread.currentThread().getName()
                        + " 收到：" + line);
                    writer.println("server reply: " + line);     // 回复
                }
            } catch (IOException e) {
                System.out.println("客户端异常断开");
            } finally {
                try { socket.close(); } catch (IOException ignored) {}
                System.out.println("一个客户端下线");
            }
        }
    }
}
```

> 💡 这是「BIO + 多线程」的经典模型。缺点是连接数 = 线程数，万级连接就万线程，内存吃不消。生产环境用 NIO（Selector 多路复用）或 AIO，但理解 BIO 多线程模型是进阶的基础。

### Java 7：NIO.2（AIO）异步通道

Java 7 引入 `AsynchronousServerSocketChannel`，真正异步非阻塞的 IO：

```java
import java.net.*;
import java.nio.channels.*;
import java.nio.ByteBuffer;

AsynchronousServerSocketChannel server =
    AsynchronousServerSocketChannel.open().bind(new InetSocketAddress(8888));
// accept 回调，非阻塞
server.accept(null, new CompletionHandler<AsynchronousSocketChannel, Void>() {
    public void completed(AsynchronousSocketChannel client, Void att) {
        server.accept(null, this);   // 继续接待下一个
        ByteBuffer buf = ByteBuffer.allocate(1024);
        client.read(buf, null, new CompletionHandler<Integer, Void>() {
            public void completed(Integer len, Void att) {
                System.out.println(new String(buf.array(), 0, len));
            }
            public void failed(Throwable e, Void att) { e.printStackTrace(); }
        });
    }
    public void failed(Throwable e, Void att) { e.printStackTrace(); }
});
```

> 💡 AIO 由操作系统回调通知，无需线程阻塞等待，适合高连接数场景。但 Linux 下 AIO 实现不理想，Netty 等框架仍以 NIO 为主。

### Java 11：HttpClient（替代 HttpURLConnection）

Java 11 内置现代 HTTP 客户端，支持 HTTP/2、异步：

```java
import java.net.http.*;
import java.net.URI;

HttpClient client = HttpClient.newBuilder()
    .version(HttpClient.Version.HTTP_2)
    .build();
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users"))
    .GET()
    .build();

// 同步
HttpResponse<String> resp = client.send(request, HttpResponse.BodyHandlers.ofString());
System.out.println(resp.statusCode());
System.out.println(resp.body());

// 异步
client.sendAsync(request, HttpResponse.BodyHandlers.ofString())
    .thenApply(HttpResponse::body)
    .thenAccept(System.out::println);   // ✅ 与 CompletableFuture 无缝衔接
```

> ⚠️ Java 8 环境下没有内置 HttpClient，需用 Apache HttpClient 或 OkHttp 等第三方库。

## 学习建议

1. **先跑通最简单的 TCP 收发**：把案例 1 的服务端和客户端分别在两个 main 里启动，看到「你好服务端」被回显，建立对 Socket 通信的直觉，再往下学复杂的。
2. **重点理解 TCP 的字节流无边界**：自己写一个会粘包的例子（连续两次 write，服务端一次 read 收到全部），再分别用 shutdownOutput 和 readLine 解决，体会两种方案的差异，这是 TCP 编程的核心难点。
3. **动手写聊天室**：案例 3 的聊天室是网络编程的集大成练习，涉及多线程、IO 流、转发、客户端读写分离，完整实现一遍，网络编程就算入门了。
4. **对比 TCP 和 UDP 写一遍**：同样的「发消息」需求，分别用 TCP 和 UDP 实现，体会有连接与无连接、可靠与不可靠、字节流与数据报的区别，面试常考对比。
5. **理解 BIO 多线程的局限**：本篇的多线程服务端是 BIO 模型，连接数等于线程数，想清楚它的瓶颈在哪（内存、上下文切换），这会为后续学 NIO/Netty 打下认知基础，不要止步于此。
