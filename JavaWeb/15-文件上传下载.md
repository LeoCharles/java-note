# 文件上传下载

上一篇讲了 AJAX + JSON，前后端分离的数据交互。但有种数据不能简单塞进 JSON——**文件**。图片、文档、视频怎么上传到服务器？下载时又怎么把文件流发给浏览器？本篇讲清文件上传的 `multipart/form-data` 编码、Servlet 3.0 的 `@MultipartConfig` + `Part` API、文件下载的响应头与流写出。这是 Spring Boot `MultipartFile` + `spring.servlet.multipart` 的底层。

> 💡 本篇建议写一个上传表单 + Servlet，上传一张图片，用 F12 看 `multipart/form-data` 请求体的结构——你会看到一段段 boundary 分隔的内容，每段是一个表单字段或文件。亲眼看到 multipart 的结构。

---

## 一、文件上传的原理：multipart/form-data

### 1.1 为什么不能用普通表单

普通表单用 `application/x-www-form-urlencoded` 编码，键值对拼成 `name=张三&age=20`。但文件是二进制，不能这么拼——会把二进制搞乱。所以文件上传用专门的编码 `multipart/form-data`。

```html
<!-- 上传表单：必须 method=post + enctype=multipart/form-data -->
<form action="/upload" method="post" enctype="multipart/form-data">
    用户名：<input type="text" name="username"><br>
    头像：<input type="file" name="avatar"><br>
    <button>上传</button>
</form>
```

> ⚠️ **三个必须**：文件上传表单必须 `method="post"`（GET 拼在 URL 装不下二进制）、`enctype="multipart/form-data"`（专用编码）、`<input type="file">`（文件选择框）。缺一不可。

### 1.2 multipart 请求体结构

`multipart/form-data` 用 boundary（分隔符）把请求体分成多段，每段是一个字段或文件：

```
POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryABC123

------WebKitFormBoundaryABC123
Content-Disposition: form-data; name="username"

张三
------WebKitFormBoundaryABC123
Content-Disposition: form-data; name="avatar"; filename="photo.jpg"
Content-Type: image/jpeg

<二进制图片数据>
------WebKitFormBoundaryABC123--
```

> 💡 **multipart 的本质**：用 boundary 把"普通字段"和"文件字段"分隔开，每段有自己的头（`Content-Disposition` 说明字段名/文件名，`Content-Type` 说明文件类型）。**服务器要按 boundary 解析这段请求体**，提取出字段和文件。这就是文件上传的底层原理。

## 二、Servlet 3.0 文件上传 ⭐

### 2.1 @MultipartConfig

Servlet 3.0 前文件上传要靠第三方库（commons-fileupload）。Servlet 3.0 内置支持，用 `@MultipartConfig` 注解开启：

```java
@WebServlet("/upload")
@MultipartConfig(
    fileSizeThreshold = 1024 * 1024,    // 超过此大小写临时文件（字节）
    maxFileSize = 1024 * 1024 * 5,       // 单个文件最大 5MB
    maxRequestSize = 1024 * 1024 * 10,   // 整个请求最大 10MB
    location = "D:/temp"                  // 临时目录
)
public class UploadServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws IOException, ServletException {
        req.setCharacterEncoding("utf-8");

        // 1. 取普通字段（和普通表单一样）
        String username = req.getParameter("username");

        // 2. 取文件：getPart 单个文件
        Part avatarPart = req.getPart("avatar");
        String fileName = avatarPart.getSubmittedFileName();   // 原始文件名
        long size = avatarPart.getSize();                       // 文件大小
        String contentType = avatarPart.getContentType();       // image/jpeg

        // 3. 保存文件
        String savePath = "D:/uploads/" + UUID.randomUUID() + "_" + fileName;
        avatarPart.write(savePath);   // 写到磁盘

        resp.setContentType("text/html;charset=utf-8");
        resp.getWriter().write("上传成功：" + username + "，文件：" + fileName);
    }
}
```

### 2.2 Part API

`Part` 接口代表一个上传的部分（字段或文件）：

| 方法 | 作用 |
| :--- | :--- |
| `getSubmittedFileName()` | 获取原始文件名 |
| `getSize()` | 文件大小（字节） |
| `getContentType()` | 文件 MIME 类型（image/jpeg） |
| `getName()` | 字段名（表单的 name） |
| `getInputStream()` | 读文件内容的流 |
| `write(path)` | 写到指定路径 |

### 2.3 多文件上传

```java
// getParts 取所有部分，过滤出文件
for (Part part : req.getParts()) {
    if (part.getSubmittedFileName() != null) {   // 是文件（非普通字段）
        part.write("D:/uploads/" + part.getSubmittedFileName());
    } else {
        // 普通字段
        String value = part.getName() + ": " + req.getParameter(part.getName());
    }
}
```

> 💡 **`getSubmittedFileName() != null` 区分文件和字段**：普通字段的 `getSubmittedFileName()` 返回 null，文件返回文件名。遍历 `getParts()` 时用它区分。

> ⚠️ **文件名安全**：用户上传的文件名可能含路径（`../../etc/passwd`）或特殊字符，**不能直接用原文件名保存**——要重命名（UUID）或校验。路径穿越攻击是文件上传的常见漏洞。

### 2.4 commons-fileupload（了解）

Servlet 3.0 前的主流方案，现已少用：

```java
// Servlet 3.0 前用 commons-fileupload（了解原理即可）
DiskFileItemFactory factory = new DiskFileItemFactory();
ServletFileUpload upload = new ServletFileUpload(factory);
List<FileItem> items = upload.parseRequest(req);
for (FileItem item : items) {
    if (!item.isFormField()) {   // 是文件
        item.write(new File("D:/uploads/" + item.getName()));
    }
}
```

> 💡 **commons-fileupload 已边缘化**：Servlet 3.0 内置 `@MultipartConfig` + `Part` 后，不再需要第三方库。Spring Boot 的 `MultipartFile` 底层就是 Servlet 3.0 的 `Part` 封装。**了解 commons-fileupload 是为了看懂老项目**。

## 三、文件下载

文件下载在 05 篇讲过基础（`Content-Disposition` + 字节流），本篇补充完整流程。

### 3.1 下载原理

下载的核心是两个响应头 + 字节流：

```java
@WebServlet("/download")
public class DownloadServlet extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        String filename = req.getParameter("file");

        // 1. 找到文件
        File file = new File("D:/uploads/" + filename);
        if (!file.exists()) {
            resp.sendError(404, "文件不存在");
            return;
        }

        // 2. 设响应头：告诉浏览器下载（attachment）+ 文件名
        String encodedName = URLEncoder.encode(filename, "utf-8").replace("+", "%20");
        resp.setHeader("Content-Disposition", "attachment; filename=" + encodedName);
        resp.setContentType("application/octet-stream");   // 二进制流
        resp.setContentLengthLong(file.length());            // 文件大小

        // 3. 字节流写出（05 篇讲过）
        try (FileInputStream in = new FileInputStream(file);
             ServletOutputStream out = resp.getOutputStream()) {
            byte[] buf = new byte[8192];
            int len;
            while ((len = in.read(buf)) != -1) {
                out.write(buf, 0, len);
            }
        }
    }
}
```

### 3.2 关键响应头

| 响应头 | 作用 | 示例 |
| :--- | :--- | :--- |
| `Content-Disposition` | **attachment 下载 / inline 在线预览** + 文件名 | `attachment; filename=report.pdf` |
| `Content-Type` | 文件类型 | `application/octet-stream`（通用二进制） |
| `Content-Length` | 文件大小 | `102400` |

> 💡 **attachment vs inline**：`attachment` 强制下载，`inline` 允许浏览器在线预览（如 PDF/图片直接显示）。图片预览用 `inline`，文件下载用 `attachment`。

> ⚠️ **中文文件名编码**：`Content-Disposition` 的 filename 中文在不同浏览器乱码，必须 `URLEncoder.encode` + `replace("+", "%20")`（05 篇讲过）。不同浏览器对文件名编码的处理不同，这是下载的常见坑。

### 3.3 在线预览（图片/ PDF）

```java
// 图片在线预览（inline + 正确 Content-Type）
@WebServlet("/image")
public class ImageServlet extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        resp.setContentType("image/jpeg");   // 浏览器直接显示而非下载
        // 不设 Content-Disposition，默认 inline
        Files.copy(Path.of("D:/uploads/photo.jpg"), resp.getOutputStream());
    }
}
```

> 💡 **预览 vs 下载的区别在响应头**：预览设 `Content-Type: image/jpeg` 不设 `Content-Disposition`（或 `inline`），浏览器识别类型直接显示；下载设 `Content-Disposition: attachment` 强制下载。**同一个文件，响应头不同，浏览器行为不同**。

## 四、断点续传雏形

大文件下载支持断点续传（中断后从断点继续），核心是 `Range` 请求头 + `206 Partial Content` 响应：

```
请求：Range: bytes=1048576-    （从第 1MB 开始）
响应：HTTP/1.1 206 Partial Content
      Content-Range: bytes 1048576-2097151/4194304
```

```java
// 断点续传核心逻辑（雏形）
String range = req.getHeader("Range");   // bytes=1048576-
if (range != null) {
    long start = Long.parseLong(range.substring("bytes=".length()).split("-")[0]);
    resp.setStatus(206);
    resp.setHeader("Content-Range", "bytes " + start + "-" + (file.length()-1) + "/" + file.length());
    // 从 start 开始读文件写出
}
```

> 💡 **断点续传了解原理即可**：实际开发用 Nginx 静态文件服务或云存储（OSS）自带断点续传，不手写。但理解 `Range`/`206`/`Content-Range` 三个头，遇到大文件下载问题时能排查。

---

## ⚠️ 重点

1. **文件上传表单三必须**：`method=post` + `enctype=multipart/form-data` + `type=file`。
2. **multipart 用 boundary 分隔字段和文件**：服务器按 boundary 解析请求体。
3. **Servlet 3.0 `@MultipartConfig` + `Part`**：内置文件上传，不用第三方库。
4. **`getPart` 取单文件，`getParts` 取多文件**，`getSubmittedFileName` 区分文件和字段。
5. **文件名要重命名（UUID）**：防路径穿越、防重名覆盖、防特殊字符。
6. **下载设 `Content-Disposition: attachment`**：强制下载；`inline` 在线预览。
7. **中文文件名要 URL 编码**：`URLEncoder.encode` + `replace("+","%20")`。
8. **下载用字节流**：字符流会损坏二进制（05 篇强调过字符流字节流不能混用）。
9. **断点续传靠 `Range`/`206`/`Content-Range`**：大文件下载，了解原理即可。

## 💻 实战案例：头像上传 + 下载

需求：用户上传头像，服务端重命名保存，返回访问 URL；支持下载/预览。

**上传 Servlet**：

```java
@WebServlet("/upload")
@MultipartConfig(maxFileSize = 1024 * 1024 * 2)   // 单文件最大 2MB
public class UploadServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws IOException, ServletException {
        req.setCharacterEncoding("utf-8");
        resp.setContentType("application/json;charset=utf-8");

        Part file = req.getPart("avatar");
        // 校验类型（只允许图片）
        String contentType = file.getContentType();
        if (!contentType.startsWith("image/")) {
            resp.getWriter().write("{\"error\":\"只能上传图片\"}");
            return;
        }

        // 重命名：UUID + 原扩展名
        String original = file.getSubmittedFileName();   // photo.jpg
        String ext = original.substring(original.lastIndexOf("."));
        String newName = UUID.randomUUID() + ext;

        // 保存
        file.write("D:/uploads/" + newName);

        // 返回访问路径
        resp.getWriter().write("{\"url\":\"/download?file=" + newName + "\"}");
    }
}
```

**下载/预览 Servlet**：

```java
@WebServlet("/download")
public class DownloadServlet extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        String filename = req.getParameter("file");
        File file = new File("D:/uploads/" + filename);
        if (!file.exists()) { resp.sendError(404); return; }

        String mode = req.getParameter("mode");   // preview 或 download
        if ("download".equals(mode)) {
            // 下载：attachment
            String encoded = URLEncoder.encode(filename, "utf-8").replace("+", "%20");
            resp.setHeader("Content-Disposition", "attachment; filename=" + encoded);
            resp.setContentType("application/octet-stream");
        } else {
            // 预览：inline + 正确类型
            resp.setContentType(Files.probeContentType(file.toPath()));
        }
        resp.setContentLengthLong(file.length());
        Files.copy(file.toPath(), resp.getOutputStream());
    }
}
```

**前端**：

```html
<form action="/upload" method="post" enctype="multipart/form-data">
    <input type="file" name="avatar" accept="image/*">
    <button>上传</button>
</form>
<img id="preview">
<script>
document.querySelector("form").addEventListener("submit", async (e) => {
    e.preventDefault();
    let formData = new FormData(e.target);
    let resp = await fetch("/upload", { method: "POST", body: formData });
    let data = await resp.json();
    document.getElementById("preview").src = data.url;   // 预览
});
</script>
```

> 💡 **FormData 是 AJAX 上传的关键**：`new FormData(form)` 自动用 `multipart/form-data` 编码，不用手动拼 boundary。fetch + FormData 是现代文件上传的标准方式。

## 📌 在 Spring Boot 中

> 本篇讲的 `multipart/form-data`、`@MultipartConfig` + `Part`、文件下载响应头，在 Spring Boot 中由 `MultipartFile` + `spring.servlet.multipart` 配置接管。下面逐一对照，给出实际开发代码，以及"出问题怎么回到文件上传原理排查"。实际开发你不用手动解析 multipart、不用手动写 `Part.write`——`MultipartFile` 一个参数搞定，但理解了本篇，上传大小限制、文件名乱码、下载损坏问题时才知道怎么查。

### 1. 文件上传：从"@MultipartConfig + Part"到"MultipartFile"

**原生**：本篇 2.1 用 `@MultipartConfig` + `req.getPart("avatar")` + `part.write()`。
**Spring Boot**：Controller 方法参数 `MultipartFile`，自动解析。

```java
@RestController
public class UploadController {

    @PostMapping("/upload")
    public Map<String, String> upload(@RequestParam("avatar") MultipartFile file) {
        // MultipartFile 自动注入（底层是 Servlet 3.0 的 Part）
        String originalName = file.getOriginalFilename();   // 原始文件名
        String contentType = file.getContentType();          // image/jpeg
        long size = file.getSize();                          // 大小

        // 重命名保存
        String ext = originalName.substring(originalName.lastIndexOf("."));
        String newName = UUID.randomUUID() + ext;
        try {
            file.transferTo(new File("D:/uploads/" + newName));   // 等价 part.write()
        } catch (IOException e) {
            throw new RuntimeException("保存失败", e);
        }

        return Map.of("url", "/download?file=" + newName);
    }

    // 多文件上传
    @PostMapping("/upload/batch")
    public String batch(@RequestParam("files") MultipartFile[] files) {
        for (MultipartFile f : files) {
            // 逐个处理
        }
        return "上传 " + files.length + " 个文件";
    }
}
```

> 💡 **原理对应**：`MultipartFile` 底层就是本篇 Servlet 3.0 的 `Part`——`getOriginalFilename()` 对应 `getSubmittedFileName()`，`transferTo()` 对应 `part.write()`，`getInputStream()` 对应 `part.getInputStream()`。**Spring Boot 把 `@MultipartConfig` + `Part` 封装成 `MultipartFile`，自动注入到 Controller 参数**，不用手动 `getPart`。

> 💡 **原理排查**：上传报 "Maximum upload size exceeded"？文件超过限制，调 `spring.servlet.multipart.max-file-size`。报 400 "Required request part 'avatar' is not present"？前端 `name` 和 `@RequestParam("avatar")` 不一致。回到上传原理：multipart 按 boundary 解析，字段名要对上。

### 2. 上传配置：从"@MultipartConfig 注解"到"application.yml"

**原生**：本篇 2.1 用 `@MultipartConfig(maxFileSize=...)` 注解配大小限制。
**Spring Boot**：`application.yml` 全局配置。

```yaml
spring:
  servlet:
    multipart:
      enabled: true                       # 开启 multipart 支持（默认 true）
      max-file-size: 5MB                  # 单文件最大（对应 @MultipartConfig maxFileSize）
      max-request-size: 10MB              # 整个请求最大（对应 maxRequestSize）
      file-size-threshold: 1MB            # 超过写临时文件
      location: D:/temp                   # 临时目录
```

> 💡 **原理对应**：`spring.servlet.multipart.*` 底层就是配 Servlet 的 `MultipartConfig`——`max-file-size` 对应 `maxFileSize`，`max-request-size` 对应 `maxRequestSize`。**本篇注解配的限制，Spring Boot 用 yml 全局生效**，所有上传接口统一受控。

> 💡 **原理排查**：上传大文件报错？检查 `max-file-size`/`max-request-size` 是否够大、Nginx/Tomcat 的 `maxPostSize` 是否限制了。回到上传原理：multipart 解析有大小上限，超了就拒绝。

### 3. 文件下载：从"setHeader Content-Disposition + 字节流"到"ResponseEntity<Resource>"

**原生**：本篇 3.1 手动设 `Content-Disposition` + `getOutputStream` 写字节流。
**Spring Boot**：`ResponseEntity` + `Resource` 封装（05 篇讲过）。

```java
@GetMapping("/download")
public ResponseEntity<Resource> download(@RequestParam String file) throws IOException {
    Path path = Path.of("D:/uploads/" + file);
    if (!Files.exists(path)) {
        return ResponseEntity.notFound().build();
    }

    Resource resource = new FileSystemResource(path);
    String encoded = URLEncoder.encode(file, "utf-8").replace("+", "%20");

    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=" + encoded)
            .contentType(MediaType.APPLICATION_OCTET_STREAM)
            .contentLength(Files.size(path))
            .body(resource);   // 框架自动用字节流写出
}
```

> 💡 **原理对应**：`Content-Disposition` + 字节流写出，和本篇 3.1 完全一样，只是用 `Resource` 抽象文件、框架自动写流。**本篇学的下载原理（attachment 头、字节流、中文文件名编码），Spring Boot 一个都没少**。

> 💡 **原理排查**：下载文件名乱码？检查 `URLEncoder.encode` + `replace("+","%20")`（本篇 3.2 讲过）。下载内容损坏？检查是否用了字符流写二进制（05 篇强调字符流字节流不能混用）、`Content-Type` 是否 `application/octet-stream`。回到下载原理：二进制必须用字节流。

### 4. 在线预览：从"inline + Content-Type"到"produces + Resource"

**原生**：本篇 3.3 设 `Content-Type: image/jpeg` + `inline` 预览。
**Spring Boot**：`produces` 指定类型 + `Resource`。

```java
@GetMapping(value = "/preview/{name}", produces = "image/jpeg")
public ResponseEntity<Resource> preview(@PathVariable String name) {
    Resource resource = new FileSystemResource("D:/uploads/" + name);
    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION, "inline; filename=" + name)
            .body(resource);   // 浏览器识别 image/jpeg 直接显示
}
```

> 💡 **原理对应**：`produces = "image/jpeg"` 底层设 `Content-Type` 响应头，`inline` 允许预览。**本篇讲的"预览 vs 下载靠响应头区分"，Spring Boot 用 produces + Content-Disposition 表达**。

### 5. 文件存储：从"本地磁盘"到"云存储 + 抽象"

**原生**：本篇存本地磁盘 `D:/uploads/`。
**Spring Boot 实战**：用云存储（OSS/S3/MinIO），服务器不存本地——分布式、CDN、断点续传都由云服务提供。

```java
@Service
public class FileService {
    @Autowired
    private OssClient ossClient;   // 阿里 OSS / AWS S3

    public String upload(MultipartFile file) throws IOException {
        String key = UUID.randomUUID() + getExt(file.getOriginalFilename());
        ossClient.putObject("my-bucket", key, file.getInputStream());
        return "https://my-bucket.oss-cn-beijing.aliyuncs.com/" + key;
    }
}
```

> 💡 **原理对应**：云存储是本篇"本地磁盘存储"的分布式进化——文件不存服务器本地（单机、不共享、易丢），存到云存储（分布式、高可用、CDN 加速）。**但上传的 multipart 解析、文件重命名、类型校验原理不变**，只是存储目的地从本地磁盘换成云。

> 💡 **原理排查**：上传成功但访问不了？检查存储路径权限、云存储的访问策略（public-read）、CDN 配置。回到上传原理：文件要存到能访问的地方，本地要开静态资源映射，云端要设公开读。

---

> 一句话：**文件上传靠 `multipart/form-data` 编码 + boundary 分隔，下载靠 `Content-Disposition` + 字节流**。Spring Boot 里你不用手动解析 multipart、不用手动写流——`MultipartFile` 自动接收文件，`spring.servlet.multipart.*` 配置限制，`ResponseEntity<Resource>` 做下载。但底层还是本篇的 Part + 响应头 + 字节流。理解了本篇，上传大小限制、文件名乱码、下载损坏、预览 vs 下载问题对你就是透明的。**出上传超限、415、下载乱码、内容损坏问题时，你仍要回到本篇原理排查**：multipart 限制配了吗、文件名编码了吗、用字节流了吗、Content-Disposition 对吗。

## 本章小结

本篇讲清了文件上传下载：上传用 `multipart/form-data` 编码（boundary 分隔字段和文件），Servlet 3.0 `@MultipartConfig` + `Part` API 接收，文件要重命名（UUID）防路径穿越；下载设 `Content-Disposition: attachment` + 字节流，中文文件名要 URL 编码，`inline` 在线预览。重点掌握上传表单三必须、`Part` API、文件名重命名安全、下载响应头、attachment vs inline、断点续传的 `Range`/`206`。核心认知：**Spring Boot 的 `MultipartFile` + `spring.servlet.multipart` 是本篇 `@MultipartConfig` + `Part` 的自动化**。下一篇 [16-异步 Servlet](16-异步%20Servlet.md) 讲 Servlet 3.0 的异步处理，理解 Spring Boot `@Async`/`DeferredResult` 的底层。
