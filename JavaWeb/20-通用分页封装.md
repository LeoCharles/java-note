# 通用分页封装

前面 JDBC 篇、DBUtils 篇的查询都是"一次查所有"，但在 Web 项目中，一张表可能有几十万行——一次全查出来不仅内存爆了，前端也没法展示。**分页查询**是 Web 后端最基础的能力之一：每次只取一页数据，同时告诉前端"总共多少条、多少页"。本篇从 SQL 分页原理出发，设计一个通用的 `PageBean<T>` 分页模型，封装查询条件拼装逻辑，最后引出 MyBatis PageHelper 的实现原理。这是 Spring Boot 分页插件的前身。

> 💡 本篇建议亲手实现一个 `PageBean` 工具类，然后用它改写 DBUtils 篇或 21 篇综合案例的查询方法——用统一的分页模型替代每个 Servlet 里手写的 LIMIT + COUNT，感受"通用模型的工程价值"。理解了本篇，MyBatis PageHelper 的分页原理对你就是透明的。

---

## 一、为什么要封装分页

### 1.1 不封装的样子

每个查询页面都要写一遍：

```java
// 每查一个表，都要手写 LIMIT + COUNT —— 样板！又臭又长！
String countSql = "SELECT COUNT(*) FROM student WHERE name LIKE ?";
Long total = queryRunner.query(countSql, new ScalarHandler<>(), "%" + keyword + "%");

int offset = (page - 1) * pageSize;
String dataSql = "SELECT * FROM student WHERE name LIKE ? LIMIT ?, ?";
List<Student> list = queryRunner.query(dataSql, new BeanListHandler<>(Student.class),
        "%" + keyword + "%", offset, pageSize);

// 再把 total、list、page、pageSize 拼成一个结果返回
```

每个 DAO 都重复这套逻辑——**SQL 拼接方式不统一、参数传递易错、返回结构不一致**。封装分页的目的：**一套代码处理所有分页，DAO 只关心 SQL 本身**。

### 1.2 封装的三大目标

| 目标 | 说明 |
| :--- | :--- |
| **统一模型** | 所有分页查询返回同一个 `PageBean<T>`，含数据列表 + 分页信息 |
| **复用 SQL 拼装** | COUNT 和 LIMIT 的拼接逻辑固化在工具类里，DAO 只需提供原始 SQL |
| **参数一致传递** | 条件参数一次传入，COUNT 和查询共用一个参数数组 |

## 二、SQL 分页原理

### 2.1 MySQL 的 LIMIT

```sql
-- 第 1 页，每页 5 条
SELECT * FROM student LIMIT 0, 5;    -- 跳过 0 条，取 5 条

-- 第 2 页，每页 5 条
SELECT * FROM student LIMIT 5, 5;    -- 跳过 5 条，取 5 条

-- 第 n 页，每页 size 条
SELECT * FROM student LIMIT (n-1)*size, size;

-- MySQL 也支持 OFFSET 语法（语义更清晰）
SELECT * FROM student LIMIT 5 OFFSET 10;   -- 取 5 条，跳过 10 条
```

### 2.2 分页必须配合 COUNT ⭐

只查当页数据不够——前端需要知道**总页数**来渲染分页条。所以每次分页查询实际执行两条 SQL：

```
① SELECT COUNT(*) FROM table WHERE 条件     → total（总条数）
② SELECT * FROM table WHERE 条件 LIMIT offset, size   → data（当前页数据）
```

> ⚠️ **COUNT 和 LIMIT 查询必须使用相同条件**（WHERE 子句一致），否则总数和当前页数据对不上。

### 2.3 不同数据库的分页语法

| 数据库 | 分页语法 |
| :--- | :--- |
| MySQL | `LIMIT offset, size` |
| PostgreSQL | `LIMIT size OFFSET offset` |
| Oracle | `ROWNUM` 子查询或 `OFFSET ... FETCH` (12c+) |
| SQL Server | `OFFSET ... FETCH` (2012+) 或 `TOP` + `ROW_NUMBER` |

> 💡 **为什么 Hibernate/MyBatis PageHelper 需要"方言"**：因为每种数据库的分页语法不同。本篇只聚焦 MySQL。

## 三、PageBean 通用分页模型 ⭐

### 3.1 模型设计

```java
/**
 * 通用分页结果封装
 * @param <T> 每行数据的类型
 */
public class PageBean<T> {
    // ===== 当前页数据 =====
    private List<T> rows;           // 当前页数据列表

    // ===== 分页参数（前端传过来） =====
    private int pageNum;            // 当前页码（从 1 开始）
    private int pageSize;           // 每页条数

    // ===== 分页计算结果（后端算出来） =====
    private long total;             // 总条数
    private int pages;              // 总页数
    private boolean isFirstPage;    // 第一页？
    private boolean isLastPage;     // 最后一页？

    // ===== 导航页码（前端渲染 "1 2 3 ... 10" 用） =====
    private int firstPage;          // 导航起始页
    private int lastPage;           // 导航结束页

    /**
     * 分页查询入口——静态工厂方法
     *
     * @param pageNum  当前页码（1-based）
     * @param pageSize 每页条数
     * @param total    查询 COUNT 得到的总条数
     * @param rows     当前页数据（通过 LIMIT 查询得到）
     */
    public PageBean(int pageNum, int pageSize, long total, List<T> rows) {
        this.pageNum = pageNum;
        this.pageSize = pageSize;
        this.total = total;
        this.rows = rows;

        // 计算总页数
        this.pages = (int) Math.ceil((double) total / pageSize);
        // 防止总页数为 0（总条数为 0 时）
        if (this.pages == 0) this.pages = 1;
        // 防止页码越界
        if (this.pageNum < 1) this.pageNum = 1;
        if (this.pageNum > this.pages) this.pageNum = this.pages;

        this.isFirstPage = (this.pageNum == 1);
        this.isLastPage = (this.pageNum == this.pages);

        // 计算导航页码（显示 10 页可选）
        calcNavigatePages();
    }

    /**
     * 计算导航栏显示的页码范围
     * 例如当前第 7 页，总共 100 页 → 导航显示 2-11
     */
    private void calcNavigatePages() {
        int navigatePages = 10;   // 导航栏最多显示 10 页
        if (pages <= navigatePages) {
            this.firstPage = 1;
            this.lastPage = pages;
        } else {
            // 当前页居中，左右各一半
            this.firstPage = pageNum - navigatePages / 2;
            this.lastPage = pageNum + navigatePages / 2;
            // 左边界越界
            if (this.firstPage < 1) {
                this.firstPage = 1;
                this.lastPage = navigatePages;
            }
            // 右边界越界
            if (this.lastPage > this.pages) {
                this.lastPage = this.pages;
                this.firstPage = this.pages - navigatePages + 1;
            }
        }
    }

    // ===== Getter =====
    public List<T> getRows() { return rows; }
    public int getPageNum() { return pageNum; }
    public int getPageSize() { return pageSize; }
    public long getTotal() { return total; }
    public int getPages() { return pages; }
    public boolean isFirstPage() { return isFirstPage; }
    public boolean isLastPage() { return isLastPage; }
    public int getFirstPage() { return firstPage; }
    public int getLastPage() { return lastPage; }
}
```

> 💡 **设计要点**：
> 1. **页码从 1 开始**：符合人类习惯，SQL 的 offset 在工具类内部转换 `(pageNum-1)*pageSize`。
> 2. **导航页码范围**：总页数 1000 页时不可能全显示，只显示当前页附近的 10 页。
> 3. **总页数 ≥ 1**：即使没有数据（total=0），也返回 page=1, pages=1，避免除零异常。
> 4. **pageNum 防越界**：小于 1 设为 1，大于 pages 设为 pages。

### 3.2 序列化为 JSON 传给前端

```java
// 用 Jackson / Fastjson 序列化 PageBean 给前端（Servlet 返回 JSON）
PageBean<Student> page = new PageBean<>(2, 5, 55, studentList);

// 序列化后的 JSON：
{
    "rows": [
        { "id": 6,  "name": "赵六",  "age": 20 },
        { "id": 7,  "name": "钱七",  "age": 21 },
        // ... 5 条
    ],
    "pageNum": 2,
    "pageSize": 5,
    "total": 55,
    "pages": 11,
    "isFirstPage": false,
    "isLastPage": false,
    "firstPage": 1,
    "lastPage": 10
}
```

前端拿到这个 JSON，就能渲染分页条：`[上一页] 1 2 [3] 4 5 ... 11 [下一页]`。

## 四、带条件的分页查询设计

### 4.1 条件对象的封装

分页查询通常伴随筛选条件（姓名模糊、年龄范围等）。把这些条件封装成一个对象：

```java
/**
 * 查询条件对象——封装所有可选的筛选条件
 */
public class StudentQuery {
    private String name;       // 姓名（模糊查询）
    private Integer minAge;    // 最小年龄
    private Integer maxAge;    // 最大年龄
    private String sex;        // 性别（精确匹配）

    // Getter / Setter 省略...

    /**
     * 是否没有任何条件（用于判断是否需要 WHERE 关键字）
     */
    public boolean isEmpty() {
        return name == null && minAge == null && maxAge == null && sex == null;
    }
}
```

### 4.2 条件拼 SQL 的工具方法

条件对象的终极目标是**自动生成 WHERE 子句 + 参数数组**，避免每个 DAO 手写拼接：

```java
public class SqlBuilder {

    /**
     * 拼装 WHERE 子句和对应的参数数组。
     *
     * 使用说明：
     *   每个条件调 .append("AND age >= ?", minAge)
     *   最后调 .build() 得到 WHERE 子句 + 参数数组
     */
    public static class WhereBuilder {
        private StringBuilder sql = new StringBuilder();
        private List<Object> params = new ArrayList<>();
        private boolean first = true;   // 第一个条件用 WHERE，后续用 AND

        public WhereBuilder append(String fragment, Object param) {
            if (param == null) return this;     // null 条件跳过
            if (param instanceof String && ((String) param).isEmpty()) return this;

            if (first) {
                sql.append(" WHERE ").append(fragment);
                first = false;
            } else {
                sql.append(" AND ").append(fragment.replace("AND ", ""));
            }
            params.add(param);
            return this;
        }

        /** 只拼 SQL 片段，不设参数（适用于 BETWEEN、IN 等需要多个参数的情况） */
        public WhereBuilder appendSql(String fragment) {
            if (first) { sql.append(" WHERE ").append(fragment); first = false; }
            else       { sql.append(" AND ").append(fragment); }
            return this;
        }

        /** 追加参数（配合 appendSql 使用） */
        public WhereBuilder addParam(Object param) {
            params.add(param);
            return this;
        }

        public String getSql() { return sql.toString(); }
        public Object[] getParams() { return params.toArray(); }
    }
}
```

### 4.3 通用的分页查询方法

把条件拼装 + COUNT + LIMIT 查询整合成一个通用方法：

```java
public class PageHelper {

    /**
     * 执行分页查询
     *
     * @param runner    DBUtils QueryRunner
     * @param baseSql   基础 SQL（不含 WHERE 和 LIMIT），如 "SELECT * FROM student"
     * @param countSql  COUNT SQL（不含 WHERE），如 "SELECT COUNT(*) FROM student"
     * @param where     WHERE 子句（可为空字符串）
     * @param params    WHERE 子句对应的参数
     * @param pageNum   页码（1-based）
     * @param pageSize  每页条数
     * @param handler   ResultSet 到对象的映射（BeanHandler/BeanListHandler）
     */
    public static <T> PageBean<T> queryPage(
            QueryRunner runner,
            String baseSql,
            String countSql,
            String where,
            Object[] params,
            int pageNum,
            int pageSize,
            ResultSetHandler<List<T>> handler) throws SQLException {

        // ① COUNT 查询
        String fullCountSql = countSql + where;
        long total = runner.query(fullCountSql, new ScalarHandler<>(), params);

        // ② 数据查询（拼 LIMIT）
        String fullDataSql = baseSql + where + " LIMIT ?, ?";
        int offset = (pageNum - 1) * pageSize;
        Object[] dataParams = mergeParams(params, offset, pageSize);
        List<T> rows = runner.query(fullDataSql, handler, dataParams);

        // ③ 封装结果
        return new PageBean<>(pageNum, pageSize, total, rows);
    }

    /** 把分页参数追加到条件参数末尾 */
    private static Object[] mergeParams(Object[] original, Object... append) {
        Object[] result = new Object[original.length + append.length];
        System.arraycopy(original, 0, result, 0, original.length);
        System.arraycopy(append, 0, result, original.length, append.length);
        return result;
    }
}
```

## 五、Servlet + 分页的完整示例

把上面的分页模型用到 Servlet 里，一个分页查询接口的完整代码：

```java
@WebServlet("/student/page")
public class StudentPageServlet extends HttpServlet {

    private final QueryRunner runner = new QueryRunner(HikariUtil.getDataSource());

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        // 1. 接收分页参数（带默认值和校验）
        int pageNum = parseIntOrDefault(req.getParameter("pageNum"), 1);
        int pageSize = parseIntOrDefault(req.getParameter("pageSize"), 5);
        if (pageSize > 100) pageSize = 100;   // 防止恶意拉全表

        // 2. 接收筛选条件
        String name = req.getParameter("name");
        String sex = req.getParameter("sex");
        String minAgeStr = req.getParameter("minAge");

        // 3. 拼装 WHERE 条件
        SqlBuilder.WhereBuilder wb = new SqlBuilder.WhereBuilder();
        wb.append("name LIKE ?", name != null ? "%" + name + "%" : null);
        wb.append("sex = ?", sex);
        wb.append("age >= ?", minAgeStr != null ? Integer.parseInt(minAgeStr) : null);

        // 4. 执行分页查询
        try {
            PageBean<Student> page = PageHelper.queryPage(
                runner,
                "SELECT id, name, age, sex FROM student",
                "SELECT COUNT(*) FROM student",
                wb.getSql(),
                wb.getParams(),
                pageNum,
                pageSize,
                new BeanListHandler<>(Student.class)
            );

            // 5. 返回 JSON
            resp.setContentType("application/json;charset=utf-8");
            resp.getWriter().write(new ObjectMapper().writeValueAsString(page));
        } catch (SQLException e) {
            throw new ServletException(e);
        }
    }

    private int parseIntOrDefault(String s, int defaultValue) {
        if (s == null || s.isEmpty()) return defaultValue;
        try {
            return Integer.parseInt(s);
        } catch (NumberFormatException e) {
            return defaultValue;
        }
    }
}
```

访问 `http://localhost:8080/student/page?pageNum=2&pageSize=5&name=张&sex=男`，返回分页 JSON。

> 💡 **这段代码的工程价值**：`PageHelper.queryPage()` 把"COUNT + LIMIT + 参数合并 + 封装结果"固化成一个方法——**任何表、任何条件的查询，都复用这一行**。你的 DAO 只关心"基础 SQL 是什么"和"条件怎么拼"，分页逻辑完全委托给工具类。这正是 MyBatis PageHelper 的核心思路。

---

## ⚠️ 重点

1. **分页必须两条 SQL**：COUNT（总数）+ LIMIT（当前页数据），两条 SQL 的 WHERE 条件必须一致。
2. **PageBean 的页码从 1 开始**：SQL offset 的转换 `(pageNum-1)*pageSize` 在工具类内部完成，DAO 不接触 offset。
3. **防止大页码攻击**：`pageSize` 上限（如 100），防止恶意请求一次性拉全表。
4. **pageNum 防越界**：小于 1 或大于总页数时自动修正，防止 SQL offset 为负数。
5. **总页数为 0 时兜底为 1**：防止除零和前端渲染异常。
6. **COUNT 查询的性能**：大数据量下 `SELECT COUNT(*)` 可能很慢，生产环境考虑用缓存、或用 `EXPLAIN` 估算行数。
7. **条件查询的 SQL 拼接安全问题**：永远用占位符 `?`，禁止拼接用户输入（防 SQL 注入）。

## 💻 实战案例：学生管理的分页查询

需求：学生管理列表页，支持"按姓名模糊搜索 + 按年龄范围过滤 + 按性别筛选"的分页查询。

**Servlet**：

```java
@WebServlet("/student/list")
public class StudentListServlet extends HttpServlet {

    private final QueryRunner runner = new QueryRunner(HikariUtil.getDataSource());

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        // 取分页参数
        int pageNum = parseIntOrDefault(req.getParameter("pageNum"), 1);
        int pageSize = clamp(parseIntOrDefault(req.getParameter("pageSize"), 10), 1, 100);

        // 取筛选条件
        StudentQuery query = new StudentQuery();
        query.setName(req.getParameter("name"));
        query.setSex(req.getParameter("sex"));
        String minAge = req.getParameter("minAge");
        String maxAge = req.getParameter("maxAge");
        if (minAge != null) query.setMinAge(Integer.parseInt(minAge));
        if (maxAge != null) query.setMaxAge(Integer.parseInt(maxAge));

        try {
            PageBean<Student> page = queryStudents(runner, query, pageNum, pageSize);
            writeJson(resp, page);
        } catch (SQLException e) {
            throw new ServletException(e);
        }
    }

    /** 核心分页查询方法——本篇的封装成果 */
    private PageBean<Student> queryStudents(QueryRunner runner, StudentQuery q,
                                             int pageNum, int pageSize) throws SQLException {
        SqlBuilder.WhereBuilder wb = new SqlBuilder.WhereBuilder();
        wb.append("name LIKE ?", q.getName() != null ? "%" + q.getName() + "%" : null);
        wb.append("sex = ?", q.getSex());
        wb.append("age >= ?", q.getMinAge());
        wb.append("age <= ?", q.getMaxAge());

        return PageHelper.queryPage(
            runner,
            "SELECT id, name, age, sex FROM student",
            "SELECT COUNT(*) FROM student",
            wb.getSql(),
            wb.getParams(),
            pageNum,
            pageSize,
            new BeanListHandler<>(Student.class)
        );
    }

    // ===== 工具方法 =====
    private void writeJson(HttpServletResponse resp, Object obj) throws IOException {
        resp.setContentType("application/json;charset=utf-8");
        resp.getWriter().write(new ObjectMapper().writeValueAsString(obj));
    }

    private int parseIntOrDefault(String s, int def) {
        try { return s == null ? def : Integer.parseInt(s); }
        catch (NumberFormatException e) { return def; }
    }

    private int clamp(int val, int min, int max) {
        return Math.max(min, Math.min(val, max));
    }
}
```

## 🚀 新版本补充

- **Java 8 Stream**：`Stream.skip(offset).limit(size)` 也可以做分页，但只适用于内存数据，不能替代 SQL 分页。
- **Servlet 3.1+**：非阻塞 IO 可以让分页查询异步执行（结合异步 Servlet），大量并发时不阻塞 Tomcat 线程。
- **MySQL 8.0+**：窗口函数 `ROW_NUMBER() OVER()` 可以替代 LIMIT 做复杂分页（如"取每组内前 N 条"后再分页）。

## 📌 在 Spring Boot 中

> 本篇的分页模型、条件拼装、COUNT+LIMIT 模板，在 Spring Boot 中被 MyBatis PageHelper 或 Spring Data 的分页全面封装。下面逐一对照，给出实际开发代码，以及"出问题怎么回到原理排查"。

### 1. MyBatis PageHelper：从"手动写两条 SQL"到"一行分页"

**原生**：你的 DAO 方法要写两条 SQL（COUNT + LIMIT），手动拼分页参数。
**MyBatis PageHelper**：**只写查询 SQL，分页自动**——PageHelper 用拦截器自动追加 COUNT 和 LIMIT。

```java
// 你的 Mapper 只写查询 SQL，不用管分页
@Mapper
public interface StudentMapper {

    @Select("SELECT id, name, age, sex FROM student " +
            "WHERE name LIKE CONCAT('%', #{name}, '%') " +
            "AND sex = #{sex} AND age >= #{minAge} AND age <= #{maxAge}")
    List<Student> findByCondition(StudentQuery query);   // 只写查询，不写 COUNT + LIMIT
}

// Service 层：一行 PageHelper.startPage 自动分页
@Service
public class StudentService {
    @Autowired
    private StudentMapper mapper;

    public PageInfo<Student> findByPage(StudentQuery query, int pageNum, int pageSize) {
        PageHelper.startPage(pageNum, pageSize);   // ⬅️ 这一行自动拼 COUNT + LIMIT
        List<Student> list = mapper.findByCondition(query);   // 只调查询方法
        return new PageInfo<>(list);   // PageInfo 就是你本篇的 PageBean（功能更多）
    }
}
```

```java
// PageInfo 的属性（比本篇 PageBean 更丰富）
PageInfo<Student> page = studentService.findByPage(query, 1, 10);

page.getList();           // 当前页数据（对应本篇 rows）
page.getPageNum();        // 页码
page.getPageSize();       // 每页条数
page.getTotal();          // 总条数（对应本篇 total）
page.getPages();          // 总页数（对应本篇 pages）
page.isIsFirstPage();     // 是否是第一页
page.isIsLastPage();      // 是否是最后一页
page.getNavigatepageNums();   // 导航页码数组（对应本篇 firstPage/lastPage 的计算结果）
```

> 💡 **原理对应**：`PageHelper.startPage()` 内部做了什么？它通过 MyBatis 拦截器，在 `findByCondition` 执行的 SQL **执行前**：
> 1. 用 ThreadLocal 存储页码、每页条数；
> 2. 拦截你的查询 SQL，先执行一条 `SELECT COUNT(*) FROM (你的SQL) tmp` 拿到 total；
> 3. 再给原 SQL 追加 `LIMIT offset, size`；
> 4. 把 total + rows 封装为 PageInfo。
>
> **本质上就是本篇 PageHelper 做的事情**——只是 MyBatis PageHelper 用拦截器实现了"零侵入"：你的 Mapper 方法不用改，分页逻辑自动注入。

> 💡 **原理排查**：PageHelper 分页不生效？三个高频原因：
> 1. **`PageHelper.startPage()` 和查询方法之间不要有其他 MyBatis 调用**——ThreadLocal 只对"紧跟着的下一个查询"生效。
> 2. **查询方法返回类型不是 `List`**——PageHelper 拦截的查询必须返回 List。
> 3. **properties 配置`helperDialect=mysql`** 要配对——不同数据库的 LIMIT 语法不同，PageHelper 需要知道是哪个"方言"。

### 2. 条件查询：从"手动拼 SQL"到"MyBatis 动态 SQL"

**原生**：`SqlBuilder.WhereBuilder` 手动拼 WHERE + `?` 参数（本篇设计的工具类）。
**Spring Boot**：MyBatis 的 `<where>`/`<if>` 标签（XML）或 MyBatis-Plus 的 `QueryWrapper`。

```java
// 方式一：MyBatis XML 动态 SQL
// StudentMapper.xml
<select id="findByCondition" resultType="Student">
    SELECT * FROM student
    <where>
        <if test="name != null and name != ''">
            AND name LIKE CONCAT('%', #{name}, '%')
        </if>
        <if test="sex != null and sex != ''">
            AND sex = #{sex}
        </if>
        <if test="minAge != null">
            AND age >= #{minAge}
        </if>
        <if test="maxAge != null">
            AND age &lt;= #{maxAge}
        </if>
    </where>
</select>
```

```java
// 方式二：MyBatis-Plus QueryWrapper（纯 Java 代码，无需 XML）
@Service
public class StudentService {
    @Autowired
    private StudentMapper mapper;   // extends BaseMapper<Student>

    public PageInfo<Student> findByPage(StudentQuery query, int pageNum, int pageSize) {
        PageHelper.startPage(pageNum, pageSize);

        QueryWrapper<Student> wrapper = new QueryWrapper<>();
        wrapper.like(StringUtils.hasText(query.getName()), "name", query.getName())
               .eq(StringUtils.hasText(query.getSex()), "sex", query.getSex())
               .ge(query.getMinAge() != null, "age", query.getMinAge())
               .le(query.getMaxAge() != null, "age", query.getMaxAge());

        List<Student> list = mapper.selectList(wrapper);   // BaseMapper 自带 selectList
        return new PageInfo<>(list);
    }
}
```

> 💡 **原理对应**：`QueryWrapper` 就是本篇 `SqlBuilder.WhereBuilder` 的 Spring Boot 版——同样是"条件非空才拼入 SQL，全用占位符防注入"。区别是：本篇用 `StringBuilder` 拼 SQL 字符串，MyBatis-Plus 用 `QueryWrapper` 构建条件对象，更安全、可读性更好。

### 3. Spring Data JPA 分页：从"手写 SQL"到"方法名即查询"

**原生**：手写 SQL + COUNT + LIMIT + 封装 PageBean。
**JPA**：`Pageable` 对象，Repository 方法返回 `Page<T>`。

```java
// JPA Repository：方法名即查询 + 自动分页
public interface StudentRepository extends JpaRepository<Student, Long> {

    // 方法名定义查询条件，传 Pageable 自动分页
    Page<Student> findByNameContainingAndSexAndAgeBetween(
            String name, String sex, Integer minAge, Integer maxAge, Pageable pageable);
}

// Service
@Service
public class StudentService {
    @Autowired
    private StudentRepository repo;

    public Page<Student> findByPage(StudentQuery q, int pageNum, int pageSize) {
        Pageable pageable = PageRequest.of(pageNum - 1, pageSize);   // pageNum 从 0 开始！
        return repo.findByNameContainingAndSexAndAgeBetween(
                q.getName(), q.getSex(), q.getMinAge(), q.getMaxAge(), pageable);
    }
}

// Page<T> 属性（对应本篇 PageBean）
Page<Student> page = ...;
page.getContent();        // 当前页数据 → rows
page.getNumber();         // 页码（0-based）
page.getSize();           // 每页条数 → pageSize
page.getTotalElements();  // 总条数 → total
page.getTotalPages();     // 总页数 → pages
page.isFirst();           // → isFirstPage
page.isLast();            // → isLastPage
```

> ⚠️ **JPA 的 Pageable 页码从 0 开始**（不是 1）。前端传过来的 pageNum=1，要转为 `PageRequest.of(0, size)`。这是 Spring Data 设计的一个坑——人类从 1 开始数页码，JPA 从 0 开始。

### 4. RESTful 分页响应：统一的 API 格式

Spring Boot 项目通常定义统一的 API 响应格式，分页数据嵌入其中：

```java
// 统一响应体
public class ApiResponse<T> {
    private int code;        // 200 成功
    private String msg;
    private T data;
    // 构造方法 / Getter / Setter 省略...
}

// 分页响应（Data 里放分页信息 + 数据）
public class PageResponse<T> {
    private long total;
    private int pages;
    private int pageNum;
    private int pageSize;
    private List<T> rows;
    // 从 PageBean / PageInfo 转换...
}

// Controller
@RestController
@RequestMapping("/api/student")
public class StudentController {
    @Autowired
    private StudentService service;

    @GetMapping("/page")
    public ApiResponse<PageResponse<Student>> page(StudentQuery query,
            @RequestParam(defaultValue = "1") int pageNum,
            @RequestParam(defaultValue = "10") int pageSize) {
        PageInfo<Student> page = service.findByPage(query, pageNum, pageSize);
        return ApiResponse.ok(PageResponse.from(page));   // PageInfo → PageResponse
    }
}
```

实际返回的 JSON（与前端对接）：

```json
{
    "code": 200,
    "msg": "success",
    "data": {
        "total": 55,
        "pages": 6,
        "pageNum": 2,
        "pageSize": 10,
        "rows": [
            { "id": 11, "name": "张三丰", "age": 20, "sex": "男" },
            ...
        ]
    }
}
```

> 💡 **这就是前后端分离的标准分页接口格式**——`code` + `msg` 表达状态，`data` 里是分页信息 + 数据数组。前端拿到这个 JSON，直接渲染表格 + 分页条。

---

> 一句话：**MyBatis PageHelper 的 `PageHelper.startPage()` + `PageInfo` 就是你本篇 `PageHelper.queryPage()` + `PageBean` 的"零侵入版"**——用拦截器自动追加 COUNT + LIMIT，你只需写一条查询 SQL。`QueryWrapper` 是你 `WhereBuilder` 的工程化版。**出分页不生效、COUNT 结果不对、导航页码异常时，你仍要回到本篇原理排查**：SQL 是否被拦截了、COUNT 条件是否和查询一致、pageNum 是从 1 还是从 0 开始。

## 本章小结

本篇建立了分页查询的完整认知：分页必须两条 SQL（COUNT + LIMIT），WHERE 条件必须一致。重点掌握 `PageBean<T>` 通用分页模型的字段设计（rows/total/pages/pageNum/pageSize + 导航页码计算）、`WhereBuilder` 的条件拼装与 SQL 注入防护、`PageHelper.queryPage()` 的通用分页方法封装。核心认知：**"两条 SQL + 条件一致 + 结果封装"是所有分页的共同模式**——MyBatis PageHelper 用拦截器自动追加 COUNT 和 LIMIT，JPA 用 `Pageable` + `Page<T>`，但底层原理和本篇完全一致。至此阶段七完成，下一篇 [21-综合案例：学生管理系统](21-综合案例：学生管理系统.md) 用原生技术栈完成完整项目，把前七个阶段全部串起来。
