# 拦截器与全局异常处理

上一篇学了怎么写接口、怎么绑定参数。本篇聚焦在 **Controller 执行前/后** 的拦截处理：请求进来时怎么检查登录、响应出去时怎么统一处理异常。这两件事——**拦截器（HandlerInterceptor）** 和**全局异常处理（@ControllerAdvice）**——是每个 Spring Boot 项目的标配。

> 💡 学完这篇，你的项目就具备了"请求进来先检查、出错了统一兜底"的完整能力。配合下一篇 MyBatis 整合，一个后端项目的骨架就完整了。

## 一、拦截器（HandlerInterceptor）

### 1.1 拦截器和过滤器的区别

很多人在 JavaWeb 学过 Filter，又在 Spring 学到 Interceptor，搞不清楚两者的区别：

| | Filter（过滤器） | HandlerInterceptor（拦截器） |
| :--- | :--- | :--- |
| **属于** | Java Servlet 规范 | Spring MVC 框架 |
| **拦截范围** | 所有请求（包括静态资源） | 只拦截进入 Spring MVC 的请求 |
| **执行层面** | Servlet 容器层 | Spring MVC 层 |
| **能获取的上下文** | 只有 ServletRequest/Response | 可以获取 Controller 方法、参数、返回值 |
| **谁控制** | Tomcat / Servlet 容器 | Spring IoC 容器（可以注入 Bean） |

```
HTTP 请求
    │
    ▼
Filter（Servlet 层）—— 编码、XSS 过滤
    │
    ▼
DispatcherServlet
    │
    ▼
HandlerInterceptor.preHandle()  —— 登录校验、权限检查
    │
    ▼
Controller 方法
    │
    ▼
HandlerInterceptor.postHandle() —— 记录响应状态
    │
    ▼
HandlerInterceptor.afterCompletion() —— 清理资源、记录耗时
    │
    ▼
HTTP 响应
```

### 1.2 Interceptor 的三个方法

```java
public interface HandlerInterceptor {
    /**
     * Controller 方法执行前
     * return true  → 放行，继续执行
     * return false → 拦截，请求到此为止
     */
    default boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                              Object handler) throws Exception {
        return true;
    }

    /**
     * Controller 方法执行后，视图渲染前
     * 如果 Controller 抛异常，这个方法不会执行
     */
    default void postHandle(HttpServletRequest request, HttpServletResponse response,
                            Object handler, @Nullable ModelAndView modelAndView) {
    }

    /**
     * 整个请求完成后（视图渲染完毕 / 异常处理后）
     * 类似 finally，无论成功还是异常都会执行
     */
    default void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                 Object handler, @Nullable Exception ex) {
    }
}
```

### 1.3 实战：登录校验拦截器

```java
@Component
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        // 1. 从请求头获取 Token
        String token = request.getHeader("Authorization");

        // 2. 校验 Token
        if (token == null || !token.startsWith("Bearer ")) {
            response.setContentType("application/json;charset=utf-8");
            response.getWriter().write("{\"code\":401,\"message\":\"请先登录\"}");
            return false;  // ← 拦截，不往后走了
        }

        // 3. 解析 Token，获取用户信息存入 request 属性
        String userId = JwtUtil.parseUserId(token.substring(7));
        request.setAttribute("userId", userId);

        return true;  // ← 放行
    }
}
```

### 1.4 注册拦截器

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    @Autowired
    private LoginInterceptor loginInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/api/**")           // 拦截 /api/ 开头的请求
                .excludePathPatterns(                  // 排除登录和注册接口
                        "/api/login",
                        "/api/register",
                        "/api/public/**"
                )
                .order(1);                             // 执行顺序
    }
}
```

### 1.5 实战：请求日志拦截器

```java
@Component
public class RequestLogInterceptor implements HandlerInterceptor {
    private static final Logger log = LoggerFactory.getLogger(RequestLogInterceptor.class);

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) {
        request.setAttribute("startTime", System.currentTimeMillis());
        log.info(">>> [{}] {} 开始", request.getMethod(), request.getRequestURI());
        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        Long startTime = (Long) request.getAttribute("startTime");
        long cost = System.currentTimeMillis() - startTime;
        int status = response.getStatus();
        if (ex != null) {
            log.error(">>> [{}] {} 异常 ({}ms): {}",
                    request.getMethod(), request.getRequestURI(), cost, ex.getMessage());
        } else {
            log.info(">>> [{}] {} 完成, 状态:{}, 耗时:{}ms",
                    request.getMethod(), request.getRequestURI(), status, cost);
        }
    }
}
```

## 二、全局异常处理 ⭐

### 2.1 @ControllerAdvice + @ExceptionHandler

```java
@RestControllerAdvice  // = @ControllerAdvice + @ResponseBody
public class GlobalExceptionHandler {

    // 业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusiness(BusinessException e) {
        log.warn("业务异常：{}", e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    // 参数校验异常
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValidation(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(f -> f.getField() + ": " + f.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return Result.fail(400, message);
    }

    // 404 - 请求找不到
    @ExceptionHandler(NoHandlerFoundException.class)
    public Result<?> handleNotFound(NoHandlerFoundException e) {
        return Result.fail(404, "接口不存在：" + e.getRequestURL());
    }

    // 405 - HTTP 方法不支持
    @ExceptionHandler(HttpRequestMethodNotSupportedException.class)
    public Result<?> handleMethodNotSupported(HttpRequestMethodNotSupportedException e) {
        return Result.fail(405, "不支持的请求方法：" + e.getMethod());
    }

    // 运行时异常
    @ExceptionHandler(RuntimeException.class)
    public Result<?> handleRuntime(RuntimeException e) {
        log.error("系统异常", e);
        return Result.fail(500, "服务器内部错误");
    }

    // 兜底：所有未被上面捕获的异常
    @ExceptionHandler(Exception.class)
    public Result<?> handleAll(Exception e) {
        log.error("未知异常", e);
        return Result.fail(500, "未知错误");
    }
}
```

### 2.2 自定义业务异常

```java
@Getter
public class BusinessException extends RuntimeException {
    private final int code;

    public BusinessException(String message) {
        super(message);
        this.code = 500;
    }

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    // 常用语义化静态工厂
    public static BusinessException notFound(String message) {
        return new BusinessException(404, message);
    }

    public static BusinessException badRequest(String message) {
        return new BusinessException(400, message);
    }

    public static BusinessException forbidden(String message) {
        return new BusinessException(403, message);
    }
}
```

```java
// 使用
@Service
public class UserService {
    public User getById(Long id) {
        return userDao.findById(id)
                .orElseThrow(() -> BusinessException.notFound("用户不存在"));
    }
}

// 前端收到的响应：
// {"code":404,"message":"用户不存在","data":null}
```

### 2.3 异常处理的优先级

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // Spring 按方法参数匹配最具体的异常类型
    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusiness(BusinessException e) { ... }  // 第1优先

    @ExceptionHandler(RuntimeException.class)
    public Result<?> handleRuntime(RuntimeException e) { ... }    // 第2优先

    @ExceptionHandler(Exception.class)
    public Result<?> handleAll(Exception e) { ... }               // 兜底
}
```

**匹配规则**：异常的类继承关系中，**最近（最具体）的异常类型**优先匹配。`BusinessException` 继承自 `RuntimeException` 继承自 `Exception`，所以 `BusinessException` 优先匹配第一个方法，其他 `RuntimeException` 匹配第二个，其余匹配兜底的第三个。

### 2.4 404 配置注意事项

Spring Boot 默认不把 404 抛到异常处理器中，需要手动开启：

```yaml
spring:
  mvc:
    throw-exception-if-no-handler-found: true  # 没有匹配的 Controller 时抛异常
  web:
    resources:
      add-mappings: false  # 关闭静态资源的默认映射
```

## 💻 实战案例

### 案例：登录拦截器 + 全局异常的完整协作

```
用户请求 GET /api/orders/1（未登录）
    │
    ▼
LoginInterceptor.preHandle()
    → 没有 Token → return false
    → 响应 401: {"code":401,"message":"请先登录"}
    → 请求结束
────────────────────────────────
用户请求 GET /api/orders/1（已登录）
    │
    ▼
LoginInterceptor.preHandle()
    → Token 有效 → 存入 userId → return true
    │
    ▼
OrderController.getById(1)
    │
    ▼
OrderService.getById(1)
    → 查询数据库 → 订单不存在
    → throw BusinessException.notFound("订单不存在")
    │
    ▼
GlobalExceptionHandler.handleBusiness()
    → {"code":404,"message":"订单不存在"}
────────────────────────────────
用户请求 GET /api/orders/1（已登录）
    │
    ▼
LoginInterceptor.preHandle() → 通过
    │
    ▼
OrderController.getById(1)
    │
    ▼
OrderService.getById(1)
    → 查询数据库 → 正常返回
    │
    ▼
200: {"code":200,"message":"success","data":{...}}
```

## 🎯 面试高频

### Q1：Filter 和 Interceptor 的区别？

**答**：
- **Filter** 是 Servlet 规范，在 Servlet 容器层执行，可以拦截所有请求（含静态资源），无法获取 Spring 的 Controller 和方法信息
- **Interceptor** 是 Spring MVC 框架的，在 Spring 容器层执行，可以注入 Spring Bean，能获取到被调用的 Controller 方法、参数、返回值
- Filter 在 Interceptor 之前执行（Filter → DispatcherServlet → Interceptor → Controller）

### Q2：@ControllerAdvice 和 @ExceptionHandler 的工作原理？

**答**：`@ControllerAdvice` 是 AOP 的变体，本质上是一个全局的 `@ExceptionHandler`。Spring MVC 在 DispatcherServlet 处理请求的过程中捕获异常后，会查找注册的 `@ExceptionHandler` 方法，按异常类型匹配最具体的一个来处理，生成标准响应。

## 📌 在 Spring Boot 中

- Spring Boot 提供了 `HandlerInterceptor` 接口用于拦截请求，需配合 `WebMvcConfigurer` 注册
- `@RestControllerAdvice` = `@ControllerAdvice` + `@ResponseBody`，是 Spring Boot 项目的全局异常处理标配
- Spring Boot 的 `ErrorMvcAutoConfiguration` 内置了 `/error` 错误页面，但自定义 `@ExceptionHandler` 会覆盖它
- Spring Security 的本质就是一串 Filter 链，而不是 Interceptor——理解了 Filter 和 Interceptor 的区别，才能理解 Security 在哪个层面拦截

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| Interceptor 三方法 | preHandle(放行/拦截)、postHandle(Controller后)、afterCompletion(完成后) |
| Filter vs Interceptor | Filter(Servlet层) → Interceptor(Spring层)，Filter先执行 |
| @ExceptionHandler | 按异常类型匹配，最近继承优先 |
| @ControllerAdvice | 全局异常处理，配合 @ExceptionHandler 使用 |
| 自定义业务异常 | 语义化的异常类，前端看到的都是友好提示 |

## 学习建议

1. **写一个完整的登录拦截 + 全局异常的项目骨架**：一个 LoginInterceptor + 一个 GlobalExceptionHandler + 一个 BusinessException。这是 Spring Boot 项目的"标准配置"，做好了后面加业务只是在往里填东西。
2. **不要混用 Filter 和 Interceptor**：登录鉴权用 Interceptor（可以在 Spring 容器中注入 UserService 等 Bean），编码 / XSS 过滤用 Filter（Servlet 层通用，不受 Spring 管理）。
3. **异常处理要分层**：Controller 层 → 参数校验 + 接口异常；Service 层 → 抛 BusinessException；全局异常处理 → 统一兜底。每层只处理自己关心的异常。
