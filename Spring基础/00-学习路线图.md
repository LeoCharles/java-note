# Spring 学习路线图

> 本文档是整个 Spring 学习笔记的**总导航**，按由浅入深的顺序组织全部知识点文档。
> 前置基础：已学完 [Java SE 学习路线图](../Java基础/00-学习路线图.md)（至少到反射、注解、动态代理）；建议先了解 [Maven 使用文档](../Spring基础/Maven%20使用文档.md)——Spring 依赖通过 Maven 管理。
> 学习定位：**面向 Spring Framework 核心原理**。目标是学完后能深入理解 IoC 容器、DI 注入、Bean 生命周期、AOP 切面、事务管理等核心机制——这些是 Spring Boot 自动配置的底层基础。
> 阅读建议：按编号顺序学习，每篇配合代码动手敲一遍；带 ⭐ 的是开发高频/面试重点，务必吃透。

---

## 这份路线图的设计理念

在开始列知识点之前，先说清楚"为什么这么排"：

1. **Spring基础是"原理课"，Spring实战是"工程课"**。本目录专注 Spring Framework 核心机制（IoC/DI/AOP/事务），不涉及 Spring Boot 自动配置、Starter、内嵌 Tomcat 等工程化内容——那些属于 [Spring实战](../Spring实战/00-学习路线图.md) 的范畴。**学完 Spring基础，你才能真正理解 Spring Boot 的 `@SpringBootApplication` 在帮你做了什么**。
2. **IoC 与 DI 是整座大厦的地基**。阶段一占了 4 篇，投入最多篇幅——IoC 容器的思想、Bean 的注册与生命周期、DI 的多种注入方式是所有后续知识的前提。地基不牢，后面的 AOP、事务、Spring MVC 都是空中楼阁。
3. **先配置后注解，逐步过渡**。传统 Spring 教程从 XML 配置开始，但现代开发已全面注解化。本路线图采用"XML 理解原理 → 注解作为主力 → Java Config 补充"的顺序，让你既懂旧代码的 XML，也能写现代的注解。
4. **AOP 是 Spring 的第二个核心**。IoC 管对象的创建和装配，AOP 管横切逻辑（日志/事务/权限/缓存）。理解 AOP 的代理机制，才能理解 `@Transactional` 为什么能管事务、`@Cacheable` 为什么能管缓存。
5. **事务是数据库操作的基石**。把事务管理单独成篇，因为 `@Transactional` 是后端开发中最容易踩坑的注解——传播行为、隔离级别、回滚规则，一个没搞对就是生产事故。
6. **与 Spring实战 的分工**：本目录讲"Spring 是什么、怎么工作的"，[Spring实战](../Spring实战/00-学习路线图.md) 讲"Spring Boot 怎么做业务"。本目录是原理，实战目录是应用。

## 阶段一：IoC 容器与 Bean

> IoC（Inversion of Control，控制反转）是 Spring 最核心的思想。这 4 篇从"为什么要用 IoC"讲到 Bean 的一生（从创建到销毁），是整个 Spring 学习的地基。

- [01-IoC 思想与原理解析](01-IoC%20思想与原理解析.md) ⭐
  - 传统 new 对象的耦合问题；工厂模式解耦；IoC 容器本质（Map 存储 + 反射创建）；**控制反转的两种含义**（创建权反转 + 依赖获取权反转）；DI 与 IoC 的关系
  - 📌 对 Spring Boot 的意义：`@SpringBootApplication` 启动的 `ApplicationContext` 就是一个巨大的 IoC 容器
- [02-Spring 容器与 Bean 注册](02-Spring%20容器与%20Bean%20注册.md) ⭐
  - `BeanFactory` 与 `ApplicationContext` 体系；**三种 Bean 注册方式**：XML `<bean>`、`@Component` 系列注解、`@Bean` Java Config；`@ComponentScan` 扫描机制；Bean 命名规则
  - 📌 对 Spring Boot 的意义：`@SpringBootApplication` 自带 `@ComponentScan`，Spring Boot 的 Starter 通过 `@Bean` 自动注册组件
- [03-Bean 作用域与生命周期](03-Bean%20作用域与生命周期.md) ⭐
  - **五种作用域**：singleton/prototype/request/session/application；singleton 与 prototype 的坑（prototype 注入 singleton 失效）；**Bean 生命周期全流程**：构造 → 属性填充 → `@PostConstruct` → `InitializingBean` → 使用 → `@PreDestroy` → `DisposableBean`；`BeanPostProcessor` 后处理器
  - 📌 对 Spring Boot 的意义：Spring Boot 自动配置大量使用 `BeanPostProcessor`
- [04-条件装配与 Profile](04-条件装配与%20Profile.md)
  - `@Conditional` 条件装配；`@Profile` 环境切换；`@ConditionalOnClass`/`@ConditionalOnMissingBean` 等 Boot 条件注解；配置优先级
  - 📌 对 Spring Boot 的意义：Spring Boot 的"自动配置"就是靠 `@ConditionalOnClass`/`@ConditionalOnMissingBean` 实现的

## 阶段二：DI 依赖注入

> DI（Dependency Injection，依赖注入）是 IoC 的具体实现方式。这 3 篇讲清 Spring 怎么把 Bean 注入到需要它的地方，以及自动装配的规则与陷阱。

- [05-依赖注入方式详解](05-依赖注入方式详解.md) ⭐
  - **三种注入方式**：构造器注入（推荐）、Setter 注入、字段注入（`@Autowired`）；构造器注入 vs Setter 注入的选型原则；Lombok `@RequiredArgsConstructor` 简化构造器注入
  - 📌 对 Spring Boot 的意义：Spring 官方推荐构造器注入，Spring Boot 项目中 `@RequiredArgsConstructor` 是主流写法
- [06-@Autowired 与自动装配](06-@Autowired%20与自动装配.md) ⭐
  - `@Autowired` 按类型注入；`@Qualifier` 按名称限定；`@Primary` 设置首选；`@Resource`（JSR-250）与 `@Autowired` 的区别；**注入 `List`/`Map` 收集同类型 Bean**；`required = false` 可选注入
  - 📌 对 Spring Boot 的意义：`@Autowired` 是 Spring Boot 中最常用的注解之一，面试必问注入规则
- [07-循环依赖与三级缓存](07-循环依赖与三级缓存.md) ⭐⭐
  - **循环依赖的三种场景**：构造器注入循环（无法解决）、Setter 注入循环（可解决）、字段注入循环（可解决）；**Spring 三级缓存机制**：singletonObjects → earlySingletonObjects → singletonFactories；`@Lazy` 延迟注入解决循环依赖
  - 📌 对 Spring Boot 的意义：Spring Boot 开发中循环依赖是常见错误，理解三级缓存才能定位和解决

## 阶段三：AOP 面向切面编程

> AOP（Aspect-Oriented Programming）是 Spring 仅次于 IoC 的第二大核心。它让你在不修改原代码的情况下，统一给多个方法增加日志、事务、权限等横切逻辑。

- [08-AOP 概念与代理机制](08-AOP%20概念与代理机制.md) ⭐
  - AOP 核心概念：切面/切点/通知/连接点/织入；**JDK 动态代理**（基于接口）vs **CGLIB 代理**（基于继承）；Spring Boot 默认代理策略；`@EnableAspectJAutoProxy`；AOP 的局限（内部调用失效、final 方法无法代理）
  - 📌 对 Spring Boot 的意义：`@Transactional` 内部调用不生效就是因为 AOP 代理机制——这篇让你彻底搞懂
- [09-通知类型与切点表达式](09-通知类型与切点表达式.md) ⭐
  - **五种通知**：`@Before`/`@AfterReturning`/`@AfterThrowing`/`@After`/`@Around`；`@Around` 是最强大的通知（控制执行/修改参数/修改返回值）；**切点表达式**：execution / within / @annotation / args；`@Pointcut` 复用切点
  - 📌 对 Spring Boot 的意义：`@Cacheable` 用 `@Around` 实现，`@Transactional` 也用 `@Around` 管理事务
- [10-AOP 实战：日志、权限与缓存](10-AOP%20实战：日志、权限与缓存.md) ⭐
  - **三大经典场景**：统一操作日志（记录方法/参数/IP/耗时）、方法级权限校验（`@PreAuthorize` 前置通知）、自定义缓存注解（`@Around` 手动缓存）；多个切面的执行顺序 `@Order`
  - 📌 对 Spring Boot 的意义：这篇学完，你就能自己写出 `@Cacheable`/`@Transactional` 级别的自定义注解

## 阶段四：Spring 事务管理

> 事务是数据库操作正确性的保证。Spring 通过 AOP 实现了声明式事务 `@Transactional`，但背后的传播行为和隔离级别必须吃透。

- [11-声明式事务 @Transactional](11-声明式事务%20@Transactional.md) ⭐
  - 编程式事务 vs 声明式事务；`@Transactional` 用法与原理（AOP 代理）；`PlatformTransactionManager` 事务管理器；`DataSourceTransactionManager`；**回滚规则**（默认只回滚 RuntimeException + Error，受检异常不回滚）；`rollbackFor` 指定回滚异常
  - 📌 对 Spring Boot 的意义：Spring Boot 自动配置了 `DataSourceTransactionManager`，开箱即用的 `@Transactional`
- [12-事务传播与隔离级别](12-事务传播与隔离级别.md) ⭐⭐
  - **七种传播行为**：REQUIRED（默认）/REQUIRES_NEW/NESTED/SUPPORTS/NOT_SUPPORTED/MANDATORY/NEVER；**REQUIRED vs REQUIRES_NEW 的区别与场景**（下单扣库存用 REQUIRED，日志记录用 REQUIRES_NEW）；**四种隔离级别**：READ_UNCOMMITTED/READ_COMMITTED/REPEATABLE_READ/SERIALIZABLE；脏读/不可重复读/幻读；MySQL 默认 RR，Oracle 默认 RC
  - 📌 对 Spring Boot 的意义：面试必问、生产必踩坑，这个是事务篇的重中之重

## 阶段五：Spring MVC 核心

> Spring MVC 是 Spring 的 Web 框架模块。在 Spring Boot 时代，你不需要配置 DispatcherServlet，但理解它的工作原理能让你在调接口、写拦截器、处理异常时更有底气。

- [13-Spring MVC 架构与请求流程](13-Spring%20MVC%20架构与请求流程.md) ⭐
  - **前端控制器模式**；DispatcherServlet → HandlerMapping → HandlerAdapter → ViewResolver 完整请求链路；`@Controller` 与 `@RestController` 的区别（`@ResponseBody` 自动序列化）；Spring MVC 与 Servlet 的关系
  - 📌 对 Spring Boot 的意义：Spring Boot 自动注册了 DispatcherServlet，理解这个流程才能调通任何 Spring Boot 接口
- [14-请求映射与参数绑定](14-请求映射与参数绑定.md) ⭐
  - `@RequestMapping`/`@GetMapping`/`@PostMapping`/`@PutMapping`/`@DeleteMapping`；**参数绑定**：`@RequestParam`/`@PathVariable`/`@RequestBody`/`@RequestHeader`/`@ModelAttribute`；参数校验 `@Valid` + `@NotNull`/`@NotEmpty`；统一返回格式 `Result<T>`
  - 📌 对 Spring Boot 的意义：这是写 Spring Boot 接口的日常，理解每个注解的适用场景
- [15-拦截器与统一异常处理](15-拦截器与统一异常处理.md) ⭐
  - `HandlerInterceptor` 三方法（preHandle/postHandle/afterCompletion）；拦截器 vs 过滤器（Filter）的区别与执行顺序；`@ControllerAdvice` + `@ExceptionHandler` 全局异常；拦截器实战：登录校验、请求日志、跨域处理
  - 📌 对 Spring Boot 的意义：Spring Boot 项目中拦截器和全局异常是标配

## 阶段六：整合与高级特性

> 收尾阶段，将 Spring 与常用框架整合，同时理解 Spring 内部的设计模式。

- [16-Spring 整合 MyBatis](16-Spring%20整合%20MyBatis.md) ⭐
  - `SqlSessionFactoryBean` 注册；`MapperScannerConfigurer` 扫描 Mapper 接口；MyBatis 的 `@Mapper` 本质（`FactoryBean` 代理）；整合流程与纯 MyBatis 对比
  - 📌 对 Spring Boot 的意义：Spring Boot 的 `mybatis-spring-boot-starter` 自动配置了 `SqlSessionFactory` + `MapperScanner`，这篇让你理解自动配置做了什么
- [17-Spring 中的设计模式](17-Spring%20中的设计模式.md)
  - **Spring 中经典设计模式**：单例（Bean 默认 scope）、工厂（`BeanFactory`/`FactoryBean`）、代理（AOP）、模板方法（`JdbcTemplate`/`RestTemplate`）、观察者（`ApplicationListener`）、策略（`PlatformTransactionManager`）；面试高频
  - 📌 对 Spring Boot 的意义：理解这些模式，你就能举一反三看懂 Spring 全家桶源码
- [18-Spring 单元测试](18-Spring%20单元测试.md)
  - `@SpringBootTest` vs `@SpringJUnitConfig`；`@MockBean`/`@SpyBean` Mock 依赖；测试 Service 层（不启动完整容器）；测试 Controller 层（`MockMvc`）；`@Transactional` 测试自动回滚
  - 📌 对 Spring Boot 的意义：Spring Boot 项目 Test Starter 自动配置了测试环境

## 学习建议

1. **先理解 IoC，再学其他**。阶段一一定要吃透——"到底什么是控制反转"、"Bean 的完整生命周期是怎样的"。IoC 是整个 Spring 的基石，地基没打好后面全白学。
2. **手写代码验证，别光看**。Spring 是"设计得极好但光看不练学不会"的框架。每篇的代码示例务必在 IDEA 中跑一遍，尤其是 Bean 生命周期、AOP 代理失效、事务传播行为——这些必须亲手验证才能建立直觉。
3. **AOP 结合 Java SE 动态代理学**。如果你在 [Java基础/44-反射](../Java基础/44-反射.md) 里学过了动态代理，AOP 的代理机制就好懂一大半。如果你还没学反射和动态代理，建议先回去复习。
4. **事务篇的两个传播行为对比是重中之重**。REQUIRED vs REQUIRES_NEW 的区别在面试和实际开发中都是高频考点，务必用代码验证不同传播行为下的事务回滚结果。
5. **MVC 流程要能画出来**。面试常问"一个 HTTP 请求到达 Spring Boot 后经历了什么"——从 DispatcherServlet 到 HandlerMapping、HandlerAdapter、ViewResolver 的完整链路要能复述。
6. **设计模式篇是面试利器**。"Spring 中用了哪些设计模式"是经典面试题，学完 17 篇你就能答出工厂、代理、单例、模板方法、观察者 5 个以上。
7. **配合注解速查手册**：学习过程中遇到不认识的注解，随时翻 [注解速查手册](../Spring基础/注解速查手册.md) 查看用法。
8. **带着"Spring Boot 是怎么封装这个的"视角学**。每学完一个 Spring 基础概念，回想一下 Spring Boot 对应做了什么——`@ComponentScan` → `@SpringBootApplication` 自带扫描，`BeanPostProcessor` → Spring Boot Starter 自动配置，`@Transactional` → AOP 代理机制。本路线图每篇都标注了 📌。
9. **不要跳过循环依赖**。第七篇是面试大热门，"Spring 怎么解决循环依赖""为什么三级缓存不是两级"——背答案没用，理解三级缓存每一级的设计目的才算懂。
