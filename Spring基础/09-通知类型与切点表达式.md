# 通知类型与切点表达式

上一篇学了 AOP 的代理机制——Spring 用 JDK/CGLIB 动态代理把切面逻辑织入目标方法。本篇是 AOP 的"工具箱"：五种通知类型（什么时候切）+ 切点表达式（在哪切）。把这套组合拳学会，你就能写出生产级的切面代码了。

> 💡 如果说上一篇是 AOP 的"发动机原理"，这篇就是"驾驶技术"——告诉你方向盘（通知）怎么打、导航（切点表达式）怎么写。

---

## 一、五种通知类型

### 1.1 通知一览表

| 注解 | 执行时机 | 能获取什么 | 能控制什么 |
| :--- | :--- | :--- | :--- |
| `@Before` | 目标方法执行**前** | 方法参数 | ❌ 不能阻止执行 |
| `@AfterReturning` | 目标方法**正常返回后** | 方法参数 + 返回值 | ❌ 不能改返回值 |
| `@AfterThrowing` | 目标方法**抛出异常后** | 方法参数 + 异常对象 | ❌ 不能吞异常 |
| `@After` | 目标方法**执行完毕后**（类 finally） | 只有 JoinPoint | ❌ 什么都不能控制 |
| `@Around` | 包裹整个目标方法 | 方法参数 + 返回值 + 异常 | ✅ 能决定是否执行、能改参数、能改返回值 |

### 1.2 @Before：前置通知

```java
@Aspect
@Component
public class LogAspect {

    @Before("execution(* com.example.service.*.*(..))")
    public void before(JoinPoint joinPoint) {
        // 获取方法签名
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        String methodName = signature.getName();

        // 获取参数
        Object[] args = joinPoint.getArgs();
        String params = Arrays.toString(args);

        log.info("调用方法：{}, 参数：{}", methodName, params);
    }
}
```

**适用场景**：记录操作日志、校验参数、权限检查（调用前阻止）

> ⚠️ 如果要在 `@Before` 中**阻止方法执行**，需要抛异常（如 `AccessDeniedException`），不能像 `@Around` 那样选择不调 `proceed()`。

### 1.3 @AfterReturning：返回后通知

```java
@AfterReturning(
    pointcut = "execution(* com.example.service.*.*(..))",
    returning = "result"   // ← 方法返回值绑定到这个参数
)
public void afterReturning(JoinPoint joinPoint, Object result) {
    String methodName = joinPoint.getSignature().getName();
    log.info("方法 {} 执行成功，返回值：{}", methodName, result);
}
```

**适用场景**：缓存结果、记录成功日志、对返回值做后处理（但不能修改）

> 💡 `returning` 属性的值必须和参数名一致。如果方法返回 `void`，`result` 就是 `null`。

### 1.4 @AfterThrowing：异常通知

```java
@AfterThrowing(
    pointcut = "execution(* com.example.service.*.*(..))",
    throwing = "ex"    // ← 抛出的异常绑定到这个参数
)
public void afterThrowing(JoinPoint joinPoint, Exception ex) {
    String methodName = joinPoint.getSignature().getName();
    Object[] args = joinPoint.getArgs();
    log.error("方法 {} 执行异常，参数：{}，异常：{}", methodName, Arrays.toString(args), ex.getMessage());
}
```

**适用场景**：记录错误日志、发送告警通知

> ⚠️ `@AfterThrowing` 只能记录异常，**不能吞掉异常**（不能让方法看起来正常返回了）。如果需要吞异常，用 `@Around`。

### 1.5 @After：最终通知

```java
@After("execution(* com.example.service.*.*(..))")
public void after(JoinPoint joinPoint) {
    String methodName = joinPoint.getSignature().getName();
    log.info("方法 {} 执行结束", methodName);
    // 类似 finally 块——不管成功还是异常，都会执行
}
```

**适用场景**：清理资源、记录请求结束时间（配合 @Before 计算耗时）

### 1.6 @Around：环绕通知（最强大）⭐⭐

```java
@Around("execution(* com.example.service.*.*(..))")
public Object around(ProceedingJoinPoint joinPoint) throws Throwable {
    String methodName = joinPoint.getSignature().getName();
    long start = System.currentTimeMillis();

    Object result;
    try {
        // 1. 执行前
        log.info(">>> {} 开始执行", methodName);

        // 2. 执行目标方法（可以修改参数！）
        result = joinPoint.proceed();  // ← 不调这行，目标方法就不执行！

        // 3. 正常返回后（可以修改返回值！）
        log.info(">>> {} 执行成功，耗时 {}ms", methodName, System.currentTimeMillis() - start);
        return result;

    } catch (Exception e) {
        // 4. 抛异常时
        log.error(">>> {} 执行失败，耗时 {}ms", methodName, System.currentTimeMillis() - start, e);
        throw e;  // 可以吞掉，也可以重新包装后抛出

    } finally {
        // 5. 无论成功还是异常
        log.info(">>> {} 执行完毕", methodName);
    }
}
```

**适用场景**：
- 统一的请求日志（记录耗时、参数、返回值）
- 自定义缓存注解（@Around 中判断缓存命中，命中直接返回、不调 `proceed`）
- 重试机制（try-catch 中循环调 `proceed`）
- 方法级权限校验（校验失败直接 return，不调 `proceed`）
- 分布式锁（加锁 → proceed → 解锁）

## 二、切点表达式 ⭐

### 2.1 execution：方法执行切点（最常用）

```
execution(修饰符? 返回值类型 包路径.类名.方法名(参数列表) throws 异常?)
                ↑ 可选
```

**示例**：

```java
// 1. 匹配所有 public 方法
execution(public * *(..))

// 2. 匹配 service 包下所有类的所有方法（参数任意、返回值任意）
execution(* com.example.service.*.*(..))
//       ↑ 返回值       ↑ 包      ↑ 类  ↑ 方法

// 3. 匹配 service 包及子包下所有方法
execution(* com.example.service..*.*(..))
//                             ↑↑ 两个点 = 包含子包

// 4. 匹配所有 find 开头的方法
execution(* com.example.service.*.find*(..))

// 5. 匹配参数为 Long、返回值为 void 的方法
execution(void com.example.service.*.delete(Long))

// 6. 匹配第一个参数为 Long，其余参数任意
execution(* com.example.service.*.*(Long, ..))
//                                         ↑↑ 两个点 = 剩余参数任意

// 7. 匹配所有 save* 方法，第一个参数任意但有 @Valid 注解
execution(* com.example.service.*.save*(@javax.validation.Valid *, ..))
```

### 2.2 within：按类/包匹配

```java
// 匹配 service 包下所有方法
@Pointcut("within(com.example.service.*)")
public void serviceLayer() {}

// 匹配所有 Controller
@Pointcut("within(@org.springframework.web.bind.annotation.RestController *)")
public void controllerLayer() {}
```

### 2.3 @annotation：按注解匹配（实用利器）

```java
// 自定义注解
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface AuditLog {
    String value();
}

// 切面拦截所有标 @AuditLog 的方法
@Around("@annotation(auditLog)")
public Object audit(ProceedingJoinPoint joinPoint, AuditLog auditLog) throws Throwable {
    String operation = auditLog.value();  // 获取注解参数
    log.info("操作：{}", operation);
    Object result = joinPoint.proceed();
    log.info("操作 {} 完成", operation);
    return result;
}
```

```java
// 使用
@Service
public class OrderService {
    @AuditLog("创建订单")  // 这个方法自动被日志切面拦截
    public void createOrder(Order order) { ... }
}
```

> 💡 `@annotation` 是 AOP 实战中最灵活的切点方式——给方法贴一个自定义注解，切面就自动生效，比写复杂的 execution 表达式直观得多。

### 2.4 @args / args / @target / target：进阶匹配

```java
// args：按方法参数类型匹配
@Before("execution(* com.example.service.*.*(..)) && args(order, ..)")
public void handleOrder(Order order) {
    // 只拦截参数包含 Order 的方法，并将它绑定到 order 变量
}

// @args：参数上有特定注解
@Before("@args(com.example.annotation.Validated)")
public void validateArgs() {
    // 参数类型上标了 @Validated 注解的方法
}

// @target：目标类上有特定注解
@Before("@target(org.springframework.transaction.annotation.Transactional)")
public void transactionalBean() {
    // 拦截标注了 @Transactional 的类的所有方法
}
```

### 2.5 bean：按 Bean 名称匹配（Spring 独有）

```java
// 拦截 Bean 名称以 "Service" 结尾的
@Pointcut("bean(*Service)")
public void serviceBeans() {}

// 拦截特定 Bean
@Pointcut("bean(orderService)")
public void orderServiceOnly() {}
```

## 三、切点复用：@Pointcut

### 3.1 定义可复用的切点

```java
@Aspect
@Component
public class LogAspect {

    // 定义切点（给切点表达式起个名字）
    @Pointcut("execution(* com.example.service.*.*(..))")
    public void serviceLayer() {}

    @Pointcut("execution(* com.example.controller.*.*(..))")
    public void controllerLayer() {}

    // 组合切点
    @Pointcut("serviceLayer() || controllerLayer()")
    public void webLayer() {}

    // 使用切点
    @Before("webLayer()")
    public void logAccess(JoinPoint joinPoint) {
        log.info("访问：{}", joinPoint.getSignature().getName());
    }
}
```

### 3.2 切点表达式运算符

| 运算符 | 含义 | 示例 |
| :--- | :--- | :--- |
| `&&` | 与 | `serviceLayer() && !logPointcut()` |
| `\|\|` | 或 | `controllerLayer() \|\| serviceLayer()` |
| `!` | 非 | `!execution(* *.get*(..))` 排除 getter |

```java
// 复用：Web 层日志 + 计时
@Before("webLayer()")
public void logStart(JoinPoint jp) { ... }

@Around("webLayer()")
public Object logTime(ProceedingJoinPoint jp) throws Throwable {
    long start = System.currentTimeMillis();
    Object result = jp.proceed();
    log.info("{} 耗时 {}ms", jp.getSignature().getName(), System.currentTimeMillis() - start);
    return result;
}
```

## 四、多切面的执行顺序：@Order

```java
@Aspect
@Component
@Order(1)   // 值越小，越先执行
public class PermissionAspect {
    @Before("serviceLayer()")
    public void check() {
        // 权限先于日志检查
    }
}

@Aspect
@Component
@Order(2)
public class LogAspect {
    @Before("serviceLayer()")
    public void log() {
        // 日志在权限之后记录
    }
}

@Aspect
@Component
@Order(3)
public class CacheAspect {
    @Around("serviceLayer()")
    public Object cache(ProceedingJoinPoint jp) {
        // 缓存最外层
    }
}
```

**多层切面的执行顺序**：

```
→ @Order(1) @Before
→ @Order(2) @Before
→ @Order(3) @Around 开始
    → 目标方法执行
→ @Order(3) @Around 结束
→ @Order(2) @After
→ @Order(1) @After
```

## 💻 实战案例

### 案例：自定义 @CacheResult 缓存注解

```java
// 1. 自定义注解
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface CacheResult {
    String key();      // 缓存 key
    long ttl() default 60;  // 过期时间（秒）
}

// 2. 切面实现
@Aspect
@Component
@Order(3)
public class CacheAspect {
    private final Map<String, CacheEntry> localCache = new ConcurrentHashMap<>();

    @Around("@annotation(cacheResult)")
    public Object cache(ProceedingJoinPoint joinPoint, CacheResult cacheResult) throws Throwable {
        String key = cacheResult.key();
        long ttl = cacheResult.ttl();

        // 查缓存
        CacheEntry entry = localCache.get(key);
        if (entry != null && !entry.isExpired()) {
            System.out.println(">>> [缓存命中] key=" + key);
            return entry.value;
        }

        // 缓存未命中 → 执行方法
        System.out.println(">>> [缓存未命中] key=" + key);
        Object result = joinPoint.proceed();

        // 存入缓存
        localCache.put(key, new CacheEntry(result, System.currentTimeMillis() + ttl * 1000));
        return result;
    }

    static class CacheEntry {
        Object value;
        long expireAt;
        CacheEntry(Object value, long expireAt) { this.value = value; this.expireAt = expireAt; }
        boolean isExpired() { return System.currentTimeMillis() > expireAt; }
    }
}

// 3. 使用
@Service
public class ProductService {
    @CacheResult(key = "hot_products", ttl = 300)  // 缓存5分钟
    public List<Product> getHotProducts() {
        // 模拟从数据库查询
        System.out.println("查询数据库...");
        return List.of(new Product("A"), new Product("B"));
    }
}
```

## 🎯 面试高频

### Q1：@Around 和 @Before + @AfterReturning 有什么区别？

**答**：
- `@Around` 能**控制方法是否执行**（不调 `proceed()` 即可）、能**修改参数**、能**修改返回值**、能**吞掉异常**
- `@Before` 只能在执行前做操作，`@AfterReturning` 只能获取返回值但不能修改
- `@Around` 是"一句话说了算"的通知，其他四种是观察者

### Q2：如何获取目标方法的参数和返回值？

**答**：在 `@Around` 中通过 `joinPoint.getArgs()` 获取参数数组；通过 `joinPoint.proceed()` 的返回值获取方法返回值。在 `@AfterReturning` 中通过 `returning` 属性绑定返回值参数。

## 📌 在 Spring Boot 中

- `@Transactional` 本质就是 `@Around`：在目标方法执行前开启事务、执行后提交/回滚
- `@Cacheable` 也是 `@Around`：先查缓存 → 命中直接返回（不调 `proceed`）→ 未命中执行方法并缓存
- `@Async` 也是 `@Around`：不调 `proceed` 而是把方法执行提交给线程池
- Spring Boot 的 `spring.aop.auto=true` 默认启用 AOP 自动配置

## 本章小结

| 知识点 | 要点 |
| :--- | :--- |
| @Before | 前置通知，可获取参数，不能阻止执行 |
| @AfterReturning | 正常返回后，可获取返回值（不能改） |
| @AfterThrowing | 异常后，可获取异常（不能吞） |
| @After | 最终通知，类比 finally |
| @Around | 环绕通知，全能——可控执行、改参、改返回值、吞异常 |
| execution 表达式 | `execution(返回值 包.类.方法(参数))`：`*` 匹配任意，`..` 匹配多层/多参数 |
| @annotation | 按方法注解匹配，最灵活的自定义切面方式 |
| @Pointcut | 定义可复用的切点，支持 && / \|\| / ! 组合 |
| @Order | 多切面排序，值越小优先级越高 |

---

## 学习建议

1. **每个通知类型都写一遍**。特别是 `@Around`：写一个切面，记录每个接口调用的参数、返回值、异常、耗时，四个信息一个切面搞定。
2. **掌握 @annotation 的自定义注解模式**。自己写一个 `@RateLimit` 或 `@AuditLog` 注解，配上对应的切面，这比背 execution 表达式实用得多。
3. **不要滥用 AOP**。切面让代码"隐式生效"，但过度使用会导致"追代码不知道谁在哪改了什么"。只在横切逻辑（日志、缓存、事务、权限）中使用。
