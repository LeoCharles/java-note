# 第一章：启动与自动配置

> 这一组注解决定"应用怎么启动、扫哪些包、自动配什么"。

## 1.1 核心注解

| 注解 | 频率 | 作用 | 一句话记忆 |
|---|---|---|---|
| `@SpringBootApplication` | ⭐⭐⭐ | 启动类三合一注解 | **"开机键"**，写在 main 所在类上 |
| `@Configuration` | ⭐⭐ | 标记类为配置类（里面可写 `@Bean`） | **"配置文件类"** |
| `@SpringBootConfiguration` | ⭐ | `@Configuration` 的 Spring Boot 版本 | 就是 `@Configuration`，基本不单独用 |
| `@EnableAutoConfiguration` | ⭐⭐⭐ | 开启自动配置（核心魔法） | **"自动挡"**，根据依赖自动配 |
| `@ComponentScan` | ⭐⭐ | 扫描包下的 `@Component` | **"雷达"**，扫描哪些类要注册 |

### `@SpringBootApplication` 拆解

```java
@SpringBootApplication  // 它其实是下面三个注解的组合
// = @SpringBootConfiguration  → 标记配置类
// + @EnableAutoConfiguration   → 开启自动配置
// + @ComponentScan             → 扫描当前包及子包
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

> **⚠️ 最常见的坑**：启动类必须在**根包**下（如 `com.example.demo`），否则扫描不到子包里的 Controller/Service。详见主文档第七章 7.5。

### 排除自动配置

```java
// 想关掉某个自动配置（比如不要数据源自动配置）
@SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})
// 或排除多个
@SpringBootApplication(excludeName = {"org.springframework.boot.autoconfigure...XXX"})
```

## 1.2 Profile（环境隔离）

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Profile("dev")` | ⭐⭐ | 只在指定环境激活该 Bean/配置 |

```java
@Configuration
@Profile("dev")  // 只在 dev 环境生效
public class DevConfig { ... }

// 配合 application-dev.yml 使用，启动时 --spring.profiles.active=dev
```

## 1.3 导入资源

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Import(XXXConfig.class)` | ⭐ | 显式导入一个配置类 |
| `@ImportResource("classpath:beans.xml")` | ⭐ | 导入 XML 配置（老项目迁移用） |
| `@PropertySource("classpath:xxx.properties")` | ⭐ | 导入额外 properties 文件 |

> **记忆口诀**：启动三件套 = **"开机键 `@SpringBootApplication` + 自动挡 `@EnableAutoConfiguration` + 雷达 `@ComponentScan`"**，平时只用第一个。

# 第二章：组件注册（Bean 定义）

> 这一组注解回答"哪些类要交给 Spring 管理（变成 Bean）"。

## 2.1 分层组件注解（最常用）

这四个**本质都是 `@Component`**，只是语义不同，方便分层和扫包过滤。

| 注解 | 频率 | 用在哪一层 | 语义 | 前端类比 |
|---|---|---|---|---|
| `@Component` | ⭐⭐⭐ | 通用工具/组件 | 通用组件 | 通用装饰器 |
| `@Controller` | ⭐⭐ | Controller 层 | 处理请求（返回视图） | Express Router |
| `@RestController` | ⭐⭐⭐ | Controller 层 | `@Controller` + `@ResponseBody`（返回 JSON） | API 路由 |
| `@Service` | ⭐⭐⭐ | Service 层 | 业务逻辑 | 业务逻辑层 |
| `@Repository` | ⭐⭐ | Repository 层 | 数据访问（额外做异常转换） | ORM 层 |
| `@Configuration` | ⭐⭐ | 配置类 | 配置类（含 `@Bean` 方法） | config.js |

```java
@RestController  // = @Controller + @ResponseBody，返回 JSON
@RequestMapping("/api/users")
public class UserController { ... }

@Service
public class UserServiceImpl implements UserService { ... }

@Repository
public interface UserRepository extends JpaRepository<User, Long> { ... }

@Configuration
public class WebConfig { ... }
```

> **💡 选哪个？** 写 API 接口用 `@RestController`；业务逻辑用 `@Service`；数据库访问用 `@Repository`；其他工具类用 `@Component`。

## 2.2 `@Bean`（方法级注册）

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Bean` | ⭐⭐⭐ | 在 `@Configuration` 类的方法上，把方法返回值注册为 Bean |

```java
@Configuration
public class SecurityConfig {

    @Bean  // 把这个方法的返回值交给 Spring 管理
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}
```

> **💡 前端类比**：`@Bean` ≈ 在模块里 `export default new XXX()`，框架帮你注入到别处。**第三方库的类没法加 `@Component`，只能用 `@Bean` 注册。**

## 2.3 Bean 作用域与控制

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Scope("singleton")` | ⭐ | 单例（默认） |
| `@Scope("prototype")` | ⭐ | 每次获取都新建 |
| `@Lazy` | ⭐⭐ | 懒加载（用到才创建，可解循环依赖） |
| `@Primary` | ⭐⭐ | 多个同类 Bean 时，标记为默认首选 |
| `@Qualifier("名字")` | ⭐⭐ | 指定注入哪个 Bean（配合 `@Autowired`） |
| `@DependsOn("xxx")` | ⭐ | 指定 Bean 创建顺序 |
| `@Order(1)` | ⭐ | 排序（拦截器、过滤器等） |

```java
// 多个实现时指定默认
@Service
@Primary  // 有多个 UserService 实现时，默认注入这个
public class UserServiceImpl implements UserService { ... }

// 指定注入某个
@Autowired
@Qualifier("userServiceImpl")  // 按名字注入
private UserService userService;
```

> **记忆口诀**：注册 Bean 两条路——**"类上贴 `@Component` 系（自己写的类），方法上贴 `@Bean`（第三方的类）"**。多个实现打架时，**`@Primary` 选默认，`@Qualifier` 点名**。

# 第三章：依赖注入

> 这一组注解回答"Bean 之间的依赖怎么自动塞进去"。

## 3.1 注入注解对比

| 注解 | 频率 | 来源 | 作用 | 推荐度 |
|---|---|---|---|---|
| `@Autowired` | ⭐⭐⭐ | Spring | 按类型注入 | ⚠️ 字段注入能用但不推荐 |
| `@Qualifier` | ⭐⭐ | Spring | 按名字指定（配合 `@Autowired`） | 多实现时用 |
| `@Resource` | ⭐ | JSR-250 | 默认按名字，找不到再按类型 | 老项目常见 |
| `@Inject` | ⭐ | JSR-330 | 类似 `@Autowired` | 很少用 |
| `@Value` | ⭐⭐⭐ | Spring | 注入配置值 | 读 yml/properties |

## 3.2 三种注入方式（强烈推荐构造器注入）

```java
// ✅ 方式1：构造器注入（Spring 官方推荐，配合 Lombok 最简洁）
@RestController
@RequiredArgsConstructor  // Lombok 自动生成 final 字段构造器
public class UserController {
    private final UserService userService;  // final + 构造器注入
}

// ⚠️ 方式2：字段注入（简单但不推荐，难测试、循环依赖易爆）
@RestController
public class UserController {
    @Autowired
    private UserService userService;
}

// 方式3：Setter 注入（可选依赖时用）
@RestController
public class UserController {
    private UserService userService;
    @Autowired
    public void setUserService(UserService userService) {
        this.userService = userService;
    }
}
```

> **💡 为什么推荐构造器注入？** ① 字段可声明 `final`（不可变，线程安全）；② 不依赖 Spring 容器也能 new 出来测试；③ 循环依赖在启动时就报错，不藏雷。

## 3.3 `@Value` 读取配置

```java
@Value("${app.jwt.secret}")          // 读 yml 里的 app.jwt.secret
private String secret;

@Value("${app.jwt.expiration:86400}") // 冒号后是默认值
private long expiration;

@Value("#{systemProperties['user.home']}")  // SpEL 表达式
private String homeDir;

// 批量读取推荐用 @ConfigurationProperties（见第十二章）
```

> **记忆口诀**：注入就记 **"`@Autowired` 按类型，`@Qualifier` 点名，`@Value` 读配置，构造器注入最推荐"**。

# 第四章：Web 与 Controller 层

> 这是日常写接口用得最多的一组，必须牢记。

## 4.1 请求映射（Mapping）

| 注解 | 频率 | HTTP 方法 | 用途 |
|---|---|---|---|
| `@RequestMapping` | ⭐⭐ | 全部 | 通用映射（可指定 method） |
| `@GetMapping` | ⭐⭐⭐ | GET | 查询 |
| `@PostMapping` | ⭐⭐⭐ | POST | 新增 |
| `@PutMapping` | ⭐⭐⭐ | PUT | 全量更新 |
| `@PatchMapping` | ⭐ | PATCH | 部分更新 |
| `@DeleteMapping` | ⭐⭐⭐ | DELETE | 删除 |

```java
@RestController
@RequestMapping("/api/users")  // 类级别：公共前缀
public class UserController {

    @GetMapping              // GET /api/users
    @GetMapping("/{id}")     // GET /api/users/{id}
    @PostMapping             // POST /api/users
    @PutMapping("/{id}")     // PUT /api/users/{id}
    @DeleteMapping("/{id}")  // DELETE /api/users/{id}
}
```

> **💡 前端类比**：`@GetMapping("/x")` ≈ Express `router.get('/x', handler)`。

## 4.2 参数提取（最常用的一组）

| 注解 | 频率 | 从哪取参数 | 示例 |
|---|---|---|---|
| `@PathVariable` | ⭐⭐⭐ | URL 路径占位符 | `/users/{id}` → `@PathVariable Long id` |
| `@RequestParam` | ⭐⭐⭐ | URL 查询串 | `?page=0&size=10` |
| `@RequestBody` | ⭐⭐⭐ | 请求体（JSON） | POST/PUT 的 body |
| `@RequestHeader` | ⭐⭐ | 请求头 | `Authorization` 等 |
| `@CookieValue` | ⭐ | Cookie | `@CookieValue("JSESSIONID")` |
| `@RequestPart` | ⭐ | 文件上传 | `@RequestPart("file") MultipartFile` |
| `@ModelAttribute` | ⭐ | 表单绑定 | 表单提交多个字段 |
| `@RequestAttribute` | ⭐ | request 域属性 | 拦截器塞的值 |

```java
@GetMapping("/{id}")
public User get(@PathVariable Long id) { ... }              // 路径参数

@GetMapping
public List<User> list(
    @RequestParam(defaultValue = "0") int page,             // ?page=0
    @RequestParam(defaultValue = "10") int size,            // &size=10
    @RequestParam(required = false) String keyword          // 可选
) { ... }

@PostMapping
public User create(@Valid @RequestBody UserCreateRequest req) { ... }  // JSON body

@GetMapping
public User byHeader(@RequestHeader("Authorization") String token) { ... }
```

> **记忆口诀**：参数三件套——**"路径 `@PathVariable`、查询 `@RequestParam`、请求体 `@RequestBody`"**。

## 4.3 响应与跨域

| 注解 | 频率 | 作用 |
|---|---|---|
| `@ResponseBody` | ⭐⭐ | 方法返回值直接写进响应体（转 JSON） |
| `@RestController` | ⭐⭐⭐ | `@Controller` + `@ResponseBody`（类级别） |
| `@ResponseStatus(code)` | ⭐ | 指定响应状态码 |
| `@CrossOrigin` | ⭐⭐ | 允许跨域（方法/类级别） |
| `@RestControllerAdvice` | ⭐⭐⭐ | 全局异常处理 + `@ResponseBody` |

```java
@CrossOrigin(origins = "http://localhost:3000")  // 允许前端跨域
@RestController
public class UserController { ... }

@DeleteMapping("/{id}")
@ResponseStatus(HttpStatus.NO_CONTENT)  // 返回 204
public void delete(@PathVariable Long id) { ... }
```

## 4.4 全局异常处理

| 注解 | 频率 | 作用 |
|---|---|---|
| `@RestControllerAdvice` | ⭐⭐⭐ | 全局异常处理类（返回 JSON） |
| `@ControllerAdvice` | ⭐⭐ | 全局异常处理类（可返回视图） |
| `@ExceptionHandler(XxxException.class)` | ⭐⭐⭐ | 处理指定异常 |

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)  // 捕获业务异常
    public ResponseEntity<ApiResponse<Void>> handle(BusinessException e) {
        return ResponseEntity.badRequest()
            .body(ApiResponse.error(e.getCode(), e.getMessage()));
    }

    @ExceptionHandler(Exception.class)  // 兜底：所有未捕获异常
    public ResponseEntity<ApiResponse<Void>> handleAll(Exception e) { ... }
}
```

> **记忆口诀**：Web 层四组——**"映射 `@XxxMapping`、取参 `@PathVariable/@RequestParam/@RequestBody`、响应 `@RestController`、异常 `@RestControllerAdvice + @ExceptionHandler`"**。

# 第五章：参数校验

> 来自 `jakarta.validation`（旧名 `javax.validation`），配合 `@Valid` 触发。

## 5.1 触发校验

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Valid` | ⭐⭐⭐ | 标在方法参数上，触发校验（标准 JSR） |
| `@Validated` | ⭐⭐ | Spring 增强，支持分组校验、标在类上 |

```java
@PostMapping
public User create(@Valid @RequestBody UserCreateRequest req) { ... }
//                 ^^^^^ 触发 req 里的校验注解
```

## 5.2 空值校验（最容易混淆的三兄弟）

| 注解 | 频率 | 适用类型 | 区别 |
|---|---|---|---|
| `@NotNull` | ⭐⭐⭐ | 任意类型 | 不能为 null（可为空串） |
| `@NotEmpty` | ⭐⭐ | 字符串/集合 | 不能为 null 且 size > 0 |
| `@NotBlank` | ⭐⭐⭐ | 字符串 | 不能为 null 且必须含非空白字符 |

> **💡 区分记忆**：
> - `@NotNull`：只要不是 null 就行，`""` 也通过
> - `@NotEmpty`：不能 null 也不能空集合/空串
> - `@NotBlank`：字符串专用，`"  "`（纯空格）也过不了

## 5.3 数值与长度校验

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Min(value)` | ⭐⭐⭐ | 最小值（整数） |
| `@Max(value)` | ⭐⭐⭐ | 最大值（整数） |
| `@DecimalMin` / `@DecimalMax` | ⭐ | 最小/最大值（小数） |
| `@Size(min, max)` | ⭐⭐ | 字符串/集合长度范围 |
| `@Positive` / `@PositiveOrZero` | ⭐ | 必须正数 / 非负 |
| `@Negative` / `@NegativeOrZero` | ⭐ | 必须负数 / 非正 |
| `@Digits(integer, fraction)` | ⭐ | 数字整数位/小数位限制 |

## 5.4 格式与范围校验

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Email` | ⭐⭐⭐ | 邮箱格式 |
| `@Pattern(regexp)` | ⭐⭐ | 正则匹配 |
| `@Past` / `@PastOrPresent` | ⭐ | 必须是过去时间 |
| `@Future` / `@FutureOrPresent` | ⭐ | 必须是未来时间 |
| `@AssertTrue` / `@AssertFalse` | ⭐ | 必须为 true/false |

```java
@Data
public class UserCreateRequest {
    @NotBlank(message = "姓名不能为空")
    private String name;

    @Min(value = 1) @Max(value = 150)
    private Integer age;

    @Email @NotBlank
    private String email;

    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式错误")
    private String phone;
}
```

> **记忆口诀**：校验两步走——**"DTO 字段上贴规则（`@NotBlank/@Email/@Min`），Controller 参数上贴 `@Valid` 触发"**。失败抛 `MethodArgumentNotValidException`，交给全局异常处理。

# 第六章：数据访问（JPA/Hibernate）

> 来自 `jakarta.persistence.*`（JPA）和 `org.springframework.data.*`（Spring Data）。

## 6.1 实体类映射

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Entity` | ⭐⭐⭐ | 标记类为数据库实体 |
| `@Table(name = "users")` | ⭐⭐ | 映射表名（不写则用类名） |
| `@MappedSuperclass` | ⭐⭐ | 公共字段基类（本身不映射表） |

## 6.2 主键与列

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Id` | ⭐⭐⭐ | 主键 |
| `@GeneratedValue` | ⭐⭐⭐ | 主键生成策略（自增/UUID 等） |
| `@Column` | ⭐⭐⭐ | 列映射（名/长度/是否可空等） |
| `@Transient` | ⭐⭐ | 该字段不映射到数据库 |
| `@Version` | ⭐ | 乐观锁版本字段 |

```java
@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)  // 数据库自增
    private Long id;

    @Column(nullable = false, length = 50)
    private String name;

    @Column(name = "created_at", updatable = false)  // 列名映射，不可更新
    private LocalDateTime createdAt;

    @Transient  // 不入库
    private String tempField;
}
```

## 6.3 关联关系（四件套）

| 注解 | 频率 | 关系 | 例子 |
|---|---|---|---|
| `@OneToOne` | ⭐⭐ | 一对一 | 用户↔用户详情 |
| `@OneToMany` | ⭐⭐ | 一对多 | 部门→多个员工 |
| `@ManyToOne` | ⭐⭐⭐ | 多对一 | 多个员工→部门（最常用） |
| `@ManyToMany` | ⭐ | 多对多 | 学生↔课程 |
| `@JoinColumn` | ⭐⭐ | 指定外键列 | `@JoinColumn(name = "dept_id")` |
| `@JoinTable` | ⭐ | 多对多中间表 | |

```java
// 多对一（最常见）
@ManyToOne(fetch = FetchType.LAZY)  // 懒加载，避免 N+1
@JoinColumn(name = "dept_id")
private Department department;

// 一对多
@OneToMany(mappedBy = "department", cascade = CascadeType.ALL)
private List<Employee> employees;
```

> **💡 `fetch`**：`LAZY` 懒加载（用到才查，默认对 `@OneToMany`/`@ManyToMany`），`EAGER` 立即加载（默认对 `@ManyToOne`/`@OneToOne`）。生产环境优先 LAZY。

## 6.4 生命周期回调

| 注解 | 频率 | 触发时机 |
|---|---|---|
| `@PrePersist` | ⭐⭐ | insert 前 |
| `@PostPersist` | ⭐ | insert 后 |
| `@PreUpdate` | ⭐⭐ | update 前 |
| `@PostUpdate` | ⭐ | update 后 |
| `@PreRemove` | ⭐ | delete 前 |
| `@PostRemove` | ⭐ | delete 后 |
| `@PostLoad` | ⭐ | 查询加载后 |

```java
@PrePersist
protected void onCreate() {
    this.createdAt = LocalDateTime.now();  // 新增时自动填创建时间
}

@PreUpdate
protected void onUpdate() {
    this.updatedAt = LocalDateTime.now();  // 更新时自动填更新时间
}
```

## 6.5 Spring Data JPA 查询

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Query("JPQL")` | ⭐⭐⭐ | 自定义查询 |
| `@Query(value="原生SQL", nativeQuery=true)` | ⭐⭐ | 原生 SQL |
| `@Param("name")` | ⭐⭐⭐ | 给查询参数命名 |
| `@Modifying` | ⭐⭐ | 标记 update/delete 操作 |
| `@Transactional` | ⭐⭐ | 配合 `@Modifying` 使用 |

```java
public interface UserRepository extends JpaRepository<User, Long> {

    // 方法名自动生成 SQL（无需注解）
    Optional<User> findByEmail(String email);
    List<User> findByAgeGreaterThan(int age);

    // 自定义 JPQL
    @Query("SELECT u FROM User u WHERE u.age BETWEEN :min AND :max")
    List<User> findByAgeRange(@Param("min") int min, @Param("max") int max);

    // 原生 SQL
    @Query(value = "SELECT * FROM users WHERE email = ?1", nativeQuery = true)
    User findByEmailNative(String email);

    // 修改操作必须加 @Modifying + @Transactional
    @Modifying
    @Transactional
    @Query("UPDATE User u SET u.status = :status WHERE u.id = :id")
    int updateStatus(@Param("id") Long id, @Param("status") int status);
}
```

> **记忆口诀**：JPA 三层——**"类上映射 `@Entity/@Table/@Id/@Column`、关系 `@ManyToOne` 等四件套、查询 `@Query/@Param/@Modifying`"**。简单查询靠方法名，复杂查询靠 `@Query`。

# 第七章：事务管理

> 数据库事务，保证一组操作要么全成功，要么全回滚。

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Transactional` | ⭐⭐⭐ | 声明式事务 |
| `@EnableTransactionManagement` | ⭐ | 开启事务管理（Spring Boot 已自动开启） |

## 7.1 常用属性

```java
@Transactional(
    readOnly = true,           // 只读事务（查询用，优化性能）
    rollbackFor = Exception.class,  // 遇到哪些异常回滚（默认只回滚 RuntimeException）
    timeout = 30,              // 超时秒数
    isolation = Isolation.DEFAULT,  // 隔离级别
    propagation = Propagation.REQUIRED  // 传播行为
)
public class UserServiceImpl { ... }
```

## 7.2 实战用法

```java
@Service
@RequiredArgsConstructor
@Transactional(readOnly = true)  // 类级别：默认只读（查询多）
public class UserServiceImpl implements UserService {

    // 写操作单独覆盖成读写事务
    @Override
    @Transactional  // 默认读写事务
    public UserResponse create(UserCreateRequest req) {
        // 多个写操作在同一事务，失败一起回滚
        userRepository.save(user);
        logRepository.save(log);
        return toResponse(user);
    }
}
```

> **⚠️ 事务失效的常见坑**（主文档附录也提到）：
> 1. **同类方法调用**：`a()` 调本类的 `b()`，`b()` 上的 `@Transactional` 不生效（没走代理）
> 2. 方法不是 `public`
> 3. 异常被 `try-catch` 吞掉（不抛出就不回滚）
> 4. 默认只回滚 `RuntimeException`，受检异常要加 `rollbackFor = Exception.class`

> **记忆口诀**：事务就记 **"`@Transactional`，查询加 `readOnly=true`，写操作别忘加，同类调用会失效"**。

# 第八章：AOP 面向切面

> 在不修改业务代码的情况下，加日志/权限/性能监控等横切逻辑。前端类比：Express 中间件 / React HOC。

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Aspect` | ⭐⭐ | 标记切面类（需配合 `@Component`） |
| `@Pointcut` | ⭐⭐ | 定义切点（可复用的拦截规则） |
| `@Before` | ⭐⭐ | 方法执行前 |
| `@After` | ⭐ | 方法执行后（无论是否异常） |
| `@AfterReturning` | ⭐⭐ | 方法正常返回后 |
| `@AfterThrowing` | ⭐⭐ | 方法抛异常后 |
| `@Around` | ⭐⭐⭐ | 环绕（最强大，前后都能控制） |

```java
@Aspect
@Component
public class LoggingAspect {

    // 定义切点：拦截 controller 包下所有方法
    @Pointcut("execution(* com.example.demo.controller.*.*(..))")
    public void controllerPointcut() {}

    // 环绕通知：前后都能加逻辑
    @Around("controllerPointcut()")
    public Object log(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = pjp.proceed();  // 执行原方法
        long cost = System.currentTimeMillis() - start;
        log.info("{} 耗时 {}ms", pjp.getSignature().getName(), cost);
        return result;
    }

    // 前置通知
    @Before("controllerPointcut()")
    public void before(JoinPoint jp) {
        log.info("开始执行：{}", jp.getSignature().getName());
    }
}
```

> **💡 切点表达式速记**：`execution(修饰符 返回值 包.类.方法(参数))`
> - `execution(* com.example..*.*(..))` → com.example 下所有方法
> - `@annotation(xxx)` → 带某注解的方法
> - `bean(userService)` → 指定 Bean

> **记忆口诀**：AOP 五通知按时间排——**"前 `@Before`、环 `@Around`、返 `@AfterReturning`、异 `@AfterThrowing`、后 `@After`"**，最常用 `@Around`（全能）。

# 第九章：定时任务与异步

## 9.1 定时任务

| 注解 | 频率 | 作用 |
|---|---|---|
| `@EnableScheduling` | ⭐⭐⭐ | 启动类开启定时任务支持 |
| `@Scheduled` | ⭐⭐⭐ | 标记方法为定时任务 |

```java
@SpringBootApplication
@EnableScheduling  // 必须加这个，@Scheduled 才生效
public class DemoApplication { ... }

@Component
public class ScheduledTasks {

    @Scheduled(fixedRate = 60000)      // 每 60 秒执行（从上次开始算）
    public void task1() { ... }

    @Scheduled(fixedDelay = 60000)     // 上次结束后等 60 秒再执行
    public void task2() { ... }

    @Scheduled(initialDelay = 5000, fixedRate = 60000)  // 启动后 5 秒才开始
    public void task3() { ... }

    @Scheduled(cron = "0 0 2 * * ?")   // Cron 表达式：每天凌晨 2 点
    public void dailyReport() { ... }
}
```

> **💡 Cron 表达式**：`秒 分 时 日 月 周`
> - `0 0 2 * * ?` = 每天 2:00
> - `0 */5 * * * ?` = 每 5 分钟
> - `0 0 9 ? * MON-FRI` = 工作日 9:00

## 9.2 异步执行

| 注解 | 频率 | 作用 |
|---|---|---|
| `@EnableAsync` | ⭐⭐ | 启动类开启异步支持 |
| `@Async` | ⭐⭐⭐ | 方法异步执行（不阻塞调用方） |

```java
@SpringBootApplication
@EnableAsync
public class DemoApplication { ... }

@Service
public class EmailService {

    @Async  // 这个方法会在独立线程执行，调用方立即返回
    public void sendEmail(String to) {
        // 耗时发邮件操作
    }
}
```

> **⚠️ `@Async` 失效坑**：同类内部调用不生效（和事务一样的代理问题）；方法必须 `public`。

> **记忆口诀**：定时异步都要**"先开总开关（`@EnableXxx`）再用注解（`@Scheduled`/`@Async`）"**。

# 第十章：缓存

| 注解 | 频率 | 作用 |
|---|---|---|
| `@EnableCaching` | ⭐⭐ | 开启缓存支持 |
| `@Cacheable` | ⭐⭐⭐ | 查询：有缓存直接返回，没有则执行方法并缓存 |
| `@CachePut` | ⭐⭐ | 更新：执行方法并把结果放入缓存 |
| `@CacheEvict` | ⭐⭐ | 删除：清除缓存 |
| `@Caching` | ⭐ | 组合多个缓存操作 |
| `@CacheConfig` | ⭐ | 类级别公共缓存配置 |

```java
@Service
@CacheConfig(cacheNames = "users")  // 类级别统一配置缓存名
public class UserServiceImpl {

    @Cacheable(key = "#id")  // 先查缓存，没有再查库并缓存
    public User findById(Long id) {
        return userRepository.findById(id).orElse(null);
    }

    @CachePut(key = "#result.id")  // 执行后更新缓存
    public User update(User user) { return userRepository.save(user); }

    @CacheEvict(key = "#id")  // 删除数据时清缓存
    public void delete(Long id) { userRepository.deleteById(id); }

    @CacheEvict(allEntries = true)  // 清空整个 users 缓存
    public void clearAll() { ... }
}
```

> **记忆口诀**：缓存三件套——**"查 `@Cacheable`、改 `@CachePut`、删 `@CacheEvict`"**，先开 `@EnableCaching`。

# 第十一章：条件装配

> Spring Boot 自动配置的核心机制：满足条件才注册 Bean。自定义时也常用。

| 注解 | 频率 | 条件 |
|---|---|---|
| `@ConditionalOnProperty` | ⭐⭐⭐ | 配置项满足条件 |
| `@ConditionalOnClass` | ⭐ | classpath 有指定类 |
| `@ConditionalOnMissingClass` | ⭐ | classpath 没有指定类 |
| `@ConditionalOnBean` | ⭐⭐ | 容器里有指定 Bean |
| `@ConditionalOnMissingBean` | ⭐⭐⭐ | 容器里没有指定 Bean（自定义覆盖默认） |
| `@ConditionalOnWebApplication` | ⭐ | 是 Web 应用 |
| `@ConditionalOnNotWebApplication` | ⭐ | 不是 Web 应用 |
| `@ConditionalOnExpression` | ⭐ | SpEL 表达式成立 |
| `@Profile("dev")` | ⭐⭐ | 指定环境（见第一章） |

```java
// 配置开关：只有 app.cache.enabled=true 时才注册
@Configuration
@ConditionalOnProperty(name = "app.cache.enabled", havingValue = "true")
public class CacheConfig { ... }

// 容器里没有某个 Bean 时才注册（让用户能覆盖默认实现）
@Bean
@ConditionalOnMissingBean(UserService.class)
public UserService defaultUserService() { return new DefaultUserService(); }
```

> **记忆口诀**：条件装配都是 **"`@ConditionalOnXxx`"** 句式——**"有类/没类、有 Bean/没 Bean、有配置/是 Web"**，满足才装配。

# 第十二章：配置属性绑定

> 把 yml 里的配置批量绑定到 Java 对象，比 `@Value` 一个个读优雅得多。

| 注解 | 频率 | 作用 |
|---|---|---|
| `@ConfigurationProperties(prefix = "app")` | ⭐⭐⭐ | 批量绑定配置前缀到字段 |
| `@ConfigurationPropertiesScan` | ⭐⭐ | 自动扫描配置类 |
| `@EnableConfigurationProperties(Xxx.class)` | ⭐⭐ | 显式启用某配置类 |
| `@NestedConfigurationProperty` | ⭐ | 标记嵌套配置属性 |
| `@Value` | ⭐⭐⭐ | 单个值注入（见第三章） |

```yaml
# application.yml
app:
  jwt:
    secret: my-secret-key
    expiration: 86400000
```

```java
@Data
@Component
@ConfigurationProperties(prefix = "app.jwt")  // 绑定 app.jwt 下的所有配置
public class JwtProperties {
    private String secret;
    private long expiration;
}

// 使用时直接注入
@RequiredArgsConstructor
public class JwtUtil {
    private final JwtProperties props;  // 自动拿到 secret/expiration
}
```

> **💡 `@Value` vs `@ConfigurationProperties`**：
> - 单个值、临时用 → `@Value`
> - 一组相关配置、多处复用 → `@ConfigurationProperties`（类型安全、可校验）

> **记忆口诀**：配置绑定 **"`@ConfigurationProperties(prefix=...)` + `@Component`"**，一组配置一个类。

# 第十三章：测试

| 注解 | 频率 | 作用 |
|---|---|---|
| `@SpringBootTest` | ⭐⭐⭐ | 启动完整上下文做集成测试 |
| `@MockBean` | ⭐⭐⭐ | 用 Mockito 替换容器中的 Bean |
| `@SpyBean` | ⭐ | 部分模拟（保留真实逻辑，可打桩） |
| `@WebMvcTest` | ⭐⭐ | 只测 Web 层（不启动完整上下文） |
| `@DataJpaTest` | ⭐⭐ | 只测 JPA 层（自动配内存库） |
| `@RestClientTest` | ⭐ | 测 RestTemplate/RestClient |
| `@TestConfiguration` | ⭐⭐ | 测试专用配置类 |
| `@ActiveProfiles("test")` | ⭐⭐ | 激活测试 profile |
| `@TestPropertySource` | ⭐ | 注入测试属性 |
| `@Transactional` | ⭐⭐ | 测试中默认回滚（不污染库） |
| `@Rollback` / `@Commit` | ⭐ | 控制测试后是否回滚 |
| `@DirtiesContext` | ⭐ | 测试后重建上下文 |
| `@AutoConfigureMockMvc` | ⭐⭐ | 自动注入 MockMvc |

```java
@SpringBootTest  // 启动完整 Spring 上下文
@ActiveProfiles("test")  // 用 test 配置
class UserServiceTest {

    @Autowired
    private UserService userService;

    @MockBean  // 替换真实 Repository，隔离数据库
    private UserRepository userRepository;

    @Test
    void testFindById() {
        when(userRepository.findById(1L))
            .thenReturn(Optional.of(new User("张三", 25)));
        UserResponse u = userService.findById(1L);
        assertEquals("张三", u.getName());
    }
}

// 只测 Controller（轻量）
@WebMvcTest(UserController.class)
@AutoConfigureMockMvc
class UserControllerTest {
    @Autowired private MockMvc mockMvc;
    @MockBean private UserService userService;  // Service 打桩
}
```

> **记忆口诀**：测试三档——**"全量 `@SpringBootTest`、Web 层 `@WebMvcTest`、JPA 层 `@DataJpaTest`"**，替身用 `@MockBean`。

# 第十四章：Lombok

> 编译期生成样板代码，Java 项目几乎必用。需装 IDE 插件 + 开启注解处理。

## 14.1 实体/DTO 常用

| 注解 | 频率 | 生成内容 |
|---|---|---|
| `@Data` | ⭐⭐⭐ | getter+setter+toString+equals+hashCode |
| `@Getter` / `@Setter` | ⭐⭐ | 单独生成 get/set |
| `@NoArgsConstructor` | ⭐⭐⭐ | 无参构造器 |
| `@AllArgsConstructor` | ⭐⭐ | 全参构造器 |
| `@RequiredArgsConstructor` | ⭐⭐⭐ | final 字段构造器（构造器注入神器） |
| `@Builder` | ⭐⭐⭐ | 建造者模式 |
| `@ToString` | ⭐ | toString |
| `@EqualsAndHashCode` | ⭐ | equals/hashCode |
| `@Value` | ⭐ | 不可变类（全 final + getter） |

## 14.2 其他实用

| 注解 | 频率 | 作用 |
|---|---|---|
| `@Slf4j` | ⭐⭐⭐ | 注入 `log`（直接 `log.info(...)`） |
| `@NonNull` | ⭐⭐ | 非空校验（生成判空） |
| `@SneakyThrows` | ⭐ | 偷偷抛受检异常（不写 throws） |
| `@Accessors(chain=true)` | ⭐ | 链式 setter（`user.setName().setAge()`） |

```java
// 实体类标准搭配
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class UserResponse {
    private Long id;
    private String name;
    // 直接 userResponse.builder().id(1).name("x").build()
}

// Controller/Service 标准搭配（构造器注入 + 日志）
@Slf4j
@Service
@RequiredArgsConstructor
public class UserServiceImpl {
    private final UserRepository userRepository;  // 自动构造器注入
    // 直接用 log.info("xxx")
}
```

> **⚠️ 注意**：`@Data` 用在 `@Entity` 上可能因 `equals/hashCode` 触发懒加载，实体类建议用 `@Getter @Setter` 而非 `@Data`。

> **记忆口诀**：Lombok 三套搭配——**"实体 `@Data + @NoArgsConstructor + @Builder`、服务 `@RequiredArgsConstructor + @Slf4j`、DTO `@Data + @Builder`"**。

# 第十五章：生命周期与事件

| 注解 | 频率 | 作用 |
|---|---|---|
| `@PostConstruct` | ⭐⭐⭐ | Bean 初始化完成后执行 |
| `@PreDestroy` | ⭐⭐ | Bean 销毁前执行 |
| `@EventListener` | ⭐⭐ | 监听 Spring 事件 |
| `@TransactionalEventListener` | ⭐ | 事务相关阶段监听事件 |
| `@Async` | ⭐⭐ | 事件监听异步执行（见第九章） |

```java
@Component
public class CacheWarmer {

    public void warmUp() {
        log.info("预热缓存...");

    @PreDestroy  // 容器关闭前执行（释放资源）

        log.info("清理资源...");

// 事件监听
@Component
public class UserEventListener {

}
```

# 记忆口诀总览

把所有口诀集中在这里，反复看几遍就记住了：

| 类别 | 口诀 |
|---|---|
| 启动 | 开机键 `@SpringBootApplication` + 自动挡 `@EnableAutoConfiguration` + 雷达 `@ComponentScan` |
| 注册 | 类上贴 `@Component` 系，方法上贴 `@Bean`；多实现打架用 `@Primary` 选默认、`@Qualifier` 点名 |
| 注入 | `@Autowired` 按类型、`@Qualifier` 点名、`@Value` 读配置、构造器注入最推荐 |
| Web | 映射 `@XxxMapping`、取参 `@PathVariable/@RequestParam/@RequestBody`、响应 `@RestController`、异常 `@RestControllerAdvice + @ExceptionHandler` |
| 校验 | DTO 字段贴规则（`@NotBlank/@Email/@Min`）、Controller 参数贴 `@Valid` 触发 |
| JPA | 类映射 `@Entity/@Table/@Id/@Column`、关系 `@ManyToOne` 四件套、查询 `@Query/@Param/@Modifying` |
| 事务 | `@Transactional`，查询加 `readOnly=true`，同类调用会失效 |
| AOP | 前 `@Before`、环 `@Around`、返 `@AfterReturning`、异 `@AfterThrowing`、后 `@After` |
| 定时/异步 | 先开总开关 `@EnableXxx`，再用 `@Scheduled`/`@Async` |
| 缓存 | 查 `@Cacheable`、改 `@CachePut`、删 `@CacheEvict`，先开 `@EnableCaching` |
| 条件 | `@ConditionalOnXxx` 句式：有类/没类、有 Bean/没 Bean、有配置/是 Web |
| 配置 | `@ConfigurationProperties(prefix=...)` + `@Component`，一组配置一个类 |
| 测试 | 全量 `@SpringBootTest`、Web 层 `@WebMvcTest`、JPA 层 `@DataJpaTest`，替身 `@MockBean` |
| Lombok | 实体 `@Data+@NoArgsConstructor+@Builder`、服务 `@RequiredArgsConstructor+@Slf4j` |
| 生命周期 | 生 `@PostConstruct`、死 `@PreDestroy`、事件 `@EventListener` |

# 常用注解组合速查

实际开发中，注解往往是"组合拳"。下面是最常见的搭配模板：

## 1. Controller 标准搭配

```java
@RestController                  // 返回 JSON
@RequestMapping("/api/users")   // 路径前缀
@RequiredArgsConstructor        // 构造器注入
@CrossOrigin                    // 跨域（如需）
public class UserController {
    private final UserService userService;
}
```

## 2. Service 标准搭配

```java
@Service
@RequiredArgsConstructor
@Transactional(readOnly = true)  // 默认只读
@Slf4j
public class UserServiceImpl implements UserService {
    private final UserRepository userRepository;
}
```

## 3. Entity 标准搭配

```java
@Entity
@Table(name = "users")
@Getter @Setter                  // 实体不建议用 @Data
@NoArgsConstructor
@AllArgsConstructor
public class User {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
}
```

## 4. DTO 标准搭配

```java
@Data                            // DTO 用 @Data 没问题
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class UserCreateRequest {
    @NotBlank private String name;
    @Email private String email;
}
```

## 5. 配置类标准搭配

```java
@Data
@Component
@ConfigurationProperties(prefix = "app.jwt")
public class JwtProperties {
    private String secret;
    private long expiration;
}
```

## 6. 全局异常处理标准搭配

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<...> handle(BusinessException e) { ... }
}
```

## 7. 定时任务标准搭配

```java
// 启动类
@SpringBootApplication
@EnableScheduling

// 任务类
@Component
@Slf4j
public class ScheduledTasks {
    @Scheduled(cron = "0 0 2 * * ?")
    public void dailyJob() { ... }
}
```
